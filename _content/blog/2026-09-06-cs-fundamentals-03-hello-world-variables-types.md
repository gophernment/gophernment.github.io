# แกะโค้ดทีละคำ: hello world, ตัวแปร และชนิดข้อมูลพื้นฐาน (ตอนที่ 03) — CS Fundamentals: จาก 0 สู่พื้นฐานที่แท้จริง

> 📅 เขียนเมื่อ: 6 กันยายน 2026 | โค้ดตัวอย่างทุกชิ้นทดสอบจริงด้วย Go 1.24.4 (เครื่องที่ใช้เขียนซีรีส์นี้); เวอร์ชันล่าสุดของ Go ณ วันเขียนคือ **1.27.1** (ตรวจจากหน้า https://go.dev/dl — major release ล่าสุด 1.27.0 ออกเมื่อ 19 สิงหาคม 2026 ตาม https://go.dev/doc/devel/release)
> ⚠️ เวอร์ชันเครื่องมือ/ภาษามีการออกใหม่เรื่อย ๆ — ตรวจสอบเอกสารล่าสุดก่อนใช้งานจริงเสมอ

ตอน 02 เรารัน hello world สำเร็จเป็นครั้งแรก — น่าจะรู้สึกเหมือนเปิดประตูเข้าไปในโลกใหม่ได้แล้ว แต่ถ้าสังเกตดี ๆ เรายังแค่ "พิมพ์ตามแล้วมันทำงาน" ยังไม่ได้ตั้งคำถามว่า **แต่ละคำในโค้ด 5 บรรทัด (ไม่นับบรรทัดว่าง) นั้นแปลว่าอะไรกันแน่**

ตอนนี้คือตอนที่เราเปลี่ยนจาก "พิมพ์ตาม" เป็น "เข้าใจ" — เหมือนเรียนภาษา: ก่อนหน้านี้ท่องประโยคได้ ตอนนี้จะเริ่มแยกคำ รู้ว่าคำไหนเป็นคำนาม คำไหนเป็นคำกริยา แล้วค่อยเริ่มแต่งประโยคเอง

เป้าหมายของตอนนี้: **อ่านจบแล้ว คุณอธิบายโค้ด hello world ได้ทุกคำ ประกาศตัวแปร (variable = ช่องเก็บค่า) เป็น และรู้ว่าข้อมูลแต่ละชนิดในคอมพิวเตอร์ต่างกันยังไง** — พร้อมโจทย์ที่เริ่มท้าทายขึ้น

## เริ่มจากของเดิม: แกะ hello world ทีละบรรทัด

เปิด VS Code ขึ้นมา สร้างไฟล์ใหม่ชื่อ `main.go` ในโฟลเดอร์ `gopher-course` ของเรา แล้วพิมพ์โค้ดชุดเดิมจากตอน 02 (ถ้ายังจำไม่ได้ว่าสร้างโฟลเดอร์ยังไง — กลับไปทวนตอน 02 ก่อน):

```go
package main

import "fmt"

func main() {
    fmt.Println("สวัสดี ชาวโลก!")
}
```

คราวนี้เราจะไม่รันทิ้งไว้เฉย ๆ แต่จะแกะ**ทีละบรรทัด** เหมือนช่างเครื่องแกะเครื่องยนต์:

```
บรรทัด 1:  package main          ← ประกาศว่า "ไฟล์นี้อยู่ในกล่อง (package) ชื่อ main"
บรรทัด 2:  (ว่าง — กันบรรทัดให้อ่านง่าย ไม่มีความหมายต่อโค้ด)
บรรทัด 3:  import "fmt"          ← ขอใช้กล่องสำเร็จรูปชื่อ fmt
บรรทัด 4:  (ว่าง)
บรรทัด 5:  func main() {         ← ประกาศฟังก์ชันชื่อ main = จุดเริ่มต้นของโปรแกรม
บรรทัด 6:      fmt.Println("สวัสดี ชาวโลก!")   ← คำสั่งที่ 1 (และคำสั่งเดียว) ของเรา
บรรทัด 7:  }                     ← ปีกกาปิด (ปีกกา = เครื่องหมาย { }): จบฟังก์ชัน main
```

ทีนี้มาทำความเข้าใจแต่ละคำ — ขออธิบายทีละคำ ใจเย็น ๆ:

### `package main` — กล่องที่บรรจุโค้ดของเรา

**package** (แพ็กเกจ = กล่อง/ซองสำหรับรวมโค้ดเข้าด้วยกัน อ่านว่า แพ็ก-เกจ ไม่ใช่ พัสดุ) คือวิธีที่ภาษา Go จัดระเบียบโค้ด: โค้ดทุกไฟล์ต้องอยู่ "ในกล่อง" ไหนกล่องหนึ่งเสมอ บรรทัดแรกของทุกไฟล์ `.go` จึงต้องเป็น `package <ชื่อกล่อง>` เสมอ

ทำไมต้องมีกล่อง? เพราะพอโปรเจกต์ใหญ่ขึ้น โค้ดอาจมีเป็นร้อย ๆ ไฟล์ — ถ้าเอาทุกอย่างปนกันหมดจะหาไม่เจอ กล่องช่วยแยก: กล่องนี้เก็บโค้ดเกี่ยวกับการคำนวณ กล่องนั้นเก็บโค้ดเกี่ยวกับการแสดงผล (จะเห็นตอน import ข้างล่าง)

แล้วทำไมชื่อต้องเป็น **`main`** พอดี? เพราะมีกฎพิเศษของ Go อยู่ว่า: **โปรแกรมที่ "รันได้ด้วยตัวเอง" ต้องอยู่ใน package ชื่อ main** — เปรียบเหมือนกฎของอาคาร: ตึกที่จะเปิดเป็นร้านค้าได้ต้องมีป้ายชื่อตามแบบที่กำหนดไว้ ส่วน package ชื่ออื่นเป็น "ชิ้นส่วน" ที่รอถูกเรียกใช้ ไม่ใช่ตัวโปรแกรมเต็มตัว (จะเข้าใจลึกขึ้นตอน 05 เรื่องฟังก์ชันและการแบ่งงาน)

### `import "fmt"` — ขอยืมกล่องสำเร็จรูป

**import** (อิมพอร์ต = นำเข้า) คือคำสั่ง "ขอยืมของในกล่องอื่นมาใช้" ส่วน **fmt** คือชื่อกล่องสำเร็จรูปที่ภาษา Go แถมมาให้ (ย่อจาก format = จัดรูปแบบ) — ข้างในมีฟังก์ชัน (function = กล่องเล็ก ๆ ที่ทำงานอย่างหนึ่งให้เรา เราเรียกใช้มันทีละครั้ง) สำหรับพิมพ์ข้อความออกจอ

ของที่แถมมากับภาษานี้เรียกรวมว่า **standard library** (สแตนดาร์ด ไลบรารี = ห้องสมุดมาตรฐาน = ชุดกล่องสำเร็จรูปที่มากับตัวภาษา ไม่ต้องดาวน์โหลดเพิ่ม) — ตอน 02 เราติดตั้ง Go ไป ตัว standard library มาด้วยในนั้นแล้ว เราจึงแค่ "import" ก็ใช้ได้ทันที

จุดสำคัญ: **import แล้วไม่ใช้ = compile ไม่ผ่าน** — compile (คัมไพล์) คือขั้นตอนที่ตัวแปลภาษาตรวจและแปลงโค้ดของเรา ถ้าโค้ดผิดกฎแม้จุดเดียวจะไม่ยอมสร้างโปรแกรมให้ (รายละเอียดด้านล่าง) — (จำ error หน้าตาแบบนี้ไว้ — เป็นโจทย์ข้อ 3 ของตอน 02 ที่ให้ทายไว้ ตอนนี้เฉลยได้เลย):

```
./main.go:3:8: "fmt" imported and not used
```

(ทดสอบจริง — แปลว่า "กล่อง fmt ที่ import ไว้ในบรรทัด 3 ไม่ถูกใช้" Go บอกได้แม่นถึงตำแหน่ง: ไฟล์ main.go บรรทัด 3 หลัก 8)

### `func main() { ... }` — จุดเริ่มต้นของทุกโปรแกรม

**func** (ย่อจาก function = ฟังก์ชัน) คือคำสัญญาณว่า "ต่อไปนี้คือการประกาศฟังก์ชัน" — ฟังก์ชันคือชุดคำสั่งที่ทำงานร่วมกันเป็นหน่วยเดียว เปรียบได้กับสูตรอาหาร: ชื่อสูตร + ส่วนผสม (input = ของที่ส่งเข้าไป) + ขั้นตอน

**`main`** คือชื่อฟังก์ชัน — และเป็นชื่อพิเศษอีกครั้ง: **โปรแกรม Go ทุกโปรแกรมต้องมีฟังก์ชันชื่อ main เพราะมันคือ "ประตูหน้า" ที่ระบบปฏิบัติการ (OS = ตัวจัดการเครื่องที่เราเรียนตอน 01) เปิดให้โปรแกรมเราเข้า** — พอเราสั่ง `go run main.go` OS จะเรียกฟังก์ชัน main ของเราให้ทำงานทีละบรรทัด ไล่จากบรรทัดแรกในปีกกาไปจนจบ

**`()`** (วงเล็บกลม) คือที่สำหรับ "ของที่ส่งให้ฟังก์ชัน" เรียกว่า argument (อาร์กิวเมนต์ = ตัวที่ส่งให้ฟังก์ชันใช้ทำงาน) — ฟังก์ชัน main ของเราไม่ต้องการของเพิ่ม จึงวางว่างไว้

**`{` กับ `}`** (ปีกกาเปิด-ปิด = curly brace) คือเครื่องหมาย "ขอบเขต": บอกว่าคำสั่งไหนบ้างอยู่ในฟังก์ชันนี้ — ทุกอย่างระหว่างปีกกาคือ "เนื้อตัว" ของฟังก์ชัน main

### `fmt.Println("สวัสดี ชาวโลก!")` — คำสั่งเดียวของเรา

แยกเป็นชิ้น ๆ:

- **`fmt.Println`** = "เรียกฟังก์ชันชื่อ Println (ย่อจาก print line = พิมพ์แล้วขึ้นบรรทัดใหม่) ที่อยู่ในกล่อง fmt" — สังเกตจุด `.` คั่นกลาง เหมือนพูดว่า "ในกล่อง fmt มีฟังก์ชัน Println" — พอจบบรรทัดนี้ ข้อความจะถูกพิมพ์ออกจอ แล้วเคอร์เซอร์เลื่อนขึ้นบรรทัดใหม่ให้อัตโนมัติ
- **`"สวัสดี ชาวโลก!"`** คือ argument ที่ส่งให้ Println — ข้อความที่อยู่ในเครื่องหมายคำพูดคู่ (`"`) นี้เรียกว่า **string** (สตริง = สาย/เส้น = ข้อมูลชนิดข้อความ — คำนี้จะอยู่กับเราไปตลอดอาชีพ เรียนเต็มรูปแบบในหัวข้อชนิดข้อมูลด้านล่าง)
- สังเกตว่าเรา**ไม่ต้องใส่เครื่องหมาย `;` (เซมิโคลอน) ท้ายบรรทัด** — ในภาษา C (ที่เราจะเรียนตอน 13) ต้องใส่ทุกบรรทัด แต่ Go เติมให้อัตโนมัติตอนจบบรรทัด เราจึงเขียนแค่ขึ้นบรรทัดใหม่ก็พอ

### สิ่งที่ไม่เห็นในโค้ด แต่สำคัญ: comment

ในโค้ดตัวอย่างบางช่วงผมจะใส่ข้อความที่ขึ้นต้นด้วย `//` เช่น:

```go
// นี่คือ comment (คอมเมนต์ = ข้อความอธิบาย) — Go ไม่สนใจบรรทัดนี้เลย
fmt.Println("สวัสดี") // comment ต่อท้ายโค้ดก็ได้
```

`//` คือ **comment** — ข้อความที่เขียนเพื่อให้**คน**อ่าน ไม่ใช่ให้คอมพิวเตอร์อ่าน Go จะข้ามมันไปทั้งหมด comment คือสมุดโน้ตติดข้างโค้ด ใช้บอกว่า "บรรทัดนี้ทำอะไร ทำไมถึงทำแบบนี้" — dev มืออาชีพเขียน comment เพื่อเพื่อนร่วมทีม (รวมถึงตัวเราในอีก 6 เดือนข้างหน้าที่อาจลืมไปแล้วว่าโค้ดนี้คิดอะไรอยู่)

## ทำไมต้องรู้ "ภาษา" ของภาษาถึงขนาดนี้

มือใหม่อาจสงสัย: "แค่จะพิมพ์ข้อความออกจอ ทำไมต้องรู้ว่า package คืออะไร func คืออะไร — พิมพ์ตามแล้วรันได้ไม่พอหรือ?"

ขอตอบแบบอาจารย์ตรง ๆ: เพราะ**ตอนนี้คือตอนที่เรากำหนดอนาคตของการเรียน** ถ้าคุณผ่านตอนนี้ไปโดยคิดว่า "โค้ดคือชุดคำวิเศษที่พิมพ์ตามได้" — อีก 5 ตอนข้างหน้าเมื่อโค้ดยาวขึ้นเป็น 50 บรรทัด คุณจะหลงทางเพราะต่อคำวิเศษไม่ถูก แต่ถ้าวันนี้คุณเข้าใจว่าโค้ดคือ**ประโยคที่มีไวยากรณ์** (syntax = ซินแทกซ์ = กฎการเรียงคำของภาษา) คุณจะเริ่ม "แต่งประโยค" เองได้ ไม่ใช่ท่อง

และมีเหตุผลเชิงลึกกว่านั้น ที่โยงกับ "ตึก 5 ชั้น" จากตอน 01:

- **compiler ต้องอ่านโค้ดเป็น "ประโยค" ก่อนถึงจะแปลได้** — จำได้ไหมตอน 01 ว่า compiler (ตัวแปลภาษาโปรแกรมเป็นภาษาเครื่อง) คือเครื่องจักรที่อ่านโค้ดเราแล้วแปลงเป็นภาษาเครื่อง? เครื่องจักรนั้นอ่านทีละคำและเช็คไวยากรณ์: คำว่า `package` ต้องมาก่อน `import` ต้องมี string อยู่ในเครื่องหมายคำพูด ต้องมีปีกกาครบทุกอัน — ถ้าผิดแม้จุดเดียว compiler จะปฏิเสธทั้งไฟล์ (error แบบ syntax error ที่เจอตอน 02) เราเรียนโครงสร้างตอนนี้ จึงเท่ากับเรียน "ไวยากรณ์ที่ compiler ตรวจ" นั่นเอง (ตอน 26–27 เราจะสร้างตัวอ่านโค้ดแบบนี้เองจากศูนย์!)
- **ตัวแปรกับชนิดข้อมูลคือของที่ compiler ตรวจ "ก่อน" โปรแกรมเกิด** — จุดเด่นของภาษาตระกูลที่ Go อยู่ในกลุ่ม (เรียกว่า statically typed = สเตติกัลลี ไทป์ด = ภาษาที่ตรวจชนิดข้อมูลตอน compile) คือ compiler จับความผิดพลาดได้**ตั้งแต่ก่อนรัน** เช่น เอาข้อความไปบวกเลข — เรื่องนี้คือหัวใจของหัวข้อถัดไป
- **ฟังก์ชัน main คือจุดที่ OS กับโปรแกรมเราพบกัน** — ตอน 19 เราจะเรียน syscall (ระบบเรียก = ช่องที่โปรแกรมขอให้ OS ทำงาน) และเห็นว่า OS ต้องรู้ว่าจุดเริ่มของโปรแกรมอยู่ตรงไหน ฟังก์ชัน main คือสัญญาที่ภาษาทุกภาษาทำกับ OS: "จุดเริ่มของฉันอยู่ตรงนี้" (ภาษา C ก็มี main เหมือนกัน — ตอน 13 จะเห็นของจริง)

พูดให้ง่าย: **ตอนนี้คุณไม่ได้แค่เรียนวิธีพิมพ์โค้ด แต่กำลังเรียน "ภาษา" ที่คน 3 กลุ่มพูดกัน — คุณ, compiler และ OS**

## ตัวแปร: กล่องใส่ของที่มีป้ายชื่อ

โค้ดที่พิมพ์ข้อความตายตัวแบบ hello world ยัง "โง่" อยู่ เพราะข้อมูลทุกอย่างเขียนตายในโค้ด — โปรแกรมจริงต้อง**จำข้อมูล**ได้ เช่น จำชื่อคุณ จำราคาสินค้า จำจำนวนครั้งที่กดปุ่ม แล้วเอาข้อมูลนั้นมาคิดต่อ

ที่เก็บข้อมูลในโปรแกรมเรียกว่า **variable** (แวเรียเบิล = ตัวแปร — แปลตรงตัวว่า "สิ่งที่เปลี่ยนค่าได้") ขอเปรียบให้เห็นภาพ: variable คือ**กล่องใส่ของที่มีป้ายชื่อติดอยู่**

![กายวิภาคของตัวแปร: ชื่อป้าย ชนิด ค่า](/assets/diagrams/03-var-anatomy.svg)

เวลาเขียนโปรแกรม เราสั่งว่า "ขอกล่องใบหนึ่ง ชื่อ age เอาไว้ใส่เลขจำนวนเต็ม ใส่เลข 30 ลงไปก่อน" — จากนั้นเมื่อไรก็ตามที่เขียนคำว่า `age` ในโค้ด โปรแกรมจะรู้ทันทีว่าหมายถึง "ค่าที่อยู่ในกล่อง age ตอนนี้"

### ประกาศตัวแปร 2 แบบ: `var` กับ `:=`

ภาษา Go ให้วิธีประกาศตัวแปร 2 แบบ ใช้คนละสถานการณ์:

**แบบที่ 1: `var` — บอกชนิดเองอย่างชัดเจน**

```go
var name string      // ขอกล่องชื่อ name เอาไว้ใส่ข้อความ (ยังไม่ใส่ของ)
name = "สมชาย"       // เปิดกล่อง ใส่ข้อความ "สมชาย" ลงไป (assign = แอสไซน์ = กำหนด/ใส่ค่า)

var age int = 30     // ขอกล่องชื่อ age ชนิด int แล้วใส่ 30 ลงไปในบรรทัดเดียวเลย
```

- `var` (ย่อจาก variable) คือคำสั่ง "ขอประกาศตัวแปร"
- คำว่า `int`, `string` ที่ตามมาคือ **type** (ไทป์ = ชนิด/ประเภทของข้อมูล) — บอกว่ากล่องนี้จะเก็บของชนิดไหนได้บ้าง
- เครื่องหมาย `=` คือคำสั่ง "ใส่ค่านี้ลงกล่อง" เรียกว่า assignment (แอสไซเมนต์ = การกำหนดค่า) — สังเกตว่าเป็นการ**ใส่ค่าทีหลัง**ได้ด้วย ไม่จำเป็นต้องใส่ตอนขอกล่อง

**แบบที่ 2: `:=` — ให้ Go เดาชนิดให้**

```go
city := "กรุงเทพฯ"   // Go เห็นว่าใส่ข้อความ → เดาเองว่า city เป็น string
score := 95          // Go เห็นว่าใส่เลขจำนวนเต็ม → เดาเองว่า score เป็น int
```

`:=` (อ่านว่า "walrus" = วอลรัส เพราะหน้าตาเหมือนวอลรัสนอนตะแคง — dev ชอบตั้งชื่อเล่นแบบนี้) แปลว่า "ประกาศตัวแปรใหม่ แล้วใส่ค่าให้ — ส่วนชนิดอะไร Go เดาเองจากค่าที่ให้" วิธีนี้สั้นและอ่านง่าย ใช้บ่อยมากใน Go

**แล้วจะเลือกแบบไหน?** กฎง่าย ๆ ของ dev Go:
- ใส่ค่าให้ตั้งแต่แรก และอยากได้โค้ดสั้น → ใช้ `:=`
- ยังไม่รู้ค่าตอนประกาศ (จะไปกรอกทีหลัง เช่น รับจากผู้ใช้) → ใช้ `var` เต็มรูปแบบ

ทั้งสองแบบให้ผลเหมือนกัน — ต่างแค่ "ใครเป็นคนบอกชนิด": `var` = เราบอกเอง, `:=` = ให้ Go เดา

### ตัวแปรเปลี่ยนค่าได้ แต่ "ชนิด" เปลี่ยนไม่ได้

ชื่อ "ตัวแปร" บอกอยู่แล้วว่าเปลี่ยนได้ — ลองดู:

```go
score := 95
fmt.Println(score) // 95
score = 100        // เปิดกล่อง เอาของเก่าออก ใส่ 100 แทน (ใช้ = ธรรมดา เพราะกล่องมีอยู่แล้ว)
fmt.Println(score) // 100
```

จุดที่มือใหม่สับสนบ่อย: **ประกาศครั้งแรกใช้ `:=` แต่เปลี่ยนค่าครั้งต่อไปใช้ `=`** — ถ้าเผลอใช้ `:=` ซ้ำกับชื่อเดิม Go จะบ่นว่า "no new variables on left side of :=" (ไม่มีตัวแปรใหม่ทางซ้ายของ :=) เพราะ `:=` แปลว่า "**ขอกล่องใหม่**" แต่กล่องชื่อนี้มีอยู่แล้ว

ที่สำคัญกว่านั้น: กล่องที่ขอไปแล้ว**ชนิดจะเปลี่ยนไม่ได้** — กล่องที่บอกว่าใส่ int ได้ จะเอา string ไปยัดไม่ได้:

```go
score := 95
score = "หนึ่งร้อย"  // error: cannot use "หนึ่งร้อย" (untyped string constant) as int value in assignment
```

(ทดสอบจริง — Go บอกว่า "ใช้ข้อความ 'หนึ่งร้อย' เป็นค่า int ไม่ได้") — สังเกตคำว่า **untyped** (อันไทป์ด) ใน error: หมายถึงค่าที่เราเขียนตรง ๆ ในโค้ด เช่น "หนึ่งร้อย" หรือ 2026 ซึ่งยังไม่มีชนิดตายตัวในตัวเอง จนกว่า compiler จะเทียบกับที่เอาไปใช้ (ตรงนี้คือจับคู่กับ int) — คำนี้จะโผล่ใน error บ่อย ๆ ขอให้จำไว้ นี่คือสิ่งที่เรียกว่า **type safety** (ไทป์ เซฟตี้ = ความปลอดภัยของชนิด = ระบบที่กันไม่ให้ข้อมูลผิดชนิดปนกัน) — compiler ทำหน้าที่เป็นยามเฝ้ากล่องทุกใบ คอยห้ามไม่ให้เราเอาของผิดชนิดใส่ — ดุตอนนี้ แต่จะขอบคุณมันตอนโปรเจกต์ใหญ่ เพราะบั๊ก (bug = ข้อผิดพลาด/จุดพังในโปรแกรม) จำนวนมหาศาลในโลกจริงเกิดจาก "ข้อมูลชนิดไม่ตรงกัน" พอ compiler จับได้ตั้งแต่ต้น เราก็ไม่ต้องไปนั่งงมตอนโปรแกรมรัน

### const: กล่องที่ใส่แล้ว "ล็อก" ไม่ให้เปลี่ยน

บางค่ามีไว้ใช้ตลอดทั้งโปรแกรมและ**ห้ามเปลี่ยน** เช่น ชื่อโปรแกรม หรือค่าคงที่ทางคณิตศาสตร์ — เราใช้ **const** (ย่อจาก constant = คอนสแตนต์ = ค่าคงที่):

```go
const pi = 3.14159   // pi จะเป็น 3.14159 ตลอดกาล
fmt.Println(pi)

pi = 3.14            // error: cannot assign to pi (neither addressable nor a map index expression)
```

(ทดสอบจริง — คำเตือนนี้ยาวหน่อย แต่แปลง่าย ๆ ว่า "จะกำหนดค่าให้ pi ไม่ได้ เพราะ pi เป็น const") const ต่างจาก var ตรงที่**ต้องใส่ค่าให้ตอนประกาศ** (ไม่มีกล่องว่างสำหรับ const) และ**ใส่ทีหลังไม่ได้อีก** — เหตุผลของ const คือกันตัวเองเผลอไปแก้ค่าสำคัญโดยไม่รู้ตัว ถ้าโปรแกรมมี "ตัวเลขลึกลับ" กระจายเต็มโค้ด เช่น `price * 0.07` — 0.07 คืออะไร? ภาษี? ค่าคอมมิชชัน? — การตั้ง const ชื่อ `taxRate` แล้วใช้ชื่อนั้นแทนตัวเลข จะทำให้โค้ดอ่านรู้เรื่องขึ้นมาก (dev เรียกตัวเลขลึกลับแบบนี้ว่า magic number = เมจิก นัมเบอร์ = เลขที่โผล่มาลอย ๆ โดยไม่มีคำอธิบาย — เป็นสิ่งที่ควรเลี่ยง)

### กติกาการตั้งชื่อ: เล็ก-ใหญ่ ต่างกัน และห้ามใช้คำสงวน

- ตั้งชื่อตัวแปรเป็นอะไรก็ได้ที่**ขึ้นต้นด้วยตัวอักษรหรือ _ (underscore = อันเดอร์สกอร์ = ขีดล่าง)** แล้วตามด้วยตัวอักษร/ตัวเลข/underscore เช่น `age`, `score1`, `my_name` — แต่ dev Go นิยม **camelCase** (แคมเมล เคส = การเขียนแบบอูฐ: คำแรกตัวเล็ก คำต่อไปตัวใหญ่ ไม่มีขีดคั่น) เช่น `myName`, `totalPrice` เพราะเห็นแล้วอ่านง่าย
- **Go แยกพิมพ์เล็กพิมพ์ใหญ่** — `Age` กับ `age` คือคนละตัวแปรกัน (จำ error `undefined: fmt.println` ตอน 02 ได้ไหม — นั่นคือผลของกติกานี้)
- **ห้ามใช้ "คำสงวน"** (keyword = คีย์เวิร์ด = คำที่ภาษาสงวนไว้ใช้เป็นคำสั่ง) ตั้งชื่อ เช่น `var`, `func`, `package` — คำเหล่านี้คือไวยากรณ์ของภาษา เอาไปตั้งชื่อกล่องไม่ได้ เหมือนเราไม่ตั้งชื่อลูกว่า "นายกฯ"
- ภาษา Go **อนุญาตให้ใช้ชื่อภาษาไทยเป็นตัวแปรได้จริง** เช่น `ภาษา := "ไทย"` (ทดสอบจริง — รันผ่าน!) เพราะ Go รองรับตัวอักษรยูนิโคด (unicode = มาตรฐานรหัสตัวอักษรสากล — ตอน 08 จะลงลึก) — แต่มีเงื่อนไข: ใช้ได้เฉพาะคำที่**ไม่มีสระหรือวรรณยุกต์ซ้อนบนตัวอักษร** เช่น `ภาษา`, `ไทย` — ส่วนคำอย่าง `ชื่อ` (มี ื กับ ้ ซ้อนบนตัว ช) **ใช้ไม่ได้** เพราะ Go ให้เฉพาะ "ตัวอักษรเต็มตัว" เท่านั้นเป็นชื่อตัวแปรได้ เครื่องหมายซ้อนพวกนั้นไม่นับเป็นอักษร (error จริง: `invalid character U+0E37 'ื' in identifier`) — แต่ต่อให้ใช้ได้ dev ทั่วโลกรวมถึงทีมเรา**ก็ไม่นิยม**อยู่ดี เพราะโค้ดต้องอ่านร่วมกับคนทั้งโลก เครื่องมือบางตัวจัดการชื่อภาษาไทยไม่ดี และภาษาไทยไม่มีช่องว่างระหว่างคำทำให้อ่านชื่อยาวยาก — ฝึกใช้ชื่ออังกฤษตั้งแต่ตอนนี้ จะชินไปจนทำงานจริง

## ชนิดข้อมูลพื้นฐาน 4 แบบ: int, float64, string, bool

คอมพิวเตอร์เก็บข้อมูลเป็นเลข 0 กับ 1 เท่านั้น (ตอน 08 จะเรียนการแทนข้อมูลเต็มรูปแบบ) แต่**คน**เขียนโปรแกรมคิดเป็นตัวเลข ข้อความ จริง/เท็จ — ภาษาโปรแกรมจึงเป็นสะพาน: เราบอกชนิดของข้อมูล compiler จะจัดการแปลงเป็น 0/1 ให้เอง

ชนิดข้อมูลพื้นฐานของ Go ที่ใช้บ่อยสุดมี 4 แบบ (ในคอร์สนี้จะใช้ 4 ตัวนี้เป็นหลัก ไปอีกไกล):

| ชนิด (type) | อ่านว่า | เก็บอะไร | ตัวอย่างค่าที่ใส่ได้ |
|---|---|---|---|
| `int` | อินท์ (ย่อจาก integer = อินทีเจอร์) | **จำนวนเต็ม** ไม่มีจุดทศนิยม (บวก/ลบ/ศูนย์) | `-5`, `0`, `30`, `1000000` |
| `float64` | โฟลต-ซิกซ์ตีโฟร์ | **จำนวนทศนิยม** (มีจุดทศนิยมได้) | `3.14`, `-0.5`, `25.0` |
| `string` | สตริง | **ข้อความ** ต้องอยู่ในเครื่องหมายคำพูดคู่ `"` | `"สวัสดี"`, `"Go"`, `"123"` |
| `bool` | บูล (ย่อจาก boolean = บูลเลียน) | **จริงหรือเท็จ** แค่ 2 ค่า | `true` (จริง), `false` (เท็จ) |

(ตัวเลข 64 ใน `float64` หมายถึงใช้เนื้อที่ 64 บิต (bit = บิต = หน่วยข้อมูลเล็กสุด คือ 0 หรือ 1 ตัวเดียว) ในการเก็บ — มี `float32` ที่เบากว่าแต่น้อยความละเอียดด้วย ส่วน int ก็มีรุ่นย่อย int8/int16/int32/int64 — แต่คอร์สนี้ใช้ `int` กับ `float64` เป็นหลักพอ ชนิดละเอียดกว่านี้เรียนตอน 08)

ลองรันโปรแกรมที่ใช้ครบทั้ง 4 ชนิด — สร้างไฟล์ `types.go` ในโฟลเดอร์ `gopher-course`:

```go
package main

import "fmt"

func main() {
    var days int = 7               // จำนวนเต็ม
    var price float64 = 25.50      // จำนวนทศนิยม
    var greeting string = "สวัสดี" // ข้อความ
    var isOpen bool = true         // จริง/เท็จ

    fmt.Println(days)
    fmt.Println(price)
    fmt.Println(greeting)
    fmt.Println(isOpen)
}
```

รัน `go run types.go` — ผลลัพธ์จริงบนเครื่องผม:

```
7
25.5
สวัสดี
true
```

สังเกต 2 จุด: `25.50` พอพิมพ์ออกมาเป็น `25.5` (เลข 0 ต่อท้ายไม่มีความหมายกับคอมพิวเตอร์) และ `fmt.Println` ใช้ argument กี่ตัวก็ได้ คั่นด้วยเครื่องหมายจุลภาค (comma) มันจะพิมพ์ให้เรียงกันโดยเว้นช่องว่างให้อัตโนมัติ

### กับดักที่ 1 (เรื่องที่มือใหม่พลาดบ่อยที่สุด): int กับ float64 "ไม่ใช่ของอย่างเดียวกัน"

คนที่เพิ่งหัดเขียนโปรแกรมมักคิดว่า "เลขก็คือเลข จะใส่ชนิดไหนก็ได้" — **ไม่จริง** ใน Go (และภาษาตระกูลเดียวกัน) `int` กับ `float64` คือของคนละชนิดกัน และ**ผสมกันทำเลขไม่ได้**:

```go
a := 10     // Go เดา: int
b := 2.5    // Go เดา: float64
fmt.Println(a + b) // error!
```

error จริงที่ได้:

```
./types_bad.go:8:17: invalid operation: a + b (mismatched types int and float64)
```

(หมายเหตุ: เลขบรรทัด `8:17` นับจากไฟล์เต็ม `types_bad.go` ของผม ซึ่งมี `package main` / `import "fmt"` / `func main() {` นำหน้า 5 บรรทัด — snippet ข้างบนตัดมาเฉพาะโค้ดในฟังก์ชัน เลขบรรทัดจึงไม่ตรงกับที่เห็นใน snippet)

(ทดสอบจริง — แปลว่า "การคำนวณ a + b ใช้ไม่ได้: ชนิดไม่ตรงกัน ระหว่าง int กับ float64") — สังเกตคำว่า **mismatched types** (มิสมัทช์ ไทป์ส = ชนิดไม่ตรงกัน) error นี้จะตามหลอกหลอนคุณทั้งอาชีพ ขอให้จำหน้าไว้ให้ขึ้นใจ

แล้วจะบวกเลข 10 กับ 2.5 ยังไง? วิธีคือ**แปลงชนิดให้ตรงกันก่อน** — ภาษา Go ให้เรา "หล่อ" ค่าจากชนิดหนึ่งไปอีกชนิดหนึ่งด้วยการเขียนชื่อชนิดวงเล็บค่าอยู่ข้างหลัง เรียกว่า **type conversion** (ไทป์ คอนเวอร์ชัน = การแปลงชนิด):

```go
a := 10
b := 2.5
fmt.Println(float64(a) + b) // 12.5 — แปลง a จาก int เป็น float64 ก่อน แล้วค่อยบวก
```

`float64(a)` อ่านว่า "เอาค่า a ไปหล่อเป็น float64" — พอทั้งคู่เป็น float64 ด้วยกัน บวกกันได้ทันที (ชนิดไหนไม่ตรง ให้แปลงอีกฝ่ายให้กลายเป็นชนิดเดียวกัน — กฎทองข้อนี้)

### กับดักที่ 2: การหารจำนวนเต็ม "ตัดเศษทิ้ง"

เรื่องนี้ทำให้มือใหม่ทั่วโลกงง เพราะ**เครื่องคิดเลขกับคอมพิวเตอร์ตอบไม่เหมือนกัน** ลองรัน:

```go
package main

import "fmt"

func main() {
    fmt.Println(7 / 2)      // ผลลัพธ์?
    fmt.Println(7.0 / 2.0)  // ผลลัพธ์?
}
```

ผลจริง:

```
3
3.5
```

`7 / 2` ตอบ **3** ไม่ใช่ 3.5! เพราะเลขทั้งสองตัวเป็น int (จำนวนเต็ม) — **int หาร int ให้ผลเป็น int เสมอ เศษถูกตัดทิ้ง** (ภาษาโปรแกรมเรียกว่า integer division = อินทีเจอร์ ดิวิชัน = การหารแบบจำนวนเต็ม) ส่วน `7.0 / 2.0` เป็น float64 ทั้งคู่ จึงได้ 3.5 เต็ม ๆ

จำไว้ว่า: **ชนิดของผลลัพธ์ขึ้นกับชนิดของตัวตั้งตัวหาร** — ถ้าอยากได้คำตอบทศนิยม ต้องมีตัวเลขทศนิยมร่วมวงด้วยสักตัว (`7.0 / 2` หรือ `float64(7) / 2` ก็ได้)

ยังมีตัวดำเนินการ (operator = โอเปอเรเตอร์ = เครื่องหมายที่สั่งให้คำนวณ/เปรียบเทียบ) ที่ควรรู้จักครบในวันนี้:

```go
a := 10
b := 3

fmt.Println(a + b) // 13  — บวก
fmt.Println(a - b) // 7   — ลบ
fmt.Println(a * b) // 30  — คูณ (ใช้ * ไม่ใช่ x)
fmt.Println(a / b) // 3   — หารแบบ int: เศษถูกตัดทิ้ง!
fmt.Println(a % b) // 1   — modulus (มอดูลัส) = หารเอาแต่เศษ: 10 หาร 3 ได้ 3 เศษ 1
```

เครื่องหมาย `%` คือตัวดำเนินการที่มือใหม่ไม่ค่อยรู้จักแต่มีประโยชน์มาก (เอาไว้เช็คเลขคู่คี่ หาวันที่ซ้ำรอบ ฯลฯ) — อ่านว่า modulus แปลว่า "หารแล้วเอาส่วนเหลือ"

### กับดักที่ 3: ข้อความ (string) ต่อกันได้ แต่ "บวก" กับเลขไม่ได้

string ก็มีตัวดำเนินการ `+` ของมัน — แต่ความหมายต่างกัน: string + string คือการ**ต่อข้อความ** (concatenation = คอนแคททิเนชัน = การต่อสายข้อความเข้าด้วยกัน) ไม่ใช่การบวกเลข:

```go
first := "สวัสดี"
second := "ชาวโลก"
fmt.Println(first + " " + second) // สวัสดี ชาวโลก
```

(`" "` คือ string ที่มีช่องว่างหนึ่งช่อง ใช้คั่นกลาง) แต่ระวัง — ถ้าเผลอเอาข้อความไปบวกเลข:

```go
fmt.Println("ปี " + 2026) // error!
```

error จริง:

```
./main.go:6:17: invalid operation: "ปี " + 2026 (mismatched types untyped string and untyped int)
```

(หมายเหตุ: เลขบรรทัด `6:17` นับจากไฟล์เต็ม `main.go` ของผมที่มี `package main` / `import "fmt"` / `func main() {` นำหน้า — snippet ข้างบนตัดมาเฉพาะบรรทัดในฟังก์ชัน)

(ทดสอบจริง — "เอาข้อความบวกกับเลขใช้ไม่ได้: ชนิดไม่ตรงกัน"; คำว่า untyped ใน error หมายถึงค่าที่เขียนตรง ๆ ยังไม่มีชนิด — อ่าน gloss ในหัวข้อตัวแปร) — ต่อให้ `"2026"` จะหน้าตาเหมือนเลข แต่พออยู่ในเครื่องหมายคำพูด มันคือ**ข้อความ** ไม่ใช่จำนวน — `"2" + "2"` ให้ผลเป็น `"22"` (ต่อข้อความ) ไม่ใช่ `4` (บวกเลข) จุดนี้สับสนกันบ่อย ขีดเส้นใต้ไว้

### bool: ความจริงเพียง 2 ค่า

`bool` เก็บได้แค่ `true` (จริง) กับ `false` (เท็จ) — ตัวมันเองดูง่าย แต่**มันคือรากฐานของทุกการตัดสินใจในโปรแกรม**: โปรแกรมจะ "คิด" ได้ ก็ต่อเมื่อมี bool ให้นำไปตัดสินใจ เช่น "ถ้าผู้ใช้กดปุ่ม (true) ให้ทำอย่างนี้" — เราจะใช้ bool เต็มรูปแบบตอนหน้า (ตอน 04: if/else)

วันนี้ขอแนะนำที่มาของ bool ให้นิด: มักเกิดจาก**การเปรียบเทียบ** ซึ่งใช้เครื่องหมาย `==` (เท่ากับไหม), `!=` (ไม่เท่ากับไหม), `<`, `>`, `<=`, `>=`:

```go
fmt.Println(10 > 3)   // true  — 10 มากกว่า 3 จริง
fmt.Println(10 == 3)  // false — 10 เท่ากับ 3 ไหม? ไม่
```

**ระวัง `=` กับ `==` ปนกัน** — `=` คือ "ใส่ค่า" ส่วน `==` คือ "ถามว่าเท่ากันไหม" ผิดคนละเรื่องเลย (จะเห็นตอน 04 ว่าถ้าเผลอใช้ผิด โปรแกรมพังทั้งโปรเจกต์)

## ตัวแปรอยู่ "ที่ไหน" ในคอมพิวเตอร์จริง — เกริ่นสู่ตอนหน้า ๆ

ขอพาคุณมองลึกลงไปอีกชั้นหนึ่ง เพราะคอร์สนี้สัญญาไว้แล้วว่าจะขุดให้ถึง "พื้นฐานที่แท้จริง": **ตัวแปรที่เราเขียนในโค้ด ไปอยู่ที่ไหนในเครื่องจริง?**

คำตอบสั้น ๆ: อยู่ใน **RAM** (แรม = หน่วยความจำหลักของเครื่อง — ที่เก็บข้อมูลชั่วคราวขณะโปรแกรมทำงาน) ซึ่งจริง ๆ แล้วคือ**ช่องเล็ก ๆ เรียงกันเป็นล้าน ๆ ช่อง แต่ละช่องมีเลขที่ (address = แอดเดรส = ที่อยู่) กำกับ**

![ตัวแปรตอน compile กับตอน run ใน RAM](/assets/diagrams/03-compile-vs-run-ram.svg)

ความเข้าใจ 3 ข้อที่จะติดตัวคุณไปตลอด:

1. **ชื่อตัวแปร (`age`) ไม่ได้ถูกเก็บใน RAM** — RAM เก็บแต่ค่า (30) ส่วนชื่อเป็นแค่ "ป้าย" ที่ compiler ใช้ตอน compile; พอ compile เสร็จ ชื่อจะกลายเป็นเลขที่ช่อง (address) — dev ที่ทำงานกับภาษา C (ตอน 13–14) จะเห็นเลขที่ช่องนี้ด้วยตาตัวเองผ่านสิ่งที่เรียกว่า pointer (พอยน์เตอร์ = ตัวชี้ตำแหน่ง)
2. **ชนิดข้อมูล = การบอก compiler ว่า "จองช่องใหญ่แค่ไหน"** — int ต้องการเนื้อที่จำนวนหนึ่ง float64 ต้องการอีกขนาด string ยาวเท่าไรก็ได้ต้องจัดการพิเศษ — compiler ใช้ชนิดเป็นตัวกำหนดขนาดการจอง (ตอน 10 เราจะสร้าง RAM จำลองและเห็นการจองช่องด้วยตา; ตอน 08 จะเห็นว่าตัวเลข 30 ถูกเก็บเป็น 0/1 ยังไง)
3. **การ "เปลี่ยนค่าตัวแปร" คือการเอาค่าใหม่ไปทับช่องเดิม** — `age = 31` แปลว่า "ไปที่ช่องของ age แล้วเขียนเลข 31 ทับเลข 30 เดิม" — ไม่ได้ขอกล่องใหม่

ประเด็นที่ 2 คือเหตุผลลึกที่ compiler ดุเรื่องชนิดขนาดนั้น: **ถ้า compiler ไม่รู้ว่าช่องนี้ใหญ่แค่ไหน มันจองเนื้อที่ไม่ถูก และถ้าเราเอาของผิดขนาดไปยัด ช่องข้าง ๆ จะพัง** — ความผิดพลาดแบบนี้ในภาษาที่ปล่อยอิสระ (เช่น C ที่ให้เราจัดการเอง) นำไปสู่บั๊กและช่องโหว่ความปลอดภัยระดับโลก (ตอน 16 จะเล่าให้ฟัง) Go เลือกดุตั้งแต่ compile เพื่อไม่ให้เรื่องแบบนี้เกิด — ตอนนี้ที่รู้สึกว่า "Go จู้จี้" จะค่อย ๆ กลายเป็น "Go ดูแลเรา"

## ลงมือทำ: โปรแกรม "MyProfile" ที่จำข้อมูลเราและคำนวณ BMI

ถึงเวลารวมทุกอย่างที่เรียนวันนี้เป็นโปรแกรมจริง — สร้างไฟล์ใหม่ชื่อ `profile.go` ในโฟลเดอร์ `gopher-course`:

```go
package main

import "fmt"

func main() {
    // --- ค่าคงที่ของโปรแกรมนี้ ---
    const appName = "MyProfile v0.1"
    fmt.Println("โปรแกรม:", appName)

    // --- ข้อมูลส่วนตัว (ตัวแปร) ---
    var name string = "สมชาย"
    var age int = 30
    var height float64 = 1.75 // ส่วนสูง หน่วยเมตร
    var weight float64 = 68.5 // น้ำหนัก หน่วยกิโลกรัม
    var lovesCoding bool = true

    fmt.Println("ชื่อ:", name)
    fmt.Println("อายุ:", age, "ปี")
    fmt.Println("ส่วนสูง:", height, "เมตร")
    fmt.Println("น้ำหนัก:", weight, "กิโลกรัม")
    fmt.Println("ชอบเขียนโค้ด:", lovesCoding)

    // --- คำนวณ BMI: น้ำหนัก(กก.) หารด้วย ส่วนสูง(เมตร) ยกกำลังสอง ---
    bmi := weight / (height * height)
    fmt.Println("BMI:", bmi)

    // --- อีกหนึ่งปีผ่านไป: ตัวแปรเปลี่ยนค่าได้ด้วย = ---
    age = age + 1
    fmt.Println("ปีหน้า อายุ:", age, "ปี")
}
```

รัน `go run profile.go` — ผลลัพธ์จริงบนเครื่องผม:

```
โปรแกรม: MyProfile v0.1
ชื่อ: สมชาย
อายุ: 30 ปี
ส่วนสูง: 1.75 เมตร
น้ำหนัก: 68.5 กิโลกรัม
ชอบเขียนโค้ด: true
BMI: 22.367346938775512
ปีหน้า อายุ: 31 ปี
```

ขอชี้จุดที่น่าสนใจในโปรแกรมนี้:

- **`bmi := weight / (height * height)`** — `:=` เดาเองว่า bmi เป็น float64 (เพราะตัวตั้งตัวหารเป็น float64 ทั้งคู่) ส่วนวงเล็บคือการบอก "คำนวณในวงเล็บก่อน" เหมือนคณิตศาสตร์ — `height * height` คือส่วนสูงยกกำลังสอง
- **เลขทศนิยมยาวเฟื้อย** — `22.367346938775512` คือสิ่งที่ float64 คำนวณออกมาจริง ๆ (คอมพิวเตอร์คำนวณแม่นยำระดับหนึ่ง แล้วต้องมีเลขเพี้ยนท้าย ๆ เสมอ — เรื่องนี้มีเบื้องหลังลึกซึ้ง เรียนตอน 08) dev แก้ด้วยการ "จัดรูปแบบตอนพิมพ์" ให้เหลือ 2 ตำแหน่ง — ใช้ฟังก์ชัน `fmt.Printf` (ย่อจาก print formatted = พิมพ์แบบจัดรูปแบบ):

```go
fmt.Printf("BMI: %.2f\n", bmi) // %.2f = แสดงทศนิยม 2 ตำแหน่ง, \n = ขึ้นบรรทัดใหม่
```

(ทดสอบจริง: พิมพ์ `BMI: 22.37`) — จำ `Printf` ไว้ก่อน เดี๋ยวตอนถัด ๆ ไปเราจะใช้มันบ่อย แต่ตอนนี้ยังใช้ `Println` ไปก่อนได้
- **`age = age + 1`** — อ่านว่า "เอาค่า age ปัจจุบัน (30) บวก 1 แล้วใส่กลับลงกล่อง age" ผลคือ 31 — การเขียนแบบ "ตัวแปร = ตัวแปร + ค่า" นี้เจอบ่อยมากจน Go มีตัวย่อให้: `age += 1` แปลว่าเหมือนกัน (และ `age++` ก็คือ "บวกทีละ 1" — dev ใช้กันจนชิน แต่ตอนนี้ขอให้เขียนเต็ม ๆ ก่อน จะได้เห็นภาพว่ามันทำอะไร)

> ⚠️ **เตือนคนที่คิดจะทำงานสายเงิน/บัญชี**: ห้ามใช้ `float64` เก็บเงินเด็ดขาด — เลขเพี้ยนท้ายแบบ `22.367346...` ที่เพิ่งเห็นจะทำให้ยอดรวมเพี้ยนสะสมเรื่อย ๆ (เช่น คิดภาษี `ราคา × 0.07` บ่อย ๆ เข้า) dev สายงานเงินจึงเก็บเงินเป็น**จำนวนเต็มของหน่วยย่อยสุด** (25.50 บาท = เก็บ 2550 สตางค์) หรือใช้ชนิดทศนิยมที่แม่นยำ (decimal) ที่ออกแบบมาเพื่องานเงินโดยเฉพาะ (จะลงลึกตอน 08) — ถ้าอยากเห็นของจริง ลองรัน `b := 0.1` กับ `c := 0.2` แล้วสั่ง `fmt.Println(b + c)` — จะได้ `0.30000000000000004` (ถ้าเขียน `0.1 + 0.2` ตรง ๆ กลับได้ 0.3 เพราะ Go คิดให้ตอน compile แบบละเอียด — พอค่ามาจากตัวแปรตอนโปรแกรมรันจริง ความเพี้ยนถึงโผล่ให้เห็น)

ลองแก้ข้อมูลในโปรแกรมเป็นของตัวเอง (ชื่อ อายุ ส่วนสูง น้ำหนัก) แล้วรันดู — นี่คือครั้งแรกที่คุณ**แต่งประโยคเอง** ไม่ใช่ท่องตาม

## กับดักยอดฮิตของมือใหม่ + error ที่จะเจอ

รวม error ที่เจอบ่อยสุดตอนหัดเขียนตัวแปร (ทุกอันทดสอบจริง ขอให้ลองทำพังดูเอง แล้วเทียบกับที่เขียนไว้ — ฝึกวงจร "สร้าง → พัง → อ่าน → สร้างใหม่" จากตอน 02):

| โค้ดที่ทำให้พัง | error จริง | แปลว่า | วิธีแก้ |
|---|---|---|---|
| ประกาศตัวแปรแล้วไม่ใช้ | `declared and not used: x` | "ประกาศ x แล้วไม่เคยใช้" — Go ไม่ให้มีของที่จองไว้แล้วทิ้งเปล่า | ใช้มันในโค้ด หรือลบประกาศทิ้ง |
| import แล้วไม่ใช้ | `"fmt" imported and not used` | "import fmt มาแล้วไม่ใช้" | ใช้ fmt หรือลบบรรทัด import |
| `a := 10` แล้วเอาไปบวก `2.5` | `2.5 (untyped float constant) truncated to int` | "บีบ 2.5 (ค่าคงที่ทศนิยม) ให้เป็น int ตามชนิดของ a ไม่ได้ — เศษถูกตัดทิ้ง" — เพราะ 2.5 ที่เขียนตรง ๆ เป็น untyped constant (ดู gloss ข้างบน) Go เลยพยายามปรับให้เป็น int ให้เข้ากับ a ก่อน (ต่างจากกับดักที่ 1 ที่เป็นตัวแปร float64 จริง ๆ: `b := 2.5` แล้ว `a + b` จะ error แบบ mismatched types ตามที่เขียนไว้ข้างบน) | แปลงให้เป็นชนิดเดียวกัน: `float64(a) + 2.5` |
| เปลี่ยนค่า const | `cannot assign to pi (neither addressable nor a map index expression)` | "กำหนดค่าให้ pi ไม่ได้ เพราะเป็น const" | ใช้ `var` ถ้าต้องการให้เปลี่ยนได้ |
| `"ปี " + 2026` | `invalid operation: "ปี " + 2026 (mismatched types untyped string and untyped int)` | "ข้อความบวกเลขไม่ได้" | แปลงเลขเป็นข้อความก่อน หรือใช้ Printf |
| `var n int = 1.5` | `cannot use 1.5 (untyped float constant) as int value in variable declaration (truncated)` | "ใช้ 1.5 (ค่าคงที่ทศนิยม) เป็นค่า int ในตอนประกาศตัวแปรไม่ได้ — เศษถูกตัดทิ้ง" int เก็บทศนิยมไม่ได้ | เปลี่ยนชนิดเป็น float64 |

อ่าน error ด้วยสูตรเดิมจากตอน 02: **`ชื่อไฟล์:เลขบรรทัด:เลขหลัก: สาเหตุ`** — ทุก error ข้างบน Go ชี้พิกัดมาให้เป๊ะ ๆ แล้ว เหลือแค่เราแปล "สาเหตุ" แล้วแก้ทีละจุด

## โจทย์ประจำตอน

### ระดับ Drill (10–15 นาที)

1. **อธิบายโค้ด hello world ให้คนที่ไม่เคยเห็นโค้ดฟัง** ทีละบรรทัด: package คืออะไร ทำไมต้อง main ทำไมต้อง import fmt — ถ้าอธิบายให้ปู่ย่าฟังรู้เรื่อง แปลว่าเข้าใจจริง (ห้ามใช้ศัพท์ซ้อนศัพท์)
2. **ทายก่อนรัน** (แล้วค่อยรันเทียบ — ฝึก "พยากรณ์แล้วตรวจ"):
   - `fmt.Println(10 / 4)` ได้อะไร? แล้ว `fmt.Println(10.0 / 4.0)` ล่ะ?
   - `fmt.Println("10" + "4")` ได้อะไร? (ข้อนี้กับข้อบนตอบไม่เหมือนกัน — อธิบายได้ไหมว่าทำไม)
3. **แก้โค้ดพัง**: โค้ดข้างล่าง compile ไม่ผ่าน 3 จุด — หาให้ครบ แล้วแก้ให้รันได้ (Hint: มองหาตัวแปรที่ประกาศแล้วไม่ใช้, ชนิดไม่ตรงกัน, และ const ที่โดนเปลี่ยน):

```go
package main

import "fmt"

func main() {
    var name string = "สมชาย"
    const birthYear = 1996
    birthYear = 1997

    var age int = 30
    var height float64 = 1.75
    fmt.Println("อายุรวม:", age+height)

    var unused int = 5
    fmt.Println("ชื่อ:", name)
    fmt.Println("ปีเกิด:", birthYear)
}
```

### ระดับ Mini-project (30–60 นาที) — "กล่องความทรงจำ + เครื่องคำนวณส่วนตัว"

เขียนโปรแกรม `memory.go` ที่ทำได้ครบ 4 อย่างนี้:

1. **บันทึกข้อมูล "คนสำคัญในชีวิต"** 3 คน ด้วยตัวแปร 3 ชุด — ต่อคนบันทึก 5 ค่า: ชื่อ (string) + อายุ (int) + ส่วนสูงหน่วยเมตร (float64) + น้ำหนักหน่วยกิโลกรัม (float64) + "ยังติดต่อกันอยู่ไหม" (bool) แล้วพิมพ์สรุปทั้ง 3 คน (Hint: ตั้งชื่อให้ต่างกัน เช่น `name1, name2, name3` สำหรับชื่อ, `age1...`, `height1...`, `weight1...` และ `contact1...` สำหรับ bool — เดี๋ยวตอน 06 เราจะเรียนวิธีเก็บหลายค่าให้**เป็นระเบียบกว่าเดิม**ด้วย **slice** (สไลซ์ = ชุดของค่าหลายค่าที่เรียงกันอยู่ในตัวแปรเดียว) แต่ตอนนี้ใช้วิธีตรงไปตรงมาก่อน)
2. **คำนวณอายุรวม** ของทั้ง 3 คน แล้วพิมพ์ออกมา (Hint: ประกาศ `totalAge := age1 + age2 + age3` — แต่ระวัง ถ้าความสูงเป็น float64 กับอายุเป็น int เอามาบวกกันไม่ได้นะ!)
3. **BMI ของคนแรก** — ใช้ `height1` กับ `weight1` (ชนิด float64) ที่ประกาศไว้แล้วในข้อ 1 สำหรับคนแรก มาคำนวณ BMI = `weight1 / (height1 * height1)` (สูตรเดียวกับตัวอย่าง MyProfile) แล้วลองหาวิธีพิมพ์ให้เหลือทศนิยม 2 ตำแหน่ง (Hint: ค้นหาคำว่า `fmt.Printf` กับ `%.2f` — ทักษะการค้นหาคือทักษะจริง)
4. **เพิ่ม const `programName`** กับ `version` แล้วให้โปรแกรมพิมพ์ชื่อ+เวอร์ชันเป็นบรรทัดแรก — แล้วลอง**จงใจ**เปลี่ยนค่า const ดูว่า error บอกอะไร เขียนลงสมุดว่า error บอกว่าอะไร ที่บรรทัดไหน

**เกณฑ์ผ่าน:** โปรแกรมรันได้ ไม่มี error มีการใช้ครบทั้ง 4 ชนิดข้อมูล (int, float64, string, bool) และมี const อย่างน้อย 1 ตัว

## สรุปตอนที่ 03

- **hello world 5 บรรทัด (ไม่นับบรรทัดว่าง)** = package (กล่องรวมโค้ด) + import (ขอยืมกล่องสำเร็จรูป) + func main (จุดเริ่มที่ OS เรียก) + คำสั่งพิมพ์ — ทุกคำมีหน้าที่ ทุกคำคือไวยากรณ์ที่ compiler ตรวจ
- **ตัวแปร (variable)** = กล่องมีป้ายชื่อ ประกาศได้ 2 แบบ: `var` (เราบอกชนิดเอง) กับ `:=` (ให้ Go เดา) — เปลี่ยนค่าได้ด้วย `=` แต่ชนิดเปลี่ยนไม่ได้ และ**เปลี่ยน const ไม่ได้** (const = ค่าคงที่ ใส่ครั้งเดียวจบ)
- **ชนิดข้อมูล 4 แบบ**: `int` (จำนวนเต็ม), `float64` (ทศนิยม), `string` (ข้อความ), `bool` (จริง/เท็จ) — compiler ใช้ชนิดเป็นตัวกำหนดขนาดช่องใน RAM และคอยกันไม่ให้เอาของผิดชนิดใส่กล่อง
- **กับดัก 3 อันที่มือใหม่เจอทุกคน**: กับดักที่ 1 — int กับ float64 บวกกันไม่ได้ (ต้องแปลงชนิดก่อน), กับดักที่ 2 — int หาร int ได้ผลเป็น int (เศษโดนตัด), กับดักที่ 3 — ข้อความกับเลขบวกกันไม่ได้ (`"2"+"2"` = `"22"`)
- ตัวแปรในเครื่องจริง = ชื่อของช่องใน RAM ที่มีเลขที่ (address) กำกับ — ชนิดบอกขนาดช่อง compiler จัดการให้เอง (จะเห็นด้วยตาตอน 08, 10 และ 14)

ตอนนี้คุณพูด "ภาษา" ได้เป็นประโยคแรกแล้ว — ยังสั้นและตะกุกตะกัก แต่**โครงสร้างถูกต้อง** จากนี้ไปทุกตอนคือการต่อยอด: คำศัพท์ใหม่ โครงสร้างประโยคใหม่

ตอนหน้า (ตอน 04) เราจะทำให้โปรแกรม**ฉลาดขึ้น** — รู้จักการตัดสินใจ (if/else: "ถ้า... ไม่งั้น...") การวนซ้ำ (loop: "ทำซ้ำจนกว่า...") และการรับ input (ให้ผู้ใช้พิมพ์ค่ามาใส่ตัวแปรของเราเอง) — พอจบตอนหน้า โปรแกรมของคุณจะไม่ใช่แค่พิมพ์ข้อความตายตัวอีกต่อไป แต่**ตอบโต้กับคนใช้ได้จริง**

ระหว่างรอ อย่าลืมทำ mini-project "กล่องความทรงจำ" — และจำกฎเหล็กของคอร์สนี้: พังแล้วอ่าน error แล้วสร้างใหม่ dev ที่เก่งไม่ใช่คนไม่เคยพัง แต่คือคนที่พังแล้วลุกได้ทุกครั้ง
