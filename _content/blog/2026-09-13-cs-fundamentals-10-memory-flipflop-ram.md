ตอนที่ 09 เราสร้างเครื่องบวก-ลบ 4 บิตสำเร็จด้วยมือล้วน ๆ และจบด้วยคำถามค้างไว้ข้อเดียว:

> **ถ้าไฟฟ้าดับ ข้อมูลหาย แล้วเครื่อง "จำ" อะไรได้ยังไง?**

จริง ๆ มีคำถามที่ลึกกว่านั้นซ่อนอยู่: วงจรที่เราต่อมาทั้งหมดในตอน 09 — ไม่ว่าจะเป็น **AND gate** (ให้ผล 1 เมื่ออินพุตเป็น 1 ทั้งคู่), **OR gate** (ให้ผล 1 เมื่อมีอย่างน้อยหนึ่งอินพุตเป็น 1), **XOR gate** (ให้ผล 1 เมื่ออินพุตสองตัวไม่เหมือนกัน), **adder** (วงจรบวกเลข) หรือ **ALU** (Arithmetic Logic Unit = หน่วยคำนวณและตรรกะ ชิ้นส่วนในซีพียูที่บวก-ลบ-เทียบ-AND/OR ให้) — มีคุณสมบัติร่วมกันอย่างหนึ่งที่เรายังไม่ได้เอ่ยชื่อ: **มันจำอะไรไม่ได้เลย**

ป้อน `A = 1`, `B = 0` เข้าไป มันให้ผลลัพธ์ออกมาทันที แต่พอเราดึงสาย `A` กับ `B` ออก (ตัดสัญญาณออก) ผลลัพธ์ก็หายไปด้วย เหมือนเครื่องคิดเลขที่ไม่มีที่เก็บผลลัพธ์ พอปล่อยปุ่ม ก็ไม่เหลืออะไรไว้ให้อ่าน

แต่คอมพิวเตอร์ "จำ" ได้ — ตัวแปรที่เราประกาศใน Go ตอน 03–07 ค่ามันค้างอยู่ในเครื่องได้เป็นชั่วโมงเป็นวัน ถ้าโปรแกรมยังไม่จบ แล้วอะไรคือกลไกที่ทำให้วงจรไฟฟ้าธรรมดา "จำ" ได้?

คำตอบคือหัวข้อของตอนนี้ทั้งหมด: **flip-flop** (ฟลิปฟล็อป = วงจรจำ 1 บิต ที่ "พลิก" ไปมาระหว่าง 0 กับ 1 แล้วค้างค่าไว้) → **register** → **RAM** สามสิ่งนี้คือหน่วยความจำของเครื่องทุกเครื่องบนโลก และเป็นตอนที่เชื่อมสิ่งที่เราเรียนตอน 07 (ตัวแปรอยู่ใน RAM) กับวงจรจริง ๆ ที่เราต่อในตอน 09 เข้าด้วยกัน

ตอนนี้ไม่มีโค้ด Go ให้พิมพ์ เพราะเรากำลังทำงานในชั้นที่ต่ำกว่าระดับโค้ด (ระดับวงจร) แต่มีวงจรให้ต่อใน CircuitVerse ทุกวงจรต่อได้จริง ตรวจผลได้จริง เหมือนที่ผ่านมา

## 0. ปัญหา: วงจร "คำนวณ" จำไม่ได้

ก่อนจะสร้างความจำ เราต้องรู้จักวงจรสองตระกูลใหญ่ของโลกดิจิทัลก่อน เพราะทุกอย่างในตอนนี้อยู่บนเส้นแบ่งระหว่างสองตระกูลนี้

> **คำศัพท์: bit** (บิต) = หน่วยข้อมูลเล็กสุด เก็บค่าได้ 2 ค่า (0 หรือ 1) — เราเจอมาแล้วตอน 08

**ตระกูลที่ 1 — วงจรคำนวณ** (เรียกทับศัพท์ว่า **combinational logic** = วงจรที่ผลลัพธ์ขึ้นอยู่กับอินพุต "ตอนนั้น" เท่านั้น): ทุกวงจรในตอน 09 อยู่ในตระกูลนี้ ไม่ว่า XOR, adder, หรือ ALU ล้วนทำงานแบบ "เอาบิตเข้า ใช้กติกาตายตัว แปลงเป็นบิตออก" ทันที — ไม่มีอะไรถูกเก็บไว้ข้างใน

**ตระกูลที่ 2 — วงจรจำ** (เรียกว่า **sequential logic** = วงจรที่ผลลัพธ์ขึ้นอยู่กับ "อินพุตตอนนี้ + สถานะในอดีต"): นี่คือวงจรที่เราจะสร้างวันนี้ มันมี "ความทรงจำ" ว่าก่อนหน้านี้เกิดอะไรขึ้น

ดูภาพที่ 1 เปรียบเทียบสองตระกูลนี้เคียงกัน

![เปรียบเทียบวงจรคำนวณที่จำค่าไม่ได้ กับวงจรจำที่มีเส้นป้อนกลับ ทำให้ค่าเดิมค้างอยู่ได้](/assets/diagrams/ep10-01-combinational-vs-sequential.svg)

ในภาพซ้าย (A) พอเราปล่อยอินพุต `A`, `B` หายไป ผลลัพธ์ของ XOR หายทันที เพราะวงจรไม่เก็บอะไรไว้เลย

แต่ภาพขวา (B) มีสิ่งใหม่ที่เราไม่เคยเห็นในตอน 09: **เส้นป้อนกลับ** (feedback = การเอาค่าเอาต์พุตของวงจร วนกลับมาเป็นอินพุตของตัวมันเอง) — เส้นสีเขียวที่ลากจากเอาต์พุต `Q` กลับลงมาที่ gate ข้างล่าง

> **คำศัพท์:** วงจร "จำ" ได้ ก็เพราะมีเส้นป้อนกลับ — สัญญาณวนกลับมาเป็นวงปิด ค่าเก่าจึง "ค้าง" อยู่ในวงจรได้แม้ไม่มีอินพุตใหม่ นี่คือหัวใจของหน่วยความจำทั้งปวง

วงจรที่เห็นในภาพขวา (B) มีชื่อเรียกว่า **SR latch** (แลตช์) และมันคือหน่วยความจำ 1 บิต ที่เล็กที่สุดเท่าที่มนุษย์สร้างได้ มาดูมันทีละชิ้น

## 1. SR latch: วงจรจำค่าได้ 1 บิต

มาแยกดู **SR latch** (อ่านว่า "เอส-อาร์ แลตช์") ที่เพิ่งเห็นในภาพที่ 1 ทีละชิ้น — ประกอบจาก **NOR gate** (ได้ผลเป็น `1` ก็ต่อเมื่ออินพุตเป็น `0` ทั้งคู่) แค่ 2 ตัว เอามาไขว้กัน (ภาพที่ 1 ฝั่ง B)

มันมีขาเข้าสองขา:

- **S** = Set (ตั้งค่าเป็น 1)
- **R** = Reset (ล้างค่าเป็น 0)

และขาออกสองขา:

- **Q** = ค่าที่วงจรจำอยู่ (บิตที่เราเก็บ)
- **Q′** (อ่านว่า "คิว-ไพรม์" หรือ "คิว-บาร์") = ค่าตรงข้ามของ Q เสมอ — ถ้า Q เป็น 1, Q′ เป็น 0 และกลับกัน

กติกาของมันมีแค่ 3 ข้อ (จดไว้ก่อน แล้วเดี๋ยวเราจะต่อเองใน CircuitVerse ให้เห็นกับตา):

| S (ตั้งค่า) | R (ล้างค่า) | สิ่งที่เกิดขึ้นกับ Q |
|---|---|---|
| 0 | 0 | **ค้างค่าเดิม** — จำไว้ตามเดิม (นี่คือท่า "จำ") |
| 1 | 0 | **ตั้งเป็น 1** — Q กลายเป็น 1 |
| 0 | 1 | **ล้างเป็น 0** — Q กลายเป็น 0 |
| 1 | 1 | ⚠️ สถานะต้องห้าม (invalid) — เกิดความกำกวม ห้ามใช้ |

ลองอ่านกติกาช้า ๆ เพราะมันคือหัวใจของทุกอย่างในตอนนี้:

1. ถ้าเราไม่แตะอะไรเลย (`S = 0, R = 0`) วงจรจะ **ค้างค่าเดิมไว้** — บิตไหนอยู่ก็อยู่แบบนั้น นี่แหละคือการ "จำ"
2. ถ้าเราจ่ายไฟให้ขา S ชั่วครู่ (`S = 1, R = 0`) Q จะกระโดดเป็น 1 — แล้วแม้เราปล่อย S กลับเป็น 0 Q ก็ **ยังเป็น 1 อยู่** เพราะเข้าท่า "ค้างค่าเดิม"
3. กลับกัน ถ้าเราจ่ายไฟให้ R (`S = 0, R = 1`) Q จะถูกล้างเป็น 0 และค้าง 0 ไว้

เห็นภาพหรือยัง? เราสามารถ "เขียนค่า" เข้าไป แล้วมันก็ "จำ" ไว้ได้เรื่อย ๆ — **นี่คือหน่วยความจำ 1 บิต** มันไม่ต้องมีอะไรคอยป้อนซ้ำ ไม่ต้องมีไฟเลี้ยงค้างไว้เป็นพิเศษ มันแค่เก็บสถานะไว้

**แล้วทำไมต้องห้าม `S = 1, R = 1` พร้อมกัน?** เพราะถ้าตั้งกับล้างพร้อมกัน มันขัดกันเอง: Q กับ Q′ จะกลายเป็น 0 ทั้งคู่ (ขัดกับกติกาที่ว่า Q′ ต้องตรงข้าม Q) แล้วพอเราปล่อยทั้งสองขาพร้อมกัน วงจรจะ "แข่งกันเอง" ว่าสุดท้ายจะค้างค่า 0 หรือ 1 — ผลออกมาไม่แน่นอน (เรียกว่า race condition = การแข่งกันเองของสัญญาณ) ซึ่งเราต้องการหลีกเลี่ยง

ปัญหาเรื่อง "ห้ามตั้งกับล้างพร้อมกัน" นี้ดูเหมือนเรื่องจุกจิก แต่มันเป็นเหตุผลโดยตรงที่ทำให้เราต้องสร้างสิ่งที่ซับซ้อนขึ้นอีกหนึ่งระดับ นั่นคือ D flip-flop ในหัวข้อถัดไป

## 2. D flip-flop: เติม gate แล้วเติมนาฬิกา

SR latch ใช้งานจริงมีข้อเสีย 2 อย่าง:

1. **ต้องจำกติกาเอง** — ต้องคอยระวังไม่ให้ S กับ R เป็น 1 พร้อมกัน ซึ่งพอวงจรใหญ่ขึ้น การจำกติกาทุกจุดเป็นเรื่องผิดพลาดง่าย
2. **เขียนได้ตลอดเวลา** — S หรือ R เปลี่ยนตอนไหน ค่าก็เปลี่ยนตามทันที ซึ่งในเครื่องจริงที่มีสัญญาณกระเพื่อมไปมา ข้อมูลอาจ "ทะลัก" เข้าไปตอนที่เราไม่ต้องการ

วิธีแก้ข้อ 1 ง่ายมาก: **แทนที่จะมีสองขา S กับ R เราเหลือขาเดียวชื่อ D (Data)** แล้วให้วงจรจัดการ "ตั้งหรือล้าง" ให้เอง — ถ้า D เป็น 1 ก็ตั้ง ถ้า D เป็น 0 ก็ล้าง เราไม่ต้องจำกติกาอีกต่อไป

วิธีแก้ข้อ 2 ต้องมี "gate" คอยกั้น: เราต้องการให้วงจร "ยอมรับค่าใหม่" เฉพาะจังหวะที่เราอนุญาต เท่านั้น — และจังหวะนั้นถูกกำหนดโดย **นาฬิกา**

> **คำศัพท์: clock (นาฬิกา)** = สัญญาณไฟฟ้าที่เต้นเป็นจังหวะ ขึ้น-ลง-ขึ้น-ลง สม่ำเสมอ เหมือนเครื่องเมตรอนอมของนักดนตรี มันไม่เกี่ยวกับเวลาจริง (ไม่ใช่ "กี่โมง") แต่มันคือ "จังหวะ" ที่ทั้งเครื่องทำงานพร้อมกัน

ดูภาพที่ 2 ซึ่งเดินจาก SR latch → D latch → D flip-flop ทีละขั้น

![จาก SR latch สู่ D flip-flop: เติม gate แล้วเติมนาฬิกา พร้อมตารางความจริง](/assets/diagrams/ep10-02-sr-latch-d-flipflop.svg)

**ขั้นที่ 1 — gated D latch (D latch ที่มี gate)** (ภาพที่ 2 ฝั่ง A): เราเอา SR latch มา แล้วเติม gate **AND** (ออก 1 เมื่ออินพุตเป็น 1 ทั้งคู่) + **NOT** (กลับค่า 0↔1) เข้าไป เพื่อให้มีขา **E (enable = อนุญาต)** คอยเปิด-ปิด เมื่อ `E = 1` gate เปิด Q วิ่งตาม D ทันที; เมื่อ `E = 0` gate ปิด Q ตรึงค่าเดิมไว้

แต่ปัญหายังไม่จบ: ถ้า E เปิดค้างไว้ แล้ว D กระพริบไปมา (0→1→0→1) Q ก็กระพริบตามทุกครั้ง — ข้อมูลยัง "ทะลัก" เข้ามาได้อยู่ดี เราเลยต้องเข้มงวดขึ้นอีก

**ขั้นที่ 2 — D flip-flop** (ภาพที่ 2 ฝั่ง B): เอา D latch สองตัวมาซ้อนกัน (ตัวหลักเรียกว่า master ตัวรองเรียกว่า slave) แล้วคุมด้วย clock ผลคือวงจรจะยอมรับค่า D เฉพาะจังหวะที่สัญญาณ clock เปลี่ยนจาก 0 เป็น 1 — เรียกว่า **ขอบขาขึ้น** (rising edge = จังหวะที่สัญญาณปีนจาก 0 ขึ้นไป 1) เพียงจังหวะเดียวเท่านั้น

> **คำศัพท์: edge-triggered** = วงจรที่ตอบสนองเฉพาะ "ขอบ" (จังหวะเปลี่ยนสถานะ) ของสัญญาณ ไม่ใช่ "ระดับ" ของสัญญาณ D flip-flop เป็น edge-triggered: ค่าจะเปลี่ยนแค่ตอนขอบขาขึ้นของ clock เท่านั้น ระหว่างนั้น D เปลี่ยนไปม้ากี่ครั้งก็ไม่มีผล

นี่คือคุณสมบัติที่ทำให้เครื่องทำงานเป็นระเบียบ: **ทุกหน่วยความจำในเครื่อง รับค่าใหม่พร้อมกัน ในจังหวะ clock เดียวกัน** — คล้ายนักกีฬาทั้งทีมที่ "ออกวิ่งพร้อมกันตอนปืนดัง" ไม่ใช่ต่างคนต่างวิ่งมั่ว ๆ

**D flip-flop = หน่วยความจำ 1 บิตที่ใช้งานจริง** มีขา D (ข้อมูลเข้า), clock (จังหวะรับค่า), Q (ค่าที่จำอยู่) — และใน CircuitVerse มี D flip-flop สำเร็จรูปให้ใช้ (เป็น edge-triggered อยู่แล้ว) โดยเราไม่ต้องต่อ master-slave เอง แต่เราจะต่อ SR latch จาก NOR 2 ตัวเองหนึ่งรอบเพื่อให้เห็นเส้นป้อนกลับกับตา

## 3. register: เอา flip-flop มาเรียงกัน

flip-flop หนึ่งตัวจำได้ 1 บิต แต่ตัวแปรจริง ๆ ต้องใช้หลายบิต — `int64` และ `float64` กว้าง 64 บิต (ส่วน `int`/`uint` เฉย ๆ กว้างเท่าขนาด "คำ" ของเครื่อง — word = จำนวนบิตที่เครื่องจัดการทีละคำ: Raspberry Pi ที่เราใช้เป็นเครื่อง 64 บิต จึงได้ 64 บิต แต่อุปกรณ์ฝังตัวรุ่นเล็กอาจเป็น 32 บิต — ตามตอน 08)

วิธีแก้ตรงไปตรงมา: **เอา D flip-flop หลายตัวมาเรียงกัน แล้วแชร์ clock ตัวเดียวกัน** — บิตที่ 0 (บิตขวาสุด ตัวมีค่าน้อยสุด ตามที่เรียนตอน 08) อยู่ปลายขวา เรียงขึ้นไปถึงบิตที่ 3 (ซ้ายสุด)

ผลที่ได้เรียกว่า **register** (รีจิสเตอร์)

> **คำศัพท์: register** = ที่พักข้อมูลชั่วคราวในซีพียู เก็บข้อมูลชุดหนึ่ง (เช่น 4 บิต, 8 บิต, 64 บิต) ไว้ใน flip-flop หลายตัวที่ใช้ clock เดียวกัน — "ชั่วคราว" เพราะมันเร็วมากและอยู่ใกล้ชิ้นคำนวณที่สุด ใช้เก็บค่าที่กำลังถูกประมวลผลอยู่

ดูภาพที่ 3

![register 4 บิตที่สร้างจาก D flip-flop 4 ตัวใช้ clock ตัวเดียวกัน พร้อมตารางแสดงการโหลดค่า](/assets/diagrams/ep10-03-register-4bit.svg)

ภาพนี้สำคัญตรงเส้นสีเขียวเส้นเดียวที่วิ่งเข้า flip-flop ทั้ง 4 ตัว: **clock ตัวเดียว** นี่คือความหมายของคำว่า register — ทุกบิตจะรับค่าใหม่ "พร้อมกัน" ในจังหวะเดียวกันเป๊ะ

ดูตารางในภาพ B (ค่าทุกค่าอ่านจากซ้ายไปขวา คือ บิต 3 → บิต 0):

- ขอบ clock ที่ 1: `D = 0110` → register กลายเป็น `0110`
- ขอบ clock ที่ 2: `D = 1011` → register กลายเป็น `1011`
- ระหว่างนั้น D เปลี่ยนเป็น `0011` แต่ register ยังค้าง `1011` อยู่ — เพราะยังไม่มีขอบ clock ใหม่

นี่คือหัวใจของ "ที่พักข้อมูล": ค่าที่อยู่ใน register จะค้างอยู่จนกว่าจะมีขอบ clock ใหม่มาบอกว่า "รับค่าใหม่"

จำภาพนี้ไว้ให้ดี เพราะ register คือสะพานเชื่อมระหว่างวงจรคำนวณ (ตอน 09) กับหน่วยความจำ (ตอนนี้): ตัวเลขที่ ALU คำนวณเสร็จ ต้องมีที่พักไว้สักครู่ก่อนเอาไปใช้ต่อ — และที่พักนั้นก็คือ register

## 4. RAM: register หลายตัว + เลข address

ตอนนี้เราจำได้แล้ว 1 บิต (flip-flop) และ N บิต (register) แต่โปรแกรมหนึ่งมีตัวแปรเป็นร้อยเป็นพัน ต้องมีที่เก็บ "เป็นกอง ๆ" — นั่นคือ RAM

> **คำศัพท์: RAM** (Random Access Memory = หน่วยความจำที่เข้าถึงแบบสุ่ม) = หน่วยความจำหลักของเครื่อง คำว่า "random access" ไม่ได้แปลว่า "สุ่มมั่ว" แต่แปลว่า **เราข้ามไปอ่านช่องไหนก็ได้ โดยใช้เวลาเท่ากันทุกช่อง** (ต่างจากเทปเพลงที่ต้องกรอไปตามลำดับ) — เราจะเห็นว่ามันเป็นจริงได้ยังไงในหัวข้อนี้

ไอเดียของ RAM ตรงไปตรงมา: **เอา register หลาย ๆ ตัวมาเรียงเป็นแถว แล้วติด "เลขที่" ให้แต่ละแถว** เลขที่นั้นเรียกว่า **address**

> **คำศัพท์: address (แอดเดรส / เลขที่อยู่)** = ตัวเลขที่ระบุ "ช่อง" ใน RAM ว่าข้อมูลอยู่ช่องไหน — เหมือนเลขที่บ้าน บ้านแต่ละหลัง (ช่องข้อมูล) มีเลขที่ (address) กำกับ และไปรษณีย์ (วงจร) รู้ว่าต้องไปส่งบ้านไหนจากเลขที่นั้น

ดูภาพที่ 4

![โครงสร้าง RAM: เลข address ผ่าน decoder เพื่อเลือกแถวหน่วยความจำหนึ่งแถว พร้อมตาราง address และคำอธิบายว่าตัวแปรในโค้ดอยู่ที่ address ใด](/assets/diagrams/ep10-04-ram-address-decoder.svg)

ภาพนี้คือ RAM จิ๋วขนาด 4 ช่อง × 4 บิต:

- **แถว (row)** แต่ละแถว = register 4 บิต หนึ่งตัว (ในภาพแทนด้วยกล่อง FF 4 ตัว — FF = ตัวย่อของ flip-flop)
- **address** เป็นตัวเลข 2 บิต (`A1 A0`) เลือกได้ 4 แถว เพราะ 2 บิตแทนค่าได้ 4 ค่า (2² = 4): `00`, `01`, `10`, `11`
- **decoder** (ตัวถอดรหัส — เจอตอน 09) แปลง address ให้ "เลือกแถวเดียว" ส่วนอีก 3 แถวไม่ถูกแตะเลย — เส้นที่ decoder ลากไปยังแต่ละแถวเรียกว่า **word line** (เส้นเลือกแถว) และ "2→4" ในภาพหมายถึง "รับเข้า 2 บิต จ่ายออก 4 เส้น"

แล้ว "เข้าถึงแบบสุ่มใช้เวลาเท่ากัน" เกิดจากตรงนี้: ไม่ว่า address เป็น `00` หรือ `11` วงจรก็แค่ "ถอดรหัสแล้วเลือกแถว" เหมือนกันหมด ไม่มีการกรอไล่ไปทีละแถว จึงใช้เวลาเท่ากันทุกช่อง

**หนึ่ง address = หนึ่งช่องข้อมูล** ที่เรียกว่า **word** (เวิร์ด — ในความหมายของ RAM นี้ = จำนวนบิตที่อ่าน/เขียนได้ในครั้งเดียว) — ในภาพ word กว้าง 4 บิต แต่เครื่องจริง 1 address มักเท่ากับ 1 ไบต์ (8 บิต) — เจอไบต์แล้วตอน 08

**ของจริงสองชนิด (รู้ไว้คร่าว ๆ):**

- **SRAM** (Static RAM) = เก็บบิตด้วย flip-flop แบบที่เราเรียนเป๊ะ — เร็วมาก แต่แพงและกินพื้นที่ ใช้ทำ cache (แคช = หน่วยความจำความเร็วสูงเล็ก ๆ คั่นระหว่างซีพียูกับ RAM หลัก)
- **DRAM** (Dynamic RAM) = เก็บบิตด้วย "ตัวเก็บประจุ" (capacitor = ชิ้นส่วนที่เก็บประจุไฟฟ้าเล็ก ๆ) ซึ่งรั่วไหลได้ ต้องคอย "รีเฟรช" (refresh = ชาร์จซ้ำ) เป็นระยะ — ถูกและจุได้มาก นี่คือ RAM หลักของเครื่องเรา

ใน CircuitVerse มี RAM element (element = ชิ้นส่วนที่ลากมาวางบนกระดานใน CircuitVerse) สำเร็จรูป (มีพิน = ขา = จุดต่อสายของชิ้นส่วน ชื่อ ADDRESS, DATA IN, WRITE, DATA OUT) ให้ตั้งความกว้าง address และความกว้างข้อมูลได้ — เดี๋ยวเราใช้ในโจทย์

## 5. ทำไมเรื่องนี้สำคัญ: ตัวแปรที่เราเขียน = flip-flop ใน RAM

ถึงตรงนี้เราน่าจะเดาออกแล้วว่าทำไมเรื่องนี้ถึงเป็น "พื้นฐานที่แท้จริง":

ตอน 03 เราเขียน `var x int = 5` แล้ว Go ก็ "จำ" ค่า 5 ไว้ให้เราตลอดโปรแกรม — **ตอนนั้นเรายังไม่รู้ว่ามันจำได้ยังไง ตอนนี้เรารู้แล้ว**

สิ่งที่เกิดขึ้นเบื้องหลัง (ย่อ ๆ เพราะรายละเอียดทั้งหมดรอตอน 14 เรื่อง pointer และตอน 15 เรื่อง stack/heap):

1. ตอน compile (compile = แปลงโค้ดเป็นไฟล์ที่เครื่องรันได้ โดยโปรแกรมที่ทำหน้าที่นี้เรียกว่า **คอมไพเลอร์** = compiler — เราจะเรียนเต็ม ๆ ตอน 17) ตัวแปร `x` จะถูกจองพื้นที่ใน RAM — ถ้าเป็น `int64` ก็คือ 8 ไบต์ (8 address ติดกัน) พร้อม address ของไบต์แรก
2. ชื่อ `x` ที่เราเขียน เป็นแค่ **ป้ายกำกับ** ที่คอมไพเลอร์จำไว้ว่า "ค่าอยู่ที่ address ไหน" — เครื่องจริง ๆ มันเห็นแค่เลข address กับบิต ไม่เห็นชื่อ `x`
3. พอโปรแกรมรัน (run = สั่งให้โปรแกรมเริ่มทำงาน) ตัวเลข 5 ก็กลายเป็นก้อนบิต `000...0101` ที่ไปค้างอยู่ใน flip-flop (SRAM) หรือตัวเก็บประจุ (DRAM) ที่ address นั้น

นึกภาพในภาพที่ 4 ฝั่ง B: "ตัวแปร" กับ "ช่องใน RAM" เป็นเรื่องเดียวกัน ต่างกันแค่เราเรียกชื่อมันว่าอะไร

นี่คือเหตุผลที่เราต้องเรียนทั้งตอน 08 (บิต/ไบต์), ตอน 09 (วงจรคำนวณ), และตอนนี้ (วงจรจำ) ครบสามตอน — ถึงจะมองทะลุว่า "ตัวแปร" ที่ดูเป็นนามธรรม แท้จริงแล้วมันคืออะไรในระดับเครื่อง

## 6. ลงมือทำ: ต่อวงจรใน CircuitVerse

> **ก่อนเริ่ม:** เปิด https://circuitverse.org แล้วสร้าง project ใหม่ — ทดสอบได้ทันที (คลิก/สลับสวิตช์ได้เลย) · สวิตช์/ปุ่ม อยู่ในกลุ่ม **Input** · ไฟ LED อยู่ในกลุ่ม **Output** · logic gate อยู่ในกลุ่ม **Gates** · D flip-flop, Clock และ RAM อยู่ในกลุ่ม **Sequential Elements**

**ข้อ A — สร้าง SR latch จาก NOR 2 ตัว (เห็นเส้นป้อนกลับกับตา)**

1. ลาก gate **NOR** 2 ตัวมาวาง (ค้นหาในแถบ "Gates" เลือก NOR)
2. ต่อเอาต์พุตของ NOR ตัวบน กลับเข้าเป็นอินพุตหนึ่งของ NOR ตัวล่าง และกลับกัน (นี่คือเส้นป้อนกลับ)
3. ต่อ output สองตัว: NOR ตัวบนให้ Q, NOR ตัวล่างให้ Q′ แล้วติดป้ายด้วยเครื่องมือ Label
4. ต่อ input สองตัวแทน **R** (เข้ากับ NOR ตัวบน ตัวที่ให้ Q) และ **S** (เข้ากับ NOR ตัวล่าง ตัวที่ให้ Q′) — จำง่าย ๆ ว่า S ต้องเข้า gate ที่ให้ Q′ เพราะขา NOR ที่เป็น 1 จะดึงเอาต์พุตของตัวเองเป็น 0 (ตรงกับภาพที่ 1)
5. ทดสอบ: สลับ S เป็น 1 แล้วกลับเป็น 0 → Q ติดค้าง (จำได้!) แล้วสลับ R เป็น 1 แล้วกลับ 0 → Q ดับค้าง (ถูกล้าง)

**ข้อ B — ใช้ D flip-flop สำเร็จรูป**

1. ลาก **D Flip Flop** มาวาง (อยู่ในกลุ่ม Sequential Elements) — ตัวนี้เป็น edge-triggered อยู่แล้ว
2. ต่อ input D (สวิตช์จากกลุ่ม Input), clock และ output Q — สำหรับ clock ให้ใช้ปุ่ม **Button** (กลุ่ม Input) เพื่อทดสอบทีละขอบชัด ๆ (ถ้าใช้ element **Clock** — กลุ่ม Sequential Elements — มันจะเต้นอัตโนมัติทุก 500 ms แล้ว Q จะเปลี่ยนเองระหว่างทดสอบ; อยากใช้ Clock ก็ปิด **Clock Enabled** ใน Project Properties แผงขวาก่อน)
3. ลองสลับ D ไปมาระหว่างที่ clock (ปุ่ม Button) ยังเป็น 0 — Q ไม่เปลี่ยน แล้วกดปุ่มหนึ่งครั้ง (ปล่อยเป็น 1 ชั่วครู่แล้วกลับ 0) → Q รับค่า D ตอนขอบขาขึ้นพอดี

**ข้อ C — สร้าง register 4 บิต**

1. ลาก D Flip Flop 4 ตัวมาวางเรียงกัน
2. ต่อ input D3..D0 เข้า flip-flop แต่ละตัว
3. ต่อ clock (ปุ่ม Button หนึ่งปุ่ม) ตัวเดียวกันเข้า flip-flop ทั้ง 4 ตัว (ลากเส้นเชื่อม)
4. ต่อ Q3..Q0 ออกไปที่ output 4 ตัว
5. กดปุ่มครั้งที่ 1 ขณะ D = `0110` → Q = `0110` · เปลี่ยน D เป็น `1011` แล้วกดปุ่มครั้งที่ 2 → Q = `1011` · จากนั้นเปลี่ยน D เป็น `0011` แล้วอ่าน Q → ยังเป็น `1011` (เพราะไม่มีขอบ clock ใหม่) — ตรงกับตารางในภาพที่ 3

**ข้อ D — ใช้ RAM element สำเร็จรูป**

1. ลาก **RAM** มาวาง (กลุ่ม Sequential Elements) แล้วเปิดแผง Properties (ด้านขวา) ตั้ง **Address Width = 2** (เลือกได้ 4 ช่อง) และตั้ง **BitWidth = 4** (ช่อง BitWidth อยู่ด้านบนของแผง Properties — ข้อมูลกว้าง 4 บิต)
2. ต่อ input ตามพิน: ADDRESS (2 บิต), DATA IN (4 บิต), WRITE (1 บิต)
3. ทดสอบเขียน: ตั้ง ADDRESS = `01`, DATA = `1010`, แล้วสลับ WRITE เป็น 1 แล้วกลับเป็น 0 → ค่าถูกเขียนเข้าแถวที่ 1
4. ทดสอบอ่าน: เปลี่ยน DATA เป็น `0000` (โดยยังตั้ง ADDRESS = `01` อยู่) แล้วดู DATA OUT → ยังอ่าน `1010` ได้จากแถวที่ 1 (เพราะข้อมูลถูกจำไว้แล้ว)

ถ้าทำถึงข้อ D ได้ครบ แปลว่าคุณสร้างหน่วยความจำที่อ่าน-เขียนได้จริง ด้วยมือล้วน ๆ — และกลไกภายในมันก็คือ flip-flop ที่เราต่อเองในข้อ A–C นั่นแหละ

### ระดับ 2 — mini-project: หน่วยความจำ 4 ช่องที่เขียน-อ่านได้

4. **DATA OUT** 4 บิต (ใช้ไฟ LED 4 ดวง — LED = หลอดไฟเล็ก ๆ ที่ติด/ดับตามสัญญาณ)

แล้วทดสอบตามลำดับ (บันทึกผลทุกขั้น):

- เขียน `1100` ลง address `00`
- เขียน `0011` ลง address `01`
- เขียน `1010` ลง address `10`
- เขียน `0101` ลง address `11`
- จากนั้นไล่อ่านทั้ง 4 address กลับมา — ต้องอ่านได้ `1100, 0011, 1010, 0101` ตามลำดับ

(ท้าทาย) ลองเปลี่ยนจาก "เขียนค่าตายตัวด้วยสวิตช์" เป็น "นำค่าที่ ALU บวกลบออกมา (จากตอน 09) มาเขียนเข้า RAM" — ตรงนี้แหละที่วงจรคำนวณกับวงจรจำมาเจอกันเป็นครั้งแรก และนั่นคือแกนในของซีพียูจริง ๆ ที่เราจะประกอบเข้าด้วยกันในตอนถัดไป

## สรุป

วันนี้เราเดินจาก "วงจรที่จำไม่ได้" ไปจนถึง "หน่วยความจำทั้งก้อน" ครบเส้นทาง:

- **combinational logic** = วงจรคำนวณ จำไม่ได้ · **sequential logic** = วงจรจำ มีเส้นป้อนกลับ
- **SR latch** = NOR 2 ตัวไขว้กัน จำได้ 1 บิต — `S=0,R=0` ค้างค่า, `S=1` ตั้ง, `R=1` ล้าง, `S=R=1` ห้ามใช้
- **D flip-flop** = SR latch + gate + นาฬิกา รับค่าเฉพาะขอบขาขึ้น (edge-triggered) — หน่วยความจำ 1 บิตที่ใช้จริง
- **register** = D flip-flop หลายตัว + clock เดียว เก็บ N บิตพร้อมกัน
- **RAM** = register หลายตัว + address + decoder — เลข address เลือกว่าอ่าน/เขียนช่องไหน
- **address** = "เลขที่บ้าน" ของข้อมูล · "ตัวแปร" ในโค้ดคือป้ายกำกับที่ชี้ไปยัง address หนึ่งใน RAM

และจุดที่สำคัญที่สุดในเชิง "พื้นฐานที่แท้จริง": **ทุกตัวแปรในโค้ดที่เราเคยเขียน (Go หรือภาษาไหนก็ตาม) ในที่สุดก็คือบิตที่ค้างอยู่ใน flip-flop หรือตัวเก็บประจุ ณ address หนึ่งใน RAM** — จากตอนนี้ไป เวลาเขียน `var x = 5` คุณจะรู้ว่าเบื้องหลังมี flip-flop ตัวเล็ก ๆ เรียงกันหลายสิบตัวกำลัง "จำ" เลข 5 ให้คุณอยู่

ตอนต่อไปเราจะเอาสองสิ่งที่เราสร้างมา (วงจรคำนวณจากตอน 09 + วงจรจำจากตอนนี้) มาประกอบกันเป็น **ซีพียู** — เรียนวงจร fetch-decode-execute ว่าเครื่อง "อ่านคำสั่ง → ถอดความหมาย → ลงมือทำ" ซ้ำ ๆ เป็นล้านล้านครั้งต่อวินาทีได้ยังไง
