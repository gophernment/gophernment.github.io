# ตั้งเครื่องมือให้พร้อม — ติดตั้ง Go, Editor, Terminal แล้วรันโค้ดแรกด้วยมือคุณเอง (ตอนที่ 02) — CS Fundamentals: จาก 0 สู่พื้นฐานที่แท้จริง

> 📅 เขียนเมื่อ: 5 กันยายน 2026 | โค้ดตัวอย่างทดสอบจริงด้วย Go 1.24.4 ที่ติดตั้งบนเครื่องผม; เวอร์ชันล่าสุดของ Go ณ วันเขียนคือ 1.27.1 (ออก 1 กันยายน 2026 — ตรวจจาก go.dev/doc/devel/release)
> ⚠️ เวอร์ชันเครื่องมือ/ภาษามีการออกใหม่เรื่อย ๆ — ตรวจสอบเอกสารล่าสุดก่อนใช้งานจริงเสมอ

ตอนที่แล้ว (ตอน 01) เราคุยกันถึง "ตึก 5 ชั้น" ของซอฟต์แวร์ และตกลงกันว่าจะใช้ **ภาษา Go** เป็นพาหนะขุดลงไปทีละชั้น แต่อย่าลืมว่าเราเป็นแค่คนถือแผนที่ — ยังไม่มีเครื่องมืออยู่ในมือเลย

ตอนนี้คือวัน "ตั้งโรงงาน" ยังไม่ต้องเขียนโค้ดที่ซับซ้อนอะไร เป้าหมายเดียวของตอนนี้คือ: **เมื่ออ่านจบ คุณมีเครื่องมือครบและรันโปรแกรมแรกของคุณเองได้จริง** เหมือนช่างไม้ที่วันแรกไม่ต้องต่อเรือน — แค่มีเลื่อย มีค้อน แล้วรู้วิธีใช้ ต่อไปค่อยฝึกฝีมือ

ขอเล่าให้ฟังก่อนว่า dev (developer = นักพัฒนาโปรแกรม) ทำงานกับเครื่องมืออะไรบ้าง แล้วเราจะติดตั้งทีละตัว ลงมือทำไปพร้อมกัน

## เครื่องมือ 3 อย่างที่ dev ใช้ทุกวัน

เวลาเห็นคนทำงานเป็น dev ในหนังหรือในคลิป จะเห็นเขาทำ 3 อย่างวนไปมา: **พิมพ์คำสั่ง** บ้าง **แก้โค้ดในหน้าต่าง editor** บ้าง และ**รันโปรแกรม** บ้าง เบื้องหลังทั้งสามคือเครื่องมือชุดนี้:

```
            คุณ (คนสั่งงาน)
                 │
   ┌─────────────┼───────────────────┐
   ▼             ▼                   ▼
[terminal]   [editor/IDE]      [compiler/toolchain]
 พิมพ์คำสั่ง    เขียน/แก้โค้ด      แปลภาษาให้เครื่อง
 เช่น go run    เป็นไฟล์ .go       ทำงานได้ (Go)
```

- **terminal** (เทอร์มินัล = หน้าต่างพิมพ์คำสั่ง บางทีเรียก command line = แถวคำสั่ง หรือ console) คือหน้าต่างที่คุณพิมพ์คำสั่งเป็นข้อความ แล้วเครื่องทำตาม เช่น สั่ง "รันไฟล์นี้" "ย้ายไปโฟลเดอร์นั้น" — ไม่มีปุ่มกด มีแต่ตัวหนังสือ
- **editor** (editor = โปรแกรมแก้ข้อความ เรียกเต็มว่า text editor = โปรแกรมแก้ไฟล์ข้อความ) คือที่ใช้เขียนโค้ด ซึ่งเป็นข้อความธรรมดานี่แหละ แต่ editor เก่ง ๆ จะช่วยย้อมสีคำสั่ง เตือนว่าพิมพ์ผิด เติมโค้ดให้บางส่วน (IDE = editor รุ่นครบเครื่อง อธิบายในหัวข้อ VS Code ด้านล่าง)
- **compiler/toolchain** — ตอน 01 รู้จัก compiler (ตัวแปลภาษาโค้ดเป็นภาษาเครื่อง) ไปแล้ว ส่วน toolchain (ทูลเชน = ชุดเครื่องมือที่ทำงานต่อกันเป็นสายพาน) ของ Go คือชุดคำสั่ง `go` ที่มาพร้อมกัน เช่น `go run` สั่งรัน `go build` สั่งสร้างไฟล์โปรแกรม เราจะเรียกรวม ๆ ว่า "Go" หรือ "Go toolchain"

ถ้าจะเปรียบ: terminal คือพวงมาลัยกับคันเร่ง, editor คือห้องทำงานที่เราเขียนแบบแปลน, Go คือเครื่องยนต์ — ครบสามอย่างถึงจะขับไปไหนได้

## ติดตั้ง Go (ภาษาโปรแกรมของเรา)

### ศัพท์ 2 คำที่ต้องรู้ก่อนกดติดตั้ง

- **installer** (อินสตอลเลอร์ = โปรแกรมติดตั้ง) คือไฟล์โปรแกรมที่คอย "ติดตั้ง" ของให้เข้าที่เข้าทาง — คัดลอกไฟล์ไปไว้โฟลเดอร์ที่ถูกต้อง ตั้งค่าต่าง ๆ ให้ บางตัวถามเรากด Next/Continue ไปเรื่อย ๆ
- **PATH** (อ่านว่า พาธ = ทางเดิน) — เวลาเราพิมพ์คำสั่ง `go version` ใน terminal เครื่องต้องรู้ว่าคำสั่ง `go` คือโปรแกรมอะไรอยู่ที่ไหน PATH คือ **รายการที่อยู่โฟลเดอร์ที่ OS (ระบบปฏิบัติการ) ใช้ค้นหาโปรแกรม** เมื่อเราพิมพ์ชื่อคำสั่งโดยไม่บอกที่อยู่เต็ม โชคดีที่ installer ของ Go ตั้ง PATH ให้เราเกือบหมด — เราจึงแค่ต้องรู้ว่ามันคืออะไร เผื่อเวลาเจอปัญหา

แหล่งดาวน์โหลดอย่างเป็นทางการคือ **https://go.dev/dl** (หน้าดาวน์โหลดของภาษา Go) — หน้าเว็บนี้จะให้เลือก OS กับสถาปัตยกรรมเครื่อง (architecture = ตระกูลชิปประมวลผล เช่น amd64 = ชิปตระกูล Intel/AMD ทั่วไป หรือ arm64 = ชิปตระกูล ARM เช่น ใน Mac รุ่นใหม่หรือ Raspberry Pi) และ**แนะนำไฟล์ที่ตรงกับเครื่องเราให้เอง** เลือกตามนั้นได้เลย

### Windows

1. เปิด https://go.dev/dl แล้วโหลดไฟล์ที่ลงท้าย `.msi` (ตัวติดตั้งของ Windows — ตัวอย่างชื่อ `go1.27.1.windows-amd64.msi`)
2. ดับเบิลคลิกไฟล์ แล้วกด Next ไปเรื่อย ๆ จนเสร็จ — installer จะติดตั้ง Go ไว้ที่ `C:\Program Files\Go` และ**ตั้งค่า PATH ให้อัตโนมัติ**
3. เปิด **PowerShell** (โปรแกรม terminal ของ Windows — กดปุ่ม Start พิมพ์ powershell แล้ว Enter) แล้วพิมพ์:

```
go version
```

ถ้าเห็นข้อความขึ้นต้นด้วย `go version go1.27.1 ...` แปลว่าสำเร็จ (ตัวเลขอาจใหม่กว่านี้ ถ้าคุณโหลดทีหลัง)

### macOS

1. โหลดไฟล์ที่ลงท้าย `.pkg` จาก https://go.dev/dl (Mac ชิป Apple ใช้ `darwin-arm64`, Mac รุ่นเก่าชิป Intel ใช้ `darwin-amd64` — หน้าเว็บแนะนำให้)
2. ดับเบิลคลิก `.pkg` แล้วกด Continue ไปเรื่อย ๆ — ติดตั้งลงที่ `/usr/local/go` และตั้ง PATH ให้เอง
3. เปิดแอป **Terminal** (อยู่ในโฟลเดอร์ Utilities หรือค้นหาได้) แล้วพิมพ์:

```
go version
```

เห็นข้อความ `go version go1.27.1 ...` = สำเร็จ

### Linux

1. โหลดไฟล์ `.tar.gz` (ไฟล์บีบอัด วิธีแกะคือคำสั่ง `tar`) จาก https://go.dev/dl เช่น `go1.27.1.linux-amd64.tar.gz` (เครื่อง ARM ใช้ `linux-arm64`)
2. เปิด terminal (ถ้ายังเปิดไม่เป็น — อ่านหัวข้อ Terminal ด้านล่างก่อน แล้วกลับมา) แล้ว cd ไปโฟลเดอร์ที่ดาวน์โหลดไฟล์ไว้ก่อน เช่น `cd ~/Downloads` (`~` = ทิลเดอ ย่อของโฟลเดอร์บ้าน — อธิบายเพิ่มในหัวข้อลงมือ) แล้วรันสองคำสั่งนี้ (คำสั่งแรกคือ "ลบ Go รุ่นเก่าทิ้งถ้ามี" คำสั่งสองคือ "แกะไฟล์ที่โหลดมาไปไว้ที่ /usr/local") — ถ้าเครื่องถามรหัสผ่านก็พิมพ์ไป (สองคำสั่งนี้ต้องมีสิทธิ์ระดับผู้ดูแล: root = บัญชีผู้ดูแลของระบบ ส่วน sudo = คำสั่งที่ขอสิทธิ์ผู้ดูแลชั่วคราวเฉพาะคำสั่งนั้น — อย่าสับสนว่าเป็นสิ่งเดียวกัน):

```
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.27.1.linux-amd64.tar.gz
```

> ⚠️ ถ้าชื่อไฟล์ที่โหลดมาไม่ตรงกับชื่อไฟล์ในคำสั่ง (เครื่อง ARM หรือเวอร์ชันใหม่ออกแล้ว) ให้แก้ชื่อไฟล์ในคำสั่งให้ตรงกับไฟล์ที่โหลดจริง

3. ต่อจากนี้ต้อง "บอก PATH ให้รู้จัก Go" โดยเพิ่มบรรทัดนี้ลงในไฟล์ `~/.profile` (ไฟล์ตั้งค่าส่วนตัวของเราในโฟลเดอร์บ้าน):

> ⚠️ ขั้นนี้ต้องใช้ editor เปิดไฟล์ — ถ้ายังไม่มี editor ในมือ **อย่าเพิ่งทำขั้นนี้** ให้ข้ามไปติดตั้ง VS Code ในหัวข้อถัดไปให้เสร็จก่อน แล้วค่อยกลับมาเปิด `~/.profile` ด้วย VS Code ตามนี้:

> 1. **เปิดไฟล์:** ใน VS Code กด File → Open File… เลือกไฟล์ `.profile` ในโฟลเดอร์บ้าน แล้วเพิ่มบรรทัดด้านล่างลงไป
> 2. **หาไฟล์ไม่เจอ?** เพราะ `.profile` เป็นไฟล์ซ่อน (ชื่อขึ้นต้นด้วยจุด กล่อง Open File… มักไม่โชว์) — ให้ใช้ File → Open Folder… แล้วคลิก `.profile` ในรายการด้านซ้าย หรือกด Ctrl+H ในหน้าต่าง Open File เพื่อโชว์ไฟล์ซ่อน
> 3. **ไม่มีไฟล์ `.profile` เลย?** บาง distro เช่น Fedora ใช้ `.bash_profile` แทน — ให้เพิ่มบรรทัดลงในไฟล์ที่ distro ของคุณอ่านตอนเปิด terminal (เช่น `~/.bash_profile`) หรือถ้าไม่แน่ใจ สร้างไฟล์ใหม่ชื่อ `.profile` ในโฟลเดอร์บ้านก็ได้

```
export PATH=$PATH:/usr/local/go/bin
```

(คำสั่งนี้แปลว่า "ให้ PATH เดิม ต่อท้ายด้วย /usr/local/go/bin" — สังเกตว่าใช้ `:` คั่น เพราะ PATH คือรายการที่คั่นด้วยเครื่องหมายทวิภาค) พอแก้เสร็จ ให้ปิด terminal แล้วเปิดใหม่ หรือพิมพ์ `source ~/.profile` เพื่อโหลดค่าทันที แล้วตรวจ:

```
go version
```

> หมายเหตุ: เครื่องมือเสริมที่ลงผ่านคำสั่ง `go install` (เช่นตัวช่วยภาษา) จะอยู่ที่โฟลเดอร์ `$(go env GOPATH)/bin` — ถ้าจะใช้ต้องเพิ่ม `export PATH="$PATH:$(go env GOPATH)/bin"` ลงใน `~/.profile` ด้วย แต่คอร์สนี้ใช้แค่ `go run`/`go build` ที่มากับ Go อยู่แล้ว **ไม่ต้องทำตอนนี้**

### ถ้าติดตั้งแล้ว แต่เครื่องบอก "go: command not found"

ข้อความนี้แปลตรงตัว: **เครื่องหาโปรแกรมชื่อ go ไม่เจอ** — ปกติเพราะ PATH ยังไม่รู้จักตำแหน่งของ Go (หรือยังไม่ได้เปิด terminal ใหม่หลังติดตั้ง) ลองปิด-เปิด terminal ก่อน ถ้ายังไม่หาย ให้กลับไปทวนขั้นตอน PATH ของระบบตัวเอง — นี่คือตัวอย่างแรกของสิ่งที่ตอนท้ายบทเราจะฝึก: **อ่าน error ให้เป็น แล้วแก้ทีละจุด**

> หมายเหตุเล็กน้อย: เครื่องที่ผมใช้ทดสอบโค้ดในซีรีส์นี้รัน Go 1.24.4 อยู่ (วิธีเช็คเหมือนกันทุกเวอร์ชัน — พิมพ์ `go version`) แต่ถ้าคุณติดตั้งใหม่ตามขั้นตอนข้างบนวันนี้ คุณจะได้เวอร์ชัน 1.27.1 ซึ่งใหม่กว่า — โค้ดในคอร์สนี้เขียนให้รันได้ทั้งสองเวอร์ชัน ไม่ต้องกังวล

## Editor: VS Code — ที่เขียนโค้ด

### text editor กับ IDE ต่างกันยังไง

- **text editor** (โปรแกรมแก้ข้อความ) ใช้แก้ไฟล์ข้อความอะไรก็ได้ รวมทั้งโค้ด — เบา เปิดไว อย่าง Notepad (แผ่นจดบันทึก) ก็เป็น text editor แต่ดิบเกินไป
- **IDE** (อ่านว่า ไอ-ดี-อี ย่อจาก Integrated Development Environment = สภาพแวดล้อมการพัฒนาที่รวมทุกอย่างไว้) คือ editor ที่ฝังเครื่องมือ dev มาด้วย เช่น รันโปรแกรมในตัว ไล่จุดบกพร่อง (debug) ในตัว เชื่อมฐานข้อมูล — หนักแต่ครบเครื่อง ตัวอย่าง IDE เต็มรูปแบบ เช่น Visual Studio, IntelliJ
- **VS Code** (Visual Studio Code) คือ**editor ฟรี**ของ Microsoft ที่อยู่ตรงกลางระหว่างสองอย่าง: เบาพอเหมือน text editor แต่ต่อเติมเป็น IDE ได้ด้วย **extension** (เอกซ์เทนชัน = ส่วนเสริมที่เพิ่มความสามารถให้โปรแกรมหลัก) — เป็น editor ยอดนิยมอันดับต้น ๆ ของโลก dev และดาวน์โหลดฟรีที่ **https://code.visualstudio.com** (ชื่อเดียวกับ Visual Studio แต่คนละโปรแกรมกันนะ — VS Code เบากว่าและเป็นที่นิยมกว่าในหมู่ dev สมัยใหม่)

ตอนนี้ให้ทำสองอย่าง: **ติดตั้ง VS Code** จาก code.visualstudio.com แล้วเปิดโปรแกรมขึ้นมา จะเห็นหน้าต่าง ๆ ประกอบด้วยแถบเมนู พื้นที่ว่างสำหรับไฟล์ และไอคอนแถวซ้าย (activity bar = แถบกิจกรรม) — ยังไม่ต้องจำอะไรทั้งหมด เดี๋ยวใช้ไปก็คุ้นเอง

### ติดตั้ง extension "Go" อย่างเป็นทางการจาก Go Team

ขั้นตอนนี้สำคัญ — เปิด VS Code แล้ว:

1. คลิกไอคอน **Extensions** ที่แถวซ้าย (รูปสี่เหลี่ยมต่อกัน 4 ชิ้น เหมือนต่อบล็อก)
2. พิมพ์ค้นหา: `Go`
3. เลือกตัวที่ชื่อ **Go** และชื่อผู้เผยแพร่ (publisher = ผู้จัดทำ) คือ **Go Team at Google** — ตัวนี้คือ extension ทางการของทีมภาษา Go เอง ไม่ใช่ของคนอื่นที่ชื่อคล้ายกัน (เช็คจากรหัสประจำตัว (id) ใน marketplace — ศูนย์รวมส่วนเสริมของ VS Code — ต้องเป็น `golang.Go`)
4. กด Install

**extension คืออะไร** — ต่อยอดจากข้างบน: VS Code เองยังไม่รู้อะไรเกี่ยวกับภาษา Go มันเป็นแค่ editor เก่ง ๆ พอติดตั้ง extension Go มันถึง "เข้าใจ" ภาษา: ย้อมสีโค้ดให้อ่านง่าย เตือนตอนพิมพ์ผิด และ**จัดรูปแบบโค้ดให้อัตโนมัติตอนเซฟด้วย gofmt** (เครื่องมือจัดรูปแบบที่เล่าไว้ตอน 01) — เหมือนซื้อเครื่องจักรที่โรงงาน แล้วต่อสายไฟให้มันรู้จักภาษาของงานเรา

เบื้องหลังที่ควรรู้: extension Go ทำงานร่วมกับ **gopls** (ออกเสียงว่า กอ-เพิลส์ — ย่อจาก Go + please) ซึ่งเป็น **language server** (แลงเกวจ เซิร์ฟเวอร์ = โปรแกรมที่คอย "อ่านโค้ดทั้งโปรเจกต์" ให้ editor ตลอดเวลา เพื่อตอบคำถามเช่น "ตรงนี้พิมพ์ผิดไหม" "ฟังก์ชันนี้ใช้ที่ไหนบ้าง") พอเปิดไฟล์ `.go` ครั้งแรก ตัว extension จะติดตั้ง gopls ให้เองอัตโนมัติ (บางกรณีอาจมีแถบถามขึ้นมา ให้กด Install/Yes ไปได้เลย) — นี่คือของทางการจากทีม Go ทั้งหมด

ถ้าคุณใช้ Linux และข้ามขั้น PATH ตอนหัวข้อติดตั้ง Go — กลับไปทำตอนนี้ (เปิด `~/.profile` แล้วเพิ่มบรรทัด PATH) ก่อนเรียนต่อ

## Terminal: บ้านหลังใหม่ของคุณ + คำสั่งพื้นฐาน 3 คำ

ตอนนี้เรามี Go แล้ว มี VS Code แล้ว เหลืออีกอย่างที่ต้องคุ้น: **terminal** เพราะคำสั่ง `go run` ที่จะใช้ทุกตอน พิมพ์ที่ terminal

- Windows: เปิด **PowerShell** (หรือ Windows Terminal ที่มากับ Windows 11)
- macOS: เปิด **Terminal**
- Linux: เปิด terminal — ส่วนใหญ่กด **Ctrl+Alt+T** หรือค้นหา "Terminal" ในเมนูแอป โปรแกรม terminal จะต่างกันนิดหน่อยตาม distro (ดิสโทร = Linux แต่ละเวอร์ชัน/ตระกูล เช่น Ubuntu, Debian, Fedora) ที่ใช้ แต่ใช้งานเหมือนกัน

เวลาพิมพ์ คุณจะเห็น **prompt** (พร้อมต์ = สัญลักษณ์บอกว่า "พร้อมรับคำสั่ง") เช่น `$` บน macOS/Linux หรือ `PS C:\Users\you>` บน PowerShell — ไม่ต้องกังวลว่าหน้าตาต่างกัน สิ่งที่ต้องรู้คือ: เราพิมพ์คำสั่งต่อท้าย prompt แล้วกด Enter เครื่องจะทำแล้วตอบกลับมา

ขอสอนคำสั่งพื้นฐาน 3 คำ ที่จะใช้ไปตลอดอาชีพ:

| คำสั่ง | แปลว่า | ใช้ทำอะไร |
|---|---|---|
| `pwd` | print working directory (พิมพ์โฟลเดอร์ที่ทำงานอยู่) | ถามว่า "ตอนนี้ฉันอยู่ในโฟลเดอร์ไหน" — Windows ใช้คำสั่งนี้ได้เหมือนกัน |
| `ls` | list (แสดงรายการ) | แสดงไฟล์ในโฟลเดอร์ปัจจุบัน — Windows ใช้ `dir` (หรือ `ls` ก็ใช้ได้ใน PowerShell) |
| `cd` | change directory (เปลี่ยนโฟลเดอร์) | เดินเข้าออกโฟลเดอร์ เช่น `cd gopher-course` เข้าไปในโฟลเดอร์นั้น, `cd ..` ถอยออกไปโฟลเดอร์บน |

ศัพท์ที่เพิ่งโผล่: **directory** (ดิเรกทอรี) คือโฟลเดอร์นั่นเอง — dev ชอบใช้คำนี้ และ **current directory / working directory** (เคอร์เรนต์/เวิร์กกิงดิเรกทอรี = โฟลเดอร์ที่เรายืนอยู่ตอนนี้) เวลาโปรแกรมทำงาน มันจะทำงาน "ที่" โฟลเดอร์ปัจจุบันนี้ — จำไว้ เกี่ยวพันกับ error ตอนท้ายบท

ลองเปิด terminal แล้วพิมพ์ตาม:

```
pwd
```

เครื่องจะตอบที่อยู่โฟลเดอร์ปัจจุบัน เช่น `/home/you` (Linux), `/Users/you` (macOS) หรือ `C:\Users\you` (Windows) — นี่คือ "บ้าน" ของคุณในคอมพิวเตอร์ ที่ dev เรียกว่า home directory (โฮมไดเรกทอรี = โฟลเดอร์ส่วนตัว)

เทคนิคเล็ก ๆ ที่ dev ใช้ทุกวัน: พิมพ์ชื่อโฟลเดอร์แล้วกด **Tab** เครื่องจะเติมชื่อที่เหลือให้เอง (autocomplete = เติมอัตโนมัติ) และกด **ปุ่มลูกศร ↑** เพื่อเรียกคำสั่งก่อนหน้า — ลองใช้ดู จะรู้สึกว่าพิมพ์เร็วขึ้นมาก

## ลงมือ: สร้างโฟลเดอร์โปรเจกต์แล้วรัน hello world แรก

เริ่มจากสร้าง "ที่ทำงาน" สำหรับคอร์สนี้ ตั้งชื่ออะไรก็ได้ที่จำง่าย ขอแนะนำ `gopher-course` (gopher = เจ้ามาร์มอตมาสคอตของภาษา Go — ตอน 01 เล่าถึงคนสร้าง Unix ที่ออกแบบ Go ให้จำง่าย มาร์มอตก็เป็นมาสคอตที่จำง่ายเหมือนกัน):

แถมอีก 1 คำสั่งใหม่ที่เพิ่งใช้ในโค้ดด้านล่าง: `mkdir` (make directory = สร้างโฟลเดอร์) ส่วน `~` (ทิลเดอ) ไม่ใช่คำสั่ง แต่เป็น**สัญลักษณ์**ย่อของโฟลเดอร์บ้านคุณ — `cd ~` = กลับบ้าน รันตามนี้:

```
cd ~
mkdir gopher-course
cd gopher-course
```

คราวนี้พอพิมพ์ `pwd` จะเห็นว่าเราอยู่ใน `/home/you/gopher-course` (หรือเทียบเท่า)

ต่อไป สร้างไฟล์โค้ดแรก — เปิด VS Code แล้วเลือก **File → Open Folder...** เลือกโฟลเดอร์ `gopher-course` (การเปิดทั้งโฟลเดอร์แทนที่จะเปิดไฟล์เดียว ช่วยให้ VS Code เห็นโครงสร้างงานทั้งหมด) จากนั้นสร้างไฟล์ใหม่ชื่อ `main.go` (คลิกไอคอน New File หรือ File → New File) แล้วพิมพ์โค้ดจากตอน 01 ลงไป:

```go
package main

import "fmt"

func main() {
    fmt.Println("สวัสดี ชาวโลก!")
}
```

เซฟไฟล์ (Ctrl+S หรือ Cmd+S) — ถ้าติดตั้ง extension Go แล้ว VS Code จะจัดรูปแบบให้อัตโนมัติ กลับไปที่ terminal (ซึ่งยังอยู่ในโฟลเดอร์ `gopher-course` — เช็คด้วย `pwd` ได้) แล้วรัน:

```
go run main.go
```

ผลลัพธ์ที่ควรเห็น:

```
สวัสดี ชาวโลก!
```

(ทดสอบจริงบนเครื่องผม Go 1.24.4 — รันผ่าน ได้ผลลัพธ์ข้างบน)

ยินดีด้วย — คุณรันโปรแกรมแรกด้วยมือตัวเองแล้ว! 🎉

### go run กับ go build ต่างกันยังไง — คำถามที่มือใหม่ทุกคนสงสัย

สองคำสั่งนี้เราจะใช้บ่อยมาก ขอให้เข้าใจให้ถ่องแท้ตั้งแต่ตอนนี้ เพราะมันคือหัวใจของ "ชั้น 3" (ภาษาโปรแกรม + compiler) ที่เราจะขุดลงไป:

```
go run main.go                    go build -o hello main.go
      │                                  │
      ▼                                  ▼
 แปลงโค้ดเป็นภาษาเครื่อง                   แปลงโค้ดเป็นภาษาเครื่อง
 (compile)                               (compile)
      │                                  │
      ▼                                  ▼
 รันเลย แล้วไม่เก็บไฟล์ภาษาเครื่องชั่วคราวไว้ เขียนผลลัพธ์เป็นไฟล์โปรแกรม
 (ไฟล์ภาษาเครื่องชั่วคราว)                 ลงดิสก์: executable/binary
                                           │
                                           ▼
                                      รันเมื่อไรก็ได้: ./hello
```

- **`go run main.go`** = "compile แล้วรันเลย" — ใช้ตอนที่กำลังทดลอง อยากเห็นผลเร็ว ๆ ไม่ต้องเหลือไฟล์อะไรไว้
- **`go build -o hello main.go`** = "compile แล้ว**เก็บผลลัพธ์เป็นไฟล์**" — ตัว `-o` (ย่อจาก output = ผลลัพธ์) บอกชื่อไฟล์ที่จะเขียน: `hello` — **ทั้ง Windows, macOS และ Linux จะได้ไฟล์ชื่อ `hello` ตรงตามที่สั่ง** ไม่มีนามสกุลต่อท้าย (การตั้งชื่อให้มีความหมายเองแบบนี้ก็อ่านง่ายกว่า) ส่วนไฟล์ `.exe` ที่คุ้นกันบน Windows — Go **เติมให้อัตโนมัติเฉพาะตอนไม่ใส่ `-o`** โดยตั้งชื่อตามไฟล์ต้นทาง: รัน `go build main.go` บน Windows ได้ `main.exe` แต่บน macOS/Linux ได้ `main` ถ้าอยากให้ได้ไฟล์ `.exe` บน Windows ต้องตั้งชื่อเอง: `go build -o hello.exe main.go`

ลองทำดู: รัน `go build -o hello main.go` ในโฟลเดอร์เดิม แล้วพิมพ์ `ls` จะเห็นไฟล์ใหม่ชื่อ `hello` โผล่มา — บนเครื่องผม (Linux) ไฟล์นี้มีขนาดประมาณ 2.1 MB (ทดสอบจริง) ซึ่งใหญ่เพราะข้างในมีภาษาเครื่อง + ของที่จำเป็นต่อการรันโปรแกรม Go ครบ แล้วรันไฟล์นั้นตรง ๆ:

```
./hello
```

(สัญลักษณ์ `./` หน้า hello คือ "ไฟล์ในโฟลเดอร์ปัจจุบันนี้" — จุดหนึ่งจุด = โฟลเดอร์ปัจจุบัน) ผลลัพธ์เหมือนเดิม: `สวัสดี ชาวโลก!`

ถ้าใช้ Windows: ให้สั่ง build ด้วย `go build -o hello.exe main.go` แทน แล้วค่อยพิมพ์ `.\hello.exe` เพื่อรันไฟล์ (หรือถ้าไม่ใช้ `-o` — รัน `go build main.go` จะได้ `main.exe` แล้วพิมพ์ `.\main.exe`) เพราะ Go เติม `.exe` ให้เองเฉพาะตอนไม่ใส่ `-o` เท่านั้น ส่วนสัญลักษณ์บอกตำแหน่งไฟล์ในโฟลเดอร์ปัจจุบัน บน Windows เขียนด้วยสแลชกลับหลัง `\` แทน `/` ที่ใช้บน macOS/Linux

ไฟล์ `hello` ที่เพิ่งรันนี้เรียกว่า **executable** (เอกเซคิวทะเบิล = ไฟล์ที่รัน/เปิดเป็นโปรแกรมได้) หรือ **binary** (ไบนารี = ไฟล์ภาษาเครื่องล้วน ๆ ที่คนอ่านไม่ออก) — ต่างจากไฟล์ `main.go` ที่เป็นข้อความอ่านได้ ตัว executable/binary นี้คือ "ของที่ compile เสร็จแล้ว" พร้อมเปิดรันเมื่อไรก็ได้

จุดที่ควรจดไว้ (จะลงลึกตอน 17 ว่าขั้นตอนละเอียดเป็นยังไง): `go run` กับ `go build` ต่างกันแค่**ปลายทางของผล compile** — ขั้นตอน "แปลภาษา" เหมือนกัน ตอนนี้พอแค่นี้ก่อน

## วิธีเรียนวิชานี้: สร้าง → พัง → อ่าน → สร้างใหม่

ตอนนี้คุณมีเครื่องมือครบแล้ว ก่อนจากกันตอนนี้ ขอสอน **วิธีเรียน** ของคอร์สนี้ — สำคัญพอ ๆ กับตัวเนื้อหา เพราะถ้าเรียนวิธีผิด คุณจะท้อตอนแรก ๆ ที่เจอ error แล้วเลิกกลางคัน

วิธีเรียนของคอร์สนี้คือวงจร 4 ขั้น:

```
   ┌─────────────────────────────────────────────┐
   │                                             │
   ▼                                             │
สร้าง (เขียนโค้ดจากที่เรียนมา ลองเดาได้)          │
   │                                             │
   ▼                                             │
รัน (go run)                                     │
   │                                             │
   ▼                                             │
พังไหม? ──ไม่──► ได้ผลตามคาด → ลองโจทย์ใหม่ ◄─────┘
   │ใช่
   ▼
อ่าน error ให้ละเอียด (มันบอกที่อยู่กับสาเหตุ)
   │
   ▼
แก้ไข แล้วกลับไป "สร้าง" ใหม่
```

**"สร้าง"** คือเขียนโค้ดจากสิ่งที่เพิ่งเรียน — ไม่ต้องกลัวเดาผิด "**พัง**" คือรันแล้วเจอ error (ตอน 01 รู้จักแล้ว = ข้อความแจ้งข้อผิดพลาด) "**อ่าน**" คืออ่าน error ให้เข้าใจว่ามันบอกอะไร "**สร้างใหม่**" คือแก้แล้วลองอีกครั้ง

### ทำไม "พัง" ถึงไม่ใช่ความล้มเหลว

ฟังดูขัดกับสัญชาตญาณ แต่ขอพูดแบบอาจารย์ตรง ๆ: **การพังคือข้อมูล ไม่ใช่คำพิพากษา** error ที่ขึ้นคือคอมพิวเตอร์กำลังบอกคุณอย่างสุภาพมากว่า "ฉันเดินตามโค้ดคุณไม่ไหว — เพราะสาเหตุนี้ ที่บรรทัดนี้" ถ้าไม่มี error คุณจะไม่มีวันรู้ว่าจุดไหนที่เข้าใจผิด — มันคือ **การบ้านที่เครื่องตรวจให้ฟรี**

ความเชื่อแบบนี้มีชื่อว่า **growth mindset** (โกรท ไมนด์เซต = ความเชื่อว่าความสามารถพัฒนาได้ด้วยการฝึก ไม่ใช่ของตายตัวตั้งแต่เกิด) — คนที่เชื่อว่าตัวเอง "ไม่เก่งคอม" จะอ่าน error แล้วถอดใจว่า "ฉันไม่เหมาะกับสิ่งนี้" ส่วนคนที่เชื่อว่าความสามารถฝึกได้ จะอ่าน error แล้วถามว่า "เครื่องกำลังบอกอะไรฉัน" — ผลลัพธ์ต่างกันราวฟ้ากับดิน

และถ้าย้อนไปตอน 01: คนที่สร้าง Unix, Linux, Git, Go — พวกเขาเจอของพังทั้งนั้น ที่จริง Linux เกิดจากเครื่องมือเดิม "ไม่พอใจ" Go ก็เกิดจากภาษาที่มีอยู่ "ทำงานช้า" พวกเขาไม่ได้เก่งเพราะไม่เคยพัง แต่เก่งเพราะ**พังแล้วอ่าน แล้วสร้างใหม่** — บางครั้งทั้งชีวิตวนอยู่ในวงจรนี้

### อ่าน error ยังไง — ตัวอย่างจริง

error ของ Go มีสูตรอ่านง่ายมาก ขอดึงมาจากที่รันจริงบนเครื่องผม (ตั้งใจทำพัง เพื่อให้เห็นของจริง):

**ตัวอย่างที่ 1: พิมพ์ชื่อฟังก์ชันผิด** — ผมพิมพ์ `fmt.Prntln` (ลืมตัว i):

```
# command-line-arguments
./main.go:6:9: undefined: fmt.Prntln
```

บรรทัดแรกที่ขึ้นต้นด้วย `#` นั้น**ไม่ใช่ตัว error** — มันคือชื่อโปรเจกต์ชั่วคราวที่ Go สร้างขึ้นเองตอนรันไฟล์เดี่ยว ๆ (เรายังไม่ได้ตั้งชื่อโปรเจกต์จริง) ให้ข้ามไป แล้วมองบรรทัดถัดไปซึ่งมี `ชื่อไฟล์:เลข:เลข` — นั่นคือตำแหน่งที่แท้จริงของปัญหา

อ่านเป็นสูตร: **`ชื่อไฟล์:เลขบรรทัด:เลขหลัก: สาเหตุ`**

- `./main.go` = ไฟล์ไหน (จุดข้างหน้าแปลว่า "ในโฟลเดอร์ปัจจุบัน")
- `:6` = บรรทัดที่ 6 (ลองนับจากบนสุดของไฟล์)
- `:9` = หลักที่ 9 นับจากซ้ายมือของบรรทัดนั้น (ตำแหน่งอักษร) — เลขหลักขึ้นกับช่องว่างหน้าโค้ด (indent) ด้วย: ตัวอย่างนี้ใช้ indent 4 ช่อง (เว้น 4 เคาะ) พอ VS Code จัดรูปแบบให้เป็น tab (ตอนเซฟ) เลขอาจเลื่อน แต่จุดที่ error ชี้ยังตรงเดิม
- `undefined: fmt.Prntln` = "ไม่รู้จัก fmt.Prntln" — แปลว่า Go หาฟังก์ชันชื่อนี้ไม่เจอ เพราะมันไม่มีจริง เราพิมพ์ผิด — แก้เป็น `fmt.Println`

**ตัวอย่างที่ 2: ใช้ตัวแปรที่ยังไม่ได้ประกาศ** — ผมเขียน `fmt.Println(y)` ทั้งที่ไม่เคยนิยามว่า y คืออะไร:

```
# command-line-arguments
./main.go:6:17: undefined: y
```

อ่านแบบเดียวกัน: บรรทัด 6 หลัก 17 — "y ไม่รู้จัก" (เราจะเรียนตัวแปร = ช่องเก็บค่าเต็มรูปแบบตอนหน้า แต่เห็น error แบบนี้ไว้ก่อนก็ดี)

**ตัวอย่างที่ 3: ลืมปีกกาปิด** — ถ้าเราเอา `main.go` ที่เพิ่งเขียนไป ลบปีกกาปิด `}` ตัวสุดท้ายของฟังก์ชันออก แล้วรัน จะเจอ error แบบนี้:

```
# command-line-arguments
./main.go:7:1: syntax error: unexpected EOF, expected }
```

- `syntax error` (ซินแทกซ์ เออเรอร์ = ผิดไวยากรณ์ภาษา) แปลว่า "ประโยคภาษา Go ไม่ถูกต้อง" เหมือนภาษาไทยที่เรียงคำผิดจนฟังไม่รู้เรื่อง
- `unexpected EOF` (EOF = end of file = จบไฟล์) = "จู่ ๆ ไฟล์ก็จบทั้งที่ฉันยังรอปีกกาปิดอยู่" — แก้โดยเติม `}` ปิดฟังก์ชัน

**หลักอ่าน error 3 ข้อ:**

1. **ข้ามหัว `#` แล้วมองบรรทัด `ชื่อไฟล์.go:เลข:เลข`** — บรรทัดที่ขึ้นต้นด้วย `#` (เช่น `# command-line-arguments` ในตัวอย่าง) คือชื่อโปรเจกต์ชั่วคราวที่ Go สร้างเอง ไม่ใช่ตัว error ให้ข้ามไป บรรทัดถัดไปที่มี `ชื่อไฟล์.go:เลข:เลข` คือ "ที่อยู่" ของปัญหา ต่อด้วยข้อความหลังทวิภาคซึ่งคือ "สาเหตุ"
2. **ไม่ต้องกลัวศัพท์อังกฤษ** — error คือข้อความที่ compiler เขียนให้คนอ่าน เปิด dictionary แปลคำหลักก็เข้าใจได้ (undefined = ไม่รู้จัก, expected = คาดว่าจะเจอ, unexpected = ไม่คาดว่าจะเจอ)
3. **error หลายบรรทัด อ่านทีละบรรทัด** — บางครั้ง error เยอะเพราะ error แรกทำให้ error ถัด ๆ ตามมา แก้ตัวแรก แล้วรันใหม่ บ่อยครั้งหายเกลี้ยง

### ถ้าทำตามทุกขั้นแล้วยังรันไม่ได้ — checklist 3 จุด

เวลาติดปัญหา ให้ทวน 3 จุดนี้ตามลำดับ (dev มืออาชีพก็ทำแบบนี้ ไม่ใช่เดาสุ่ม):

1. **terminal อยู่ในโฟลเดอร์เดียวกับไฟล์ไหม** — error บอก `no such file or directory` (หาไฟล์ไม่เจอ) เกือบทุกครั้งแปลว่าเรายืนผิดโฟลเดอร์ รัน `pwd` เช็ค แล้ว `cd` เข้าไปให้ถูก
2. **PATH รู้จัก go ไหม** — error บอก `go: command not found` แปลว่าติดตั้งยังไม่ครบหรือยังไม่เปิด terminal ใหม่ (ทวนหัวข้อติดตั้ง)
3. **สะกดโค้ดถูกไหม** — Go แยกพิมพ์เล็กพิมพ์ใหญ่ เช่น `fmt.Println` ถูกต้อง แต่ `fmt.println` (ตัว p เล็ก) ไม่มีจริง — error จะบอก `undefined: fmt.println` เปรียบเทียบโค้ดเรากับตัวอย่างทีละตัวอักษร (ระวัง: `println` ตัวเล็กล้วนที่ไม่มี `fmt.` นำหน้าเป็น builtin (builtin = ฟังก์ชันที่ภาษาให้มาพร้อมใช้โดยไม่ต้อง import) ที่มีจริงในภาษา แต่คนละตัวกับ `fmt.Println` ที่เราใช้กัน)

และข้อสุดท้ายที่สำคัญที่สุด: **พักเมื่อสมองตัน** — dev ที่เก่งไม่ใช่คนที่ไม่เคยติด แต่เป็นคนที่รู้จักเดินออกจากจอ 5 นาทีแล้วกลับมาใหม่ หรือเอาข้อความ error ไปค้นหา (ทุกคนที่เคยเจอ error แบบคุณ เคยโพสต์คำถามไว้แล้ว — การค้นหาด้วยคำใน error เป็นทักษะจริงอย่างหนึ่ง) — ไม่มีใครจดจำทุกอย่างได้ตั้งแต่ครั้งแรก และ**ทุกคน**รวมทั้งคนเขียนภาษา Go เองก็ยังเจอ error ทุกวัน

## โจทย์ประจำตอน

### ระดับ Drill (5–10 นาที)

1. อธิบายให้คนที่ไม่เคยเห็น terminal ฟังว่า **`go run` กับ `go build` ต่างกันยังไง** (ห้ามใช้ศัพท์ dev ซ้อนศัพท์ — ถ้าอธิบายให้ปู่ย่าฟังรู้เรื่อง แปลว่าเข้าใจจริง)
2. เขียนคำสั่ง terminal 3 คำที่เรียนวันนี้ พร้อมความหมาย และบอกว่าคำสั่งใด "ถาม" คำสั่งใด "สั่ง"
3. ทายก่อนลอง: ถ้าเราลบบรรทัด `import "fmt"` ออกจาก main.go แล้วรัน **error จะบอกว่าอะไร** (ลองทำจริงดู แล้วเทียบกับที่ทาย — นี่คือการฝึก "พยากรณ์แล้วตรวจ" ซึ่งคือวิธีคิดของ dev)

### ระดับ Mini-project (30–60 นาที)

**"เปิดโรงงาน + พังให้เป็น"** — ทำ 4 ขั้นให้ครบ:

1. ติดตั้ง Go, VS Code และ extension Go ให้ครบ — พิสูจน์ด้วยการพิมพ์ `go version` แล้วเห็นเวอร์ชันขึ้น
2. สร้างโฟลเดอร์ `gopher-course` เปิดด้วย VS Code สร้าง `main.go` รัน `go run main.go` และ `go build -o hello main.go` แล้วรันไฟล์ binary ที่ได้ — จดผลลัพธ์ทั้งสองแบบลงสมุด
3. **จงใจทำพัง 3 ครั้ง** — (ก) แก้ชื่อ `Println` เป็น `Prntln` (ข) ลบ `}` ปิดฟังก์ชันทิ้ง (ค) ลบเครื่องหมายคำพูดตัวปิดของข้อความออก (`"สวัสดี ชาวโลก!` เหลือแค่ตัวเปิด ไม่มีตัวปิด) — รันดู error แต่ละครั้ง แล้วเขียนลงสมุดว่า **error บอกว่าอะไร ที่ไฟล์ไหน บรรทัดไหน** จากนั้นแก้ให้รันผ่านทั้ง 3 อัน
4. เขียน "กฎอ่าน error" ของตัวเอง 1 ข้อที่คิดว่าจำได้แม่นที่สุด (เช่น "อ่านชื่อไฟล์กับเลขบรรทัดก่อนเสมอ") — เดี๋ยวตอน 03 ขึ้นไปเราจะใช้กฎนี้ทุกตอน

## สรุปตอนที่ 02

- ชุดเครื่องมือ dev = terminal (พิมพ์คำสั่ง) + editor (เขียนโค้ด) + Go toolchain (แปลภาษา/รัน) — เราติดตั้งครบทั้งสามแล้ว
- ติดตั้ง Go จาก **go.dev/dl** ตามระบบปฏิบัติการ (Windows: `.msi`, macOS: `.pkg`, Linux: `.tar.gz` + ตั้ง PATH) แล้วเช็คด้วย `go version`
- เขียนโค้ดที่ **VS Code** (editor ฟรีของ Microsoft) + extension **Go โดย Go Team at Google** ซึ่งทำงานกับ gopls เพื่อช่วยเติมโค้ดและจับ error
- คำสั่ง terminal พื้นฐาน: `pwd` (อยู่ไหน), `ls`/`dir` (เห็นอะไรบ้าง), `cd` (ไปไหน) — บวก `mkdir` สำหรับสร้างโฟลเดอร์
- **`go run`** = compile แล้วรันเลย (เหมาะตอนทดลอง) ส่วน **`go build`** = compile เป็นไฟล์ executable/binary ไว้รันทีหลัง
- วิธีเรียนของคอร์สนี้คือวงจร **สร้าง → พัง → อ่าน → สร้างใหม่** — error คือข้อมูลบอกจุดที่เข้าใจผิด อ่านสูตร `ไฟล์:บรรทัด:หลัก: สาเหตุ` ให้เป็น แล้วการ "พัง" จะกลายเป็นเพื่อนสนิท ไม่ใช่ศัตรู

ตอนหน้า (ตอน 03) เราจะเริ่มเขียนโค้ดจริงจังกัน: ทบทวน hello world ให้ลึกขึ้น แล้วรู้จัก **ตัวแปร** (variable = ช่องเก็บค่า) และ**ชนิดข้อมูล** (type = ชนิดของค่าที่เก็บ เช่น ตัวเลขหรือข้อความ) — พร้อมทั้งโจทย์ที่เริ่มท้าทายขึ้น

ระหว่างรอ อย่าลืมทำ mini-project "พังให้เป็น" — เพราะ dev ที่เก่งไม่ใช่คนไม่เคยพัง แต่คือคนที่พังเป็น แล้วอ่าน error ได้ทุกครั้ง
