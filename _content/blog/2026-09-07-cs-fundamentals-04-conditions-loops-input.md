# ทำให้โปรแกรมคิดเองได้: if/else, for loop และการรับ input จากผู้ใช้ (ตอนที่ 04) — CS Fundamentals: จาก 0 สู่พื้นฐานที่แท้จริง

> 📅 เขียนเมื่อ: 7 กันยายน 2026 | โค้ดตัวอย่างทุกชิ้นทดสอบจริงด้วย Go 1.24.4 (เครื่องที่ใช้เขียนซีรีส์นี้); เวอร์ชันล่าสุดของ Go ณ วันเขียนคือ **1.27.1** (ตรวจจาก https://go.dev/doc/devel/release — major release 1.27.0 ออก 19 สิงหาคม 2026 และ minor revision 1.27.1 ออก 1 กันยายน 2026)
> ⚠️ เวอร์ชันเครื่องมือ/ภาษามีการออกใหม่เรื่อย ๆ — ตรวจสอบเอกสารล่าสุดก่อนใช้งานจริงเสมอ

จนถึงตอนนี้ (ตอน 01–03) โปรแกรมที่เราเขียนได้ **ทำอะไรซ้ำ ๆ เหมือนเดิมทุกครั้ง** — ใส่ตัวแปรไว้ในโค้ด เปิดโปรแกรม มันก็พิมพ์คำตอบเดิมออกมา แล้วจบ พิมพ์ "สมชาย อายุ 30 ปี BMI 22.37" ซ้ำแล้วซ้ำเล่า ไม่ว่าจะรันกี่ครั้ง

โปรแกรมในโลกจริงไม่เป็นแบบนั้น — แอปธนาคารต้องถามว่า "จะถอนเท่าไร" แล้วตอบต่างกันตามจำนวนเงิน เกมต้องถาม "ทายเลขอะไร" แล้วบอกว่า "มากไป" หรือ "น้อยไป" ไม่ใช่พิมพ์คำตอบตายตัว

ตอนนี้คือตอนที่เราเติม "สมอง" ให้โปรแกรม 3 อย่างที่ขาดอยู่:

1. **if/else** — ให้โปรแกรม**ตัดสินใจ** (decision = ดีซิชัน): ถ้าเงื่อนไขเป็นจริงทำอย่างนี้ ไม่จริงทำอีกอย่าง
2. **for loop** — ให้โปรแกรม**วนทำซ้ำ** (loop = ลูป): ทำคำสั่งชุดเดิมกี่รอบก็ได้ตามที่เรากำหนด
3. **การรับ input** — ให้**ผู้ใช้พิมพ์ข้อมูล** (input = อินพุต = ข้อมูลที่ส่งเข้าโปรแกรม) ระหว่างที่โปรแกรมรัน แล้วโปรแกรมเอาข้อมูลนั้นไปคิดต่อ

ของทั้ง 3 อย่างนี้รวมกันเรียกว่า **flow control** (โฟลว์ คอนโทรล = การควบคุมการไหลของโปรแกรม) — คำนี้คือหัวใจของทุกโปรแกรมที่เคยเขียนกันมาบนโลก ขอให้จำไว้

เป้าหมายของตอนนี้: **อ่านจบแล้ว คุณเขียนโปรแกรมที่ "คุยกับคนใช้ได้"** — ถามชื่อ ถามอายุ คำนวณ ตอบกลับต่างกันตามเงื่อนไข และวนถามซ้ำได้จนกว่าจะพอใจ

## มองโปรแกรมเป็น "เส้นทางเดิน" — ของใหม่ทั้งตอนนี้คือการเลี้ยว

ตอน 03 เรารู้แล้วว่าโปรแกรมทำงาน**ทีละบรรทัดจากบนลงล่าง** (เรียกว่า sequential execution = ซีเควนเชียล เอ็กซ์คิวชัน = การทำงานเรียงลำดับ) — เหมือนอ่านหนังสือทีละบรรทัดจากหน้าแรกไปหน้าสุดท้าย แล้วปิดเล่ม

แต่หนังสือบางเล่ม (เช่น "เกมผจญภัย" ที่ให้พลิกไปหน้าต่าง ๆ ตามคำตอบ) บังคับให้ผู้อ่าน**เลี้ยว** — "ถ้าตอบว่าเดินเข้าไปในถ้ำ ให้พลิกไปหน้าที่ 42 ถ้าตอบว่าวิ่งหนี ให้พลิกไปหน้าที่ 15"

โปรแกรมจริงก็เป็นแบบนั้น — มองเป็นแผนที่เส้นทางได้แบบนี้:

![โปรแกรมเส้นตรง กับโปรแกรมที่มีทางแยก if/else และ loop](/assets/diagrams/04-linear-vs-branch.svg)

ที่เห็นเป็น "ลูกศรวนกลับขึ้นไป" คือ **loop** ส่วน "ทางแยก" คือ **if/else** — ถ้าเข้าใจแผนที่นี้ได้ คุณก็เข้าใจโครงสร้างของบทความนี้ทั้งตอนแล้ว เพราะที่เหลือคือรายละเอียดวิธีเขียน

**แล้วคอมพิวเตอร์จริงมัน "เลี้ยว" ยังไง?** ตอน 03 เรารู้ว่า CPU (ซีพียู = ตัวประมวลผล) รันคำสั่งทีละคำสั่งเรียงกัน แต่ในความเป็นจริง CPU มีคำสั่งพิเศษที่ทำให้โปรแกรมข้ามไปรันที่อื่นได้ — อยากรู้ว่าเป็นคำสั่งอะไร อ่านกล่องด้านล่าง (ยังไม่พร้อม ข้ามไปก่อนได้ ไม่กระทบเนื้อหาที่เหลือ):

> **อ่านข้ามได้ — เบื้องลึกของ CPU:** คำสั่งพิเศษนั้นมีชื่อว่า **branch** (บรานช์ = กิ่ง/แยกทาง) กับ **jump** (จัมพ์ = กระโดด) — คำสั่งพวกนี้บอก CPU ว่า "อย่าทำคำสั่งถัดไป ให้กระโดดไปทำที่บรรทัดอื่นแทน" — โค้ด `if` ที่เราเขียนวันนี้ พอ compile ไปแล้ว ก็กลายเป็นคำสั่ง branch แบบนี้ในภาษาเครื่อง (machine code = แมชีน โค้ด = ภาษาที่ CPU อ่านเข้าใจได้โดยตรง) — เราจะเห็นของจริงตอน 11–12 ที่เรียน CPU กับ assembly = แอสเซมบลี = ภาษาที่มนุษย์พออ่านได้ ใกล้ภาษาเครื่องที่สุด

## if / else — จุดเริ่มต้นของการตัดสินใจ

จำตอน 03 ได้ไหม เราเรียน `bool` ไว้แล้ว — ค่าที่เป็นได้แค่ `true` (จริง) กับ `false` (เท็จ) และบอกไว้ด้วยว่า "bool คือรากฐานของทุกการตัดสินใจในโปรแกรม" — **วันนี้คือวันที่เราใช้มันจริง**

โครงสร้าง `if` (อ่านว่า อิฟ = ถ้า) หน้าตาแบบนี้:

```go
if เงื่อนไข {          // ถ้าเงื่อนไขเป็น true
    // ...โค้ดที่จะรันเมื่อเงื่อนไขจริง
}
```

- **`if`** = คำสั่ง "ถ้า..."
- **เงื่อนไข** = นิพจน์ (expression = เอ็กซ์เพรสชัน = ชิ้นโค้ดที่ "ให้ค่า" ออกมา) ที่ให้ผลเป็น `bool` — ส่วนใหญ่มาจากการเปรียบเทียบแบบตอน 03 เช่น `age >= 18`
- **`{ }`** = ปีกกา ขอบเขตเดียวกับตอน 03 — โค้ดระหว่างปีกกาคือ "สิ่งที่ทำเมื่อเงื่อนไขจริง"
- ถ้าเงื่อนไขเป็น `false` โปรแกรมจะ**ข้าม**โค้ดในปีกกาไปทั้งก้อน ไม่รันแม้แต่บรรทัดเดียว

สร้างไฟล์ใหม่ชื่อ `ifelse.go` ในโฟลเดอร์ `gopher-course` (โฟลเดอร์เดียวกับตอน 02–03) แล้วพิมพ์ตาม:

```go
package main

import "fmt"

func main() {
    age := 20

    if age >= 18 {
        fmt.Println("ผู้ใหญ่")
    }
}
```

รัน `go run ifelse.go` — ผลลัพธ์จริงบนเครื่องผม:

```
ผู้ใหญ่
```

แล้วลองเปลี่ยน `age := 20` เป็น `age := 15` รันอีกครั้ง — **ไม่มีอะไรพิมพ์ออกมาเลย** เพราะเงื่อนไข `15 >= 18` เป็น false โปรแกรมจึงข้ามปีกกาทั้งก้อน — ตรงนี้แหละคือ "การตัดสินใจ": โปรแกรมเลือกทำหรือไม่ทำ ตามค่าที่เราให้

### if / else if / else — ทางเลือกหลายทาง

การตัดสินใจ "ทำ/ไม่ทำ" ยังไม่พอ บ่อยครั้งเรามีหลายทางให้เลือก เช่น เกรด A/B/C/F — ใช้ **else if** (เอลส์ อิฟ = "ไม่งั้นถ้า...") ต่อกันได้เรื่อย ๆ และปิดท้ายด้วย **else** (เอลส์ = "ไม่งั้น/นอกจากนั้น") ซึ่งคือ "ทางสุดท้าย" ที่รันเมื่อ**ทุกเงื่อนไขข้างบนเป็น false หมด**:

```go
package main

import "fmt"

func main() {
    score := 82

    if score >= 80 {
        fmt.Println("เกรด A")
    } else if score >= 70 {
        fmt.Println("เกรด B")
    } else if score >= 60 {
        fmt.Println("เกรด C")
    } else {
        fmt.Println("เกรด F — ต้องอ่านหนังสือใหม่")
    }
}
```

ผลลัพธ์จริง:

```
เกรด A
```

วิธีอ่านโค้ด: "**ถ้า**คะแนน ≥ 80 → เกรด A **ไม่งั้นถ้า** ≥ 70 → เกรด B **ไม่งั้นถ้า** ≥ 60 → เกรด C **ไม่งั้น** (คือไม่เข้าเงื่อนไขไหนเลย) → เกรด F"

จุดสำคัญที่มือใหม่สับสนบ่อย — **เงื่อนไขถูกตรวจจากบนลงล่าง แล้วหยุดที่เงื่อนไขแรกที่เป็นจริง** พอเจอเงื่อนไขจริงอันแรก โปรแกรมรันโค้ดในปีกกาอันนั้นแล้ว**กระโดดข้าม else ที่เหลือทั้งหมด** (ไม่ไปเช็คต่อ) ลองเปลี่ยน `score := 82` เป็น `score := 55` รันดู:

```
เกรด F — ต้องอ่านหนังสือใหม่
```

55 ไม่ผ่าน 80, ไม่ผ่าน 70, ไม่ผ่าน 60 → ตกไปทาง else — เพราะเหตุนี้**ลำดับของเงื่อนไขจึงสำคัญมาก** ถ้าเราเขียน `score >= 60` ไว้**ก่อน** `score >= 80` คนที่ได้ 82 จะได้เกรด C ทั้งที่ควรได้ A (เพราะเจอ "≥ 60" จริงก่อน แล้วหยุด) — หลักง่าย ๆ: **เขียนเงื่อนไขที่ "แคบ/สูง" ไว้ก่อน เงื่อนไขที่ "กว้าง/ต่ำ" ไว้ทีหลัง**

### สรุปโครงสร้าง 3 รูปแบบ

| รูปแบบ | ใช้เมื่อ | หมายเหตุ |
|---|---|---|
| `if เงื่อนไข { ... }` | ตัดสินใจทำหรือไม่ทำ อย่างเดียว | ไม่มี else ก็ได้ |
| `if ... { } else { }` | 2 ทางเลือกเท่านั้น | else = "ทุกอย่างที่ไม่ใช่เงื่อนไข" |
| `if ... { } else if ... { } ... else { }` | หลายทางเลือก | ตรวจบนลงล่าง หยุดที่จริงอันแรก |

อีกเรื่องที่ต้องรู้: **ปีกกาเป็นข้อบังคับใน Go** — ภาษา Go ไม่มี "if แบบไม่มีปีกกา" ให้เขียน ต่อให้ในปีกกามีโค้ดแค่บรรทัดเดียว ก็ต้องมีปีกกาครบทุกครั้ง และ **`else` ต้องอยู่ต่อท้ายบรรทัดเดียวกับปีกกาปิดของ `if`** — ถ้าขึ้นบรรทัดใหม่จะ compile ไม่ผ่าน (ดูตาราง error ท้ายบท)

## ตัวดำเนินการเปรียบเทียบ (ทบทวนตอน 03) + ตรรกะ && || !

ก่อนไปต่อ ขอตั้งหลักเรื่อง "เงื่อนไข" ให้ครบ เพราะต่อไปเราจะผสมเงื่อนไขหลายอันเข้าด้วยกัน

**ตัวดำเนินการเปรียบเทียบ** (comparison operator = คอมแพริสัน โอเปอเรเตอร์ = เครื่องหมายเทียบค่า) ที่เรียนตอน 03 — ให้ผลเป็น bool เสมอ:

| ตัวดำเนินการ | ความหมาย | ตัวอย่าง (สมมติ `age := 20`) | ผลลัพธ์ |
|---|---|---|---|
| `==` | เท่ากับไหม (ถาม) | `age == 20` | `true` |
| `!=` | ไม่เท่ากับไหม | `age != 18` | `true` |
| `<` | น้อยกว่า | `age < 18` | `false` |
| `>` | มากกว่า | `age > 18` | `true` |
| `<=` | น้อยกว่าหรือเท่ากับ | `age <= 20` | `true` |
| `>=` | มากกว่าหรือเท่ากับ | `age >= 18` | `true` |

**ข้อควรระวังเรื่องชนิดข้อมูลยังใช้เต็มแรง** — `age == "20"` (int เทียบกับ string) compile ไม่ผ่าน เพราะเปรียบเทียบกันคนละชนิดไม่ได้ (error จริงอยู่ในตารางท้ายบท)

### แล้วถ้าเงื่อนไขเดียวไม่พอ: `&&` `||` `!`

ชีวิตจริงแทบไม่มีเงื่อนไขเดี่ยว ๆ — "เข้าชมได้ ถ้าอายุ 18 ขึ้นไป **และ** มีตั๋ว", "ชำระด้วยเงินสด **หรือ** บัตร", "เข้าเรียนได้ ถ้า**ไม่**ใช่ช่วงปิดเทอม" — ภาษาโปรแกรมมีตัวดำเนินการตรรกะ (logical operator = โลจิคัล โอเปอเรเตอร์) ให้ 3 ตัว:

| ตัวดำเนินการ | อ่านว่า | แปลว่า | ผลลัพธ์ |
|---|---|---|---|
| `&&` | แอมเพอร์แซนด์ / and | และ | `true` เมื่อ**ทั้งสองข้าง**เป็น true นอกนั้น false |
| `\|\|` | ออร์ / or | หรือ | `true` เมื่อ**ข้างใดข้างหนึ่ง**เป็น true (หรือทั้งคู่) |
| `!` | น็อท / not | ไม่ / กลับค่า | `true` → กลายเป็น `false`, `false` → กลายเป็น `true` |

ถ้าใช้ตารางความจริง (truth table = ทรูธ เทเบิล = ตารางแสดงผลของตรรกะทุกกรณี) จะเห็นภาพชัด — ให้ `A` กับ `B` เป็น bool:

| `A` | `B` | `A && B` | `A \|\| B` | `!A` |
|---|---|---|---|---|
| `true` | `true` | `true` | `true` | `false` |
| `true` | `false` | `false` | `true` | `false` |
| `false` | `true` | `false` | `true` | `true` |
| `false` | `false` | `false` | `false` | `true` |

จำง่าย ๆ: **`&&` ต้องการทั้งคู่จริง (เคร่ง) ส่วน `||` ขอแค่ข้างใดข้างหนึ่งจริง (ผ่อน)** ส่วน `!` คือเครื่องหมาย "สลับข้าง" ของความจริง

ลองรันจริง — สร้างไฟล์ `logic.go`:

```go
package main

import "fmt"

func main() {
    age := 25
    hasTicket := true

    // && (and): ทั้งสองข้างต้อง true
    if age >= 18 && hasTicket {
        fmt.Println("เข้าดูคอนเสิร์ตได้")
    }

    // || (or): ข้างใดข้างหนึ่ง true ก็พอ
    payment := "cash"
    if payment == "cash" || payment == "card" {
        fmt.Println("ชำระเงินวิธีนี้รับได้")
    }

    // ! (not): กลับค่า bool
    isWeekend := false
    if !isWeekend {
        fmt.Println("วันนี้เป็นวันทำงาน ตั้งนาฬิกาปลุก")
    }

    // bool ตรง ๆ ใส่ใน if ได้เลย ไม่ต้องเปรียบเทียบ
    lightsOn := true
    if lightsOn {
        fmt.Println("ไฟเปิดอยู่")
    }
}
```

ผลลัพธ์จริง:

```
เข้าดูคอนเสิร์ตได้
ชำระเงินวิธีนี้รับได้
วันนี้เป็นวันทำงาน ตั้งนาฬิกาปลุก
ไฟเปิดอยู่
```

ขอชี้จุดที่มือใหม่สงสัยบ่อย:

- **ทำไม `payment == "cash" || payment == "card"` ต้องเขียนซ้ำ `payment ==`?** เพราะต้องเปรียบเทียบทีละครั้ง — เขียนย่อแบบภาษาพูดว่า "payment เป็น cash หรือ card" ไม่ได้ในภาษาโปรแกรม ต้องบอกคอมฯ ให้ครบ: "payment **เท่ากับ** cash หรือ payment **เท่ากับ** card"
- **`!isWeekend` อ่านยังไง?** "ไม่ใช่ isWeekend" — `isWeekend` เป็น false → `!false` = true → เข้าเงื่อนไข
- **`if lightsOn` ใส่ตัวแปร bool ตรง ๆ ได้** — เพราะ `if` ต้องการแค่ "ค่าที่เป็น bool" ซึ่งตัวแปร bool คือ bool อยู่แล้ว ไม่ต้องไปเปรียบเทียบกับอะไรเพิ่ม (ผิดกับภาษาโปรแกรมบางภาษาที่ยอมรับเลข 0/1 แทน bool ได้ — เรื่องนี้เป็นจุดเด่นของ Go: เงื่อนไข**ต้องเป็น bool เท่านั้น** ลองใส่เลขดู error จริงในตารางท้ายบท)

**ข้อเท็จจริงน่ารู้ (จะใช้จริงตอนโต):** `&&` กับ `||` เป็นตัวดำเนินการแบบ **short-circuit** (ชอร์ต เซอร์กิต = วงจรตัดไฟ = ตรวจแค่ที่จำเป็น) — ถ้า `A && B` และ A เป็น false แล้ว โปรแกรม**ไม่ต้องไปดู B เลย** เพราะรู้ผลแล้วว่า false ทั้งก้อน (false กับอะไรก็ได้ = false) — ในทำนองเดียวกัน `A || B` ถ้า A เป็น true ก็ไม่ดู B — dev ใช้คุณสมบัตินี้กันจริงจัง เช่น เขียน `x != 0 && 10/x > 2` เพื่อกันหารด้วยศูนย์ (ถ้า x เป็น 0 เงื่อนไขแรก false → ไม่มีทางไปถึง `10/x`) — จำไว้ก่อน เดี๋ยวตอน 05+ จะได้ใช้

## for loop — ให้คอมพิวเตอร์ทำงานซ้ำ (สิ่งที่มันถนัดที่สุด)

มนุษย์เบื่อการทำงานซ้ำ แต่คอมพิวเตอร์**ไม่เคยเบื่อ** — ความสามารถนี้แหละที่ทำให้คอมพิวเตอร์มีค่ามหาศาล ลองคิด: ถ้าอยากพิมพ์เลข 1 ถึง 100 เราจะเขียน `fmt.Println(1)` ถึง `fmt.Println(100)` รวม 100 บรรทัดหรือ? และถ้า 1 ถึง 1,000,000 ล่ะ?

**loop** (ลูป = การวนซ้ำ) คือคำตอบ — โค้ดชุดเดียว แต่สั่งให้รันซ้ำได้ตามจำนวนรอบที่ต้องการ

ภาษา Go มีคำสั่งวนซ้ำ**คำสั่งเดียว**คือ **`for`** (ฟอร์ = สำหรับ) — ภาษาโปรแกรมอื่นหลายภาษามีคำสั่งวนซ้ำหลายแบบ (while, do-while ฯลฯ) แต่ Go เลือกออกแบบให้ `for` ตัวเดียวครอบคลุมทุกกรณี ข้อดีคือเรียนครั้งเดียวจบ ไม่ต้องจำหลาย syntax

### รูปแบบแรก: `for init; condition; post { ... }` — แบบครบวงจร

โครงสร้างเต็มรูปแบบมี 3 ส่วน คั่นด้วยเครื่องหมาย `;` (เซมิโคลอน):

```go
for i := 1; i <= 5; i++ {   // for init; condition; post
    fmt.Println(i)
}
```

แยกเป็น 3 ส่วน (จำคำเรียก 3 คำนี้ไว้ — dev ใช้พูดกันทั่วโลก):

1. **`init`** (อินิท = ย่อจาก initialization = การตั้งค่าเริ่มต้น) — `i := 1` รัน**ครั้งเดียวตอนเริ่ม** ประกาศตัวแปรนับรอบ (ตัวแปรแบบนี้ dev เรียกว่า **counter** = เคาน์เตอร์ = ตัวนับ และนิยมตั้งชื่อว่า `i`, `j`, `k` ต่อกันไป)
2. **`condition`** (คอนดิชัน = เงื่อนไข) — `i <= 5` ตรวจ**ก่อนทุกครั้ง**ที่จะรันโค้ดในปีกกา ถ้า true → รัน ถ้า false → ออกจาก loop ทันที
3. **`post`** (โพสต์ = หลัง) — `i++` รัน**หลังจบโค้ดในปีกกา**ทุกครั้ง (จำจากตอน 03 ได้ไหม `i++` = `i += 1` = `i = i + 1` = "เพิ่ม i ทีละ 1")

ลำดับการทำงานจริงคือ: init (ครั้งเดียว) → เช็ค condition → ถ้าจริง รันปีกกา → รัน post → กลับไปเช็ค condition ใหม่ → ... วนแบบนี้จนกว่า condition จะเป็น false เขียนเป็นแผนภาพได้แบบนี้:

![ผังงาน for loop](/assets/diagrams/04-for-loop.svg)

สร้างไฟล์ `forloop.go` แล้วลอง:

```go
package main

import "fmt"

func main() {
    // แบบที่ 1: for init; condition; post — นับ 1 ถึง 5
    fmt.Println("--- นับ 1 ถึง 5 ---")
    for i := 1; i <= 5; i++ {
        fmt.Println(i)
    }

    // รวมเลข 1 ถึง 100: ใช้ += ที่เรียนตอน 03
    sum := 0
    for i := 1; i <= 100; i++ {
        sum += i // sum = sum + i
    }
    fmt.Println("รวม 1..100 =", sum)
}
```

ผลลัพธ์จริง:

```
--- นับ 1 ถึง 5 ---
1
2
3
4
5
รวม 1..100 = 5050
```

ขอไล่ให้ดูรอบต่อรอบของ loop แรก (ฝึก "พยากรณ์แล้วตรวจ" — ทักษะที่ใช้ทั้งอาชีพ):

| รอบที่ | ค่า `i` ตอนเช็ค | `i <= 5`? | หลังรันปีกกา → post `i++` |
|---|---|---|---|
| 1 | 1 | จริง → พิมพ์ 1 | i = 2 |
| 2 | 2 | จริง → พิมพ์ 2 | i = 3 |
| 3 | 3 | จริง → พิมพ์ 3 | i = 4 |
| 4 | 4 | จริง → พิมพ์ 4 | i = 5 |
| 5 | 5 | จริง → พิมพ์ 5 | i = 6 |
| 6 | 6 | **เท็จ → ออกจาก loop** | — |

จุดที่มือใหม่พลาดคือรอบสุดท้าย: loop วน **5 รอบ** แต่ post รัน **5 ครั้ง** และเช็ค condition **6 ครั้ง** (ครั้งสุดท้ายเป็น false) — เข้าใจตรงนี้แล้วคุณจะไม่สับสนเรื่อง "วนกี่รอบ"

### รูปแบบที่สอง: `for condition { ... }` — คล้าย while ในภาษาอื่น

ถ้าตัดส่วน init กับ post ออก เหลือแค่เงื่อนไข — ใช้เมื่อ "วนไปเรื่อย ๆ **ตราบใดที่** เงื่อนไขยังจริง" (dev ทั่วโลกเรียก loop แบบนี้ว่า while = ไวล์ = ในขณะที่):

> **สำคัญสำหรับการทดลองต่อจากนี้:** โค้ดชิ้นต่อไปนี้ (รวมถึงชิ้นถัด ๆ ไปที่บทความบอกให้ "ต่อท้ายโปรแกรมเดิม") คือ**โค้ดที่อยู่ใน func main** — ตอนเพิ่ม ให้**แทรกก่อนปีกกา `}` ที่ปิด func main** (ปีกกาปิดบรรทัดสุดท้ายของ forloop.go ที่เขียนไว้ตอนแรก) ไม่ใช่ต่อท้ายไฟล์ — เพราะถ้าเผลอวางต่อท้ายไฟล์หลังปีกกาปิดแล้ว โค้ดจะอยู่นอก main → compile ไม่ผ่านทันที

```go
    // แบบที่ 2: for condition — วนตราบใดที่ budget ยังมากกว่า 0
    fmt.Println("--- งบ 100 ใช้จ่ายรอบละ 30 ---")
    budget := 100
    for budget > 0 {
        fmt.Println("ตอนเริ่มรอบ เหลือ", budget) // พิมพ์ยอดก่อนหักของรอบนี้
        budget -= 30                             // budget = budget - 30 (ค่อยหักทีหลัง)
    }
```

ผลจริง (ต่อท้ายโปรแกรมเดิม):

```
--- งบ 100 ใช้จ่ายรอบละ 30 ---
ตอนเริ่มรอบ เหลือ 100
ตอนเริ่มรอบ เหลือ 70
ตอนเริ่มรอบ เหลือ 40
ตอนเริ่มรอบ เหลือ 10
```

อ่านผลให้ขาด: ทุกบรรทัดคือยอด**ตอนเริ่มรอบ ก่อนหัก** 30 ของรอบนั้น — เพราะโค้ดสั่งพิมพ์**ก่อน** แล้วค่อยหัก — พอรอบที่ 4 พิมพ์ 10 แล้วหัก ยอดกลายเป็น **-20** พอขึ้นรอบถัดไป เช็ค `budget > 0` เจอเท็จ (เพราะ -20 > 0 ไม่จริง) เลยออกจาก loop — สังเกตว่า -20 ไม่ถูกพิมพ์ เพราะโปรแกรมเช็คเงื่อนไข**ก่อน**รันปีกกาทุกรอบ — สรุปคือเรา**ไม่รู้ล่วงหน้าว่าจะวนกี่รอบ** วนจนกว่า budget จะหมด — loop แบบนี้เหมาะกับงาน "วนจนกว่าจะพอดี" เช่น รอผู้ใช้ป้อนข้อมูลที่ถูกต้อง (จะได้ใช้จริงในโปรแกรมรวมท้ายตอน)

### break และ continue — สั่ง "ออก" กับสั่ง "ข้าม"

บางครั้งอยากออกจาก loop **กลางคัน** หรืออยาก**ข้าม**บางรอบ — Go ให้คำสั่ง 2 ตัว:

- **`break`** (เบรก = หัก/หยุด) — ออกจาก loop ทันที ไม่วนต่ออีก (แม้ condition จะยังจริง)
- **`continue`** (คอนทินิว = ทำต่อไป) — **ข้าม**โค้ดที่เหลือในปีกกาของ**รอบนี้** แล้วกลับไปขึ้นรอบถัดไปทันที (ใน for เต็มรูปแบบ continue จะไปรัน post ก่อน แล้วค่อยเช็ค condition)

ลองต่อท้ายโปรแกรมเดิม:

```go
    // break: หยุด loop ทันทีเมื่อ i == 7
    fmt.Println("--- หยุดเมื่อ i == 7 ---")
    for i := 1; i <= 10; i++ {
        if i == 7 {
            break // เจอ 7 → ออกจาก loop เลย ไม่พิมพ์ 7
        }
        fmt.Println(i)
    }

    // continue: ข้ามเลขที่หาร 3 ลงตัว
    fmt.Println("--- ข้ามเลขที่หาร 3 ลงตัว ---")
    for i := 1; i <= 10; i++ {
        if i%3 == 0 { // % = modulus (มอดูลัส) = หารเอาเศษ (ตอน 03)
            continue // ข้ามรอบนี้ ขึ้นรอบถัดไป
        }
        fmt.Println(i)
    }
```

ผลจริง:

```
--- หยุดเมื่อ i == 7 ---
1
2
3
4
5
6
--- ข้ามเลขที่หาร 3 ลงตัว ---
1
2
4
5
7
8
10
```

ดูตัวอย่างแรก (โปรแกรม `break`): พอ `i` เป็น 7 เงื่อนไข `i == 7` จริง → `break` — ตัวเลข 7 ถึง 10 ไม่ถูกพิมพ์ (สังเกตว่า 7 เองก็ไม่ถูกพิมพ์ เพราะ break รันก่อนถึงบรรทัดพิมพ์) — ส่วนตัวอย่างที่สอง (โปรแกรม `continue`): เลข 3, 6, 9 หาร 3 ลงตัว → โดน `continue` ข้าม ตัวเลขอื่นพิมพ์ครบ

### `for { ... }` — วนไม่รู้จบ (จนกว่าจะมีคนสั่งหยุด)

ถ้าเขียน `for` เปล่า ๆ ไม่มี init/condition/post:

```go
    // แบบที่ 3: for เปล่า ๆ = วนไม่รู้จบ ต้องมี break ออกเอง
    fmt.Println("--- วนไปเรื่อย ๆ กระทั่ง i ถึง 3 ---")
    i := 0
    for {
        i++
        fmt.Println("รอบที่", i)
        if i >= 3 {
            break
        }
    }
```

ผลจริง:

```
--- วนไปเรื่อย ๆ กระทั่ง i ถึง 3 ---
รอบที่ 1
รอบที่ 2
รอบที่ 3
```

`for { }` แปลว่า "วน**ตลอดไป**" เพราะไม่มีเงื่อนไขให้เป็น false ได้เลย — โค้ดแบบนี้ dev เรียกว่า **infinite loop** (อินฟินิท ลูป = ลูปไม่มีที่สิ้นสุด) — ถ้าเขียนแล้วลืมใส่ `break` โปรแกรมจะรันค้างไม่จบ (เวลาทดลองแล้วโปรแกรม "ค้าง" ให้กด **Ctrl + C** ที่ terminal เพื่อสั่งหยุดโปรแกรม) — infinite loop ที่**ตั้งใจ**มีไว้ใช้จริง เช่น โปรแกรมรอรับคำสั่งจากผู้ใช้ตลอดเวลา วนจนกว่าผู้ใช้จะสั่งออก — เราจะใช้เทคนิคนี้ในโปรแกรมใหญ่ของตอนนี้ (โปรแกรม BMI ที่ถามซ้ำจนกว่าจะพิมพ์ q)

**แล้ว loop กับคอมพิวเตอร์จริงล่ะ?** ตอนต้นบทความพูดถึงคำสั่ง jump ของ CPU — loop คือการใช้ jump นั่นแหละ: ตอน compile โค้ด `for` จะกลายเป็น "รันคำสั่งชุดนี้ → เช็คเงื่อนไข → **กระโดดกลับไป**ที่คำสั่งแรกของชุด" วนไปมา — การวนซ้ำพันล้านรอบที่เราเห็นในโปรแกรม คือ CPU กระโดดกลับไปกลับมาในคำสั่งไม่กี่บรรทัดด้วยความเร็วระดับพันล้านครั้งต่อวินาที (ตอน 12 เราจะเขียน loop ด้วย assembly ด้วยมือเราเอง เห็นการกระโดดนี้ด้วยตา)

### เกริ่น `for range` — ตัวที่ 4 (เต็มรูปแบบตอน 06)

Go เวอร์ชัน 1.22 ขึ้นไป (เรามี 1.24.4 — สบาย) เพิ่มความสามารถให้ `for range` (เรนจ์ = ช่วง) วนเหนือ**จำนวนเต็ม**ได้:

```go
    // แบบที่ 4 (เกริ่น): for i := range N วน N รอบ โดย i เริ่มที่ 0
    fmt.Println("--- for i := range 5 ---")
    for i := range 5 {
        fmt.Println("ครั้งที่", i)
    }
```

ผลจริง:

```
--- for i := range 5 ---
ครั้งที่ 0
ครั้งที่ 1
ครั้งที่ 2
ครั้งที่ 3
ครั้งที่ 4
```

**สังเกตว่าเริ่มที่ 0 ไม่ใช่ 1** — ต่างจากตัวอย่าง `for i := 1` ก่อนหน้านี้ที่เรา**เลือกจุดเริ่มเองได้** (อยากเริ่มที่ 1 ก็เขียน `i := 1`) แต่ `for range` แบบนี้ Go **กำหนดให้เริ่มที่ 0 อัตโนมัติ** เพราะคอมพิวเตอร์นับเริ่มที่ 0 (เรื่องนี้จะฝังหัวไปตลอดอาชีพ — ตอน 06 ที่เรียน slice (สไลซ์ = ชุดข้อมูลเรียงกัน) เราจะเข้าใจว่าทำไม) — `for range` ตัวจริงใน Go ใช้กับข้อมูลชุด (slice, **map** = แมป = ชุดคู่ข้อมูล) และข้อความ ซึ่งเราจะเรียนเต็มรูปแบบตอน 06 ตอนนี้ขอแค่รู้ว่ามี และเห็นว่า "วน N รอบ" เขียนสั้นได้แค่นี้

### กับดักประจำหัวข้อ loop

1. **ลืม `i++`** — ถ้า post หาย ตัวนับไม่เพิ่ม `i <= 5` เป็นจริงตลอดกาล → infinite loop ค้างไม่จบ (กด Ctrl+C ออก)
2. **ผิดด้านของขอบเขต** — `i < 5` วน 5 รอบ (0,1,2,3,4) แต่ `i <= 5` วน 6 รอบ (0–5) — ต้องระวัง `<` กับ `<=` ให้ตรงกับจำนวนรอบที่คิด (dev เรียกบั๊กแบบนี้ว่า **off-by-one error** = ออฟ-บาย-วัน = ผิดไปหนึ่ง) — แก้ด้วยการ "พยากรณ์รอบแรกกับรอบสุดท้าย" ก่อนรันเสมอ
3. **`break` กับ `continue` ใส่ผิดที่** — break ต้องอยู่ใน loop ถึงจะออกจาก loop ได้ (ถ้าเผลอไปใส่ใน if ที่อยู่**นอก** loop จะ compile ไม่ผ่าน — error บอกว่า `break is not in a loop, switch, or select` — คำว่า switch/select = โครงสร้างอีก 2 แบบของ Go ที่ยังไม่เรียน ไม่ต้องสนใจ)

## การรับ input — ให้ผู้ใช้พิมพ์ข้อมูลเข้าโปรแกรม

มาถึงของที่ทำให้ตอนนี้ "สนุก" ที่สุดแล้ว — จนถึงตอนนี้ ข้อมูลทุกอย่างในโปรแกรมเรา**เขียนตายในโค้ด** (hardcode = ฮาร์ดโค้ด = ใส่ค่าตายตัว) แต่โปรแกรมจริงต้องรับข้อมูลจากคนใช้: ชื่อที่พิมพ์, ตัวเลขที่กด, คำตอบที่เลือก

ข้อมูลที่ผู้ใช้พิมพ์เข้ามา เรียกรวมว่า **input** (อินพุต) ส่วนผลที่โปรแกรมพิมพ์ออกไป เรียกว่า **output** (เอาต์พุต) — โปรแกรมทุกโปรแกรมคือเครื่องจักรแปลง: **input → ประมวลผล → output**

### input เดินทางมาแบบนี้

เวลาเราสั่ง `go run main.go` ใน terminal แล้วพิมพ์อะไรลงคีย์บอร์ด — ข้อมูลไหลผ่านเส้นทางนี้:

![เส้นทางของ input จากคีย์บอร์ดจนถึงโค้ด Go](/assets/diagrams/04-input-flow.svg)

(เบื้องลึก: ช่อง stdin นี้ OS เป็นคนจัดให้ — ตอน 19 ที่เรียน syscall (ระบบเรียก = ช่องที่โปรแกรมขอให้ OS ทำงาน) เราจะเห็นว่าโปรแกรม "ขออ่านข้อมูล" จาก OS ยังไง และตอน 21 จะเห็นว่า stdin จริง ๆ คือ "ไฟล์พิเศษ" อันหนึ่งที่ OS เปิดให้ตอนโปรแกรมเริ่ม — ฟังดูประหลาดแต่จริง)

### วิธีง่ายสุด: `fmt.Scanln`

กล่อง `fmt` ที่เรา import มาตลอด มีฟังก์ชันรับ input ด้วย — **`fmt.Scanln`** (อ่านว่า สแกน-ไลน์ = สแกนทีละบรรทัด) — รับค่าที่พิมพ์ แล้ว**เติมเข้าไปในตัวแปร**ที่เราเตรียมไว้:

```go
package main

import "fmt"

func main() {
    var name string // ยังไม่รู้ค่า → ใช้ var เต็มรูปแบบ (ตอน 03)
    var age int

    fmt.Print("พิมพ์ชื่อของคุณ: ") // Print = พิมพ์โดยไม่ขึ้นบรรทัดใหม่ (ต่างจาก Println)
    fmt.Scanln(&name)             // รอผู้ใช้พิมพ์ แล้วเก็บเข้าตัวแปร name

    fmt.Print("พิมพ์อายุของคุณ: ")
    fmt.Scanln(&age)

    fmt.Println("สวัสดีคุณ", name, "อายุ", age, "ปี")
}
```

สร้างไฟล์ `scan.go` รัน แล้วลองพิมพ์ `สมชาย` กับ `25` — ผลลัพธ์จริง:

```
พิมพ์ชื่อของคุณ: พิมพ์อายุของคุณ: สวัสดีคุณ สมชาย อายุ 25 ปี
```

(ตอนรันจริงใน terminal ข้อความ "พิมพ์ชื่อของคุณ:" จะโผล่แล้ว **รอ**ให้เราพิมพ์ — ในตัวอย่างนี้ผมป้อนข้อมูลล่วงหน้าให้ จึงเห็นข้อความติดกันแบบนั้น)

**เครื่องหมาย `&` ที่นำหน้าตัวแปรคืออะไร?** ตอน 03 เราบอกว่าตัวแปรคือกล่องมีป้ายชื่อ — `&name` อ่านว่า "แอดเดรสของ name" (address = ที่อยู่ของกล่อง) — การส่ง `&name` เข้าไปใน Scanln เท่ากับบอกว่า "นี่คือ**ที่อยู่**ของกล่อง name ไปเติมค่าลงในกล่องนั้นเลย" — ตอนนี้ยังไม่ต้องเข้าใจลึก (pointer = พอยน์เตอร์ = ตัวชี้ตำแหน่ง จะเรียนเต็มตอน 14) ขอให้จำ**กฎการใช้**: ฟังก์ชันรับ input ของ Go ต้องการ `&` นำหน้าตัวแปรทุกตัวที่อยากให้มันเติมค่าให้

โปรแกรมนี้ทำงานได้... **ในกรณีปกติ** แต่มีจุดอ่อน 2 จุดที่ต้องรู้ก่อนนำไปใช้จริง — ขอทดลองให้ดู:

**จุดอ่อนที่ 1: Scanln แยกคำด้วยช่องว่าง** — ลองพิมพ์ชื่อเต็มว่า `สมชาย ใจดี` (มีช่องว่าง):

```
พิมพ์ชื่อของคุณ: พิมพ์อายุของคุณ: สวัสดีคุณ สมชาย อายุ 0 ปี
```

(ทดสอบจริง) — อายุกลายเป็น **0**! เกิดอะไรขึ้น? Scanln อ่าน**ทีละคำ คั่นด้วยช่องว่าง** (ช่องว่าง = whitespace = ไวต์สเปซ ส่วนคำที่แยกได้แต่ละคำเรียกว่า token = โทเคน = ชิ้นคำ) — ไล่ตามลำดับที่เกิด:

1. พิมพ์ `สมชาย ใจดี` → `สมชาย` (คำแรก) เข้า name เรียบร้อย แต่ Scanln ยังเห็นว่ามีคำเกิน (`ใจดี`) ค้างอยู่บนบรรทัดเดียวกัน
2. Scanln จึงคืน error `expected newline` ทันที (แปลว่า "คาดว่าต้องจบที่ขึ้นบรรทัดใหม่") — แต่เรา**ยังไม่ได้รับ error นี้ไว้** มันเลยหลุดหายไป
3. คำค้าง `ใจดี` ยังวนอยู่ในช่อง input ไม่หายไปไหน
4. พอโปรแกรมรันถึง `Scanln(&age)` มันก็ดึง `ใจดี` ไปแปลงเป็น int → แปลงไม่ได้ → คืน error `expected integer` — error นี้ก็ไม่ได้รับไว้อีก มันหลุดหายไปด้วย
5. สุดท้ายตัวแปร age ไม่เคยถูกเติมค่าอีกเลย → คงค่าเริ่มต้นเป็น 0

**จุดอ่อนที่ 2: ถ้าผู้ใช้พิมพ์สิ่งที่ไม่ใช่ตัวเลข** — ลองพิมพ์ `abc` แทนอายุ โดยแก้โปรแกรมให้โชว์ error (ใช้ `_, err :=` รับค่าที่คืนมาทั้งสอง — โค้ดชั่วคราวตรงนี้แค่ให้ดูผล ยังไม่ต้องพิมพ์ตาม ส่วนวิธีรับ error อย่างถูกต้องจะเรียนเต็ม ๆ ในหัวข้อ reader.go ด้านล่าง):

```
พิมพ์อายุของคุณ: age = 0
err = expected integer
```

(ทดสอบจริง — ที่เห็น `err = expected integer` เพราะผมแก้โปรแกรม**ชั่วคราว**ให้รับ error ไว้ (`_, err :=`) แล้วสั่งพิมพ์ออกมาให้ดู อยากเห็นว่า Scanln พยายามบอกอะไรเรา) — error นี้บอกว่า "คาดว่าเป็นจำนวนเต็ม" — แต่โปรแกรมเดิมของเรา (scan.go) ไม่ได้รับ error ไว้ มันจึงหลุดหายไปเงียบ ๆ เหมือน error `expected newline` ในจุดอ่อนที่ 1 — สิ่งที่ผู้ใช้เห็นจึงมีแค่อายุเป็น 0 โดยไม่รู้ว่าเกิดอะไรขึ้น

**บทเรียน: การรับ input ที่ "แข็งแรง" (production-safe = พร้อมใช้งานจริง) ต้องทำ 3 ขั้น** — (1) อ่านมาเป็นข้อความทั้งบรรทัด (2) ตัดช่องว่างหัวท้าย (3) แปลงเป็นตัวเลข**โดยเช็ค error** — วิธีที่ dev Go ใช้กันประจำคือ bufio + strconv ตามด้านล่าง

### วิธีที่แข็งแรง: bufio + strings.TrimSpace + strconv.Atoi

พบกับของใหม่ 3 อย่าง (ทั้ง 3 อยู่ใน standard library = ห้องสมุดมาตรฐาน มากับ Go — ตอน 03):

1. **`bufio`** (บัฟ-ฟีโอ = ย่อจาก buffered I/O = การอ่าน/เขียนแบบมีบัฟเฟอร์ (บัฟเฟอร์ = ที่พักข้อมูลชั่วคราว)) — ให้ "เครื่องอ่าน" ที่อ่านได้ทีละบรรทัดเต็ม ๆ ไม่ตัดที่ช่องว่าง
2. **`strings`** (สตริงส์ = กล่องเครื่องมือจัดการข้อความ) — เราจะใช้ `strings.TrimSpace` (ทริม สเปซ = ตัดช่องว่าง) เพื่อลบ `\n` (ขึ้นบรรทัดใหม่) ที่ติดมาท้ายบรรทัด
3. **`strconv`** (สตริง-คอนเวิร์ต = ย่อจาก string conversion = แปลงข้อความ) — ให้ `strconv.Atoi` (เอ-ทู-ไอ = ย่อจาก **A**SCII **to** **I**nteger — ASCII = แอสกี = รหัสมาตรฐานที่แทนตัวอักษรด้วยตัวเลข) — แปลงข้อความที่เป็นตัวเลข เช่น "25" ให้เป็นเลขจำนวนเต็ม 25

สร้างไฟล์ `reader.go`:

```go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strconv"
    "strings"
)

func main() {
    // สร้าง "เครื่องอ่านบรรทัด" จาก stdin (ช่อง input ที่ OS เปิดให้)
    reader := bufio.NewReader(os.Stdin)

    fmt.Print("ชื่อของคุณ: ")
    name, _ := reader.ReadString('\n') // อ่านทั้งบรรทัด จนเจอ Enter (\n)
    name = strings.TrimSpace(name)     // ตัด \n กับช่องว่างหัว-ท้ายทิ้ง

    fmt.Print("อายุของคุณ: ")
    ageText, _ := reader.ReadString('\n')
    ageText = strings.TrimSpace(ageText)

    age, err := strconv.Atoi(ageText) // แปลงข้อความเป็น int
    if err != nil {
        fmt.Println("เอ๊ะ อายุที่พิมพ์มาไม่ใช่ตัวเลข:", err)
        return // จบโปรแกรมทันที (return ใน main = เลิกทำงาน)
    }

    fmt.Println("สวัสดีคุณ", name, "อายุ", age, "ปี")
}
```

ทดสอบด้วยชื่อเต็มมีช่องว่าง `สมชาย ใจดี`:

```
ชื่อของคุณ: อายุของคุณ: สวัสดีคุณ สมชาย ใจดี อายุ 30 ปี
```

(ทดสอบจริง — คราวนี้ชื่อเต็มรอดมาได้ทั้งคำ!) — อธิบายทีละบรรทัดใหม่:

- **`bufio.NewReader(os.Stdin)`** — ขอ "เครื่องอ่าน" หนึ่งตัว ไว้คอยอ่านจาก stdin — `os` คือกล่อง standard library ที่รวมเรื่องการติดต่อกับ OS (ระบบปฏิบัติการ — gloss ไว้แล้วในแผนภาพข้างบน) — `os.Stdin` คือ "ช่อง stdin" ที่เราพูดถึงในแผนภาพ
- **`reader.ReadString('\n')`** — อ่านข้อความไปเรื่อย ๆ **จนกว่าจะเจออักขระ `\n`** (นิวไลน์ = newline = เครื่องหมายขึ้นบรรทัดใหม่ — ตอนกด Enter มันจะถูกเพิ่มต่อท้าย) — ได้ทั้งบรรทัดรวม `\n` มาเป็น string
- **`strings.TrimSpace(name)`** — ลบช่องว่าง (รวมถึง `\n`) ที่หัวและท้ายข้อความทิ้ง — ไม่งั้นชื่อเราจะมี `\n` ติดท้าย (สังเกตว่า Scanln ไม่ต้องทำขั้นนี้เพราะมันจัดการให้เอง)
- **`name, _ := ...`** — อะไรคือ `_` (อันเดอร์สกอร์)? ReadString คืนค่ามา 2 อย่าง: ข้อความที่อ่านได้ กับ error (ข้อความแสดงปัญหา ถ้าอ่านไม่สำเร็จ) — `_` คือ "ถังขยะ" รับค่าที่เรา**ยังไม่สนใจ**ไว้ (dev เรียก blank identifier = แบลงก์ ไอเดนติไฟเออร์ = ชื่อว่าง) — อ่านว่า "ได้ name ส่วนอีกค่าหนึ่ง โยนทิ้งก่อน"
- **`age, err := strconv.Atoi(ageText)`** — Atoi คืนค่า **2 อย่างพร้อมกัน**: (1) ตัวเลข int ที่แปลงได้ (2) error — ถ้าแปลงสำเร็จ err จะเป็น `nil` (นิล = ว่าง/ไม่มีค่า — ภาษา Go ใช้ nil แทน "ไม่มีค่า/ไม่มีปัญหา") ถ้าแปลงไม่ได้ err จะมีข้อความบอกว่าเกิดอะไรขึ้น
- **`if err != nil { ... return }`** — ตรวจว่า "มี error ไหม? ถ้ามี พิมพ์แจ้งแล้วจบโปรแกรม" — **นี่คือแพตเทิร์น (pattern = แบบแผน/ลวดลาย) การเช็ค error ที่พบบ่อยที่สุดใน Go** dev เรียกสั้น ๆ ว่า "check error" — จำหน้าตาไว้ให้ขึ้นใจ เพราะจะเห็นมันเต็มทั้งอาชีพ (error handling เต็มรูปแบบเรียนตอน 07 ตอนนี้ขอให้รู้วิธีใช้ขั้นพื้นฐานก่อน)

ลองป้อนอายุเป็นตัวหนังสือดูว่าเกิดอะไรขึ้น:

```
ชื่อของคุณ: อายุของคุณ: เอ๊ะ อายุที่พิมพ์มาไม่ใช่ตัวเลข: strconv.Atoi: parsing "abc": invalid syntax
```

(ทดสอบจริง) — error นี้คือ **error จริงจาก strconv.Atoi** — แปลว่า "ตอนแปลง 'abc' พบไวยากรณ์ที่ไม่ถูกต้อง" — สังเกตว่าข้อความ error ของ Go ดีขนาดไหน: บอกชัดว่าฟังก์ชันอะไร (`strconv.Atoi`), ค่าอะไร (`"abc"`), และผิดยังไง (`invalid syntax` = ไวยากรณ์ไม่ถูกต้อง)

**แล้วทำไมไม่ใช้ Scanln รับ int ตรง ๆ เลย?** เพราะ Atoi ทำให้เรา**เห็นและจัดการ error ได้** — กับ Scanln ถ้าผู้ใช้พิมพ์ผิด ตัวเลขจะกลายเป็น 0 เงียบ ๆ โดยที่เราไม่รู้ตัว (เห็นแล้วในจุดอ่อนที่ 2) — แต่วิธี bufio+Atoi เราบังคับให้ "อ่านเป็นข้อความก่อน แล้วค่อยแปลงทีละขั้น" ทุกขั้นตรวจสอบได้ ผิดพลาดตรงไหนรู้ทันที

### แล้วถ้าอยากได้เลขทศนิยมล่ะ? (เช่น ส่วนสูง 1.75)

`strconv.Atoi` แปลงได้**เฉพาะจำนวนเต็ม** — ถ้าเป็นเลขทศนิยม (float64) ต้องใช้ **`strconv.ParseFloat`** (พาร์ส โฟลต = แปลงข้อความเป็นเลขทศนิยม) ซึ่งอยู่ในกล่อง strconv เดียวกัน รูปแบบคล้ายกันมาก:

```go
weight, errW := strconv.ParseFloat("68.5", 64) // 64 = ให้เป็น float64
```

ตัว `64` คือ "ความละเอียดเป็น 64 บิต" (จำจากตอน 03 ที่ float64 ใช้เนื้อที่ 64 บิต) — ใช้คู่กับชนิด float64 ที่เราเรียนมา — จำไว้ว่า: **Atoi = จำนวนเต็ม, ParseFloat = ทศนิยม**

## ลงมือทำ: โปรแกรมคำนวณ BMI ที่ "คุยกับคนใช้ได้"

ถึงเวลาเอาทุกอย่างมารวมกัน — if/else + for + input + การแปลงชนิด — สร้างไฟล์ `bmi.go`:

```go
package main

import (
    "bufio"
    "fmt"
    "math"
    "os"
    "strconv"
    "strings"
)

func main() {
    fmt.Println("=== โปรแกรมคำนวณ BMI แบบโต้ตอบ ===")
    fmt.Println("(พิมพ์ q เพื่อออกจากโปรแกรม)")

    reader := bufio.NewReader(os.Stdin)

    for { // วนไม่รู้จบ — ออกได้ด้วย q หรือเมื่อ input หมด
        fmt.Print("น้ำหนัก (กิโลกรัม เช่น 68.5): ")
        weightText, err := reader.ReadString('\n')
        if err != nil { // input หมด (กด Ctrl+D หรืออ่านไฟล์จนจบ) → เลิกอย่างสุภาพ
            fmt.Println("ลาก่อน!")
            break
        }
        weightText = strings.TrimSpace(weightText)
        if weightText == "q" { // ผู้ใช้พิมพ์ q → ออกจาก loop
            fmt.Println("ลาก่อน!")
            break
        }

        fmt.Print("ส่วนสูง (เมตร เช่น 1.75): ")
        heightText, err := reader.ReadString('\n')
        if err != nil {
            fmt.Println("ลาก่อน!")
            break
        }
        heightText = strings.TrimSpace(heightText)
        if heightText == "q" {
            fmt.Println("ลาก่อน!")
            break
        }

        // แปลงข้อความเป็น float64 — err 2 ตัว (น้ำหนักกับส่วนสูง)
        weight, errW := strconv.ParseFloat(weightText, 64)
        height, errH := strconv.ParseFloat(heightText, 64)
        if errW != nil || errH != nil { // || = มีตัวไหนผิดตัวหนึ่งก็เข้าเงื่อนไขนี้
            fmt.Println("ขอโทษครับ อ่านเป็นตัวเลขไม่ได้ — ลองพิมพ์ใหม่ (เช่น 68.5)")
            continue // ข้ามไปถามรอบใหม่ (ไม่คิดคำนวณ)
        }

        // กันค่าที่เป็นไปไม่ได้: <= 0 รวมทั้ง NaN/Inf (NaN = ไม่ใช่ตัวเลข, Inf = อนันต์ — อ่าน gloss เต็มด้านล่าง) ที่ ParseFloat รับได้แบบไม่ error
        if weight <= 0 || height <= 0 ||
            math.IsNaN(weight) || math.IsNaN(height) ||
            math.IsInf(weight, 0) || math.IsInf(height, 0) {
            fmt.Println("น้ำหนักและส่วนสูงต้องเป็นตัวเลขปกติที่มากกว่า 0 — ลองใหม่นะครับ")
            continue
        }

        bmi := weight / (height * height) // สูตรเดียวกับตอน 03

        // แปลง BMI เป็นสถานะ — else if ไล่จากน้อยไปมาก
        var status string
        if bmi < 18.5 {
            status = "น้ำหนักน้อย"
        } else if bmi < 25 {
            status = "น้ำหนักปกติ"
        } else if bmi < 30 {
            status = "น้ำหนักเกิน"
        } else {
            status = "อ้วนระดับที่ต้องพบแพทย์"
        }

        fmt.Printf("BMI = %.2f → %s\n", bmi, status) // %.2f = ที่วางเลขทศนิยม 2 ตำแหน่ง (ตอน 03), %s = ที่วาง string — status จะแทรกตรงนี้
        fmt.Println("--------------------------------")
    }
}
```

ผลลัพธ์จริงจากการป้อนข้อมูลชุดหนึ่ง (ลองไล่ดูว่าโปรแกรมตอบสนองยังไง):

```
=== โปรแกรมคำนวณ BMI แบบโต้ตอบ ===
(พิมพ์ q เพื่อออกจากโปรแกรม)
น้ำหนัก (กิโลกรัม เช่น 68.5): ส่วนสูง (เมตร เช่น 1.75): BMI = 22.37 → น้ำหนักปกติ
--------------------------------
น้ำหนัก (กิโลกรัม เช่น 68.5): ส่วนสูง (เมตร เช่น 1.75): ขอโทษครับ อ่านเป็นตัวเลขไม่ได้ — ลองพิมพ์ใหม่ (เช่น 68.5)
น้ำหนัก (กิโลกรัม เช่น 68.5): ส่วนสูง (เมตร เช่น 1.75): BMI = 22.16 → น้ำหนักปกติ
--------------------------------
น้ำหนัก (กิโลกรัม เช่น 68.5): ลาก่อน!
```

(รอบที่ 2 ของตัวอย่างนี้ ผมตั้งใจป้อน `abc` เป็นน้ำหนัก — โปรแกรมจับได้ว่าแปลงไม่ได้ พิมพ์คำขอโทษ แล้ว `continue` กลับไปถามใหม่ — รอบที่ 3 ป้อน `80` กับ `1.9` คำนวณได้ 22.16 — แล้วพิมพ์ `q` โปรแกรม `break` ออก loop บอกลาจบ)

ขอชี้เทคนิคในโปรแกรมนี้ที่ dev ใช้กันจริง:

- **`q` คือ "สัญญาณออก"** — โปรแกรมที่วนรอ input ตลอด ต้องมีวิธีให้ผู้ใช้ออก — นิยมใช้ตัวอักษรพิเศษ (q = quit = เลิก) เช็ค**ก่อน**แปลงเป็นตัวเลข เพราะ "q" แปลงเป็นตัวเลขไม่ได้อยู่แล้ว
- **`continue` ใช้เป็น "เกราะกันข้อมูลเสีย"** — ถ้าผู้ใช้พิมพ์อะไรที่ใช้ไม่ได้ โปรแกรมไม่ควรพัง แต่ควร**ถามใหม่** — continue คือคำสั่ง "รอบนี้ข้ามไป ถามรอบใหม่" ที่สมบูรณ์แบบ

- **ทำไมต้องรับ error จากการอ่าน input ด้วย?** `ReadString` จะคืน error เมื่ออ่านไม่ได้ เช่น **input หมด** — ผู้ใช้กด **Ctrl + D** (สัญญาณบอก terminal ว่า "จบการพิมพ์") หรือรันแบบป้อนข้อมูลจากไฟล์แล้วอ่านจนจบ — ถ้าใช้ `_` ทิ้ง error แบบเดิม โปรแกรมจะได้ "" แล้ววนกลับไปถามซ้ำ**ไม่รู้จบ** (dev เรียก busy loop = บิซี ลูป = ลูปถามซ้ำเร็วจนค้าง) — การเช็ค `err != nil` แล้ว `break` ในโค้ดข้างบนจึงกันอาการค้างนี้ พร้อมพิมพ์ "ลาก่อน!" ให้จบอย่างสุภาพ

- **ParseFloat ไม่ได้ดุเสมอไป** — มันยอมรับคำพิเศษอย่าง `NaN` (เอน-เอ-เอ็น = ย่อจาก not a number = "ไม่ใช่ตัวเลข") หรือ `Inf` (อินฟินิตี = อนันต์) ได้โดย**ไม่คืน error** — ถ้าไม่กัน ค่าเหล่านี้จะเล็ดรอดเงื่อนไข `weight <= 0` ไปได้ (เพราะ NaN เปรียบเทียบกับอะไรก็ได้ false) แล้วโปรแกรมอาจพิมพ์ BMI = NaN — บรรทัด `math.IsNaN` / `math.IsInf` ในโค้ด (กับ `"math"` ใน import) คือเกราะปิดช่องนี้ ลองพิมพ์ `NaN` เป็นน้ำหนักดูได้ — โปรแกรมจะบอกให้ลองใหม่ ไม่พัง
- **else if ไล่จากค่าน้อยไปหาค่าเยอะโดยไม่ต้องเขียนขอบเขตล่าง** — ดูที่ `else if bmi < 25` — ทำไมไม่ต้องเขียน `bmi >= 18.5 && bmi < 25`? เพราะถ้าถึงบรรทัดนี้ได้ แปลว่า `bmi < 18.5` เป็น false ไปแล้ว (ไม่งั้นคงจบที่เงื่อนไขแรก) — โปรแกรม**รู้อยู่แล้ว**ว่ามันผ่านอะไรมา — dev ใช้เทคนิคนี้กันตลอดเพื่อให้โค้ดสั้นและอ่านง่าย (นี่คือเหตุผลที่ตอนต้นบทเรียนย้ำว่า "เงื่อนไขถูกตรวจจากบนลงล่าง")
- **`%s` ในบรรทัดพิมพ์ผลคืออะไร** — `fmt.Printf` (พริ้นท์-เอฟ = พิมพ์แบบจัดรูปแบบ) ให้เราใส่ "ที่วาง" ไว้ในข้อความ แล้วค่อยสอดค่าทีหลัง — `%.2f` คือที่วางเลขทศนิยม 2 ตำแหน่ง (เรียนตอน 03) ส่วน `%s` (เปอร์เซ็นต์-เอส, s = string) คือ**ที่วางข้อความ** — ตอนรัน ค่า `bmi` จะถูกแทรกแทนที่ `%.2f` และ `status` แทนที่ `%s` ตามลำดับ

- **ข้อความสถานะสุขภาพ**: ขอเน้นว่าเกณฑ์ BMI ข้างบนเป็นเพียง**ตัวอย่างเพื่อการเรียน** ใช้ฝึกเขียน if/else — การวินิจฉัยสุขภาพต้องให้แพทย์ทำ (และ dev ที่ทำงานสายสุขภาพต้องระวังเรื่องนี้มาก)

โปรแกรมนี้คือ "โปรแกรมจริง" ชิ้นแรกของคุณ — มันถาม ตอบสนองผิดถูก วนซ้ำ และเลิกเมื่อผู้ใช้สั่ง — ขอให้รันแล้วลองป้อนค่าต่าง ๆ ดู (รวมถึงค่าผิด ๆ ด้วย — จะเห็นว่ามันไม่พัง!)

## ตารางสรุป: ตัวดำเนินการและโครงสร้างที่เรียนวันนี้

| ประเภท | สัญลักษณ์ | ความหมาย | ตัวอย่าง |
|---|---|---|---|
| เปรียบเทียบ | `==` `!=` `<` `>` `<=` `>=` | เท่ากับ/ไม่เท่ากับ/น้อยกว่า/มากกว่า/ฯลฯ | `age >= 18` |
| ตรรกะ | `&&` | และ — ต้องการจริงทั้งสองข้าง | `age >= 18 && hasTicket` |
| ตรรกะ | `\|\|` | หรือ — ข้างใดข้างหนึ่งจริงก็พอ | `pay == "cash" \|\| pay == "card"` |
| ตรรกะ | `!` | ไม่ — กลับค่า bool | `!isWeekend` |
| คณิตศาสตร์ (ตอน 03) | `+ - * / %` | บวก ลบ คูณ หาร หารเอาเศษ | `weight / (height * height)` |
| ตัวย่อ (ตอน 03) | `+=` `-=` `++` | เพิ่ม/ลดค่า, เพิ่มทีละ 1 | `sum += i`, `i++` |
| โครงสร้าง | `if / else if / else` | ตัดสินใจหลายทาง | เกรด A–F |
| โครงสร้าง | `for init; cond; post` | วนแบบรู้จำนวนรอบ | `for i := 1; i <= 5; i++` |
| โครงสร้าง | `for cond` | วนตราบใดที่เงื่อนไขจริง (while) | `for budget > 0` |
| โครงสร้าง | `for { }` + `break` | วนไม่รู้จบ ออกด้วย break | วนถามจนกว่าจะ q |
| โครงสร้าง | `break` / `continue` | ออกจาก loop / ข้ามรอบนี้ | ตัวอย่างด้านบน |
| รับ input | `fmt.Scanln(&x)` | อ่านคำที่พิมพ์ (ง่าย แต่มีข้อจำกัด) | `fmt.Scanln(&name)` |
| รับ input | `bufio.NewReader` + `ReadString('\n')` | อ่านทั้งบรรทัด (แข็งแรง) | `reader.ReadString('\n')` |
| แปลง | `strconv.Atoi(s)` | string → int (คืน 2 ค่า: เลข + error) | `age, err := strconv.Atoi(s)` |
| แปลง | `strconv.ParseFloat(s, 64)` | string → float64 | `weight, err := strconv.ParseFloat(s, 64)` |
| แปลง | `strings.TrimSpace(s)` | ตัดช่องว่างหัว-ท้าย string | `name = strings.TrimSpace(name)` |

## กับดักยอดฮิตของมือใหม่ + error ที่จะเจอ (ทุกอันทดสอบจริง)

ขอเน้นอีกครั้งตามสไตล์คอร์สนี้: **ลองทำพังดูเอง แล้วเทียบกับตาราง** — การเห็น error ด้วยตาตัวเอง จำได้ดีกว่าอ่านซ้ำ ๆ หลายรอบ:

| โค้ดที่ทำให้พัง | error จริง | แปลว่า | วิธีแก้ |
|---|---|---|---|
| `if age = 18 { }` (เผลอใช้ `=` แทน `==`) | `syntax error: cannot use assignment age = 18 as value` | "ใช้การกำหนดค่า age = 18 เป็นค่าไม่ได้" — `=` คือคำสั่งใส่ค่า ไม่ใช่คำถาม | เปลี่ยนเป็น `==`: `if age == 18` |
| `if 1 { }` (ลองใส่เลขแทนเงื่อนไข) | `non-boolean condition in if statement` | "เงื่อนไขใน if ไม่ใช่ bool" — Go ไม่รับเลข 0/1 แบบบางภาษา | ใส่ bool จริง: `if x > 0` หรือตัวแปร bool |
| `if age >= 18` แล้วขึ้นบรรทัดใหม่ก่อนปีกกา | `syntax error: unexpected newline, expected { after if clause` | "ขึ้นบรรทัดใหม่กะทันหัน — คาดว่าจะเจอ { หลังเงื่อนไข if" | เปิดปีกกาในบรรทัดเดียวกับ if |
| `} \n else { }` (else ขึ้นบรรทัดใหม่) | `syntax error: unexpected keyword else, expected }` | "เจอ else ที่ไม่คาดคิด" — Go บังคับ else ต่อท้ายปีกกาปิด | เขียน `} else {` ในบรรทัดเดียวกัน |
| `if 10 == "10" { }` (เปรียบเทียบคนละชนิด) | `invalid operation: 10 == "10" (mismatched types untyped int and untyped string)` | "เทียบ int กับ string ไม่ได้ — ชนิดไม่ตรงกัน" (mismatched types จากตอน 03 กลับมาอีกแล้ว) | แปลงให้ชนิดเดียวกันก่อน |
| `if 13 <= age <= 18 { }` (เขียนเหมือนคณิตศาสตร์) | `invalid operation: 13 <= age <= 18 (mismatched types untyped bool and untyped int)` | "เอา (13 <= age) ซึ่งเป็น bool ไปเทียบ <= 18 ไม่ได้" — Go ไม่รองรับการเปรียบเทียบลูกโซ่ | เขียนแยกด้วย &&: `13 <= age && age <= 18` |
| ประกาศตัวแปรในปีกกา if แล้วใช้ข้างนอก | `undefined: status` | "ไม่รู้จัก status" — ตัวแปรที่ประกาศในปีกกามองเห็นได้แค่ในปีกกา (ขอบเขต = scope สโคป) | ประกาศไว้ข้างนอก (แบบ `var status string` ในโปรแกรม BMI) |
| `strconv.Atoi("abc")` | `strconv.Atoi: parsing "abc": invalid syntax` | "แปลง 'abc' เป็นตัวเลขไม่ได้" | เช็ค `err != nil` แล้วแจ้งผู้ใช้ (หรือถามใหม่) |
| `fmt.Scanln(&age)` เมื่อผู้ใช้พิมพ์ตัวหนังสือ | (ค่า age คงเป็น 0, error: `expected integer`) | "คาดว่าเป็นจำนวนเต็ม" — error หลุดถ้าไม่รับไว้ | ใช้วงจร bufio + Atoi ที่เช็ค error |
| ลืม `i++` ใน for | (ไม่ error — โปรแกรมค้าง!) | infinite loop — ตัวนับไม่เดิน เงื่อนไขจริงตลอด | เติม post ให้ครบ (หรือใช้ `for i := range N`) |
| `break` นอก loop | `break is not in a loop, switch, or select` | "break ไม่ได้อยู่ใน loop" (switch/select = โครงสร้างอีก 2 แบบของ Go ยังไม่เรียน — ไม่ต้องสนใจ) | ย้าย break ไปไว้ในปีกกา for |
| ประกาศตัวแปรแล้วไม่ใช้ (ต่อจากตอน 03) | `declared and not used: x` | "ประกาศ x แล้วไม่ใช้" | ใช้หรือลบทิ้ง (หรือใช้ `_` รับถ้าเป็นค่าที่ไม่สนใจ) |

(หมายเหตุ: เลขบรรทัดใน error จริงนับจากไฟล์ทดสอบเต็มของผมซึ่งมี `package main` / `import` / `func main() {` นำหน้า — snippet ในตารางตัดมาเฉพาะส่วนที่ผิด เลขบรรทัดจึงต่างกันได้ ขอให้อ่านที่ "สาเหตุ" เป็นหลัก — สูตรเดิมจากตอน 02: `ชื่อไฟล์:เลขบรรทัด:เลขหลัก: สาเหตุ`)

**ของใหม่ที่ควรจำจากตารางนี้ 3 อย่าง:** (1) `=` กับ `==` ผิดกันคนละเรื่อง — ใช้ผิด compiler จับได้ทันที (ดีใจที่ Go ดุ — ภาษาโปรแกรมบางภาษาปล่อยให้รันแล้วพังทีหลัง!) (2) เงื่อนไข if ต้องเป็น bool เท่านั้น (3) ตัวแปรในปีกกา "ออกนอกปีกกาไม่ได้" — กติกาเดียวกับห้อง: ของที่ประกาศในห้อง ใช้ได้เฉพาะในห้องนั้น

## โจทย์ประจำตอน

### ระดับ Drill (10–15 นาที)

1. **ทายก่อนรัน** (แล้วค่อยรันเทียบ): `age := 20` แล้วข้อความต่อไปนี้พิมพ์อะไรออกมาบ้าง (ตอบเป็น true/false หรือตัวเลข)
   - `fmt.Println(5 > 3 && 7 < 10)`
   - `fmt.Println(5 > 3 || 7 > 10)`
   - `fmt.Println(!(5 > 3))`
2. **ไล่ loop ด้วยมือ** (ยังไม่ต้องรัน): โค้ดนี้พิมพ์อะไรออกมาบ้าง? (Hint: ไล่ทีละรอบเหมือนตารางในบทความ แล้วตรวจ `i == 2` ก่อนถึงบรรทัดพิมพ์)
   ```go
   for i := 0; i < 5; i++ {
       if i == 2 {
           continue
       }
       fmt.Println(i)
   }
   ```
   แล้วลองเปลี่ยน `continue` เป็น `break` — ผลต่างกันยังไง อธิบายได้ไหมว่าทำไม (Hint: continue = ข้าม**รอบนี้**ไปรอบหน้า, break = ออกจาก loop **ทั้งหมด**)
3. **แก้โค้ดพัง**: โค้ดข้างล่าง compile ไม่ผ่านหลายจุด — หาให้ครบแล้วแก้ให้รันได้ (Hint: มองหา `=` แทน `==`, else ผิดบรรทัด, ตัวแปรนอกขอบเขตปีกกา และเงื่อนไขชนิดไม่ตรง):
   ```go
   package main

   import "fmt"

   func main() {
       age := 20
       score := 75

       if age = 21 {
           fmt.Println("อายุเปลี่ยนแล้ว")
       }

       if score >= 80 {
           fmt.Println("เกรด A")
       }
       else {
           fmt.Println("เกรดต่ำกว่า A")
       }

       if 18 <= age <= 60 {
           fmt.Println("วัยทำงาน")
       }

       if age >= 18 {
           canDrive := "อายุถึงเกณฑ์ขับรถแล้ว"
       }
       fmt.Println(canDrive) // canDrive ประกาศในปีกกา แต่เอามาใช้ข้างนอกปีกกา
   }
   ```
4. **เขียน flow เป็นภาษาคนก่อนโค้ด** (ฝึกคิดเป็นขั้นตอน): อธิบายเป็นประโยคไทยว่าโปรแกรมนี้ควรทำอะไร: "รับคะแนนสอบมา ถ้า 80 ขึ้นไปบอกว่าเยี่ยม ถ้า 50 ขึ้นไปบอกว่าผ่าน แต่ถ้าต่ำกว่านั้นบอกว่าต้องสอบแก้ และถ้าผู้ใช้พิมพ์ q ให้จบโปรแกรม" — เขียนเป็นข้อ ๆ (เหมือนผังงาน) ก่อนลงมือเขียนโค้ดจริงในข้อ 5

### ระดับ Mini-project (30–60 นาที) — "เกมทายเลข 1–10"

เขียนโปรแกรม `guess.go` — เกมทายตัวเลขที่ใช้ครบทั้ง 3 อย่างที่เรียนวันนี้ (if/else, for, input):

1. **สุ่มเลขลับ** 1 ตัวระหว่าง 1–10 ให้โปรแกรมจำไว้: ใช้ `rand.Intn(10) + 1` — `rand` (แรนดอม = สุ่ม) คือกล่อง standard library สำหรับสุ่มเลข ต้องเพิ่ม `"math/rand"` ใน import และเรียก `rand.Intn(10)` (อินที-เอ็น = random integer = เลขจำนวนเต็มสุ่ม) จะได้เลขสุ่ม 0–9 บวก 1 ก็จะได้ 1–10 — ลองเปิดดูตัวอย่างใน https://pkg.go.dev/math/rand (ทักษะการอ่านเอกสารคือทักษะจริง)
2. **วนถามผู้ใช้** (for + bufio แบบโปรแกรม BMI) ให้ทายเลข ทุกครั้งที่ทาย ให้โปรแกรมตอบ: `น้อยไป!` ถ้าทายต่ำกว่า, `มากไป!` ถ้าทายสูงกว่า, `ถูกต้อง!` ถ้าถูก แล้วจบเกม
3. **กันข้อมูลเสีย**: ถ้าผู้ใช้พิมพ์อะไรที่ไม่ใช่ตัวเลข (เช่น `abc`) ให้บอก "พิมพ์เป็นตัวเลขสิ" แล้ว**ถามใหม่** (Hint: `continue`) — และถ้าพิมพ์ `q` ให้เฉลยเลขลับแล้วออก
4. **เพิ่มความท้าทาย**: นับจำนวนครั้งที่ทาย (Hint: ตัวแปรนับ + `++` จากตอน 03) แล้วโชว์ตอนทายถูก — "ลอง 5 ครั้ง" — แล้วลองเล่นเองว่าทายถูกภายในกี่ครั้งโดยเฉลี่ย (วิธีที่คิดตามง่ายที่สุดคือทายไล่ทีละตัวจาก 1 ขึ้นไป — รับประกันจบไม่เกิน 10 ครั้งเสมอ — ของแถมสำหรับคนอยากเก่ง: ทุกครั้งที่โปรแกรมตอบ "มากไป/น้อยไป" มันตัดตัวเลือกทิ้งไปครึ่งหนึ่ง ลองทายเลขกลาง ๆ ก่อน เช่น 5 หรือ 6 แล้วผ่าครึ่งไปเรื่อย ๆ ดู — จะจบภายใน 4 ครั้งเสมอ dev เรียกเทคนิคนี้ว่า binary search = ไบนารี เสิร์ช = ค้นหาแบบผ่าครึ่ง)

**เกณฑ์ผ่าน:** โปรแกรมรันได้ เล่นจบได้ (มีทางออกด้วย q และทางชนะด้วยการทายถูก) พิมพ์ `น้อยไป/มากไป/ถูกต้อง` ถูกต้องตามจริง และ**ไม่มีทางพัง**เมื่อผู้ใช้พิมพ์อะไรก็ตาม (ทดสอบด้วยการพิมพ์ `abc`, `0`, `-5`, `q` แล้วสลับกันไปมา — โปรแกรมต้องไม่ error ค้าง)

Hint สำหรับคนที่ทดสอบแล้วโปรแกรม "ค้าง" ตอนรันใน terminal: กด **Ctrl + C** เพื่อหยุด แล้วอ่านโค้ดหาว่าลืมอะไร (ตัวนับไม่เดิน? break หาย? q ไม่มี?)

## สรุปตอนที่ 04

- **โปรแกรม = input → ประมวลผล → output** — ที่ผ่านมาเรามีแค่ "ประมวลผล" ตอนนี้เราทำให้โปรแกรมรับข้อมูลและเลือกทางเดินได้ เรียกรวมว่า flow control
- **if / else if / else** — ตรวจเงื่อนไข (ต้องเป็น bool) จากบนลงล่าง หยุดที่จริงอันแรก — เขียนเงื่อนไขที่ "แคบ" ไว้ก่อนเสมอ — ตัวดำเนินการเปรียบเทียบ 6 ตัว (`== != < > <= >=`) จากตอน 03 คือวัตถุดิบของเงื่อนไข
- **`&&` (และ) `||` (หรือ) `!` (ไม่)** — ผสมเงื่อนไขหลายอัน — `&&` เคร่งต้องจริงทั้งคู่, `||` ผ่อนจริงข้างเดียวพอ, `!` กลับค่า — ทั้งคู่เป็น short-circuit (หยุดตรวจเมื่อได้คำตอบ)
- **for คือ loop เดียวของ Go** — 4 รูปแบบ: เต็ม (`init; cond; post`), วนตามเงื่อนไข (while), `for range N` (นับจาก 0), และ `for { }` วนไม่รู้จบ — ควบคุมด้วย `break` (ออก) กับ `continue` (ข้ามรอบ) — เบื้องลึกคือคำสั่ง jump ของ CPU ที่ทำให้โปรแกรม "กระโดดกลับ" ไปรันซ้ำ (ตอน 11–12)
- **รับ input แบบแข็งแรง 3 ขั้น**: bufio อ่านทั้งบรรทัด → `strings.TrimSpace` ตัดช่องว่าง → `strconv.Atoi` (จำนวนเต็ม) / `ParseFloat` (ทศนิยม) แปลง + **เช็ค error ทุกครั้ง** — ส่วน `fmt.Scanln` ใช้ได้กับ input ง่าย ๆ แต่พังเมื่อมีช่องว่างหรือพิมพ์ผิดชนิด
- **error กับดักยอดฮิตของตอนนี้**: `=` แทน `==`, else ขึ้นบรรทัดใหม่, เงื่อนไขไม่ใช่ bool, เปรียบเทียบคนละชนิด, เปรียบเทียบลูกโซ่ (`13 <= age <= 18`), ตัวแปรหลุดออกจากปีกกา, และลืม `i++` จนโปรแกรมค้าง

ตอนนี้โปรแกรมของคุณ**พูดได้และฟังได้**แล้ว — มันถาม ตอบ เลือก และวนซ้ำได้ตามที่เราสั่ง — เหลืออีกอย่างที่ทำให้โปรแกรมยิ่งทรงพลัง: การ**แบ่งงาน**ออกเป็นชิ้นเล็ก ๆ (ฟังก์ชัน) เพื่อไม่ให้โค้ดยาวเป็นเส้นเดียวยาว ๆ — นั่นคือเรื่องของตอนหน้า (ตอน 05)

ระหว่างรอ อย่าลืมทำ mini-project "เกมทายเลข" — และจำไว้ว่า: ทุกโปรแกรมที่ดูซับซ้อน ประกอบด้วย if/else + loop + input + ตัวแปร เรียงต่อกันทั้งนั้น — ตอนนี้คุณมี "อิฐ" ครบทุกก้อนแล้ว
