ย้อนกลับไปที่ mini-project ของตอน 05 สักครู่: โจทย์ให้เรา "ตรวจ BMI คนทั้งบ้าน" แล้วสรุปว่าใครสูงสุด ต่ำสุด ค่าเฉลี่ยเท่าไร

ลองนึกภาพว่าคุณทำโจทย์นั้นด้วยสิ่งที่รู้จนถึงตอน 05 — ตัวแปรเดี่ยวทีละตัว (`name1`, `weight1`, `name2`, `weight2`, ...) — กับบ้านที่มีคนอยู่ 10 คน คุณจะต้องประกาศตัวแปร 30–40 ตัว แล้วเขียนโค้ดเปรียบเทียบยาวเป็นวา ทั้งหมดเพื่อถามคำถามง่าย ๆ ว่า "ค่าเฉลี่ย BMI ของบ้านนี้เท่าไร"

นี่คือความรู้สึกที่ dev (นักพัฒนาโปรแกรม) ทุกคนเคยเจอ: **ตัวแปรเดี่ยวเก็บ "ของชิ้นเดียว" ได้ แต่โลกจริงเต็มไปด้วย "ของหลายชิ้น"** — รายชื่อนักเรียนทั้งห้อง, พจนานุกรมคำศัพท์, ข้อมูลผู้ใช้แต่ละคนที่ประกอบด้วยหลายช่องรวมกัน

ตอนนี้เราจะแก้ปัญหานี้ด้วยเครื่องมือ 3 ชิ้นที่ dev ใช้ทุกวัน:

- **slice** (สไลซ์) = "รายการข้อมูล" — เก็บของหลายชิ้นเรียงเป็นแถว เช่น รายชื่อ, คะแนน
- **map** (แมป) = "สมุดค้นหา" — เปิดด้วยกุญแจ (เช่น ชื่อ) แล้วได้ค่า (เช่น อายุ) กลับมาทันที
- **struct** (สตรัคต์) = "แบบฟอร์มข้อมูล" — รวมข้อมูลหลายชนิดของ "สิ่งหนึ่ง" เข้าด้วยกัน เช่น นักเรียน 1 คน = ชื่อ + คะแนน + ที่อยู่

เป้าหมายของตอนนี้: **อ่านจบแล้ว คุณเก็บข้อมูลเป็นกลุ่มได้เอง** ไม่ว่าจะเป็นรายการ, ตารางค้นหา, หรือแบบฟอร์ม — และนี่คือก้าวสุดท้ายของ "เสาที่ 4" ที่ต่อจาก ตัวแปร (ตอน 03), การควบคุม (ตอน 04), การแบ่งงาน (ตอน 05) ครบแล้วคุณก็มีเครื่องมือพื้นฐานครบชุด

## ทำไม 3 เครื่องมือนี้ถึงสำคัญ — มองจากของจริงที่คุณใช้อยู่

ก่อนลงโค้ด ขอวางภาพใหญ่ก่อนว่า slice, map, struct อยู่ใน**ของจริงทุกอย่างที่คุณแตะทุกวัน**:

- แอปธนาคารที่แสดง "ประวัติธุรกรรม 20 รายการล่าสุด" — หลังจอคือ slice ของรายการธุรกรรมเรียงตามเวลา
- เว็บไซต์ที่ให้คุณค้นหาสินค้าด้วยชื่อ — หลังจอคือ map ที่เปิด "รหัสสินค้า → ข้อมูลสินค้า" ได้ทันที
- ผู้ใช้ Facebook แต่ละคน (ชื่อ, อีเมล, วันเกิด, เพื่อน) — คือ struct ตัวหนึ่งที่รวมข้อมูลหลายชนิดของ "คนหนึ่งคน" ไว้ด้วยกัน

และถ้าลงลึกถึงระดับระบบ (ที่เราจะเรียนเต็มรูปแบบตอน 18–21): ตัวระบบปฏิบัติการเองก็จัด "รายการโปรเซส (process = งาน/แอปที่กำลังทำงานอยู่) ที่กำลังรัน" (slice), "ตารางเปิดไฟล์" (map) และ "โครงสร้างข้อมูลของไฟล์หนึ่งไฟล์" (struct) ไว้ในหน่วยความจำ — สามตัวนี้คือ vocabulary (โวแคบูลารี = คำศัพท์) พื้นฐานที่ใช้บรรยาย "ข้อมูลหลายชิ้น" ได้ทุกภาษา ไม่ใช่แค่ Go

เราเรียนผ่าน Go ก่อน เพราะภาษา Go ออกแบบทั้งสามตัวนี้มาให้เรียบง่ายและปลอดภัยที่สุดในบรรดาภาษาหลัก ๆ — เริ่มที่ตัวแรกเลย

## slice — "รายการ" ที่ขยายได้

### array กับ slice ต่างกันตรงไหน

ในภาษาโปรแกรมส่วนใหญ่มีของที่เรียกว่า **array** (แอเรย์ = ชุดข้อมูลเรียงกันเป็นแถว จำนวนช่องตายตัว) — พอประกาศแล้วใส่ได้แค่กี่ช่องตามที่บอกไว้ ใส่เกินไม่ได้

Go ก็มี array แบบนั้น แต่ dev สาย Go **แทบไม่ใช้ array ตรง ๆ** — เขาใช้ **slice** ซึ่งคือ "รายการที่ขยายขนาดได้" สร้างว่าง ๆ แล้วค่อย ๆ เติมของเข้าไปทีละชิ้นได้ไม่รู้จบ

ศัพท์ที่ต้องรู้ก่อนอ่านโค้ด:

- **element** (เอเลเมนต์ = สมาชิก/ชิ้น) — ของแต่ละชิ้นที่อยู่ในรายการ เช่น รายการ `[31, 33, 29]` มี 3 elements
- **index** (อินเดกซ์ = เลขตำแหน่ง) — ลำดับของช่อง เริ่มนับจาก **0** เสมอ — ช่องแรกคือ index 0, ช่องที่สองคือ 1, ไปเรื่อย ๆ (คอมพิวเตอร์นับเริ่มจาก 0 — เราเห็นไปแล้วตอน 04)
- **length** (เลงธ์ = ความยาว) — จำนวนชิ้นที่ "มีอยู่จริงตอนนี้" ใช้ฟังก์ชัน `len()` อ่าน
- **capacity** (คาพาซิตี = ความจุ) — จำนวนช่องที่ slice "จุได้โดยไม่ต้องขยายเพิ่ม" ใช้ `cap()` อ่าน — ตอนนี้แค่จำไว้ว่ามีคำนี้ เดี๋ยวเห็นของจริงตอน append

สร้างไฟล์ `slice1.go` ในโฟลเดอร์ `gopher-course` (โฟลเดอร์เดียวกับตอนก่อน ๆ) แล้วพิมพ์ตาม:

```go
package main

import "fmt"

func main() {
	// array (แอเรย์): ชุดข้อมูลเรียงกัน ขนาดตายตัว — 3 ช่อง ใส่เกินไม่ได้
	var scores [3]int
	scores[0] = 85
	scores[1] = 90
	scores[2] = 78
	fmt.Println("array scores:", scores)
	fmt.Println("len:", len(scores)) // len = จำนวนช่อง

	// slice: เริ่มจากว่าง (nil = ยังไม่มีช่อง/ว่าง) แล้วค่อยเติมด้วย append
	var temps []int
	fmt.Println("slice ว่าง:", temps, "| len:", len(temps), "cap:", cap(temps))
	temps = append(temps, 31)
	temps = append(temps, 33)
	temps = append(temps, 29)
	fmt.Println("หลังเติม:", temps, "| len:", len(temps), "cap:", cap(temps))

	// แก้ค่าที่ช่องโดยใช้ index
	temps[0] = 30
	fmt.Println("แก้ช่อง 0 แล้ว:", temps)
}
```

รันด้วย `go run slice1.go` — ผลลัพธ์จริงที่เครื่องของผม:

```
array scores: [85 90 78]
len: 3
slice ว่าง: [] | len: 0 cap: 0
หลังเติม: [31 33 29] | len: 3 cap: 4
แก้ช่อง 0 แล้ว: [30 33 29]
```

แกะโค้ดทีละจุด:

- `var scores [3]int` — ประกาศ **array** ของ int ขนาด 3 ช่อง (ตัวเลขใน `[3]` บอก "ตายตัว 3 ช่อง") — เขียนค่าด้วย `scores[0] = 85` ฯลฯ ใส่ช่องที่ 4 ไม่ได้
- `var temps []int` — ประกาศ **slice** ของ int — สังเกต: ในวงเล็บ `[]` **ไม่มีตัวเลข** นี่คือจุดต่างเดียวที่ตาเห็น — slice ไม่กำหนดขนาดตอนประกาศ
- `append(temps, 31)` — **append** (แอพเพนด์ = ต่อท้าย) เป็นฟังก์ชันที่ "เอาของชิ้นใหม่ไปต่อท้ายรายการ แล้วคืนรายการใหม่กลับมา" — เรา**ต้องรับค่ากลับ**ด้วย `temps = append(...)` เสมอ — Go บังคับเลย: ถ้าเขียน `append(temps, 31)` เฉย ๆ โดยไม่มี `temps =` ด้านหน้า compile ไม่ผ่าน (error: "value of type []int is not used") — เพราะ append ไม่ได้ "แก้" slice ตัวเดิม แต่มันคืน slice ก้อนใหม่มาให้เราเก็บเอง (ดูกับดักข้อ 6 ด้านล่าง)
- สังเกต `cap` ที่เปลี่ยนจาก 0 → 4 หลังเติม 3 ชิ้น: Go เผื่อช่องว่างให้ล่วงหน้า (จุได้ 4 แต่มีของจริง 3) — เพราะการ "ขยาย array ข้างหลัง" มีต้นทุน เวลาเติมไปเรื่อย ๆ Go จะจองเผื่อเป็นก้อนใหญ่ขึ้น ทำให้การเติมต่อท้ายเฉลี่ยแล้วรวดเร็ว — ตรงนี้เป็นกลไกภายในที่ dev ควรรู้ว่ามีอยู่ แต่ไม่ต้องไปควบคุมเอง

### make, index, และการตัดช่วง (slicing)

นอกจาก `append` ทีละชิ้น เรายังสร้าง slice ที่ "มีช่องพร้อมเขียน" ด้วย **make** (เมก = สร้าง) แล้วเขียนค่าเข้าไปทีละช่องด้วย index ได้เลย:

```go
package main

import "fmt"

func main() {
	// make: สร้าง slice ความยาว 5 ช่อง เต็มไปด้วย zero value (0)
	scores := make([]int, 5)
	fmt.Println("scores:", scores, "| len:", len(scores), "cap:", cap(scores))

	// เขียนค่าทีละช่องด้วย index
	scores[0] = 85
	scores[1] = 90
	scores[2] = 78
	scores[3] = 92
	scores[4] = 88
	fmt.Println("scores:", scores)

	// ตัดช่วง (slicing): s[start:stop] เอา index start ถึง stop-1
	top3 := scores[:3]    // ช่อง 0 ถึง 2
	middle := scores[1:4] // ช่อง 1 ถึง 3
	last2 := scores[3:]   // ช่อง 3 ถึง 4
	fmt.Println("scores[:3]  =", top3)
	fmt.Println("scores[1:4] =", middle)
	fmt.Println("scores[3:]  =", last2)

	// สำคัญ: top3/middle/last2 ไม่ได้ "คัดลอก" ข้อมูล — แชร์ array ก้อนเดียวกัน
	middle[0] = 99
	fmt.Println("middle[0] = 99 แล้ว:")
	fmt.Println("middle:", middle)
	fmt.Println("scores:", scores)
}
```

ผลลัพธ์จริง:

```
scores: [0 0 0 0 0] | len: 5 cap: 5
scores: [85 90 78 92 88]
scores[:3]  = [85 90 78]
scores[1:4] = [90 78 92]
scores[3:]  = [92 88]
middle[0] = 99 แล้ว:
middle: [99 78 92]
scores: [85 99 78 92 88]
```

แกะโค้ด:

- `make([]int, 5)` — สร้าง slice ของ int ยาว 5 ช่อง เต็มไปด้วย **zero value** (ซีโร่ แวลู = ค่าเริ่มต้นของชนิดนั้น — int = 0, string = "" (ข้อความว่าง), float64 = 0, bool = false — เราเคยเห็นของจริงตอน 04: ตัวแปรที่ยังไม่ถูกเติมค่า จะคงค่าเริ่มต้นตามชนิดของมัน) — แล้วเขียนค่าทีละช่องด้วย `scores[0] = 85` ฯลฯ
- **การตัดช่วง** (slicing = สไลซิง) — เขียน `s[start:stop]` แปลว่า "เอาช่องตั้งแต่ index `start` ถึง index `stop-1`" (จุดที่คนเรียนใหม่พลาดบ่อย: ตัวเลขหลังโคลอนเป็น "ช่องที่**ไม่**เอา" — `scores[1:4]` เอาช่อง 1, 2, 3 ไม่เอาช่อง 4)
- `scores[:3]` = เอาตั้งแต่ช่อง 0 ถึง 2 (ละตัวแรก = เริ่มจาก 0), `scores[3:]` = เอาช่อง 3 ถึงสุดท้าย (ละตัวหลัง = ถึงจบ)
- **จุดสำคัญที่สุดในหัวข้อนี้**: `top3`, `middle`, `last2` ไม่ได้**คัดลอก**ข้อมูลออกมา — พวกมันคือ "มุมมอง" ที่ชี้ไปยัง array ก้อน**เดียวกัน**ข้างหลัง — หลักฐานคือพอเราแก้ `middle[0] = 99` แล้ว `scores` ก็เปลี่ยนตามเป็น `[85 99 78 92 88]`

แผนผังด้านล่างสรุปโครงสร้าง slice ให้เห็นเป็นภาพ — slice แต่ละตัวจดแค่ 3 อย่าง: ชี้ array ก้อนไหน (pointer), ใช้ได้กี่ช่อง (len), จุได้กี่ช่อง (cap) — พอตัดช่วงด้วย `s[2:5]` ได้ slice ใหม่ที่ยังแชร์ array ก้อนเดิม ไม่ได้คัดลอก:

![slice คือมุมมองที่ชี้ไปยัง array ข้างหลัง: ตัดช่วงด้วย s[2:5] ได้ slice ใหม่ที่ยังแชร์ array ก้อนเดิม ไม่ได้คัดลอกข้อมูล](/assets/diagrams/ep06-01-slice-view.svg)

(หมายเหตุ: โค้ดในภาพเขียน `s := []int{10, 20, ...}` แบบใส่ค่าในปีกกาเลย — เรียกว่า **literal** จะอธิบายเป็นทางการในหัวข้อ map ด้านล่าง ตอนนี้แค่ดูภาพรวมโครงสร้างก่อน ข้าม syntax นี้ไปก่อนได้)

> 💡 **pointer** (พอยน์เตอร์ = ตัวชี้/ตัวอ้างอิง) ในภาพ — คำเต็มจะเรียนตอน 14 ตอนนี้แค่จำว่า "slice ชี้ไปที่ array อีกก้อนหนึ่ง" ก็พอ — สิ่งที่ต้องจำวันนี้มีอย่างเดียว: **slice ที่ตัดมาจาก slice เก่า แชร์ข้อมูลเดียวกัน** แก้ที่หนึ่ง เห็นผลอีกที่หนึ่ง

### วนอ่านทุกชิ้นด้วย `for range`

ตอน 04 เราวน loop รู้จำนวนรอบล่วงหน้า — แต่ของหลายชิ้น เรามักไม่รู้จำนวน (รายการมันยาวเท่าไรก็ไม่แน่) Go มีรูปแบบ loop ที่ออกแบบมาสำหรับ "วนอ่านทุกชิ้นใน slice" โดยเฉพาะ เรียกว่า **for range**:

```go
package main

import "fmt"

func main() {
	names := []string{"สมชาย", "สมหญิง", "สมปอง"}

	// for range: ได้ index (ตำแหน่ง) กับ value (ค่าประจำช่อง)
	for i, name := range names {
		fmt.Println("ช่อง", i, "=", name)
	}

	// อยากได้แค่ค่า → ใช้ _ (อันเดอร์สกอร์ = ขีดล่าง) รับ index แล้วทิ้ง
	total := 0
	nums := []int{10, 20, 30, 40}
	for _, n := range nums {
		total += n
	}
	fmt.Println("รวม:", total)

	// อยากได้แค่ index — ใช้ตอนต้องการแก้ค่าข้างใน
	for i := range nums {
		nums[i] *= 2 // คูณ 2 แล้วเก็บกลับที่ช่องเดิม
	}
	fmt.Println("nums:", nums)
}
```

ผลลัพธ์จริง:

```
ช่อง 0 = สมชาย
ช่อง 1 = สมหญิง
ช่อง 2 = สมปอง
รวม: 100
nums: [20 40 60 80]
```

แกะโค้ด:

- `names := []string{"สมชาย", "สมหญิง", "สมปอง"}` — สร้าง slice พร้อมค่าเริ่มต้นโดยใส่ค่าลงในปีกกาเลย (เรียกว่า **literal** = ลิเทอรัล = เขียนค่าโดยตรง — จะอธิบายเต็ม ๆ ในหัวข้อ map ด้านล่าง)
- `for i, name := range names` — **range** (เรนจ์ = วนทั่วช่วง) แปลว่า "วนไปทีละชิ้นของ slice โดยแต่ละรอบได้มาสองค่า: `i` = index, `name` = ค่าในช่องนั้น" — วนกี่รอบอัตโนมัติตามความยาว ไม่ต้องรู้จำนวนล่วงหน้า
- `for _, n := range nums` — ถ้าอยากได้แค่**ค่า** ไม่ใช้ index ให้ใช้ `_` (อันเดอร์สกอร์ = ขีดล่าง = "ช่องทิ้ง" รับค่าไว้แต่ไม่ใช้ — เราเจอ `_` มาบ้างแล้วตอน 04 ตอน `_, err := ...`)
- `for i := range nums` — ถ้าเขียนตัวแปรเดียวหลัง `range` ได้แค่ **index** (ไม่ใช่ค่า) — ใช้เวลาต้องการแก้ค่าข้างใน (`nums[i] *= 2`)
- `:=` และ `+=`, `*=` มาจากตอน 03 (`x *= 2` = `x = x * 2`)

กฎสำคัญของ slice ที่ควรจำติดตัว: **slice ชี้ไปยัง array ที่อยู่ข้างหลัง** — มันไม่ได้ "ถือ" ข้อมูลเอง จำภาพนี้ไว้แล้วเรื่องต่อไปจะง่ายขึ้นมาก

## map — "สมุดค้นหา" key → value

slice เก่งเรื่อง "เรียงเป็นแถว" แต่ถ้าอยากถามว่า "สมชายอายุเท่าไร" ด้วย slice เราต้องไล่หาทีละช่องจนเจอ — ช้าถ้ารายการยาว

**map** (แมป) คือโครงสร้างที่ตอบโจทย์ "ค้นหาด้วยชื่อ" โดยตรง — มันคือชุดคู่ของ **key → value** (คีย์ → แวลู):

- **key** (คีย์ = กุญแจ/คำค้น) — สิ่งที่ใช้เปิดหา เช่น ชื่อคน, รหัสสินค้า — ใน map หนึ่งคีย์ซ้ำกันไม่ได้
- **value** (แวลู = ค่าที่เก็บ) — ข้อมูลที่ติดอยู่กับคีย์นั้น เช่น อายุ, ราคา

อุปมา: map คือ**สมุดค้นหาศัพท์** — คุณเปิดหาคำว่า "key" (กุญแจ) แล้วได้คำแปล "value" ทันที โดยไม่ต้องไล่เปิดทีละหน้า เปรียบกับ slice ที่เป็นเหมือน "สมุดโน้ตเรียงหน้า" ต้องไล่เปิดไล่อ่าน

```go
package main

import "fmt"

func main() {
	// สร้าง map: key (คีย์ = กุญแจ/คำค้น) เป็น string, value (แวลู = ค่าที่เก็บ) เป็น int
	ages := make(map[string]int)
	ages["สมชาย"] = 30
	ages["สมหญิง"] = 28
	ages["สมปอง"] = 35
	fmt.Println("จำนวนสมาชิก:", len(ages))

	// อ่านค่าด้วย key
	fmt.Println("อายุสมชาย:", ages["สมชาย"])

	// อ่าน key ที่ไม่มี → ได้ zero value (0) โดยไม่พัง
	fmt.Println("อายุคนที่ไม่มี:", ages["ไม่มีตัวตน"])

	// comma-ok idiom: บอกว่า "key มีจริงไหม" แยกจาก "ค่าเป็น 0"
	age, ok := ages["สมปอง"]
	fmt.Println("สมปอง:", age, "| มีจริงไหม:", ok)
	_, ok = ages["ไม่มีตัวตน"]
	fmt.Println("ไม่มีตัวตนมีจริงไหม:", ok)

	// ลบ key ทิ้ง (ลบ key ที่ไม่มีอยู่แล้วก็ไม่ error)
	delete(ages, "สมชาย")
	delete(ages, "คนที่ไม่มีอยู่จริง")
	fmt.Println("หลังลบ:", ages)

	// วน range ทุกคู่ key→value — Go ไม่การันตีลำดับ
	for name, age := range ages {
		fmt.Println(name, "=", age)
	}
}
```

ผลลัพธ์จริง:

```
จำนวนสมาชิก: 3
อายุสมชาย: 30
อายุคนที่ไม่มี: 0
สมปอง: 35 | มีจริงไหม: true
ไม่มีตัวตนมีจริงไหม: false
หลังลบ: map[สมปอง:35 สมหญิง:28]
สมหญิง = 28
สมปอง = 35
```

แกะโค้ด:

- `make(map[string]int)` — สร้าง map ที่ key เป็น string, value เป็น int (ชนิดสองตัวในวงเล็บแหลม: ตัวแรก = ชนิด key, ตัวหลัง = ชนิด value)
- `ages["สมชาย"] = 30` — เขียนค่าด้วย `m[key] = value` — อ่านค่าด้วย `ages["สมชาย"]`
- **อ่าน key ที่ไม่มี → ได้ zero value (0) โดยไม่พัง** — สังเกตบรรทัด "อายุคนที่ไม่มี: 0" — โปรแกรมไม่ crash (ครัช = พัง/หยุดทำงานกะทันหัน) แต่มันก็**แยกไม่ออก**ว่า "ไม่มีคีย์นี้" หรือ "มีคีย์นี้แต่ค่าเป็น 0"
- **comma-ok idiom** (คอมมา-โอเค อิดิโอม = สำนวน "ค่า, ok") — `age, ok := ages["สมปอง"]` รับ 2 ค่า: ค่าที่อ่านได้ + `ok` (bool = ค่าจริง/เท็จ) ที่บอกว่า "คีย์นี้มีจริงไหม" — นี่คือวิธีแยก "ไม่มี" ออกจาก "เป็น 0" — ต้นแบบเดียวกับคู่ `(ค่า, error)` ที่เราจะเรียนเต็มรูปแบบตอน 07
- `delete(ages, "สมชาย")` — **delete** (ดีลีท = ลบ) ลบคู่ key นั้นทิ้ง — ลบ key ที่ไม่มีอยู่แล้วก็ไม่ error (ปลอดภัย)
- `for name, age := range ages` — วนทุกคู่ key→value — **สำคัญ: Go ไม่การันตีลำดับ** การวนรอบอาจได้ "สมหญิง ก่อน สมปอง" หรือสลับกันก็ได้ (ในผลลัพธ์จริงเครื่องผมเรียง สมหญิง → สมปอง ซึ่งไม่ใช่ลำดับที่ใส่) — ถ้าต้องการลำดับแน่นอน ใช้ slice (รายละเอียดตอนท้ายบท)

แผนผังด้านล่างสรุป map เป็นภาพ:

![map คือชุดคู่ key กับ value: เปิดด้วย key (เช่น ชื่อคน) แล้วได้ value (เช่น อายุ) กลับมาทันที เหมือนสมุดค้นหา](/assets/diagrams/ep06-02-map-key-value.svg)

(โค้ดในภาพ `ages := map[string]int{...}` ใช้แบบ literal = ใส่ค่าตั้งแต่ตอนสร้าง — อ่านหัวข้อถัดไปได้เลย)

### map แบบเขียนพร้อมค่าเลย (literal)

นอกจาก `make` แล้ว เราสร้าง map พร้อมค่าเริ่มต้นได้ด้วย **literal** (ลิเทอรัล = เขียนค่าโดยตรง) — เหมือนตอน 03 ที่เขียน `x := 5` แทนการประกาศแล้วค่อยกำหนด:

```go
package main

import "fmt"

func main() {
	// สร้าง map ด้วย literal — เขียน key กับ value พร้อมตอนประกาศ
	scores := map[string]float64{
		"คณิต":  85.5,
		"วิทย์": 92.0,
	}
	fmt.Println("คะแนนคณิต:", scores["คณิต"])

	// อ่าน key ที่ไม่มี → 0 — แต่ถ้าคนนั้น "ได้ 0 จริง" เราจะแยกไม่ออก!
	fmt.Println("คะแนนสังคม:", scores["สังคม"]) // 0 — ไม่มี key หรือได้ 0 กันแน่?
	scores["สังคม"] = 0                         // สมมติว่ามีคนได้ 0 จริง
	val, ok := scores["สังคม"]
	fmt.Println("สังคม:", val, "| มีจริงไหม:", ok) // comma-ok ช่วยแยกได้
}
```

ผลลัพธ์จริง:

```
คะแนนคณิต: 85.5
คะแนนสังคม: 0
สังคม: 0 | มีจริงไหม: true
```

แกะโค้ด: ตัวนี้ย้ำประเด็นเดิมให้เห็นชัด — `scores["สังคม"]` ทั้งที่ไม่มี key นี้ ให้ `0` กลับมา เหมือนกับว่ามีคน "ได้ 0 จริง" — แต่พอใช้ comma-ok (`val, ok := ...`) กลับได้ `ok = true` หลังเราเขียน `scores["สังคม"] = 0` เข้าไป ทำให้แยก "ไม่มี" (ok = false) กับ "มีแต่เป็น 0" (ok = true) ออกจากกันได้ — จำประโยคนี้ไว้: **"อ่าน map อยากรู้ว่า key มีจริงไหม ใช้ comma-ok เสมอ"**

## struct — "แบบฟอร์ม" รวมข้อมูลของสิ่งหนึ่ง

slice กับ map เก็บ "ของชิ้นเดียว" หลายชิ้น แต่ข้อมูลในโลกจริงของ "สิ่งหนึ่ง" มักประกอบด้วยหลายชนิดปนกัน — นักเรียน 1 คน มีทั้ง ชื่อ (string) และ คะแนน (float64) — ถ้าใช้ slice อย่างเดียวต้องแยกเป็น 2 รายการคู่ขนาน (`names` กับ `scores`) ซึ่งเสี่ยงที่ข้อมูลจะ "หลุดคู่" กัน

**struct** (สตรัคต์ = โครงสร้าง) แก้ปัญหานี้: มันคือ**แบบพิมพ์ (type) ที่รวมหลายช่อง (field) เป็นก้อนเดียว** — เหมือนแบบฟอร์มใบสมัคร 1 ใบที่มีช่องให้กรอกหลายช่อง

ศัพท์ที่ต้องรู้:

- **type** (ไทป์ = ชนิด/แบบพิมพ์) — "แม่แบบ" ที่บอกว่าข้อมูลแบบนี้มีช่องอะไรบ้าง — เราประกาศ `type Student struct { ... }` เพื่อนิยามว่า "นักเรียน" หน้าตาเป็นยังไง
- **field** (ฟิลด์ = ช่อง) — แต่ละช่องใน struct เช่น `Name`, `Score` — แต่ละ field มีชื่อ + ชนิดกำกับ
- **instance** (อินสแตนซ์ = ตัวอย่างที่สร้างจากแบบพิมพ์) — ตัวจริงที่กรอกค่าแล้ว เช่น `s1 := Student{Name: "สมชาย", Score: 85.5}` — จากแบบพิมพ์หนึ่งใบ สร้าง instance ได้กี่ตัวก็ได้

```go
package main

import "fmt"

// Student = แบบพิมพ์ (type) ของข้อมูลนักเรียน 1 คน
// ข้างในมี field (ฟิลด์ = ช่อง) 2 ช่อง: Name กับ Score
type Student struct {
	Name  string  // ชื่อ — ชนิด string
	Score float64 // คะแนน — ชนิด float64
}

func main() {
	// สร้าง struct ตัวหนึ่ง (instance = อินสแตนซ์ = ตัวอย่างที่สร้างจากแบบพิมพ์)
	// แบบระบุชื่อ field — เรียงสลับกันก็ได้ เพราะเราบอกชื่อกำกับ
	s1 := Student{Name: "สมชาย", Score: 85.5}
	fmt.Println("s1 ทั้งก้อน:", s1)

	// เข้าถึง field ทีละช่องด้วยจุด (dot)
	fmt.Println("ชื่อ:", s1.Name)
	fmt.Println("คะแนน:", s1.Score)

	// แก้ไข field
	s1.Score = 90
	fmt.Println("หลังแก้คะแนน:", s1.Score)

	// ไม่ระบุ field ไหน → ได้ zero value ของชนิดนั้น (string = "", float64 = 0)
	s2 := Student{Name: "สมหญิง"}
	fmt.Println("s2:", s2)

	// struct literal แบบไล่ค่าตามลำดับ field — สั้นแต่เปราะ:
	// ถ้าสลับลำดับ field ใน type ทีหลัง โค้ดจะผิดเงียบ ๆ โดยไม่ error
	s3 := Student{"สมปอง", 77.5}
	fmt.Println("s3:", s3)

	// zero value ของ struct = struct ที่ทุก field เป็น zero value
	var s4 Student
	fmt.Println("s4 (ยังไม่กรอก):", s4)
}
```

ผลลัพธ์จริง:

```
s1 ทั้งก้อน: {สมชาย 85.5}
ชื่อ: สมชาย
คะแนน: 85.5
หลังแก้คะแนน: 90
s2: {สมหญิง 0}
s3: {สมปอง 77.5}
s4 (ยังไม่กรอก): { 0}
```

แกะโค้ด:

- `type Student struct { ... }` — ประกาศแบบพิมพ์ใหม่ชื่อ `Student` (ตัวพิมพ์ใหญ่ขึ้นต้นเป็นธรรมเนียมของ Go — dev เรียก type ที่ขึ้นต้นตัวใหญ่ = "exported" (เอ็กซ์พอร์ต = ส่งออกใช้ข้าม package ได้) ตอนนี้แค่รู้ว่าตั้งชื่อแบบนี้)
- `Student{Name: "สมชาย", Score: 85.5}` — สร้าง instance แบบ**ระบุชื่อ field** (เรียกว่า struct literal แบบมีชื่อ) — ข้อดี: เรียงสลับกันก็ได้ เพราะบอกชื่อกำกับ
- `s1.Name`, `s1.Score` — เข้าถึง (และแก้) field ทีละช่องด้วย**จุด (dot)** — `.Name` แปลว่า "ช่องชื่อของ s1"
- `Student{Name: "สมหญิง"}` — field ที่ไม่ระบุจะได้ zero value ของชนิดนั้น (`Score` เป็น `0`)
- `Student{"สมปอง", 77.5}` — เขียนแบบ**ไล่ค่าตามลำดับ field** ได้ (เรียกว่า positional) — สั้นกว่าแต่**เปราะ**: ถ้าทีหลังไปสลับลำดับ field ใน `type` โค้ดบรรทัดนี้จะจับคู่ค่าผิดเงียบ ๆ ไม่มี error เตือน — dev งานจริงนิยมแบบระบุชื่อ field มากกว่า
- `var s4 Student` — ประกาศ struct เปล่า ๆ → ทุก field เป็น zero value (`{ 0}` = ชื่อ "" + คะแนน 0)

แผนผังด้านล่างสรุป struct: ฝั่งซ้ายคือแบบพิมพ์ (บอกว่ามีช่องอะไรบ้าง) ฝั่งขวาคือ instance (กรอกค่าแล้ว):

![struct คือแบบพิมพ์ที่รวมช่อง (field) หลายช่องเป็นก้อนเดียว เหมือนแบบฟอร์ม 1 ใบ และซ้อน struct ใน struct ได้](/assets/diagrams/ep06-03-struct-compose.svg)

### struct ซ้อน struct (nested struct)

field ของ struct เป็น struct อีกตัวได้ — เหมือนแบบฟอร์มที่ช่องหนึ่ง "เปิดแล้วเจอแบบฟอร์มย่อยอีกใบ":

```go
package main

import "fmt"

// Address = ที่อยู่ 1 แห่ง
type Address struct {
	Street string
	City   string
}

// Student มี field เป็น struct อีกตัวซ้อนอยู่ข้างใน (nested struct)
type Student struct {
	Name    string
	Score   float64
	Address Address
}

func main() {
	s := Student{
		Name:  "สมชาย",
		Score: 85.5,
		Address: Address{
			Street: "ถนนสุขุมวิท",
			City:   "กรุงเทพฯ",
		},
	}

	// เข้าถึง field ซ้อนสองชั้นด้วยจุดสองชั้น: s.Address.City
	fmt.Println(s.Name, "อยู่", s.Address.City)
	s.Address.City = "เชียงใหม่"
	fmt.Println("ย้ายบ้านแล้ว:", s.Address.City)
}
```

ผลลัพธ์จริง:

```
สมชาย อยู่ กรุงเทพฯ
ย้ายบ้านแล้ว: เชียงใหม่
```

แกะโค้ด: `Address` เป็น struct ตัวหนึ่ง แล้ว `Student` มี field ชื่อ `Address` ที่เป็นชนิด `Address` — เวลาเข้าถึงใช้จุดซ้อนสองชั้น `s.Address.City` ("เปิดกล่อง Student เจอกล่อง Address แล้วค่อยเปิดหา City")

## ประกอบร่าง: ทั้ง 3 ตัวทำงานด้วยกัน

ของจริงของสามตัวนี้คือ**ใช้ด้วยกัน** — มาดูโปรแกรมจัดการรายชื่อนักเรียนที่รวมครบทั้ง slice, map, struct (สร้าง `roster.go`):

โค้ดด้านล่างใช้ `fmt.Printf` กับ "ที่วาง" (verb = เวิร์บ) สามตัว — `%d` (เลขจำนวนเต็ม), `%s` (ข้อความ), `%.2f` (ทศนิยม 2 ตำแหน่ง) — อธิบายละเอียดหลังผลลัพธ์

```go
package main

import "fmt"

// Student = ข้อมูลนักเรียน 1 คน (struct)
type Student struct {
	Name  string
	Score float64
}

// addStudent เพิ่มนักเรียนต่อท้าย slice พร้อมจด "ชื่อ → ตำแหน่ง" ลงใน map index
// แล้วคืน slice ใหม่กลับมา (append อาจย้ายข้อมูลไปที่ array ใหม่)
func addStudent(list []Student, index map[string]int, name string, score float64) ([]Student, map[string]int) {
	_, exists := index[name]
	if exists {
		fmt.Println("ข้าม:", name, "— มีชื่อนี้ในระบบแล้ว")
		return list, index
	}
	if score < 0 {
		fmt.Println("ข้าม:", name, "— คะแนนติดลบไม่ได้")
		return list, index
	}
	index[name] = len(list) // จำตำแหน่ง (index) ของคนนี้ใน slice
	list = append(list, Student{Name: name, Score: score})
	return list, index
}

// findStudent หาคนจากชื่อ — เปิด map index หาตำแหน่ง แล้วไปชี้ที่ slice
// คืน Student เปล่ากับ ok = false เมื่อไม่พบ (ไม่ต้องพึ่ง zero value)
func findStudent(list []Student, index map[string]int, name string) (Student, bool) {
	pos, ok := index[name]
	if !ok {
		return Student{}, false
	}
	return list[pos], true
}

// average คำนวณค่าเฉลี่ยคะแนนทั้งห้อง — ห้องว่างได้ ให้คืน 0 ไม่พัง
func average(list []Student) float64 {
	if len(list) == 0 {
		return 0
	}
	total := 0.0
	for _, s := range list {
		total += s.Score
	}
	return total / float64(len(list)) // float64(...) = แปลง int เป็นทศนิยม — Go ไม่ยอมหารเลขคนละชนิดตรง ๆ
}

// topStudent คืนคนที่ได้คะแนนสูงสุด + ok — ตรวจห้องว่างก่อน
// (จะได้ไม่พังตอน list[0] บน slice ว่าง — เรื่อง panic จะอธิบายในหัวข้อกับดัก)
func topStudent(list []Student) (Student, bool) {
	if len(list) == 0 {
		return Student{}, false
	}
	best := list[0]
	for _, s := range list[1:] {
		if s.Score > best.Score {
			best = s
		}
	}
	return best, true
}

func main() {
	students := []Student{}    // slice ว่าง — จะเก็บ struct Student หลายตัวเรียงกัน
	byName := map[string]int{} // map index — เปิดหาชื่อ → เจอตำแหน่งใน slice ทันที

	// เพิ่มนักเรียนทีละคน (ใช้ตัวแปรเดิมรับค่ากลับ — append อาจได้ slice ใหม่)
	students, byName = addStudent(students, byName, "สมชาย", 85.5)
	students, byName = addStudent(students, byName, "สมหญิง", 92)
	students, byName = addStudent(students, byName, "สมปอง", 78.25)
	students, byName = addStudent(students, byName, "สมปอง", 99)  // ชื่อซ้ำ → ข้าม
	students, byName = addStudent(students, byName, "สมหมาย", -5) // คะแนนติดลบ → ข้าม

	fmt.Println("--- รายชื่อนักเรียน (วนด้วย range) ---")
	for i, s := range students {
		fmt.Printf("%d. %s — %.2f คะแนน\n", i+1, s.Name, s.Score) // i+1: อยากให้เลขเริ่มที่ 1 แต่ index เริ่มที่ 0
	}

	fmt.Println("--- ค้นหาด้วย map index ---")
	s, ok := findStudent(students, byName, "สมหญิง")
	if ok {
		fmt.Printf("เจอ: %s ได้ %.2f\n", s.Name, s.Score)
	}
	_, ok = findStudent(students, byName, "ไม่รู้จัก")
	if !ok {
		fmt.Println("ไม่เจอชื่อ 'ไม่รู้จัก' → ok = false")
	}

	fmt.Println("--- สถิติห้อง ---")
	fmt.Printf("จำนวนนักเรียน: %d คน\n", len(students))
	fmt.Printf("ค่าเฉลี่ยห้อง: %.2f\n", average(students))
	best, ok := topStudent(students)
	if ok {
		fmt.Printf("คะแนนสูงสุด: %s (%.2f)\n", best.Name, best.Score)
	}
}
```

ผลลัพธ์จริง:

```
ข้าม: สมปอง — มีชื่อนี้ในระบบแล้ว
ข้าม: สมหมาย — คะแนนติดลบไม่ได้
--- รายชื่อนักเรียน (วนด้วย range) ---
1. สมชาย — 85.50 คะแนน
2. สมหญิง — 92.00 คะแนน
3. สมปอง — 78.25 คะแนน
--- ค้นหาด้วย map index ---
เจอ: สมหญิง ได้ 92.00
ไม่เจอชื่อ 'ไม่รู้จัก' → ok = false
--- สถิติห้อง ---
จำนวนนักเรียน: 3 คน
ค่าเฉลี่ยห้อง: 85.25
คะแนนสูงสุด: สมหญิง (92.00)
```

โปรแกรมนี้คือตัวอย่าง **"slice + map + struct ทำงานร่วมกัน"** แบบที่ dev ใช้จริง:

หมายเหตุเรื่อง `fmt.Printf` (พริ้นท์-เอฟ = พิมพ์แบบจัดรูปแบบ — รู้จักตั้งแต่ตอน 03–04): เราใส่ "ที่วาง" (verb = เวิร์บ) ไว้ในข้อความ แล้วค่าจะถูกสอดเข้าไปแทนตามลำดับ — `%d` = ที่วางเลขจำนวนเต็ม, `%s` = ที่วางข้อความ, `%.2f` = ที่วางเลขทศนิยม 2 ตำแหน่ง — เช่น `fmt.Printf("%d. %s — %.2f คะแนน\n", i+1, s.Name, s.Score)` แปลว่า "เอาเลขลำดับ, ชื่อ, คะแนน ไปใส่ในที่วางสามช่องตามลำดับ" (`\n` = ขึ้นบรรทัดใหม่)

- **slice** (`students []Student`) — เก็บรายการนักเรียน**เรียงตามลำดับ** (เหมาะกับ "แสดงรายชื่อ", "หาคนที่ N")
- **map** (`byName map[string]int`) — จดว่า "ชื่อนี้อยู่ตำแหน่งที่เท่าไรใน slice" — พออยากหา "สมหญิง" ก็เปิด map ได้ตำแหน่งทันที (เร็ว) แล้วค่อยไปชี้ที่ slice (เรียกว่า **index** (อินเดกซ์ = ดัชนี/สารบัญ) — เหมือนสารบัญท้ายเล่มที่บอก "หัวข้อนี้อยู่หน้าไหน")
- **struct** (`Student`) — ข้อมูลของนักเรียน 1 คนที่รวม ชื่อ + คะแนน เป็นก้อนเดียว — ไม่ต้องแยกเป็น 2 slice คู่ขนาน

สังเกตนิสัย "production-safe" (โพรดักชัน-เซฟ = ปลอดภัยพอใช้ในงานจริง) ที่ซ่อนอยู่ในโค้ด:

- `addStudent` กัน**ชื่อซ้ำ** (ไม่ให้ map ถูกเขียนทับ) และ**คะแนนติดลบ** — กันข้อมูลเสียก่อนเก็บ ไม่ใช่เก็บไปแล้วค่อยเจอปัญหา
- `findStudent` คืน `(Student, bool)` — ไม่ "พึ่ง zero value" เป็นสัญญาณ "ไม่พบ" — เพราะถ้าคืน `Student{}` เปล่า ๆ คนเรียกจะแยกไม่ออกว่า "ไม่พบ" หรือ "พบแต่ชื่อว่าง"
- `average` และ `topStudent` ตรวจ **ห้องว่าง** (`len(list) == 0`) ก่อน — ไม่งั้น `total/0` หรือ `list[0]` บน slice ว่างจะทำให้โปรแกรม panic (แพนิก = โปรแกรมหยุดกะทันหันพร้อมข้อความ error — ดูหัวข้อกับดัก)

## กับดักที่ dev เจอประจำ

### 1. เขียนลง map ที่ยังไม่ `make` → panic

```go
var ages map[string]int // nil map — ประกาศแล้ว แต่ยังไม่ได้ make
ages["สมชาย"] = 30      // เขียนลง nil map → panic!
```

error จริง:

```
panic: assignment to entry in nil map
```

**nil** (นิล = "ไม่มีค่า/ว่างเปล่า") — map ที่ประกาศด้วย `var` อย่างเดียวโดยไม่ `make` จะเป็น nil (ไม่มีตัวตนจริง) อ่านได้ (ได้ zero value) แต่**เขียนไม่ได้** → ต้อง `make(map[string]int)` ก่อน หรือใช้ `map[string]int{}` ตอนประกาศ

### 2. อ่านช่องที่เกิน index → panic

```go
nums := []int{10, 20, 30}
fmt.Println(nums[5]) // ช่อง 5 ไม่มี — slice มีแค่ช่อง 0..2 → panic!
```

error จริง:

```
panic: runtime error: index out of range [5] with length 3
```

slice ยาว 3 มี index 0, 1, 2 เท่านั้น — ใช้ index ต้องไม่เกิน `len(slice)-1`

### 3. เทียบ map ด้วย `==` → compile error

```go
a := map[string]int{"x": 1}
b := map[string]int{"x": 1}
_ = a == b // map เทียบกันด้วย == ไม่ได้ → compile error
```

error จริง:

```
invalid operation: a == b (map can only be compared to nil)
```

map เทียบกันตรง ๆ ด้วย `==` ไม่ได้ (เทียบได้แค่ว่าเป็น nil หรือไม่) — ถ้าอยากรู้ว่า map สองตัวเท่ากัน ต้องวนเทียบคู่ key–value เอง — ตรงนี้ slice ก็มีข้อจำกัดคล้ายกัน (slice เทียบ `==` ไม่ได้เลย ยกเว้น `nil`)

### 4. append หลังตัดช่วง อาจเขียนทับข้อมูลใน slice ต้นฉบับ

```go
s := []int{1, 2, 3, 4}
part := s[:2] // ตัดเอา 2 ช่องแรก

part = append(part, 99) // s มี cap = 4 พอดี → เขียนต่อใน array ก้อนเดิม!
fmt.Println("s:", s)    // สังเกต: ช่องที่ 3 ของ s เปลี่ยนเป็น 99 ด้วย
fmt.Println("part:", part)
```

ผลลัพธ์จริง:

```
s: [1 2 99 4]
part: [1 2 99]
```

นี่คือผลต่อเนื่องของ "slice แชร์ array กัน" — `append` ลง `part` ยังพอมีช่องเหลือใน array ก้อนเดิม (cap เต็ม 4) เลยเขียน `99` ทับช่องที่ 3 ของ `s` ไปด้วย — นี่คือเหตุผลที่โค้ดงานจริงต้องระวังมากเวลา append บน slice ที่ได้มาจากการตัดช่วง

### 5. คัดลอก struct ที่มี slice ข้างใน — แชร์ slice กัน

```go
type Team struct {
	Name    string
	Members []string
}

a := Team{Name: "ทีม A", Members: []string{"สมชาย"}}
b := a // คัดลอก struct ทั้งก้อน (value type = ชนิดที่ copy แล้วแยกก้อน ไม่ได้แชร์ก้อนเดียวกัน)

b.Members[0] = "สมหญิง" // แก้ slice ใน b
fmt.Println("a:", a)    // a.Members เปลี่ยนตาม — เพราะ slice แชร์ข้อมูลกัน
fmt.Println("b:", b)
```

ผลลัพธ์จริง:

```
a: {ทีม A [สมหญิง]}
b: {ทีม A [สมหญิง]}
```

struct เองคัดลอกแบบ "แยกก้อน" (แก้ `b.Name` ไม่กระทบ `a`) แต่ field ที่เป็น slice จะ**แชร์ array ก้อนเดียวกัน** — แก้ผ่าน `b.Members` เห็นผลใน `a.Members` ด้วย — เรื่อง "คัดลอกตื้น vs คัดลอกลึก" (shallow vs deep copy) นี้จะเข้าใจเต็มที่เมื่อเรียน pointer ตอน 14

### 6. ลืมรับค่าคืนจาก append → compile error

```go
temps := []int{31, 33, 29}
append(temps, 40) // ลืมรับค่าคืน → compile ไม่ผ่าน!
```

error จริง:

```
append(temps, 40) (value of type []int) is not used
```

`append` เป็นฟังก์ชันพิเศษที่ Go **บังคับให้ใช้ค่าที่คืน** — เขียนทิ้งเฉย ๆ ไม่ได้ (ต่างจากฟังก์ชันทั่วไปที่เรียกแล้วทิ้งค่าที่คืนได้) — นี่คือตัวช่วยของ Go ที่กันไม่ให้เราลืมว่า append ไม่ได้แก้ slice ตัวเดิม แต่มันคืน slice ก้อนใหม่มาให้เราเก็บเอง

## สรุปตอนที่ 06

- **slice = "รายการ" ที่ขยายได้** — ต่างจาก array ตรงที่ array กำหนดขนาดตายตัวตอนประกาศ (`[3]int`) ส่วน slice ไม่มีตัวเลขในวงเล็บ (`[]int`) — สร้างด้วย `append` (ต่อท้าย) หรือ `make` (จองช่อง) — อ่านความยาว `len()`, ความจุ `cap()`
- **slice ชี้ไปยัง array ข้างหลัง** — ไม่ได้ถือข้อมูลเอง — ตัดช่วงด้วย `s[start:stop]` (เอา start ถึง stop-1) ได้ slice ใหม่ที่**แชร์ array เดิม** แก้ที่หนึ่ง เห็นผลอีกที่ — วนอ่านทุกชิ้นด้วย `for i, v := range s` (`_` ใช้ทิ้งค่าที่ไม่ต้องการ)
- **map = "สมุดค้นหา" key → value** — `make(map[string]int)` หรือ literal — อ่าน/เขียนด้วย `m[key]` — อ่าน key ที่ไม่มี ได้ zero value ไม่พัง แต่**แยกไม่ออกว่า "ไม่มี" หรือ "เป็น 0"** → ใช้ comma-ok (`v, ok := m[key]`) — ลบด้วย `delete(m, key)` — วน `range` ไม่การันตีลำดับ
- **struct = "แบบฟอร์ม" รวม field หลายช่อง** — ประกาศ `type Student struct { ... }` — สร้าง instance ด้วย `Student{Name: ..., Score: ...}` — เข้าถึง/แก้ field ด้วยจุด `.` — field ที่ไม่ระบุได้ zero value — ซ้อน struct ใน struct ได้ (`s.Address.City`)
- **ใช้ด้วยกัน**: slice เก็บ "เรียงตามลำดับ" + map เก็บ "ค้นหาด้วยชื่อ" + struct รวม "ข้อมูลของสิ่งหนึ่ง" — ใช้ map เป็น index ชี้ตำแหน่งใน slice เพื่อค้นหาเร็ว
- **กับดัก**: เขียนลง nil map → panic (ต้อง make ก่อน) · อ่าน index เกิน → panic · map เทียบ `==` ไม่ได้ · append บน slice ที่ตัดมา อาจเขียนทับต้นฉบับ · struct ที่มี field เป็น slice คัดลอกแล้วแชร์ slice กัน
- เบื้องลึก: slice ที่จดแค่ pointer + len + cap คือก้าวแรกสู่การเข้าใจว่า "ข้อมูลอยู่ในหน่วยความจำจริง ๆ ยังไง" — เราจะเจาะเต็มรูปแบบตอน 13–16 (C, pointer, stack/heap) และจะเห็นว่า "slice ชี้ array" คือภาพย่อของ "ตัวชี้" (pointer) ในภาษา C

ตอนนี้คุณมีครบทั้ง 4 เสาหลักของการเขียนโปรแกรมแล้ว: ตัวแปร (03) + การควบคุม (04) + การแบ่งงาน (05) + **การเก็บข้อมูลหลายชิ้น** (ตอนนี้) — ต่อไปเราเปลี่ยนจาก "เขียนโค้ดให้รัน" ไปเป็น "เขียนโปรแกรมที่อยู่รอดในโลกจริง": โปรแกรมที่**อ่าน/เขียนไฟล์** เก็บข้อมูลไว้ได้นาน ๆ รับ argument ตอนสั่งรัน และจัดการ error อย่างเป็นระบบ — ทั้งหมดอยู่ในตอน 07

ระหว่างรอ อย่าลืมทำ mini-project "โปรแกรมคะแนนห้องเรียน" — ตอนเขียนลองสังเกตตัวเองว่า การมี slice + map + struct ทำให้โค้ดสั้นลงและอ่านง่ายขึ้นแค่ไหน เทียบกับตอน 05 ที่ต้องใช้ตัวแปรเดี่ยวหลายสิบตัว — นี่คือจุดที่คุณเริ่ม "คิดแบบ dev" แล้ว: เลือกโครงสร้างข้อมูลให้เหมาะกับงาน ไม่ใช่ใช้ตัวแปรเดี่ยวแก้ปัญหาทุกอย่าง
