# C เบื้องต้น: เทียบกับ Go และ pointer แรกของเรา (ตอนที่ 13) — CS Fundamentals: จาก 0 สู่พื้นฐานที่แท้จริง

> 📅 เขียนเมื่อ: 16 กันยายน 2026
> ⚙️ **เวอร์ชันที่ตรวจสอบ ณ วันเขียน** — *กล่องนี้ข้ามไปก่อนได้เลย ไม่มีผลกับการอ่านเนื้อหาข้างล่าง (กลับมาดูตอนท้ายก็ได้)* ตัวเลขทั้งหมดตรวจจากแหล่งทางการ ไม่ได้ใช้ความจำ:
> - **GCC** (GNU Compiler Collection — ชุด**คอมไพเลอร์**ฟรีที่ใช้กันมากที่สุดบน Linux · คอมไพเลอร์ = ตัวแปลโค้ดที่คนเขียน ให้เป็นโปรแกรมที่เครื่องรันได้) รุ่นเสถียรล่าสุดคือ **GCC 16.2** ประกาศเมื่อ **7 สิงหาคม 2026** — ดูที่ gcc.gnu.org
> - **Clang / LLVM** (คอมไพเลอร์อีกค่ายที่ใช้บน macOS) รุ่นเสถียรล่าสุดคือ **LLVM/Clang 23.1** (รุ่นใหญ่ประจำครึ่งปีหลังของ 2026)
> - **Go** รุ่นเสถียรล่าสุดคือ **Go 1.27** ประกาศเมื่อ **19 สิงหาคม 2026** — ดูที่ go.dev/doc/go1.27
> - **มาตรฐานภาษา C** ปัจจุบันคือ **C23** — GCC ตั้งแต่รุ่น 15 ขึ้นไปใช้ `-std=gnu23` เป็นค่าเริ่มต้น (รุ่นก่อนหน้าใช้ C17) ส่วน GCC 14 ที่ใช้ทดสอบในบทความนี้ยังใช้ `-std=gnu17` เป็นค่าเริ่มต้น จึงระบุ `-std=c17` ตรง ๆ ให้ผลเหมือนกันทุกเครื่อง
> - โค้ดทุกโปรแกรมในตอนนี้ **คอมไพล์และรันจริง** ด้วย `gcc 14.2.0` บน Linux (ARM64, Raspberry Pi) ด้วยคำสั่ง `gcc -std=c17 -Wall -Wextra -Wpedantic` — ไม่มี warning และไม่มีพฤติกรรมไม่นิยาม (undefined behavior = พฤติกรรมที่มาตรฐานไม่รับประกันว่าโปรแกรมจะทำอะไร)

ตอนที่ 12 เราลงไปถึงก้นบึ้งที่สุดแล้ว: เขียน **assembly** (แอสเซมบลี = ภาษาที่เป็นชุดคำสั่งของ CPU แบบอ่านออก) ให้ LC-3 ทำงานได้จริง เห็นว่า `for` กับฟังก์ชัน จริง ๆ แล้วเป็นแค่ "กระโดดกลับ + จำที่กลับ"

แต่การเขียน assembly ให้โปรแกรมใหญ่ ๆ เป็นเรื่องที่มนุษย์ทนไม่ได้ — เราจึงต้องมีภาษาที่ **สูงกว่า assembly แต่ยังต่ำพอให้เราเห็นเครื่อง** ภาษานั้นคือ **C**

ตอนนี้เราจะเขียน C เป็นครั้งแรก และใช้ Go ที่เราเรียนมาแล้วในระยะ 1 เป็น "ไม้บรรทัด" วัดว่า C ให้อะไร และ Go ซ่อนอะไรไว้ให้เรา

## 0. ภาพรวม: จาก assembly → C → Go (บันไดสามขั้น)

![เทียบโครงสร้างโปรแกรมและ syntax ระหว่าง C กับ Go](/assets/diagrams/ep13-02-c-vs-go-syntax.svg)

**ภาพที่ 1** (เราใช้ภาพนี้ก่อนเป็นแผนที่นำทาง เดี๋ยวจะไล่ทีละแถว): งานเดียวกัน — โปรแกรม hello world (โปรแกรมแรกสุดที่ทุกภาษาเริ่มด้วย แค่พิมพ์ข้อความออกจอ), ประกาศตัวแปร, พิมพ์ออกจอ, ใช้ string — เขียนใน C (ซ้าย) กับ Go (ขวา) ต่างกันแค่ไหน

ก่อนลงมือ ขอวางบันไดให้เห็นก่อน — ตารางบันไดนี้จะกลับมาอีกหลายรอบ เราจะไต่ลงทีละขั้น:

| ขั้น | ภาษา | ใครจัดความสะดวกให้ | ใครจัดการหน่วยความจำ |
|---|---|---|---|
| สูง | **Go** | runtime ของ Go (GC, scheduler = ตัวจัดคิวว่าชิ้นงานไหนได้รันต่อ อันไหนต้องรอ · หัวใจของการมี goroutine — เดี๋ยวอธิบายในหัวข้อ 1) | **runtime** ล้างให้อัตโนมัติ (garbage collection) |
| กลาง | **C** | ตัวเราเอง + standard library บาง ๆ (ชุดฟังก์ชันสำเร็จรูปที่ภาษานี้แถมมาให้) | **ตัวเราเอง** (จองเอง คืนเอง) |
| ต่ำสุด | **assembly** | ไม่มีเลย — มีแต่ register (ช่องเก็บข้อมูลที่เร็วที่สุด ซึ่งอยู่ใน CPU — เจอเต็ม ๆ ตอน 11) กับหน่วยความจำดิบ | ตัวเราเอง |

คำถามที่ต้องตอบให้ได้หลังจบตอนนี้: **Go ช่วยเราเรื่องอะไรบ้าง ถ้าถอดมันออกจะเหลืออะไร**

คำตอบสั้น ๆ: เหลือ "C" นั่นแหละ — และนี่คือเหตุผลที่คนที่อยากเข้าใจลึกจริงต้องเรียน C

## 1. ทำไมต้องเรียน C ต่อจาก Go และ assembly

เหตุผลมีสามข้อ และข้อที่สามสำคัญที่สุด

**ข้อ 1: C เป็นภาษาที่ "ของจริง" ใช้กันอยู่ทุกวันนี้**

- **Linux kernel** (แกนกลางของระบบปฏิบัติการที่เครื่อง Raspberry Pi ของเรารันอยู่) เขียนด้วย C เป็นหลัก (มี assembly แทรกในจุดที่ต้องคุม CPU ตรง ๆ)
- **คอมไพเลอร์** จำนวนมาก รวมถึง GCC เองและ CPython (ตัวตีความภาษา Python) เขียนด้วย C/C++
- ของที่เราอาจใช้ทุกวันอย่าง SQLite, Redis, nginx ก็เป็น C
- เวลาของจริงต้องเร็วมากและต้องคุมหน่วยความจำเองได้ — สองอย่างนี้คือจุดแข็งของ C

**ข้อ 2: C คือ "ภาษากลาง" ที่ระบบปฏิบัติการคุยกับโปรแกรมด้วย**

เวลากลุ่มคนทำภาษาต่าง ๆ (Go, Rust, Python) อยากเรียกใช้บริการของระบบ (เปิดไฟล์ อ่าน keyboard ออกจอ) พวกเขาไม่ได้เขียนคุยกับ kernel ใหม่หมด — เขา**เรียกฟังก์ชัน C** ที่ kernel และ libc (C standard library ตัวมาตรฐานของระบบ) เตรียมไว้ ภาษาที่ติดตั้งบนเครื่อง Mac/Linux/WSL เกือบทั้งหมด มี "ประตูหลัง" ที่เป็น C อยู่ (มีการเรียกแบบนี้ว่า **syscall** = การเรียกใช้บริการของ kernel ผ่านฟังก์ชันที่ libc เตรียมไว้ — เรื่องนี้เป็นของตอน 19)

**ข้อ 3: C ทำให้เห็นว่า Go ซ่อนอะไรไว้ให้เรา**

จำบรรยากาศตอนเรียน Go ได้ไหม ตอนนั้นเรามี

- **garbage collector (GC)** — ตัวเก็บขยะที่คอยลบหน่วยความจำที่เราไม่ใช้แล้วให้เอง
- **memory safety** (ความปลอดภัยด้านหน่วยความจำ) — เข้าถึง array เกินขอบเขตไม่ได้ (array = ช่องข้อมูลเรียงติดกัน มีเลข index กำกับ — อธิบายหัวข้อ 3), ใช้ค่าที่ยังไม่กำหนดไม่ได้, แก้ที่อยู่ของหน่วยความจำตรง ๆ ไม่ได้
- **goroutine + runtime** — พอมี `go func()` แล้ว runtime ต้องมีตัวจัดคิวให้

ทั้งหมดนั้น **ไม่ใช่ "ภาษา" — มันคือโปรแกรมใหญ่ที่ Go แถมมาให้** และโปรแกรมนั้นเองก็เขียนด้วย Go + C + assembly อีกที

พอเราเขียน C เราจะถูกถอดของเหล่านี้ออกทีละชิ้น แล้วจะได้ความเข้าใจที่ลึกกว่าเดิม: "ที่ Go ห้ามทำ เพราะอะไร ถ้าทำแล้วจะพังยังไง" — ไม่ใช่แค่รู้ว่า "compiler ห้าม"

## 2. โปรแกรม C แรก: `hello.c`

เรามาเริ่มจากของที่เล็กที่สุดที่รันได้ สร้างไฟล์ชื่อ `hello.c` แล้วพิมพ์ตามนี้

```c
/* hello.c — โครงสร้างโปรแกรม C ที่เล็กที่สุดที่รันได้ */
#include <stdio.h>   /* ดึง "declaration" ของ printf เข้ามา (stdio = standard input/output) */

/* main() คือจุดเริ่มต้นของทุกโปรแกรม C — ระบบจะเรียกฟังก์ชันนี้เป็นอันดับแรก */
int main(void) {
    printf("สวัสดี C\n");      /* printf = "print formatted" พิมพ์ข้อความออกจอ */
    return 0;                  /* คืน 0 = "จบแบบไม่มีปัญหา" ให้ระบบปฏิบัติการ */
}
```

คอมไพล์ (compile = แปลภาษาที่คนเขียนเป็นโปรแกรมที่เครื่องรันได้) แล้วรันด้วยสองคำสั่งนี้

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -o hello hello.c
./hello
```

ผลที่ได้

```
สวัสดี C
```

### อธิบายทีละบรรทัด (เพราะเราสัญญากันไว้ตั้งแต่ตอน 1 ว่าไม่ข้ามศัพท์)

- `#include <stdio.h>` — บรรทัดนี้ขึ้นต้นด้วย `#` แปลว่าเป็นคำสั่งให้ **preprocessor** (ตัวจัดการก่อนคอมไพล์ แปลว่า "ประมวลผลล่วงหน้า") ทำงาน ไม่ใช่คำสั่งของภาษา C เอง หน้าที่ของมันวันนี้คือ "เอา **declaration** (คำประกาศหน้าตาฟังก์ชัน — บอกว่ารับอะไรเข้ามา คืนอะไรออกไป) ของ `printf` จากไฟล์ `stdio.h` ที่ระบบมีให้ มาแปะตรงนี้" — ถ้าลืมบรรทัดนี้ compiler จะไม่รู้จัก `printf` เลย: **GCC 14 ขึ้นไปถือเป็น error ทันที** (`implicit declaration of function 'printf'`) ส่วน GCC รุ่นเก่ากว่าถึงแค่เตือนแล้วเดาชนิดให้
- `int main(void)` — `main` คือชื่อฟังก์ชันที่ระบบจะเรียกเป็นอันดับแรกเสมอ · `int` ข้างหน้าคือ **ชนิดของค่าที่จะคืนกลับ** (แปลว่า main จะคืนจำนวนเต็มหนึ่งตัว) · `(void)` แปลว่า "ไม่รับ argument ใด ๆ" (argument = ค่าที่ส่งเข้าไปให้ฟังก์ชัน)
- `printf("สวัสดี C\n");` — `printf` ย่อจาก "print formatted" = พิมพ์ตามรูปแบบ · `\n` คืออักขระพิเศษแทนการขึ้นบรรทัดใหม่ (เวลาพิมพ์จริงจะไม่เห็น `\` กับ `n` เห็นแค่การขึ้นบรรทัด)
- `return 0;` — คืน `0` ให้ระบบปฏิบัติการ หมายถึง "โปรแกรมจบแบบไม่มีปัญหา" เลขอื่น (เช่น `1`) หมายถึง "จบแบบมีปัญหา" (เราเช็คได้ด้วยคำสั่ง `echo $?` หลังรันโปรแกรม — `$?` คือ "รหัสจบงานของโปรแกรมที่เพิ่งรัน" ที่ shell เก็บไว้ให้ ค่าที่ได้คือเลขนี้)
- ทุกคำสั่งจบด้วย `;` (semicolon) — **นี่คือจุดที่มือใหม่ลืมบ่อยที่สุด** Go ตัด `;` ให้เองอัตโนมัติ แต่ C ไม่ — ลืมตัวเดียวโปรแกรมไม่ผ่าน

### เทียบกับ Go ที่เราเขียนในตอน 3

```go
package main

import "fmt"

func main() {
	fmt.Println("สวัสดี Go")
}
```

| เรื่อง | C | Go |
|---|---|---|
| ประกาศว่า "นี่คือโปรแกรม" | ไม่ต้องมี — ไฟล์ `.c` ก็คือโปรแกรม | ต้องมี `package main` |
| ดึงความสามารถจากที่อื่น | `#include <stdio.h>` (ทำโดย preprocessor ก่อนคอมไพล์) | `import "fmt"` (เป็นส่วนหนึ่งของภาษา) |
| จุดเริ่มต้น | `int main(void)` | `func main()` |
| พิมพ์ออกจอ | `printf("...\n")` — ต้องใส่ `\n` เอง | `fmt.Println(...)` — ขึ้นบรรทัดให้เอง |
| บอกระบบว่าจบดี | `return 0;` | ไม่ต้อง (แต่ต้องเป็น `package main` และมี `func main`) |
| ตัวคั่นคำสั่ง | `;` ต้องใส่เอง | ใส่ก็ได้ ไม่ใส่ก็ได้ (gofmt จัดให้) |

สังเกตความต่างเชิงปรัชญาข้อแรก: **Go ใส่ "ของที่จำเป็น" มาให้ครบตั้งแต่ต้น** (`package`, `import`, การจัดรูปแบบ) ส่วน **C ให้โครงที่เล็กที่สุด แล้วปล่อยให้เราเติมเอง** — ทั้งสองแบบมีข้อดีข้อเสีย C เล็กและตรง แต่ก็พังง่ายกว่าเยอะ

## 3. ชนิดข้อมูลของ C: มีอะไร และ **ไม่มี** อะไร

ก่อนลงมือ ขอปูคำ 4 อย่างที่จะโผล่ในโค้ดข้างล่างก่อน (จะได้ไม่สะดุด):

- **ไบต์** (byte) = หน่วยนับที่เล็กที่สุดของหน่วยความจำ — 1 ไบต์ = 8 บิต (เรารู้จักบิตจากตอน 8 แล้ว)
- **array** (อาเรย์) = ช่องข้อมูลเรียงติดกันหลายช่อง แต่ละช่องมีหมายเลขกำกับ (index) เริ่มนับจาก 0 — เราเจอ slice ของ Go ในตอน 6 (slice คือ array ที่ "ยืดได้")
- **ASCII** (แอสกี) = รหัสมาตรฐานที่กำหนดให้ตัวอักษรแต่ละตัวมีเลขประจำตัว — `'A'` = 65, `'a'` = 97, `'0'` = 48 (เราเจอในตอน 8 และ 12 ตอนใช้ `x30` แปลงเลขเป็นตัวอักษร)
- **`%` ใน `printf`** = ช่องสำหรับวางค่า แต่ละตัวระบุใช้กับคนละชนิด

| ตัวระบุ | ใช้กับ | ตัวอย่าง |
|---|---|---|
| `%d` | จำนวนเต็ม (`int`) | `printf("%d", 42)` |
| `%f` / `%.2f` | ทศนิยม (`float`/`double`) — `%.2f` = เอาทศนิยม 2 ตำแหน่ง | `printf("%.1f", 3.5)` |
| `%c` | ตัวอักษร 1 ตัว (`char`) | `printf("%c", 'A')` |
| `%s` | ข้อความ (`char[]`) | `printf("%s", name)` |
| `%zu` | ขนาดเป็นไบต์ (`sizeof` คืนค่าเป็นชนิด `size_t` จึงต้องใช้ตัวนี้ ไม่ใช่ `%d`) | `printf("%zu", sizeof(int))` |
| `%p` | ที่อยู่ (address) — เจอเต็ม ๆ ในหัวข้อ 6 | `printf("%p", (void *)&x)` |

เขียนไฟล์ `types.c` แบบนี้

```c
/* types.c — ดูชนิดข้อมูลพื้นฐานของ C และขนาดจริงในหน่วยความจำ (ไบต์) */
#include <stdio.h>

int main(void) {
    int    i = 42;                 /* จำนวนเต็ม */
    float  f = 3.5f;               /* ทศนิยมความละเอียดต่ำ (ต้องมี f ต่อท้าย ไม่งั้นเป็น double) */
    double d = 3.141592653589793;  /* ทศนิยมความละเอียดสูง */
    char   c = 'A';                /* ตัวอักษร 1 ตัว (จริง ๆ คือเลข 1 ไบต์ = 65 ตามรหัส ASCII) */
    char   name[] = "Havebit";     /* C ไม่มี string ในตัว: นี่คือ array ของ char ปิดท้ายด้วย '\0' */

    printf("int    i = %d        sizeof = %zu ไบต์\n", i, sizeof i);
    printf("float  f = %.1f       sizeof = %zu ไบต์\n", f, sizeof f);
    printf("double d = %.6f     sizeof = %zu ไบต์\n", d, sizeof d);
    printf("char   c = %c (%d)    sizeof = %zu ไบต์\n", c, c, sizeof c);
    printf("char   name[] = %s   sizeof = %zu ไบต์ (7 ตัวอักษร + '\\0' 1 ตัว)\n",
           name, sizeof name);

    /* ยืนยันว่า "string" ของ C จบด้วยไบต์ 0 จริง ๆ */
    printf("name[7] = %d คือไบต์ '\\0' ที่บอกว่า 'ข้อความจบตรงนี้'\n", name[7]);

    /* C ไม่มี bool ในตัว: ธรรมเนียมเดิมคือใช้ int โดย 0 = เท็จ, ค่าอื่น = จริง */
    int is_ready = 1;
    if (is_ready) {
        printf("is_ready = %d -> ถือว่า 'จริง' (0 เท่านั้นที่ถือว่าเท็จ)\n", is_ready);
    } else {
        printf("ไม่จริง\n");
    }

    return 0;
}
```

รันแล้วได้ผลแบบนี้ (ผลจริงจากการรันบนเครื่อง ARM64 ของเรา)

```
int    i = 42        sizeof = 4 ไบต์
float  f = 3.5       sizeof = 4 ไบต์
double d = 3.141593     sizeof = 8 ไบต์
char   c = A (65)    sizeof = 1 ไบต์
char   name[] = Havebit   sizeof = 8 ไบต์ (7 ตัวอักษร + '\0' 1 ตัว)
name[7] = 0 คือไบต์ '\0' ที่บอกว่า 'ข้อความจบตรงนี้'
is_ready = 1 -> ถือว่า 'จริง' (0 เท่านั้นที่ถือว่าเท็จ)
```

### อ่าน `types.c` ทีละบล็อก (ให้ละเอียดเท่าที่เราอ่าน `hello.c` กันมาแล้ว)

- `int i = 42;` · `float f = 3.5f;` · `double d = 3.1415...;` — สามตัวนี้คือ "ตัวเลข" เหมือนกัน ต่างกันที่ความกว้างและความละเอียด: `int` เก็บจำนวนเต็ม, `float` เก็บทศนิยมแบบประหยัด (4 ไบต์), `double` เก็บทศนิยมละเอียดกว่า (8 ไบต์)
- `char c = 'A';` — ตัวอักษร 1 ตัว สังเกตว่าใช้ **เครื่องหมายคำเดี่ยว** `'A'` ไม่ใช่ `"A"` (อย่างหลังคือข้อความยาว 2 ไบต์) ข้างในจริง ๆ มันเก็บเลข 65
- `char name[] = "Havebit";` — `[]` หลังชื่อ ความหมายคือ "array ที่ไม่บอกความยาว" compiler จะนับให้เอง: ตัวอักษร 7 ตัว + ตัวปิดท้ายอีก 1 = 8 ช่อง
- `printf("... sizeof = %zu ...", sizeof i)` — `sizeof i` แปลว่า "ถามขนาดของ `i` เป็นไบต์" (กับตัวแปร ใส่วงเล็บหรือไม่ก็ได้) แล้ว `%zu` เป็นช่องสำหรับวางตัวเลขที่ `sizeof` คืนมา — `sizeof` คืนค่าเป็นชนิด `size_t` จึงต้องคู่กับ `%zu`
- `printf("... %s ...", name)` — ส่ง **ชื่อ array** เข้า `%s` ได้เลย (ไม่ต้องใส่ `&`) เพราะชื่อ array ก็คือ address ของช่องแรกนั่นเอง — เรื่องนี้จะชัดในหัวข้อ 6
- `printf("name[7] = %d ...", name[7])` — `name[7]` = ช่องที่ 8 (นับจาก 0) ซึ่งเป็นช่องที่เก็บตัวปิดท้ายข้อความ พิมพ์ด้วย `%d` เลยเห็นเป็นเลข `0` — นี่คือหลักฐานว่า "ข้อความของ C" มีศูนย์ซ่อนอยู่ท้ายจริง ๆ
- `int is_ready = 1;` + `if (is_ready)` — C ไม่มี `bool` ในตัว จึงใช้ `int` แทน: `0` = เท็จ, ทุกอย่างที่ไม่ใช่ `0` = จริง

### 3.1 `sizeof` กับความจริงที่ว่า "int ไม่ได้กว้างเท่ากันทุกเครื่อง"

`sizeof x` = คำสั่งถามว่า "ตัวแปรนี้กินที่กี่ไบต์" (หน่วยเป็นไบต์ — เราปูความหมายของไบต์ไว้ด้านบนแล้ว)

จุดที่ต้องจำให้ขึ้นใจ: **ขนาดของ `int` ขึ้นกับเครื่องและระบบปฏิบัติการ** ไม่ได้ตายตัวตามมาตรฐาน C:

- บน ARM64 Linux (เครื่อง Raspberry Pi ของเรา): `int` = 4 ไบต์ · `double` = 8 ไบต์ · pointer = 8 ไบต์ (pointer = ตัวแปรที่เก็บ address ของข้อมูล — เจอเต็ม ๆ หัวข้อ 6)
- บน Arduino (ชิป 8 บิต): `int` = 2 ไบต์

นี่คือเหตุผลที่ของจริงใน C มักใช้ชนิดที่ระบุขนาดชัดเจนจาก `<stdint.h>` เช่น `int32_t`, `uint64_t` (u = unsigned = ไม่มีเครื่องหมายลบ) — พอเขียนโปรแกรมข้ามเครื่องจะไม่พังเพราะ `int` เปลี่ยนขนาด

Go ไม่มีปัญหาแบบนี้: มาตรฐานของ Go กำหนดให้ `int32` = 4 ไบต์, `int64` = 8 ไบต์ **แน่นอนทุกแพลตฟอร์ม** (ส่วน `int` เฉย ๆ ของ Go ก็ยังขึ้นกับสถาปัตยกรรม แต่เราหลีกเลี่ยงได้) — นี่คือตัวอย่างว่า Go "ปิดรูรั่ว" ของ C ไปแล้วกี่รู

### 3.2 C ไม่มี `string` ในตัว

นี่คือจุดต่างที่คนเขียน Go ช็อกมากที่สุดตอนมาเขียน C

ใน Go เราเขียน `s := "Havebit"` แล้วได้ค่า `string` — ความยาวเท่าไรก็ได้ มี `len(s)`, `s[0]`, `s + s2` ให้ใช้ (จำได้จากตอน 3 และ 6)

ใน C **ไม่มีชนิด `string`** สิ่งที่ C มีคือ **array ของ `char` ที่ปิดท้ายด้วยไบต์ค่าศูนย์ `'\0'`** — พิมพ์ว่า `char name[] = "Havebit";` แล้ว compiler จะสร้างช่อง 8 ช่อง: 7 ช่องสำหรับตัวอักษร + 1 ช่องสำหรับ `'\0'` (ไบต์ 0 ซึ่งในผลลัพธ์ข้างบนพิมพ์ออกมาได้ `0` พอดี — สังเกตบรรทัด `name[7] = 0`)

เวลาพิมพ์ด้วย `%s` ตัว `printf` จะ **ไล่อ่านไปเรื่อย ๆ จนกว่าจะเจอไบต์ `'\0'`** แล้วหยุด — ไม่มีใครบอกมันว่า "สตริงยาว 7" มันหา "ที่จบ" ให้เองด้วยศูนย์ตัวนี้ และนี่คือที่มาของทั้งความเก่งและหายนะของ C: ถ้าลืมใส่ `'\0'` หรือเขียนทับมัน `printf` จะอ่านเลยไปเรื่อย ๆ จนกว่าจะเจอศูนย์สักตัว — เราเรียกอาการนี้ว่า **buffer over-read** และมันคือช่องโหว่ความปลอดภัยระดับตำนาน (เป็นของตอน 16)

เรื่องสุดท้ายที่โค้ดนี้สอน (และเป็นคำถามที่มือใหม่ถามบ่อยที่สุด): **`float` ต้องมี `f` ต่อท้าย**

- ค่า `3.5` เปล่า ๆ ในภาษา C มีชนิดเป็น `double` ไม่ใช่ `float`
- ถ้าไม่ใส่ `f` โปรแกรม **ยังทำงานได้** — compiler จะแปลง `double` เป็น `float` ให้แบบเงียบ ๆ ไม่มี warning
- ถ้าอยากจะให้ compiler เตือนเรื่องนี้ ต้องเปิดธงเพิ่มเองคือ `-Wfloat-conversion` (ไม่มีอยู่ใน `-Wall -Wextra`) — และเมื่อเปิดแล้ว GCC จะเตือน **เฉพาะกรณีที่ค่ามาจากตัวแปร** เช่น `double d = 3.5; float f = d;` (เตือนว่า "แปลงแล้วค่าอาจเปลี่ยน") ส่วนค่าคงที่อย่าง `float f = 3.5;` นั้น GCC ปล่อยผ่านไม่เตือน แม้เปิดธงนี้แล้วก็ตาม
- ฉะนั้นในตอนแรก ๆ ให้ใส่ `f` ทุกครั้งที่ใช้ `float` เป็นนิสัยไว้ก่อน แล้วเราจะไม่ต้องกลับมาคิดเรื่องนี้เลย

### 3.3 C ไม่มี `bool` — จนกระทั่งมันมี (เรื่องนี้ต้องเล่าให้ละเอียด)

ใน Go เราเขียน `ok := true` แล้วได้ `bool` ตรง ๆ (ตอน 4) — ใน C เลข `0` คือ "เท็จ" และ **ทุกอย่างที่ไม่ใช่ 0** คือ "จริง" ฉะนั้น

```c
int is_ready = 1;
if (is_ready) { /* เข้าทางนี้ */ }
```

ประวัติของเรื่องนี้สั้น ๆ (และเป็นบทเรียนเรื่อง "ภาษาก็วิวัฒนาการได้"):

- สมัยแรก ๆ ของ C **ไม่มี `bool`** คนเขียนจึงใช้ `int` แทน และตั้งค่าคงที่เองด้วย `#define TRUE 1`
- **C99** (มาตรฐานปี 1999) เพิ่มไฟล์ `<stdbool.h>` — พอ `#include <stdbool.h>` แล้วก็เขียน `bool b = true;` ได้ แต่ลึก ๆ มันคือ **macro** (ข้อความที่ถูกแทนที่ก่อนคอมไพล์) ที่แปลงคำว่า `bool` เป็น `_Bool` ตัวจริง — คือเป็น "ของที่แปะไว้ให้" ไม่ใช่คำสงวนของภาษา
- **C23** (มาตรฐานปัจจุบัน) ยกระดับ `bool`, `true`, `false` เป็น **คำสงวนของภาษา** เหมือน `int` เต็มตัว — **ไม่ต้อง** `#include <stdbool.h>` อีกต่อไป

เราพิสูจน์ข้อนี้กับตาด้วยการทดลองเล็ก ๆ — โปรแกรมที่ประกาศ `bool b = true;` **โดยไม่** include `<stdbool.h>` (แต่ยังต้องมี `#include <stdio.h>` เพราะใช้ `printf` — โปรแกรมเต็มอยู่ในไฟล์ `course/code/ep13/booltest.c`)

```bash
# ด้วยมาตรฐานเก่า (C17) — พัง
$ gcc -std=c17 -o booltest booltest.c
booltest.c:2:17: error: unknown type name 'bool'

# ด้วยมาตรฐานใหม่ (C23) — ผ่าน
$ gcc -std=c23 -o booltest booltest.c && ./booltest
1
```

นี่คือความต่างแบบเดียวกับตอนที่ Go เปลี่ยนเวอร์ชัน: **ภาษาที่มีอายุ 50 ปี ยังเพิ่มของใหม่ได้** และนี่คือเหตุผลที่เราต้องระบุ `-std=` ให้ชัดเจนเวลาสอนหรือเวลาเขียนโปรแกรมของจริง เพราะ "C" ที่คนอื่นพูดถึง อาจหมายถึงมาตรฐานปี 1989, 1999, 2011 หรือ 2023 ก็ได้

### 3.4 ตารางเทียบชนิดข้อมูล C ↔ Go

| งาน | C | Go | หมายเหตุ |
|---|---|---|---|
| จำนวนเต็ม | `int` (4 ไบต์บนเครื่องเรา) | `int` / `int64` / `int32` | C ไม่รับประกันขนาด, Go รับประกัน |
| จำนวนเต็มไม่มีลบ | `unsigned int` | `uint` / `uint32` | C ต้องมีคำว่า `unsigned` |
| ทศนิยม | `float` (4), `double` (8) | `float32`, `float64` | ชื่อคล้าย แต่ Go บอกความกว้างในชื่อ |
| ตัวอักษร | `char` (1 ไบต์, ค่าคือเลข) | `byte` (คือ `uint8`), `rune` (ตัวอักษร 1 ตัวตามมาตรฐาน Unicode — Unicode = มาตรฐานที่กำหนดเลขประจำตัวให้ตัวอักษรทุกภาษาทั่วโลก รวมทั้งไทย · Go เก็บ `rune` เป็นเลข `int32`) | `char` ที่จริงคือ "เลขตัวเล็ก ๆ" |
| ข้อความ | **ไม่มี** → `char[]` + `'\0'` | `string` (กว้างเท่าไรก็ได้) | ต่างกันมากที่สุดในตารางนี้ |
| ความจริง/เท็จ | `int` หรือ `bool` (C99+) | `bool` | C ใช้ 0/ไม่ใช่ 0 ได้เสมอ |
| ที่อยู่ของข้อมูล | `int *`, `char *` … | `*int`, `*Point` … | ทั้งคู่มี — เดี๋ยวเราลงลึกในหัวข้อ 6 |

## 4. ตัวแปรและการประกาศ: ลำดับคำต่างกัน

C กับ Go ประกาศตัวแปรด้วยปรัชญาต่างกันชัด ๆ

```c
int x = 5;        /* C: บอกชนิดก่อน แล้วค่อยบอกชื่อ */
double price = 99.5;
```

```go
x := 5            // Go: ให้ compiler เดาชนิดให้ ง่ายสุด
var price float64 = 99.5  // หรือเขียนเต็มก็ได้ (แบบนี้ดูคล้าย C)
```

อ่านเทียบกันให้เห็นโครง:

| C | Go | ความหมาย |
|---|---|---|
| `int x = 5;` | `var x int = 5` | บอกชนิดชัดเจน กำหนดค่าเริ่มต้น |
| `int y;` | `var y int` | ประกาศเปล่า ๆ (ดูกับดักด้านล่าง!) |
| — (ไม่มี) | `z := 7` | Go เดาชนิดให้จากค่าที่ให้ — C **ไม่มี** ของแบบนี้ |

**กับดักที่ 1 — C ให้ค่าขยะกับตัวแปรที่ไม่ได้กำหนดค่า**

```c
int y;      /* ไม่ได้กำหนดค่า */
printf("%d\n", y);   /* พิมพ์อะไรก็ได้ — อาจเป็น 0 หรือค่าใดก็ได้ (ตามมาตรฐานคือพฤติกรรมไม่นิยาม) */
```

ใน Go `var y int` ได้ `0` ทันที (เรารู้จักในชื่อ zero value) แต่ใน C ตัวแปรที่ประกาศเปล่าจะได้ **ค่าอะไรก็ได้ที่บังคับอยู่ในช่องหน่วยความจำนั้น** — มันอาจบังเอิญเป็น `0` (แล้วโปรแกรม "ดูเหมือนถูก") หรือเป็นเลขอะไรก็ได้ และตามมาตรฐานภาษาแล้วการอ่านค่านี้คือ **พฤติกรรมไม่นิยาม** — โปรแกรมอาจทำงานถูก 100 รอบแล้วพังรอบที่ 101 (เราเรียกค่านี้ว่า garbage value = ค่าขยะ)

ข่าวดีคือ **`-Wall` ที่เราใส่ทุกครั้งจะเตือนตัวนี้ให้เอง** — `warning: 'y' is used uninitialized` แต่ warning ไม่ใช่ error: โปรแกรมยังคอมไพล์ผ่านและรันได้ นี่คือเหตุผลว่าทำไม "โค้ดของเราต้องไม่มี warning" ถึงเป็นมาตรฐานขั้นต่ำ

**นิสัยที่ต้องสร้างตั้งแต่วันนี้: ประกาศตัวแปรใน C ทุกครั้ง ให้กำหนดค่าเริ่มต้นทุกครั้ง** (`int y = 0;`) นี่ไม่ใช่ความ OCD — เป็นการตัดความไม่แน่นอนออกจากโปรแกรม ซึ่งเป็นพื้นฐานของ "โค้ดที่เชื่อถือได้" ที่เราจะพูดถึงตลอดคอร์สนี้

**กับดักที่ 2 — `const` ของ C อ่อนกว่า `const` ของ Go** — C มีคำว่า `const` (`const int n = 3;`) แต่ความหมายของมันคือ "สัญญาว่าจะไม่แก้ผ่านชื่อนี้" ซึ่ง compiler ตรวจให้เพียงบางกรณี ไม่แข็งแรงเท่าของ Go ที่ห้ามแก้จริง ๆ ถ้าต้องการค่าคงที่แบบ "แทนลงไปตรง ๆ ก่อนคอมไพล์" ธรรมเนียม C คือใช้ `#define`

```c
#define MAX_SCORE 100   /* แทนข้อความตรง ๆ ก่อนคอมไพล์ ไม่มีชนิดข้อมูล */
```

เทียบกับ Go ที่ใช้ `const maxScore = 100` — ของ Go มีชนิดกำกับและตรวจให้เข้มกว่า

## 5. การควบคุม: `if` / `else` / `for` ใน C

จากตัวแปรกับค่าคงที่ในหัวข้อ 4 มาต่อที่การตัดสินใจ — C เขียน `if`/`for` หน้าตาเหมือน Go แทบทุกตัวอักษร แต่มีกับดักคนละชุด (และกับดักส่วนใหญ่มาจากเรื่องเดียว: C ไม่มีชนิดให้ compiler บังคับ)

เขียนไฟล์ `loop_control.c`

```c
/* loop_control.c — if/else และ for ใน C (ใช้บวกเลข 1 ถึง n) */
#include <stdio.h>

int main(void) {
    int n = 5;
    int sum = 0;

    /* for ใน C มี 3 ช่องคั่นด้วย ';' : เริ่มต้น ; เงื่อนไข ; ทำหลังจบรอบ */
    for (int i = 1; i <= n; i++) {
        sum += i;                  /* บวกสะสม i เข้า sum (แปลว่า sum = sum + i) */
    }
    printf("ผลบวก 1..%d = %d\n", n, sum);

    /* if / else if / else — C ไม่มี pattern matching มีแค่การเทียบเงื่อนไข */
    if (sum > 15) {
        printf("sum > 15\n");
    } else if (sum == 15) {
        printf("sum == 15 พอดี\n");
    } else {
        printf("sum < 15\n");
    }

    /* ทางเลือกอื่นของ loop: while ตรวจเงื่อนไขก่อนเข้าทำงาน (0 รอบก็ได้) */
    int countdown = n;
    while (countdown > 0) {
        printf("%d ", countdown);
        countdown--;               /* ลดลง 1 (ห้ามลืม! ไม่งั้นวนไม่จบ) */
    }
    printf("\n");
    return 0;
}
```

รันแล้วได้

```
ผลบวก 1..5 = 15
sum == 15 พอดี
5 4 3 2 1 
```

โครง `if` ใน C เหมือน Go เป๊ะ — `if (เงื่อนไข) { ... } else if ... else ...` ต่างกันแค่จุดเล็ก ๆ ที่ควรรู้:

1. **เงื่อนไขต้องเป็นค่าที่ตีความได้ว่า "จริง/เท็จ"** — ทั้งสองภาษาบังคับเรื่องนี้ แต่บังคับคนละแบบ: Go บังคับว่าเงื่อนไขต้องมีชนิดเป็น `bool` แท้ ๆ (`if 1 { }` เป็น error) ส่วน C ยอมรับจำนวนเต็ม (0 = เท็จ, ที่เหลือ = จริง) จึงเขียน `if (is_ready)` ที่ `is_ready` เป็น `int` ได้สบาย — เป็นผลโดยตรงจากเรื่อง "C ไม่มี bool" ในหัวข้อ 3.3 คือ C ไม่มีชนิดให้บังคับ จึงใช้วิธี "ตีความเลข 0/ไม่ใช่ 0" แทน
2. **C ไม่ต้องมีวงเล็บปีกกาก็ได้** เมื่อมีคำสั่งเดียว
   ```c
   if (sum > 15)
       printf("มากกว่า\n");   /* ทำงานเฉพาะบรรทัดนี้ */
   ```
   แต่ **อย่าทำ** — มือใหม่เผลอเพิ่มบรรทัดที่สองแล้วเข้าใจผิดว่ามันอยู่ในเงื่อนไขด้วย นี่เป็นบั๊กคลาสสิกของ C (และเป็นเหตุผลหนึ่งที่ Go บังคับ `{` ทุกกรณี)
3. **`for` ใน C เป็นแบบ "นับรอบด้วยมือ"** — โครง `for (เริ่มต้น ; เงื่อนไข ; ทำหลังจบรอบ)` และเมื่อเทียบกับ Go ที่เราใช้มา จะเห็นว่า:
   - `for (int i = 0; i < n; i++)` ในภาษา C = `for i := 0; i < n; i++` ใน Go (หน้าตาเดียวกันเลย!)
   - **C ไม่มี `for range`** — Go มี `for i, v := range items` ที่ไล่ทุกชิ้นใน slice ให้ (ตอน 6) ใน C ต้องเขียน `for (int i = 0; i < n; i++)` เอง แล้วเข้าถึงด้วย `items[i]` — ไม่มีการนับให้ ไม่มีตัวช่วยเรื่องขอบเขตให้ (ถ้าจำนวนรอบผิด => ออกนอก array => เรื่องใหญ่ เดี๋ยวเจอในหัวข้อ 7)
4. **C มี `do { } while (เงื่อนไข);` แต่ Go ไม่มี** — `do-while` ทำงานอย่างน้อย 1 รอบก่อนเช็คเงื่อนไข (Go ต้องใช้ `for { ...; if !cond { break } }` เขียนเอง)
5. **`switch` มีทั้งคู่ แต่พฤติกรรมต่างกัน** — C จะ "ไหลตก" ไปทำ case ถัดไปต่อทันทีถ้าไม่เขียน `break` (`break` = คำสั่ง "ออกจาก case นี้เดี๋ยวนี้" · ไม่ใส่ = ไหลต่อ เรียกว่า fallthrough ซึ่งเป็นค่าเริ่มต้นของ C) ส่วน Go **หยุดให้เอง** และถ้าอยากให้ไหลต่อต้องเขียน `fallthrough` เอง — เป็นอีกตัวอย่างของแนวคิดเดียวกัน: **Go เปลี่ยนค่าเริ่มต้นให้เป็นแบบที่ปลอดภัยกว่า**

## 6. pointer — จุดเชื่อมกับทุกอย่างที่เราเรียนมา

ถึงส่วนสำคัญที่สุดของตอนนี้แล้ว

![ตัวแปร x อยู่ที่ address หนึ่งในหน่วยความจำ และ pointer p ชี้ไปที่ address ของมัน](/assets/diagrams/ep13-01-memory-pointer-address.svg)

**ภาพที่ 2:** ด้านซ้ายคือตัวแปร `p` ซึ่งเก็บค่าตัวเลข `0x7ffd1234cf9c` — ด้านขวาคือหน่วยความจำจริงที่มีช่องเรียงกัน แต่ละช่องมี "เลขที่ช่อง" (address) และช่องที่มีชื่อ `x` ก็คือช่องที่ `p` ชี้ออกไปหาพอดี

### 6.1 "address" ไม่ใช่เรื่องใหม่สำหรับเราเลย

ย้อนไปสามตอนที่ผ่านมา — เราอธิบาย RAM ว่าเป็นตู้ล็อกเกอร์ที่มีเลขช่องกำกับ และตอนนั้นเราพูดถึงคำเหล่านี้ไปแล้ว (แยกตามตอนที่สอน จะได้กลับไปทวนถูกที่):

- **ตอน 10 (flip-flop → RAM):** **address** = เลขที่ช่องในหน่วยความจำ — แนวคิด "ตู้ล็อกเกอร์ที่มีเลขช่อง"
- **ตอน 11 (CPU):** **MAR** (Memory Address Register) = register ที่ CPU ใส่ "เลขช่อง" ที่จะเข้าถึงลงไป · **PC** (Program Counter) = register ที่เก็บ address ของคำสั่งถัดไป
- **ตอน 12 (assembly LC-3):** คำสั่ง `LD R3, LIMIT` แปลว่า "ไปอ่านช่องที่อยู่ที่ป้ายชื่อ `LIMIT` แล้วใส่ค่าลง R3" — นี่คือการเข้าถึงด้วย address ตรง ๆ

พูดอีกอย่าง: **เรารู้เรื่อง address มาตั้งแต่ตอน 10–12 แล้ว — แต่รู้ในมุมของ CPU** ตอนนี้เราจะมาเรียนมุมของ "คนเขียนโปรแกรม": ถ้าอยากเก็บที่อยู่ไว้ในมือตัวเอง จะเก็บยังไง?

คำตอบคือ **pointer**

> **คำศัพท์: pointer** (พอยน์เตอร์, ตัวชี้) = ตัวแปรที่ **เก็บ address ของข้อมูล** ไม่ได้เก็บตัวข้อมูล — เปรียบเทียบให้เห็นภาพ: ถ้าค่าของ `x` เป็น "บ้านหลังหนึ่ง" ตัว `&x` ไม่ใช่บ้านหลังนั้น แต่เป็น **บ้านเลขที่** ของมัน — เอาไปเขียนใส่กระดาษได้ ยื่นให้คนอื่นได้ และคนถือกระดาษนั้นก็ไปหาบ้านหลังนั้นได้
> **คำศัพท์: dereference** (ดีเรฟเฟอเรนซ์) = การ "เดินตามที่อยู่" ไปเอาค่าจริง ๆ ที่อยู่ตรงนั้น — กระดาษที่จดบ้านเลขที่ คือ pointer; การเอาเลขนั้นไปหาบ้านจริง ๆ แล้วเปิดประตูเข้าไป คือ dereference

### 6.2 สองเครื่องหมายที่ต้องรู้จัก: `&` และ `*`

ในภาษา C มีเครื่องหมายสองตัวที่ทุกคนสับสนตอนเริ่ม (ต้องยอมรับว่ามันสับสนจริง — ขอค่อย ๆ แกะ)

| เครื่องหมาย | ชื่ออ่าน | ทำอะไร | ตัวอย่าง |
|---|---|---|---|
| `&` | "address-of" (แอมเพอร์แซนด์) | ขอ **address** ของตัวแปร | `&x` ได้ค่าเป็น "เลขที่ช่อง" ของ `x` |
| `*` | "dereference" หรือ "star" | เดินตาม address ไป **อ่าน/เขียนค่าที่นั่น** | `*p` = ค่าที่ `p` ชี้อยู่ |

และ `*` ยังถูกใช้ตอน **ประกาศ** ตัวแปรด้วย เพื่อบอกว่า "ตัวแปรนี้เป็น pointer" — จุดนี้แหละที่ทำให้คนใหม่สับสน: `*` ตอนประกาศ (`int *p;`) กับ `*` ตอนใช้งาน (`*p = 42;`) หน้าตาเหมือนกันแต่ความหมายคนละเรื่อง

**เทคนิคอ่านโค้ด C: อ่านจากขวาไปซ้าย**

`int *p = &x;` อ่านว่า:

1. `&x` — เอา address ของ x
2. `int *p` — ตัวแปร `p` ที่ชี้ไปยัง `int` (ชนิดของ p คือ "pointer to int" = `int *`)
3. `= &x` — เอาค่าจาก **ฝั่งขวา** ไปเก็บในตัวแปร `p`

เพราะฉะนั้น **ชนิดของ pointer ต้องตรงกับชนิดของข้อมูลที่ชี้**: `int *` ชี้ไปที่ int, `double *` ชี้ไปที่ double, `char *` ชี้ไปที่ char — ทำไมต้องรู้ชนิด? เพราะเวลา dereference แล้วอ่านค่าออกมา ต้องรู้ว่าอ่าน **กี่ไบต์** และตีความเป็นตัวเลขแบบไหน (int 4 ไบต์? double 8 ไบต์?) — เรื่องนี้จะละเอียดขึ้นในตอน 14

### 6.3 ลงมือจริง: `pointer_demo.c`

```c
/* pointer_demo.c — pointer เก็บ "ที่อยู่" ของตัวแปร ไม่ใช่ค่าของตัวแปร */
#include <stdio.h>

int main(void) {
    int x = 5;
    int y = 9;

    int *p = &x;   /* p มีชนิดเป็น "pointer to int" และเก็บ address ของ x
                      (& = "ขอ address ของตัวแปรนี้") */

    printf("ค่าของ x       = %d\n", x);
    printf("address ของ x  = %p\n", (void *)&x);  /* (void *) = แปลง pointer เป็นชนิด "ไม่ระบุ" ก่อนส่งให้ %p ตามมาตรฐาน — กลไกเดียวกับที่อธิบายใต้ผลลัพธ์ข้อ 3 */
    printf("address ของ y  = %p\n", (void *)&y);
    printf("ค่าที่เก็บใน p = %p  (เท่ากับ address ของ x)\n", (void *)p);

    *p = 42;       /* '*' = dereference: "ไปที่ address นั้น แล้วแก้ค่าที่นั่น" */
    printf("หลังตั้ง *p = 42 -> x = %d\n", x);

    p = &y;        /* ย้าย pointer ให้ชี้ไปตัวอื่นได้ (pointer เป็นตัวแปรตัวหนึ่ง) */
    *p = *p + 1;   /* อ่านค่าที่ชี้อยู่ +1 แล้วเขียนกลับ */
    printf("หลัง p = &y แล้ว *p = *p + 1 -> y = %d\n", y);

    printf("sizeof(int) = %zu ไบต์, sizeof(int *) = %zu ไบต์\n", sizeof(int), sizeof(int *));
    return 0;
}
```

ผลการรันจริงบนเครื่องเรา

```
ค่าของ x       = 5
address ของ x  = 0x7ffff34b3d74
address ของ y  = 0x7ffff34b3d70
ค่าที่เก็บใน p = 0x7ffff34b3d74  (เท่ากับ address ของ x)
หลังตั้ง *p = 42 -> x = 42
หลัง p = &y แล้ว *p = *p + 1 -> y = 10
sizeof(int) = 4 ไบต์, sizeof(int *) = 8 ไบต์
```

### 6.4 อ่านผลลัพธ์ให้เป็น (นี่คือส่วนที่คนใหม่มักข้าม แต่สำคัญที่สุด)

**1) `%p` = ที่สำหรับพิมพ์ address** — เลข `0x7ffff34b3d74` ขึ้นต้นด้วย `0x` แปลว่าเป็น **เลขฐานสิบหก** (hexadecimal — เราเรียนไปแล้วในตอน 8) ที่จริงมันคือ "เลขที่ช่อง" ธรรมดา ๆ นี่แหละ แค่เขียนในฐาน 16 เพราะยาวและกลมกว่าเลขฐาน 10

**2) `&x` กับ `&y` ต่างกันแค่ 4** — `0x7ffff34b3d74` กับ `0x7ffff34b3d70` ห่างกัน 4 พอดี ซึ่งก็คือขนาดของ `int` — ทั้งสองตัวนั่งติดกันในหน่วยความจำ และนี่คือ "ของจริง" ที่ตอน 10 เราเห็นแค่ในแผนผัง: **ตัวแปรไม่ได้ลอยอยู่ที่ไหนสักแห่ง มันมีที่อยู่เป็นเลข และเราหาได้**

**3) `(void *)` ที่ใส่ใน `printf` ไม่ใช่ของประดับ** — ตามมาตรฐาน C ตัวระบุรูปแบบ `%p` ต้องรับค่าเป็น `void *` (pointer แบบ "ไม่ระบุชนิด") ตรง ๆ ถ้าส่ง `int *` เข้าไปเฉย ๆ โปรแกรมมักทำงานได้บนเครื่องส่วนใหญ่ แต่เป็นพฤติกรรมไม่นิยาม — และเราเขียนโค้ดที่ "บังเอิญได้" ไม่ได้ เราต้องเขียนแบบที่ "ถูกต้อง" (นี่เป็นนิสัยที่เราจะใช้ตลอดอาชีพ: ถ้า compiler เตือน ให้แก้ให้ถูก ไม่ใช่ปิด warning)

**4) address จะเปลี่ยนทุกรอบที่รัน — และนั่นเป็นเรื่องปกติ** — รันโปรแกรมเดิม 3 ครั้ง ได้ address ต่างกันทุกครั้ง:

```
address ของ x  = 0x7ffffd9e6f84
address ของ x  = 0x7fffcd2ae664
address ของ x  = 0x7fffd4c83df4
```

เหตุผลคือระบบปฏิบัติการใช้กลไกชื่อ **ASLR** (Address Space Layout Randomization = การสุ่มตำแหน่งหน่วยความจำ) — เป็นมาตรการความปลอดภัย: ถ้าแฮกเกอร์ไม่รู้ว่าข้อมูลอยู่ที่ address ไหนแน่ ๆ การเขียนโปรแกรมเจาะระบบก็ยากขึ้นมาก (เรื่องนี้จะกลับมาอีกครั้งในตอน 20 virtual memory)

สรุป: **ห้ามเขียนโปรแกรมที่ฝัง address ตายตัวไว้ในโค้ด** ตัวเลขบนหน้าจอเป็นของเฉพาะการรันครั้งนั้น ๆ เท่านั้น

**5) `*p = 42` แล้ว `x` กลายเป็น 42 — เพราะมันคือตัวเดียวกัน** — ไม่ใช่สำเนา ไม่ใช่การคัดลอกค่า นี่คือ "ของชิ้นเดียวกัน ถูกเรียกจาก 2 ชื่อ" แล้วมันสำคัญยังไง:

- นี่คือเหตุผลเชิงลึกที่ทำให้ pointer มีพลัง: **ฟังก์ชันหนึ่งจะแก้ค่าของตัวแปรที่อยู่ "ข้างนอก" ได้**
- แต่ต้องเข้าใจกฎพื้นฐานก่อน: **การส่ง argument เข้าฟังก์ชันใน C เป็นการ "คัดลอกค่า" เสมอ — และ Go ก็เหมือนกัน** (Go ส่งทุกอย่างแบบคัดลอกค่า ไม่ว่าจะเป็น struct ตัวใหญ่หรือ array)
- ถ้าอยากให้ฟังก์ชันแก้ตัวจริง ต้องส่ง **pointer** เข้าไป (ตอน 15 จะเห็นเต็ม ๆ)
- ที่เรารู้สึกว่า Go "ไม่เรื่องมากเท่า C" เป็นเพราะ Go มี slice, map, channel ที่ทำตัวเป็น "ของอ้างอิง" อยู่ในตัวแล้ว — ส่งไปส่งมาก็ยังชี้ของชุดเดียวกัน

**6) ขนาดต่างกันเป็น 2 เท่าตัว: `sizeof(int) = 4` แต่ `sizeof(int *) = 8`** — ตัว pointer เองก็กินที่ในหน่วยความจำ! เพราะบนเครื่อง 64 บิต ต้องเก็บ address ยาว 8 ไบต์ นี่อธิบายข้อสงสัยของมือใหม่ได้ว่า "ทำไมการมี pointer เยอะ ๆ ก็กินหน่วยความจำเหมือนกัน"

### 6.5 pointer ในแบบของ Go — ต่างกันตรงไหน

Go **ก็มี pointer** และเราสงสัยแน่ ๆ ตอนเขียน Go ครั้งแรก เจอ `&x` กับ `*p` แล้วงงว่า "อันนี้ของ C หรือเปล่า" — ใช่ เป็นแนวคิดเดียวกัน แต่ Go ใส่เข็มขัดนิรภัยให้เยอะกว่ามาก

```go
// go_pointer.go — เทียบกับ C: Go มี & และ * เหมือนกัน แต่ไม่มี pointer arithmetic
package main

import "fmt"

// struct = ชนิดข้อมูลที่เราประกอบเองจากหลายฟิลด์ (ในวงเล็บปีกกาคือรายชื่อฟิลด์ — ที่นี่ X กับ Y เป็น int ทั้งคู่)
type Point struct{ X, Y int }

func main() {
	x := 5
	p := &x // ได้ *int (address ของ x) — เหมือน C
	*p = 42
	fmt.Println("x =", x)

	// ฟิลด์ของ struct เข้าถึงผ่าน pointer ได้ตรง ๆ ไม่ต้องเขียน (*p).X
	pt := &Point{X: 1, Y: 2}
	pt.X = 10
	fmt.Println("pt =", *pt)

	// จัดสรรหน่วยความจำแบบไม่ต้อง free — GC เก็บให้
	b := make([]int, 3)
	fmt.Println("len =", len(b), "cap =", cap(b))
}
```

รันจริงได้

```
x = 42
pt = {10 2}
len = 3 cap = 3
```

จุดต่างที่ต้องเข้าใจ (มีทั้งหมด 3 เรื่องใหญ่ จะครบชุดในหัวข้อ 7):

1. **Go ให้ `&` และ `*` เหมือน C** — `p := &x` ได้ pointer ชี้ไปที่ x, `*p = 42` แก้ค่าจริงของ x เหมือนกันเป๊ะ
2. **Go เขียน `pt.X` ได้เลย แม้ `pt` เป็น pointer** — ใน C เราต้องเขียน `(*pt).X` (หรือใช้ตัวย่อ `pt->X` ซึ่งสั้นกว่าและเป็นธรรมเนียมที่ใช้กันจริง) ส่วน Go เรียบเรียงให้อัตโนมัติ ("auto-dereference") — เป็นอีกตัวอย่างของ "Go เก็บรายละเอียดที่ทำให้สับสนไว้ที่ compiler"
3. **Go ไม่ยอมให้บวก-ลบ address** — ไม่มี `p + 1`, ไม่มี `p++` ปนกับ pointer (มีเฉพาะกับตัวเลข) โดยสิ้นเชิง ในหัวข้อถัดไปเราจะดูว่า C ทำได้แค่ไหน และทำไม Go ถึงห้าม

## 7. สามจุดต่างสำคัญระหว่าง C กับ Go ที่ต้องฝังหัว

สามจุดต่างที่ต้องฝังหัว เริ่มจากข้อที่สำคัญที่สุด — ทั้งสามข้อนี้คือ "ของที่ Go แลกมา" ด้วยการตัดความสามารถบางอย่างออกไป

### 7.1 pointer arithmetic — C ทำได้ Go ห้าม (และนี่คือความต่างที่สำคัญที่สุด)

![คำสั่ง & และ * เหมือนกันใน C กับ Go แต่ C บวก address ได้ และจัดการหน่วยความจำเอง ส่วน Go ห้ามบวกและมี GC](/assets/diagrams/ep13-03-pointer-c-vs-go.svg)

**ภาพที่ 3:** เปรียบเทียบตรง ๆ ว่า 3 งาน (เอา address, เลื่อน address, จัดการหน่วยความจำ) ใน C ทำได้แบบไหน ใน Go ทำได้แบบไหน

C **บวก/ลบ address ได้** และมันบวกเป็น "ช่อง" ไม่ใช่ "ไบต์" — ลองดูจากของจริง (`pointer_walk.c`)

```c
/* pointer_walk.c — pointer arithmetic: บวก address เพื่อเดินไปช่องถัดไป (C ทำได้ Go ห้าม) */
#include <stddef.h>
#include <stdio.h>

int main(void) {
    int a[3] = {10, 20, 30};
    int *p = a;                /* ชื่อ array ใช้เป็น address ของช่องแรกได้เลย */

    printf("a[0]=%d a[1]=%d a[2]=%d\n", a[0], a[1], a[2]);
    printf("address ของ a[0] = %p\n", (void *)p);

    p = p + 1;                 /* บวก 1 = เลื่อนไป 4 ไบต์ (ขนาด int) ไม่ใช่ 1 ไบต์ */
    printf("หลัง p = p + 1 -> *p = %d (คือ a[1]) ที่ address %p\n", *p, (void *)p);
    printf("อ่านผ่าน pointer แบบไม่ใช้ index: *(a + 2) = %d\n", *(a + 2));

    /* ระยะห่างจริงเป็นไบต์ ระหว่าง a[0] กับ a[2] — ยืนยันว่า "บวก 2" = บวก 8 ไบต์ */
    /* ทำไมต้อง (char *): (1) ลบ pointer สองตัวตรง ๆ ได้ผลเป็น "จำนวนช่อง" ไม่ใช่ไบต์ จึงต้องแปลง
       เป็น char* (ช่องละ 1 ไบต์) ก่อน (2) ผลลบแบบนี้มีชนิดเป็น ptrdiff_t จาก <stddef.h> — ดูใต้ผลลัพธ์ */
    ptrdiff_t bytes_apart = (char *)(a + 2) - (char *)a;
    printf("ระยะห่าง a[0] ถึง a[2] = %td ไบต์ (= 2 x sizeof(int) = %zu)\n",
           bytes_apart, 2 * sizeof(int));
    return 0;
}
```

ผลการรันจริง

```
a[0]=10 a[1]=20 a[2]=30
address ของ a[0] = 0x7fffee5c2090
หลัง p = p + 1 -> *p = 20 (คือ a[1]) ที่ address 0x7fffee5c2094
อ่านผ่าน pointer แบบไม่ใช้ index: *(a + 2) = 30
ระยะห่าง a[0] ถึง a[2] = 8 ไบต์ (= 2 x sizeof(int) = 8)
```

อ่าน `pointer_walk.c` ทีละบรรทัด:

- `#include <stddef.h>` — ดึง declaration ของ `ptrdiff_t` (ชนิดของ "ผลลบของ pointer สองตัว") เข้ามา
- `int a[3] = {10, 20, 30};` — array 3 ช่อง ช่องละ `int`
- `int *p = a;` — ชื่อ array ใช้เป็น address ของช่องแรกได้เลย (ไม่ต้องเขียน `&a[0]`)
- `(void *)p` — แปลงเป็น `void *` ก่อนส่งให้ `%p` (กลไกเดียวกับหัวข้อ 6.4 ข้อ 3)
- `p = p + 1;` — บวก 1 = เลื่อนไป **4 ไบต์** (ขนาด `int`) ไม่ใช่ 1 ไบต์
- `*(a + 2)` — เขียนแบบไม่ใช้ index: เริ่มที่ `a` แล้วเลื่อนไป 2 ช่อง
- `ptrdiff_t bytes_apart = (char *)(a + 2) - (char *)a;` — บรรทัดที่ต้องอ่านดี ๆ: ลบ pointer ตรง ๆ ได้ผลเป็น "จำนวนช่อง" จึงต้องแปลงเป็น `char *` (ช่องละ 1 ไบต์) ก่อน ผลลบจึงออกมาเป็นไบต์ และเก็บใน `ptrdiff_t` แล้วพิมพ์ด้วย `%td`
- `2 * sizeof(int)` — ใช้ยืนยันคำตอบ: สองช่อง = 2 x 4 = 8 ไบต์

อ่านให้ดี: address เปลี่ยนจาก `...2090` เป็น `...2094` คือ **+4** ขณะที่เราเขียน `p + 1` — เพราะ C รู้ว่า `p` ชี้ไปที่ `int` ซึ่งกว้าง 4 ไบต์ มันจึงเลื่อนไป 4 ไบต์ให้เอง (ไม่ใช่ 1 ไบต์) นี่แหละความหมายของ **"การบวกเป็นช่อง ไม่ใช่เป็นไบต์"** และเพราะ index ของ array ก็คือ "ระยะห่างจากช่องแรก" นั่นหมายความว่า `a[2]` กับ `*(a + 2)` **เป็นสิ่งเดียวกันจริง ๆ** — ไม่ใช่แค่คล้ายกัน

`ptrdiff_t` ที่โผล่มาในโค้ดคือชนิดของ "ผลลบของ pointer สองตัว" (ใน `<stddef.h>`) และคำเตือนสำคัญ: **การบวกลบ pointer ที่ชี้อยู่นอก array ของตัวเอง = พฤติกรรมไม่นิยาม (undefined behavior)** — ทางแก้คือเขียนโปรแกรมให้ pointer อยู่ในขอบเขตที่ถูกต้องเสมอ

แล้ว Go ทำอะไรกับโค้ดแบบนี้? **ปฏิเสธตั้งแต่ยังไม่ทันรัน** — ลองเขียนแบบเดียวกันใน Go

```go
a := [3]int{10, 20, 30}   // ท่อนเดียวกับ مثال C ด้านบน เขียนใน Go
p := &a[0]                // p ชี้ที่ a[0] — ได้ชนิด *int
p = p + 1   // ← บรรทัดนี้ตั้งใจให้ผิด
```

compiler ของ Go ฟ้องทันที (ข้อความจริงจาก `go build` — โปรแกรมเต็มอยู่ใน `course/code/ep13/go_pointer_arith.go`)

```
./go_pointer_arith.go:9:6: invalid operation: p + 1 (mismatched types *int and untyped int)
```

ข้อความนี้บอกอะไรเรา 3 อย่าง:

- `mismatched types *int and untyped int` = "ชนิดไม่ตรงกัน: pointer ที่ชี้ไป int กับจำนวนเต็ม"
- สำหรับ Go แล้ว **การเอา pointer บวกกับเลขไม่มีความหมายตั้งแต่ระดับภาษา** — ไม่ใช่แค่ไม่มีคำสั่งให้ใช้ แต่ไวยากรณ์ไม่ยอมให้เขียนแบบนั้นเลย
- ถ้าเราเข้าใจแล้วว่าการบวก pointer หมายถึง "บวกเป็นช่อง" ซึ่งเสี่ยงมาก คอมไพเลอร์จึงตัดความสามารถนั้นทิ้งไป — งานที่ C ทำได้ในบรรทัดเดียว Go จึงต้องเขียนเป็น index

สรุปความต่างข้อนี้ให้จำง่าย ๆ

| ทำอะไร | C | Go |
|---|---|---|
| เก็บ address ของตัวแปร | `int *p = &x;` | `p := &x` |
| อ่านค่าที่ address นั้น | `*p` | `*p` |
| เลื่อนไปช่องถัดไป | `p = p + 1;` หรือ `p[i]` | ต้องใช้ index: `a[i]` (เขียน `p+1` ไม่ผ่าน) |
| เขียนทับได้ไหม | เขียนได้ทุกที่ (อันตราย) | compiler กันให้เป็นส่วนใหญ่ |
| ที่ควรใช้จริง | จัดการ array / buffer / หน่วยความจำระดับล่าง | ให้ทำงานผ่าน slice / index |

*(หมายเหตุ: Go ยังมีประตูหลังชื่อ `unsafe.Pointer` พร้อมตัวช่วยอย่าง `unsafe.Add` (เลื่อน address เองได้) และ `unsafe.Slice` (สร้าง slice จาก pointer + ความยาว) — สำหรับกรณีที่จำเป็นจริง ๆ เท่านั้น เช่นเขียน library ระดับล่างหรือติดต่อกับภาษา C แต่มันชื่อ `unsafe` โดยตั้งใจ และห้ามใช้ในการเขียนแอปทั่วไป)*

### 7.2 memory management — ใครล้างหน่วยความจำให้เรา

นี่คือจุดต่างที่ผู้เริ่มเรียน Go มักไม่เคยรู้สึกว่ามีอยู่ **จนกว่าจะเขียน C**

- **Go:** เขียน `b := make([]int, 3)` แล้วใช้ได้เลย ไม่ต้องคืนอะไรกลับตอนเลิกใช้ — GC (garbage collector) สแกนหา "ของที่ไม่มีใครอ้างถึงแล้ว" แล้วคืนหน่วยความจำให้เอง *เป็นโปรแกรมที่วิ่งไปพร้อมโปรแกรมของเรา* และนี่คือเหตุผลเดียวกันที่ทำให้ Go ต้องมี `runtime` หนัก ๆ
- **C:** ถ้าอยากได้หน่วยความจำเพิ่มระหว่างรันโปรแกรม (เช่น array ที่รู้ขนาดตอนรัน ไม่ใช่ตอนคอมไพล์) ต้องทำเอง 3 ขั้น:
  1. **ขอ** ด้วย `malloc` (memory allocate)
  2. **ใช้** ให้คุ้ม
  3. **คืน** ด้วย `free`
  ถ้าลืมคืน = **memory leak** (หน่วยความจำรั่ว — หายไปเรื่อย ๆ จนโปรแกรมตาย) · คืนซ้ำ/คืนผิดที่ = พังแบบไม่รู้สาเหตุ

```c
#include <stdio.h>
#include <stdlib.h>   /* malloc/free ประกาศอยู่ในไฟล์นี้ — ลืม include = GCC 14 error ทันที */

int main(void) {
    int *b = malloc(100 * sizeof(int));   /* ขอ 100 ช่อง (ช่องละ sizeof(int) ไบต์) */
    if (b == NULL) {                      /* ขอไม่สำเร็จเกิดขึ้นได้จริง — ต้องเช็คทุกครั้ง */
        puts("malloc ล้มเหลว: ขอหน่วยความจำไม่ได้");  /* puts = พิมพ์ข้อความแล้วขึ้นบรรทัดให้เอง */
        return 1;                         /* จบแบบมีปัญหา */
    }

    /* ...ใช้ b... */

    free(b);                              /* คืนหน่วยความจำ — C ไม่มีอะไรทำให้ */
    return 0;
}
```

หมายเหตุสองข้อที่ควรรู้ตั้งแต่ตอนนี้:

- **ทำไมไม่ต้อง cast**: `malloc` คืนค่าเป็น `void *` ซึ่งภาษา C แปลงเป็น pointer ชนิดไหนก็ได้ให้เองอัตโนมัติ (C++ ต้อง cast เอง) การใส่ cast ในภาษา C จึงไม่จำเป็น — และผู้เชี่ยวชาญหลายคนบอกว่า **ไม่ควรใส่** เพราะมันทำให้ compiler มองไม่เห็นว่าเราเผลอลืม `#include <stdlib.h>`
- **ทำไมต้องเช็ค `NULL`**: เมื่อขอหน่วยความจำไม่ได้ `malloc` จะคืน `NULL` (pointer ว่าง) — เกิดได้จริงบนเครื่องที่หน่วยความจำเต็ม และถ้าเรา dereference `NULL` โปรแกรมจะถูกสั่งหยุดทันที (segfault)

ตอนนี้ขอแค่ "จำได้ว่าเคยเห็นชื่อ `malloc` กับ `free`" — เราจะเรียนเต็ม ๆ เรื่องนี้ในตอน 16 (พร้อมกับ buffer overflow ซึ่งเป็นสาเหตุของช่องโหว่ความปลอดภัยระดับโลกเช่นกัน)

### 7.3 safety — C ให้เราทำอันตรายได้ (และจะไม่บอกว่าเรากำลังทำ)

**C ไม่ตรวจสอบขอบเขตของ array ให้** — เขียนแบบนี้ได้และคอมไพล์ผ่าน (ตัวอย่างนี้เป็นเคส **อ่าน** เกินขอบเขต):

```c
int a[3] = {10, 20, 30};
int x = a[5];     /* compile ผ่าน! รันแล้วได้อะไรก็ไม่รู้ (พฤติกรรมไม่นิยาม) */
```

- **Go:** `a[5]` เกินขอบเขต → ถ้าเป็นตัวเลขคงที่ (constant) ตรง ๆ Go ฟ้องตั้งแต่ตอนคอมไพล์เลย (`invalid argument: index 5 out of bounds [0:3]`) — ยังไม่ทันรัน · แต่ถ้า index มาจากตัวแปร (หรือเป็น slice) ที่เขียนแบบนี้ตรวจไม่ได้ล่วงหน้า Go จะ**panic** ตอนรันทันที (`index out of range [5] with length 3`) — พังตรงจุด หาง่าย
- **C:** คอมไพล์ผ่าน รันผ่าน แล้ว**อ่าน**ข้อมูลจาก "ช่องที่ 6" ที่อยู่ถัดออกไป — ค่าที่ได้ไม่มีความหมาย (อาจบังเอิญเป็นค่าของตัวแปรอื่นที่อยู่ตรงนั้น หรือเป็นขยะ) และโปรแกรมส่วนใหญ่ก็ไม่พังตรงจุดนั้นเลย · ที่ร้ายกว่าคือเคส **เขียน** เกินขอบเขต (buffer overflow) ซึ่งไปทับข้อมูลของตัวแปรอื่นได้จริง — นี่คือฝันร้ายของการดีบัก: โปรแกรม "ดูเหมือนทำงานถูก" ไปอีกครึ่งปี จนวันหนึ่งหน่วยความจำแถวนั้นเปลี่ยนไปแล้วผลลัพธ์เพี้ยน
- **แถม:** ถ้าคอมไพล์ด้วย `-O2` (เปิดปรับแต่งความเร็ว) GCC จะฉลาดขึ้นถึงขั้น **จับตัวอย่างนี้ได้เอง** และเตือนออกมาเป็นข้อความจริงแบบนี้: `warning: array subscript 5 is above array bounds of 'int[3]'` (ต่อท้ายด้วยธง `[-Warray-bounds=]` พร้อมชี้บรรทัด `int x = a[5];` และชี้ว่า `a` ถูกประกาศไว้บรรทัดไหน) — แต่จับได้เฉพาะเคสที่ตัวเลขชัดเจนแบบนี้ ไม่ใช่ทุกเคส นี่คือเหตุผลที่เราไม่พึ่ง compiler อย่างเดียว

ความต่างเชิงปรัชญาข้อนี้พูดสั้น ๆ ได้ว่า: **Go ให้ความสำคัญกับ "ถูกต้องตั้งแต่แรก" มากกว่า "เผื่อเราเก่ง"**

- Go ยอมตัดความสามารถทิ้งไปจำนวนหนึ่ง (บวก pointer, เขียนเกินขอบเขต, จองหน่วยความจำเอง)
- แล้วแลกกับสิ่งที่มันป้องกันไว้ให้เราทุกวัน: โปรแกรมที่พังแบบคาดเดาได้ และคนอื่นแก้โค้ดของเราได้อย่างปลอดภัย
- ส่วน C ก็มีเหตุผลของมัน และเหตุผลนั้นยังใช้ได้จริง — ในงานที่ต้องคุยกับ hardware, เขียน kernel, เขียน runtime, เขียนโค้ดที่ต้องคุมทุกไบต์ มันคือภาษาที่มนุษย์ทำงานร่วมกับเครื่องได้ตรงที่สุดในบรรดาภาษาที่คนอ่านออก

## 8. รันเองให้ครบขั้นตอน (สรุปคำสั่งที่ต้องใช้)

ทุกโปรแกรมในบทความนี้ใช้คำสั่งรูปแบบเดียวกัน

```bash
# 1) คอมไพล์ (แปลเป็นโปรแกรมที่รันได้)
gcc -std=c17 -Wall -Wextra -Wpedantic -o hello hello.c

# 2) รัน
./hello
```

บน **Windows** (ติดตั้ง **MinGW** = ชุด GCC สำหรับ Windows) ใช้คำสั่งเหมือนกันเป๊ะ ต่างแค่ได้ไฟล์ `hello.exe` แล้วรันด้วย `hello.exe`

อธิบายตัวเลือกที่ใส่ (ช่วงแรกให้ใส่ติดมือไปทุกครั้ง)

| ตัวเลือก | ทำอะไร | ทำไมต้องมี |
|---|---|---|
| `-std=c17` | ระบุมาตรฐาน C ที่จะใช้ | ทำให้ทุกเครื่องได้พฤติกรรมแบบเดียวกัน (GCC 15+ เปลี่ยนค่าเริ่มต้นเป็น C23 แล้ว จะได้ไม่สับสนว่าทำไมเครื่องอื่นพัง) |
| `-Wall -Wextra` | เปิด warning ระดับสำคัญและเพิ่มเติม | C ปล่อยเรื่องอันตรายให้ผ่านได้ — warning เป็นเพื่อน ไม่ใช่ศัตรู |
| `-Wpedantic` | เตือนเมื่อใช้ของนอกมาตรฐาน | ทำให้โค้ดย้ายข้ามเครื่อง/คอมไพเลอร์ได้ง่าย |
| `-o hello` | ตั้งชื่อโปรแกรมที่ได้ | ไม่ใส่จะได้ชื่อ `a.out` ซึ่งหาตัวเองไม่เจอ |
| `-O0` (ถ้าใช้) | ไม่ปรับแต่งความเร็ว | ทำให้เวลาใช้ **debugger** (โปรแกรมช่วยไล่ดูการทำงานทีละบรรทัด หยุดตรงไหนก็ดูค่าตัวแปรได้) การเดินทีละบรรทัดตรงกับโค้ดที่เราเขียน |

เทียบกับ Go ที่เราใช้มาตลอด

```bash
go run hello.go          # คอมไพล์ + รัน + ลบไฟล์ชั่วคราว ให้เลย
gcc hello.c -o hello && ./hello   # C แยกสองขั้น: คอมไพล์ แล้วค่อยรัน
```

**ข้อควรรู้:** C แยกสองขั้นชัดเจน (คอมไพล์เป็นไฟล์ → รันไฟล์นั้น) ส่วน `go run` ยุบสองขั้นเป็นคำสั่งเดียว — และเพื่อความยุติธรรมกับ Go ต้องบอกว่ารันโปรแกรม Go จริง ๆ ก็คือ `go build -o app . && ./app` ซึ่งมีสองขั้นแบบเดียวกัน (รายละเอียดการแปล `.c` → executable (ไฟล์โปรแกรมที่รันได้) ตั้งแต่ preprocessor → compile → assemble → link เป็นเนื้อหาของ**ตอน 17** ทั้งตอน — โดย **link** คือขั้นสุดท้ายที่เอาผลลัพธ์ที่คอมไพล์แล้วของหลาย ๆ ไฟล์มาประกอบกันเป็นโปรแกรมเดียว)

## 9. โจทย์ฝึก (2 ระดับ)

### ระดับ 1 — drill (ฝึกความแม่นยำ)

ตอบคำถามทั้งหมดนี้ **โดยยังไม่รันโปรแกรม** แล้วค่อยรันตรวจ (ทักษะ "ทำนายก่อนรัน" เป็นทักษะสำคัญที่สุดของวิศวกรซอฟต์แวร์)

1. `sizeof(char)` = 1 และ `sizeof(double)` = 8 บนเครื่องเรา — ถ้า `double *d;` แล้ว `d + 3` จะเลื่อนไปกี่ไบต์?
2. ใน `types.c` ถ้าเขียน `printf("%d\n", name)` (ส่ง array ของ char ให้ `%d`) จะเกิดอะไรขึ้น และถ้าเขียน `printf("%s\n", c)` (ส่ง char ให้ `%s`) จะเกิดอะไรขึ้น? (ใบ้: ชนิดของ argument ไม่ตรงกับที่ `%` กำหนด — compiler จะเตือนเรื่อง format และคำตอบไม่แม่นยำตามมาตรฐาน C · เคส `printf("%s", c)` มีโอกาส **segfault** — โปรแกรมถูกสั่งหยุดกลางทางเพราะแตะหน่วยความจำที่ไม่มีสิทธิ์ — เพราะมันจะเอาเลข 65 ไปใช้เป็น address แล้วไล่อ่านไปเรื่อย ๆ)
3. ใน `loop_control.c` ถ้าแก้ `while (countdown > 0)` เป็น `while (countdown)` — ผลลัพธ์ต่างกันไหม เพราะอะไร (ใบ้: ใช้หัวข้อ 3.3 ในเรื่อง "0 คือเท็จ")
4. โปรแกรมนี้พิมพ์อะไร แล้วแถวท้าย ๆ ต่างกันเพราะอะไร
   ```c
   int a[3] = {1, 2, 3};
   int *p = a + 2;
   printf("%d %d\n", *p, *(p - 1));
   ```

### ระดับ 2 — mini-project: `swap.c` — ฟังก์ชันที่แก้ค่าข้างนอกได้

โจทย์: เขียนโปรแกรม C ที่มีฟังก์ชัน **สลับค่าของตัวแปรสองตัว** โดยใช้ pointer

ข้อกำหนด:

1. เขียนฟังก์ชัน `void swap(int *a, int *b)` ที่สลับค่าของข้อมูลที่ pointer ทั้งสองตัวชี้อยู่
2. `main()` ประกาศ `int x = 5; int y = 9;` แล้วเรียก `swap(&x, &y)` แล้วพิมพ์ค่าออกมา — ต้องได้ `x = 9, y = 5`
3. **ท้าทาย:** เขียนเวอร์ชันที่ **ผิด** ด้วย คือ `void swap_bad(int a, int b)` (ไม่ใช้ pointer) แล้วพิสูจน์ด้วยการรันว่า `main()` ไม่เห็นการเปลี่ยนแปลง — แล้วตอบคำถามว่า "ทำไม" (ใบ้: argument ถูกคัดลอกค่าก่อนเข้าไปในฟังก์ชัน — เรื่องนี้คือเรื่องของตอน 15)
4. **ท้าทายขั้นที่สอง:** เขียนเวอร์ชันเดียวกันใน Go (`func swap(a, b *int)`) แล้วรันเทียบผล — สังเกตว่าที่ต้องใช้ `*a, *b = *b, *a` และ Go ก็บังคับให้ใส่ `&x` เหมือนกัน
5. **ท้าทายขั้นที่สาม (โจทย์ระดับ pointer ชี้ pointer):** กลับไปที่ `pointer_demo.c` แล้วแก้เป็น `int **pp = &p;` — แล้วอธิบายว่า `**pp` คืออะไร และ `pp` เก็บค่าอะไร (ใบ้: `p` เป็นตัวแปรเหมือน `x` มันจึงมี address ของตัวเองด้วย)

ตรวจผล: ทั้งสองภาษาต้องพิมพ์ `x = 9, y = 5` เหมือนกัน — ต่างกันแค่หน้าตาโค้ด ถ้าทำได้ครบทั้ง 5 ข้อ แปลว่าเราเข้าใจ pointer ในระดับที่เอาไปใช้งานได้จริงแล้ว ไม่ใช่แค่ "อ่านโค้ดเขารู้เรื่อง"

## สรุป

วันนี้เราเขียน C เป็นครั้งแรกในชีวิต และใช้ Go ที่เรียนมาแล้วเป็นกระจกส่องดูมัน เก็บหัวข้อที่ต้องจำให้ครบ:

- **C คือขั้นกลางระหว่าง assembly กับ Go** — ให้ access เครื่องโดยตรง แต่ยังอ่านเป็นภาษาคนได้ · Linux kernel และคอมไพเลอร์จำนวนมากเขียนด้วย C
- **โครงโปรแกรม C** = `#include <stdio.h>` + `int main(void) { ... return 0; }` — ต้องมี `;` ทุกคำสั่ง และเราต้องบอกระบบเองว่า "จบดี" ด้วย `return 0;`
- **ชนิดข้อมูล C ไม่ครบเหมือน Go:** ไม่มี `string` (ใช้ `char[]` ปิดท้ายด้วย `'\0'`), `bool` เพิ่งเป็นคำสงวนของภาษาตอน C23 (และ GCC 15+ ถือ C23 เป็นค่าเริ่มต้น) · `sizeof` บอกขนาดจริงเป็นไบต์ และ `int` ไม่ได้กว้างเท่ากันทุกเครื่อง
- **ตัวแปรที่ประกาศเปล่าใน C ได้ค่าขยะ** — ต่างจาก zero value ของ Go · ตั้งนิสัย "ประกาศที่ไหน กำหนดค่าที่นั่น"
- **`for (int i = 0; i < n; i++)` เขียนเหมือนกันทั้ง C และ Go** แต่ C ไม่มี `for range` ให้ใช้
- **pointer** = ตัวแปรที่เก็บ address · `&x` = ขอ address · `*p` = เดินตาม address ไปเอาค่าจริง (dereference) · ค่าของ `*p` คือ "บ้านหลังเดียวกับ x" ไม่ใช่สำเนา
- **address ไม่ใช่ของใหม่** — ตอน 10–12 เราก็เห็น PC, MAR, `LD` ทั้งหมดคือ address · ที่ใหม่คือ *ตอนนี้เราจับมันไว้ในมือได้ด้วยตัวแปรหนึ่ง*
- **สามจุดต่างที่ต้องฝังหัว:** C บวกลบ address ได้ (Go ห้ามและฟ้อง `mismatched types`), C จัดการหน่วยความจำเองด้วย `malloc`/`free` (Go มี GC), C ไม่ตรวจขอบเขต array (Go panic ให้เจอทันที)
- และคำถามที่ทำให้ทุกอย่างเชื่อมกัน: **"Go ซ่อนอะไรไว้ให้เรา?"** — วันนี้เรามีคำตอบกึ่งหนึ่งแล้ว (GC, memory safety, การห้าม pointer arithmetic) และเราจะเห็นอีกครึ่งหนึ่งในตอนที่ 31 เมื่อไปดู Go runtime กับ GC ตรง ๆ

จากนี้ไปเวลาเห็นเครื่องหมาย `&` กับ `*` ในโค้ด Go หรือ C เราจะไม่ต้องเดาอีกแล้ว — มันคือ "บ้านเลขที่" กับ "การเดินตามบ้านเลขที่ไปเคาะประตู" เท่านั้นเอง

ตอนต่อไปเราจะขยายเรื่อง pointer ให้กว้างขึ้น: **pointer กับ array ในฐานะสองหน้าตาของหน่วยความจำ** เราจะเห็นว่าทำไม `a[i]` กับ `*(a + i)` ถึงเป็นสิ่งเดียวกันจริง ๆ และเขียนโปรแกรมที่เดินผ่านหน่วยความจำด้วย pointer ได้ด้วยมือ
