ยินดีต้อนรับสู่ตอนแรกของซีรีส์ **CS Fundamentals: จาก 0 สู่พื้นฐานที่แท้จริง** — คอร์สที่ตั้งใจเขียนสำหรับคนที่ยังเขียนโปรแกรมไม่เป็นเลย แต่อยากเป็น software engineer (วิศวกรซอฟต์แวร์ = คนที่สร้างโปรแกรม/ระบบเป็นอาชีพ) แบบเร่งรัด

ขอพูดตรง ๆ อย่างที่อาจารย์ควรพูดกับนักเรียนวันแรก: ถ้าคุณหวังว่าคอร์สนี้จะสอนทำเว็บไซต์ให้เสร็จในหนึ่งสัปดาห์ คุณจะผิดหวัง แต่ถ้าคุณอยากเป็นคนที่ "เข้าใจว่าคอมพิวเตอร์ทำงานยังไงจริง ๆ" คอร์สนี้คือแผนที่เส้นทางที่คนเก่ง ๆ รุ่นหนึ่งเดินมาแล้ว ตอนนี้เป็นตอนปฐมนิเทศ เราจะยังไม่ยุ่งกับโค้ด (code = ชุดคำสั่งที่มนุษย์เขียนด้วยภาษาโปรแกรม) หนัก ๆ แต่จะมาทำความเข้าใจก่อนว่า "พื้นฐานที่แท้จริง" คืออะไร และทำไมคนที่สร้างเครื่องมือที่คุณใช้อยู่ทุกวันถึงรู้เรื่องพวกนี้กันหมด

## "เขียนเว็บได้" กับ "รู้พื้นฐานที่แท้จริง" ต่างกันตรงไหน

ลองนึกภาพคนสองคน

คนแรก**ขับรถเก่งมาก** รู้เส้นทางทุกซอกทุกมุม — ใช้รถได้คล่องแคล่วจริง ๆ คนที่สองขับน้อยกว่า แต่เปิดฝากระโปรงแล้วชี้ได้ว่าเครื่องยนต์ส่วนไหนทำอะไร ถ้ารถมีเสียงแปลก ๆ พอเดาได้ว่าปัญหามาจากส่วนไหน และที่สำคัญ — สร้างเครื่องมือซ่อมรถเองได้ ถ้าถามว่าใครเป็นช่างเครื่องยนต์ที่เก่งกว่า คำตอบคงไม่ใช่คนแรกโดยอัตโนมัติ

การ**เขียนเว็บได้**เหมือนการขับรถเก่ง — คุณเรียนวิธีใช้เครื่องมือสำเร็จรูป (framework = ชุดโค้ดสำเร็จรูปที่ช่วยสร้างแอปพลิเคชันเร็วขึ้น) จำรูปแบบ แล้วประกอบชิ้นส่วนตามที่เขาสอน เป็นทักษะที่มีค่าและหาเงินได้จริง ไม่มีใครปฏิเสธ

แต่การรู้**พื้นฐานที่แท้จริง**คือการรู้ว่าข้างใต้เครื่องมือมีอะไรอยู่: เมื่อโค้ดของคุณถูกสั่งให้ทำงาน เกิดอะไรขึ้นในคอมพิวเตอร์? ใครแปลภาษาที่คุณเขียนให้เครื่องเข้าใจ? หน่วยความจำจัดการยังไง? ทำไมโปรแกรมบางตัวช้า บางตัวพัง? คอร์สนี้จะพาคุณไปรู้จัก "ชั้นใต้ดิน" เหล่านั้นทีละชั้น

## ซอฟต์แวร์ซ้อนกันเป็นชั้น ๆ เหมือนตึกหลายชั้น

ซอฟต์แวร์ (software = โปรแกรม/ชุดคำสั่งทั้งหลาย) ที่เราใช้กันทุกวัน ไม่ได้ลอยอยู่กลางอากาศ แต่มันซ้อนกันเป็นชั้น ๆ ประมาณนี้:

```
ชั้น 5: แอปพลิเคชันที่ผู้ใช้เห็น (เว็บไซต์, แอปมือถือ, เกม)
ชั้น 4: framework (ชุดโค้ดสำเร็จรูปที่ dev เอามาต่อ; dev = developer = นักพัฒนาโปรแกรม)
ชั้น 3: ภาษาโปรแกรม (Go, C, ...) + compiler (ตัวแปลภาษา)
ชั้น 2: ระบบปฏิบัติการ (OS) + kernel (แกนกลางของ OS)
ชั้น 1: ฮาร์ดแวร์ — CPU, หน่วยความจำ, ดิสก์, การ์ดจอ

ทิศทาง "ขุดลงไป" = เรียนรู้ลึกขึ้นเรื่อย ๆ
```

ขยายศัพท์ที่เพิ่งโผล่มาทีละคำ เพราะผมรู้ว่านี่อาจเป็นครั้งแรกที่คุณเห็นมัน:

- **ภาษาโปรแกรม** คือภาษาที่คนใช้เขียนคำสั่งให้คอมพิวเตอร์ฟัง เช่น Go, C, Python, JavaScript — มนุษย์อ่านเข้าใจ (พอสมควร) แต่คอมพิวเตอร์ไม่เข้าใจภาษาคน
- **compiler** (คอมไพเลอร์ = ตัวแปลภาษา) คือโปรแกรมที่แปลโค้ดที่มนุษย์เขียน (source code = โค้ดต้นฉบับ) ให้เป็นภาษาเครื่อง (machine code = ชุดคำสั่งที่ CPU อ่านแล้วทำงานได้)
- **ระบบปฏิบัติการ** หรือ OS (Operating System) คือโปรแกรมแม่บ้านที่จัดการทรัพยากรของเครื่อง: ใครได้ใช้ CPU (หน่วยประมวลผล = สมองของคอมพิวเตอร์) ตอนไหน ไฟล์เก็บยังไง
- **kernel** (เคอร์เนิล = แกนกลาง) คือหัวใจของ OS ส่วนที่อยู่ติดฮาร์ดแวร์มากที่สุด — Windows, macOS, Linux ล้วนมี kernel ของตัวเอง

คนเขียนเว็บทั่วไปใช้ชีวิตอยู่ชั้น 4–5 แทบทั้งวัน — ประกอบหน้าเว็บ เรียกข้อมูล ซึ่งไม่ผิดอะไร แต่นั่นคือการอยู่ชั้นบนของตึก คอร์สนี้จะพาคุณ**ลงไปทีละชั้น**: เริ่มจากชั้น 3 (ภาษา Go) ขุดลงถึงชั้น 1 (ฮาร์ดแวร์) แล้วไต่กลับขึ้นมาพร้อมความเข้าใจที่เต็มขึ้น — เหมือนเรียนวิธีสร้างตึกทั้งหลัง ไม่ใช่แค่ตกแต่งห้องชั้นบน

## ทำไมเรื่องนี้ถึงสำคัญ — เรื่องจริงของคนที่สร้างเครื่องมือที่คุณใช้อยู่ทุกวัน

แทนที่จะอธิบายเป็นทฤษฎีลอย ๆ ขอเล่าเรื่องคนสี่คนที่สร้าง "ของ" ที่คุณแตะต้องทุกวันโดยไม่รู้ตัว ให้ดูว่า**สิ่งที่พวกเขารู้**คืออะไร และพาพวกเขาไปไกลแค่ไหน

### Ken Thompson (เคน ทอมป์สัน) — คนที่เขียนระบบปฏิบัติการเพราะอยากเล่นเกม

ทอมป์สันเป็นวิศวกรที่ Bell Labs (ห้องแล็บวิจัยชื่อดังของอเมริกา) ตั้งแต่ปี 1966 ตอนแรกทำงานในโปรเจกต์ระบบปฏิบัติการยักษ์ชื่อ Multics ซึ่งสุดท้าย Bell Labs ถอนตัวเพราะมันใหญ่และซับซ้อนเกินไป

ระหว่างนั้นเขาลงเกมจำลองอวกาศชื่อ Space Travel ที่ตัวเองเขียน ไปรัน (รัน = run = สั่งให้โปรแกรมทำงาน) บนเครื่อง PDP-7 เครื่องเก่าที่ว่างอยู่ แล้วพบว่าเครื่องนี้ไม่สะดวกต่อการพัฒนาโปรแกรมเท่าไร — เขาจึงเริ่มเขียน**ระบบปฏิบัติการของตัวเอง**ขึ้นมาสำหรับเครื่องนี้ ผลงานชิ้นนั้นคือ **Unix** (ยูนิกซ์) เกิดราวปี 1969 ต่อมาผลงานชิ้นนี้กลายเป็นต้นแบบ (Unix-like = ระบบที่เลียนแบบแนวคิดของ Unix แต่ไม่ได้สืบทอดโค้ดมาโดยตรง) ของ Linux และเป็นบรรพบุรุษสาย BSD (ตระกูลระบบปฏิบัติการที่สืบทอดแนวคิดจาก Unix) ที่นำมาสู่ macOS ในปัจจุบัน

ร่วมกับเพื่อนร่วมงานชื่อ **Dennis Ritchie** (เดนนิส ริตชี) ผู้คิดค้นภาษา **C** — Unix ถูกเขียนใหม่ด้วยภาษา C ในช่วงปี 1972–1973 ทำให้ย้ายไปรันบนเครื่องยี่ห้ออื่นได้ (portable = พกพา/ย้ายที่ได้) ซึ่งเป็นไอเดียที่เปลี่ยนวงการ ทั้งคู่ได้รับรางวัล **Turing Award** (รางวัลสูงสุดของวงการคอมพิวเตอร์ เทียบเท่าโนเบล) ปี 1983

และนี่คือจุดที่ทำให้เรื่องนี้ใกล้ตัวคุณ: ปี 2006 ทอมป์สันย้ายไป Google และปี 2007 ตอนอายุ 64 เขากับเพื่อนร่วมงานอีกสองคนเริ่มออกแบบ**ภาษา Go** — ภาษาที่คอร์สนี้จะใช้เรียน ย้อนไปก่อนหน้านั้น ปี 1992 เขายังเคยร่วมคิด **UTF-8** (ระบบเข้ารหัสตัวอักษรที่ทำให้คอมพิวเตอร์แสดงภาษาได้ทุกภาษา รวมทั้งภาษาไทย) กับ **Rob Pike**

ข้อคิด: เขาไม่ได้ตั้งใจปฏิวัติวงการ เขาแค่**เจอปัญหา แล้วรู้ลึกพอที่จะสร้างเครื่องมือแก้ปัญหานั้นเอง** — การสร้าง Unix ได้ เพราะเขาเข้าใจว่าใต้โค้ดลงไปมีอะไรเกิดขึ้นบ้าง

### Rob Pike (รอบ ไพก์) — คนที่ออกแบบวิธีที่ข้อความเดินทางรอบโลก

ไพก์เป็นวิศวกรชาวแคนาดา ทำงานที่ Bell Labs ปี 1980–2002 ในทีมเดียวกับทอมป์สัน เป็นสมาชิกทีมพัฒนา Unix เขียนระบบหน้าต่าง (window system = ระบบที่ทำให้จอมีหลายหน้าต่างซ้อนกัน) ตัวแรก ๆ ของ Unix ร่วมสร้างระบบปฏิบัติการวิจัยชื่อ Plan 9 และร่วมคิด UTF-8 กับทอมป์สัน — ถ้าสงสัยว่าทำไมเว็บ/อีเมลภาษาไทยถึงแสดงผลถูกต้องได้ทั้งโลก ส่วนหนึ่งต้องขอบคุณงานชิ้นนี้

เขายังเขียนหนังสือคลาสสิกกับ **Brian Kernighan** (ไบรอัน เคอร์นิแกน) ที่ dev รุ่นเก๋าแทบทุกคนเคยอ่าน ปี 2002 ย้ายไป Google ปี 2007 เป็นหนึ่งในสามคนร่วมออกแบบภาษา Go และปี 2026 นี้เองเพิ่งได้รับรางวัล **USENIX Lifetime Achievement Award** (รางวัลเกียรติยศตลอดชีพด้านระบบคอมพิวเตอร์) ยกย่องงานที่ครอบคลุมทั้งระบบปฏิบัติการ ภาษาโปรแกรม และการเข้ารหัสข้อมูล

ข้อคิด: เขาไม่ได้เก่ง "ภาษาเดียว" แต่เก่ง**ชั้นใต้** — เข้าใจ OS เข้าใจคนใช้ เข้าใจว่าข้อความถูกแทนเป็นข้อมูลยังไง แล้วความรู้นั้นก็พาเขาสร้างภาษาที่คนครึ่งโลกใช้ทุกวัน

### Richard Stallman (ริชาร์ด สตอลแมน) — คนที่เริ่มสร้าง OS ทั้งระบบเพราะอยากแก้เครื่องพิมพ์

สตอลแมนทำงานที่ห้องแล็บ AI ของ MIT (สถาบันเทคโนโลยีแมสซาชูเซตส์) ตั้งแต่ปี 1971 ในยุคที่นักเขียนโปรแกรมแบ่งปันโค้ดกันอย่างเสรี เขาเขียนโปรแกรมแก้ข้อความ (text editor) ชื่อ **Emacs** รุ่นแรกปี 1976 — โปรแกรมที่ขึ้นชื่อเรื่อง "ยืดหยุ่นและขยายได้" (extensible = เพิ่มความสามารถเองได้) และคนใช้กันถึงทุกวันนี้

จุดเปลี่ยนของชีวิตคือเรื่องเล็ก ๆ ซึ่งเขาเล่าเองบนเว็บไซต์โครงการ GNU: มีคนปฏิเสธให้ source code ของโปรแกรมควบคุมเครื่องพิมพ์ห้องแล็บ — ฟีเจอร์บางอย่างที่ขาดไปทำให้ใช้เครื่องพิมพ์ลำบากมาก แต่เขาแก้ไม่ได้เพราะไม่มีสิทธิ์เห็นโค้ด เขาตัดสินใจว่า จะไม่อยู่ในโลกที่ซอฟต์แวร์เป็น "กล่องดำ" (black box = มองข้างในไม่เห็น แก้เองไม่ได้) อีกต่อไป

วันที่ 27 กันยายน 1983 เขาประกาศโครงการ **GNU** — ความพยายามเขียนระบบปฏิบัติการแบบ Unix ทั้งระบบด้วยซอฟต์แวร์เสรี (free software = ซอฟต์แวร์ที่ผู้ใช้มีอิสระดูโค้ด แก้ไข และแบ่งปัน — free แปลว่าเสรีภาพ ไม่ใช่ราคาศูนย์) ชื่อ GNU เป็นตัวย่อแบบ recursive (ขยายแล้วมีตัวเองซ้ำข้างใน): **GNU's Not Unix** — "GNU ไม่ใช่ Unix" เริ่มลงมือเขียนจริง 5 มกราคม 1984 และตั้งมูลนิธิ FSF (Free Software Foundation) ตุลาคม 1985

ที่น่าทึ่งคือเขาสร้างเครื่องมือสำคัญเกือบทุกชิ้นด้วยตัวเอง: GNU Emacs, GCC (GNU Compiler Collection = ชุด compiler หลายภาษา), GDB (GNU Debugger = โปรแกรมช่วยไล่หาจุดบกพร่อง ซึ่ง dev เรียกว่า bug = แมลง)

เขายังคิดสัญญาอนุญาต **GPL** ที่รับรองว่าคนแก้โค้ดแล้วแจกต่อ ต้องรักษาอิสระแบบเดียวกันต่อไป (แนวคิดนี้เรียกว่า copyleft = เล่นคำกลับด้านจาก copyright)

และระบบที่เราเรียกสั้น ๆ ว่า "Linux" จริง ๆ คือ**เคอร์เนลลินุกซ์ + เครื่องมือ GNU มากมาย** คนในโครงการ GNU จึงย้ำว่าควรเรียกว่า GNU/Linux

ข้อคิด: จุดเริ่มต้นของเขาคือความอยาก**แก้สิ่งที่พัง** แล้วค้นพบว่าถ้าไม่มีสิทธิ์เห็นโค้ดก็ทำอะไรไม่ได้ — เขาจึงตอบโต้ด้วยการเรียนรู้ทุกชั้น ตั้งแต่ compiler ถึง editor ถึงกฎหมาย แล้วสร้างทางเลือกของตัวเองขึ้นมาทั้งระบบ

### Linus Torvalds (ลินุส ทอร์วัลด์ส) — นักศึกษาที่บอกว่า "แค่งานอดิเรก"

ทอร์วัลด์สเป็นนักศึกษาในฟินแลนด์ (เกิดปี 1969) ปี 1991 ตอนอายุ 21 เขาซื้อคอมพิวเตอร์ส่วนตัวเครื่องใหม่ (CPU รุ่น 386) อยากเรียนรู้การทำงานของมันให้ลึก ใช้ระบบปฏิบัติการเพื่อการศึกษาชื่อ Minix อยู่แต่รู้สึกจำกัดเกินไป เลยเริ่มเขียน**เคอร์เนลของตัวเอง**

วันที่ 25 สิงหาคม 1991 เขาโพสต์ประกาศในกลุ่มข่าวออนไลน์ (ยุคก่อนเว็บ ผู้คนคุยกันผ่านระบบข้อความชื่อ Usenet) ใจความว่า:

> "ผมกำลังเขียนระบบปฏิบัติการ (ฟรี) — แค่งานอดิเรก คงไม่ใหญ่และมืออาชีพเท่า GNU" (ข้อความจริง: *"I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu) for 386(486) AT clones."*)

เขาปล่อยเวอร์ชันแรก (0.01) วันที่ 17 กันยายน 1991 จาก "งานอดิเรก" ที่ไม่คิดว่าจะใหญ่ โค้ดชิ้นนี้เติบโตเป็น**เคอร์เนลลินุกซ์** ใต้เซิร์ฟเวอร์ (server = เครื่องที่ให้บริการเว็บไซต์/แอปแก่คนอื่น) ส่วนใหญ่ของโลก และเป็นฐานของ Android บนมือถือคุณ ปี 2005 เมื่อการดูแลโค้ดลินุกซ์ที่โตขึ้นเริ่มยุ่งยาก เขาก็ทำแบบคนในเรื่องเล่าข้างต้น: **สร้างเครื่องมือของตัวเอง** — นั่นคือ **Git** (ระบบ version control = ระบบบันทึกประวัติการแก้ไขโค้ด ให้หลายคนทำงานร่วมกันได้) ที่คุณจะใช้ตลอดอาชีพ

ข้อคิด: เขาไม่ใช่ศาสตราจารย์หรือแล็บวิจัยใหญ่ — เป็นแค่นักศึกษาที่**อยากรู้ว่าเครื่องของเขาทำงานยังไง** แล้วลงมือทำโดยไม่รอให้ใครมาสอนครบก่อน

### สิ่งที่คนทั้งสี่มีเหมือนกัน

สังเกตว่า**ไม่มีใครเก่งเพราะจำ API ของ framework ตัวใดตัวหนึ่ง** (API = หน้าตาที่โปรแกรมเปิดให้คนอื่นเรียกใช้) — แต่ทุกคนรู้**ชั้นใต้**ของระบบ และเพราะรู้ชั้นใต้ พอเจอเครื่องมือที่ไม่พอใจ พวกเขาถึง**เขียนเครื่องมือใหม่เองได้**: Unix, Emacs, Linux, Git, Go ล้วนเกิดจาก "ของที่มีอยู่ไม่ดีพอ งั้นฉันสร้างเอง" และเครื่องมือเหล่านี้ไม่ใช่ของในพิพิธภัณฑ์ — คุณกำลังใช้มันอยู่ทุกวัน

## ฟังดูยิ่งใหญ่ แต่... มันทำให้ผม "เร็ว" ขึ้นจริงเหรอ?

คำถามที่ควรถามที่สุด ขอตอบตรง ๆ: ถ้าเป้าหมายคือได้งานใน 3 เดือน การนั่งเรียนพื้นฐาน 33 ตอนอาจไม่ใช่เส้นทางสั้นที่สุด — แต่คอร์สนี้สร้างเพื่อคนที่คิดยาวกว่า และนี่คือเหตุผลเชิงปฏิบัติว่าทำไมความรู้ชั้นใต้ทำให้คุณ**เร็วในระยะยาว**:

1. **ของที่เปลี่ยนไว ไม่ใช่ของที่ควรทุ่มเวลาจดจำ** — framework มาใหม่ทุก 2–3 ปี แต่ตัวแปร (variable = ช่องเก็บค่า), เงื่อนไข, การวนซ้ำ (loop), ฟังก์ชัน (function = ชุดคำสั่งย่อยมีชื่อ), หน่วยความจำ, OS — ไม่เปลี่ยนเป็นทศวรรษ ๆ พอรู้พื้นฐาน อะไรใหม่ ๆ ก็คือ "ของเก่าห่อใหม่" ที่เรียนรู้ได้เร็ว
2. **เวลาโปรแกรมพัง คุณเดาได้ว่าพังที่ชั้นไหน** — dev ที่รู้แต่ชั้นบน พอเจอ error (ข้อความแจ้งข้อผิดพลาด) ที่ไม่เคยเห็นก็มั่วไปเรื่อย แต่คนรู้ชั้นใต้ไล่ได้: ปัญหามาจากโค้ดฉัน หน่วยความจำ หรือ OS? การ debug (ไล่หาจุดที่ทำให้โปรแกรมพัง) ที่ดีคือการเดาอย่างมีหลักการ ไม่ใช่การสุ่ม
3. **ย้ายภาษา ย้ายสายงานได้** — คนที่เรียนแค่ "วิธีใช้ framework X" ย้ายแทบไม่ได้ แต่คนที่รู้ว่าทุกภาษามีตัวแปร เงื่อนไข ฟังก์ชันเหมือนกัน จะมองภาษาใหม่เป็นแค่ "ไวยากรณ์ที่ต่างไป" แล้วปรับตัวได้ในสัปดาห์ ไม่ใช่เดือน
4. **ได้ยืนในจุดเดียวกับคนที่สร้างเครื่องมือ** — ถึงไม่ต้องเขียน kernel เป็นอาชีพ แต่การเคยเห็น "ข้างใน" ทำให้ใช้ของเหล่านั้นอย่างเข้าใจ ไม่เชื่ออย่างงมงาย และถ้าอยากสร้างเครื่องมือเองสักวัน จะรู้ว่าต้องเริ่มตรงไหน

ขอพูดอย่างถ่อมตัว: ไม่มีการันตีว่าเรียนแล้วเก่งขึ้นทันตา — แต่นี่คือเส้นทางที่คนในเรื่องเล่าข้างต้นและ dev ระดับโลกอีกจำนวนมากเดินผ่านมา และเป็นเส้นทางที่ไม่ตกเทรนด์

## ลงมือทำ (เบา ๆ): เห็นหน้าโค้ดจริงครั้งแรก

ยังไม่ต้องติดตั้งอะไรหนัก (ตอนหน้าจะติดตั้งกันละเอียด) ขอดูกันก่อนว่าโค้ด "ชั้น 3" หน้าตาเป็นยังไง

คอร์สนี้เลือก **Go** เป็นภาษาแรก ด้วยเหตุผลที่เข้ากับเรื่องเล่าข้างบน: Go เกิดจากคนที่สร้าง Unix (ทอมป์สัน, ไพก์) ซึ่งรู้ดีว่าการเขียนระบบใหญ่จริง ๆ ต้องเจออะไร — พวกเขาออกแบบภาษาให้**อ่านง่าย เรียบง่าย compile เร็ว** (compiler ของ Go แปลงโค้ดไวมาก แทบไม่ต้องนั่งรอ) และทุกวันนี้เครื่องมือโครงสร้างพื้นฐานที่ dev ใช้ทั่วโลกอย่าง Docker หรือ Kubernetes (ระบบจัดการแอปจำนวนมากบนเซิร์ฟเวอร์) ก็เขียนด้วย Go

นี่คือโปรแกรม Go ที่สั้นที่สุด — "สวัสดีชาวโลก" (hello world = โปรแกรมแรกที่คนเรียนทุกภาษามักเขียน เพื่อตรวจว่าเครื่องมือครบหรือยัง):

```go
package main

import "fmt"

func main() {
    fmt.Println("สวัสดี ชาวโลก!")
}
```

ถ้ายังติดตั้ง Go ไม่เป็น ไม่ต้องกังวลว่าตอนนี้จะรันไม่ได้ — แค่อยากให้เห็นหน้าโค้ดก่อน ตอนหน้าเราจะติดตั้งแล้วรันด้วยกัน

เซฟเป็นไฟล์ `main.go` แล้วรัน:

```
go run main.go
```

ผลลัพธ์:

```
สวัสดี ชาวโลก!
```

(ทดสอบจริงบนเครื่อง Go 1.24.4 — รันผ่าน ได้ผลลัพธ์ข้างบน — ตอนหน้าจะพาติดตั้ง Go แล้วรันโค้ดแรกด้วยกันเอง)

ดูทีละบรรทัด เพราะคำพวกนี้จะอยู่กับเราตลอดคอร์ส:

- `package main` — โค้ด Go ทุกไฟล์อยู่ใต้ "package" (แพ็กเกจ = กลุ่มของชุดโค้ด) และชื่อ `main` มีความหมายพิเศษ: บอก compiler ว่า "โปรแกรมเริ่มจากตรงนี้"
- `import "fmt"` — ขอยืมกล่องเครื่องมือสำเร็จรูปชื่อ `fmt` (ย่อจาก format) ซึ่งมีฟังก์ชัน (function = ชุดคำสั่งย่อยที่มีชื่อ เรียกใช้ซ้ำได้) สำหรับพิมพ์ข้อความออกจอ
- `func main() { ... }` — ประกาศฟังก์ชันชื่อ `main` โค้ดในปีกกา `{ }` คือคำสั่งที่ทำงานเมื่อรันโปรแกรม
- `fmt.Println("สวัสดี ชาวโลก!")` — พิมพ์ข้อความในเครื่องหมายคำพูด (เรียกว่า string = สายอักขระ) แล้วขึ้นบรรทัดใหม่ (`Println` = print line = พิมพ์ทีละบรรทัด)

ข้อสังเกต: โค้ด Go ไม่ต้องใส่ `;` ต่อท้ายบรรทัด และไม่บังคับการเว้นวรรค — แต่ Go มีเครื่องมือ `gofmt` จัดรูปแบบโค้ดให้เป็นแบบเดียวกันอัตโนมัติ เป็นปรัชญาของภาษา: ให้ทุกคนเขียนแล้วหน้าตาเหมือนกัน จะได้อ่านโค้ดกันง่าย

เบื้องหลังที่ควรรู้ไว้ (จะลงลึกในระยะ 2–3): เวลาพิมพ์ `go run main.go` เกิดเหตุการณ์ประมาณนี้

```
main.go (source code ที่มนุษย์เขียน)
        │
        ▼  compiler ของ Go แปลภาษา
ภาษาเครื่อง (machine code ที่ CPU อ่านได้)
        │
        ▼  OS ช่วยโหลดโปรแกรมเข้าไปทำงาน
CPU ทำงานตามคำสั่ง → พิมพ์ "สวัสดี ชาวโลก!"
```

จะเห็นว่าตั้งแต่บรรทัดแรกของคอร์ส โค้ดของคุณวิ่งผ่านทั้ง compiler (ชั้น 3), ระบบปฏิบัติการ (ชั้น 2) และ CPU (ชั้น 1) — สามชั้นที่เราจะขุดลงไปทำความรู้จักตลอดซีรีส์

## แผนที่เดินทาง: 33 ตอน ใน 7 ระยะ

เผื่ออยากรู้ว่า "พื้นฐานที่แท้จริง" มีอะไรบ้าง ขอแจกแผนที่เส้นทางทั้งหมด (รายละเอียดจะแยกเล่าเมื่อถึงเวลา) — ชื่อบทที่ยังไม่คุ้นตาไม่ต้องกังวล เดี๋ยวจะสอนทีละคำเมื่อถึงเวลา:

```
ระยะ 0  ปฐมนิเทศ         (ตอน 1–2)   รู้จักคอร์ส + ติดตั้งเครื่องมือ
ระยะ 1  Go: ภาษาแรก      (ตอน 3–7)   ตัวแปร, เงื่อนไข, loop, ฟังก์ชัน, โครงสร้างข้อมูล
ระยะ 2  ฮาร์ดแวร์         (ตอน 8–12)  เลขฐานสอง → วงจร → หน่วยความจำ → CPU → assembly
ระยะ 3  C + หน่วยความจำ  (ตอน 13–17) ภาษา C, pointer, stack/heap, buffer overflow
ระยะ 4  ระบบปฏิบัติการ    (ตอน 18–21) process, syscall, virtual memory, เขียน shell จิ๋ว
ระยะ 5  ทฤษฎีการคำนวณ    (ตอน 22–25) automata, parser, Turing machine
ระยะ 6  compiler          (ตอน 26–30) สร้างภาษาโปรแกรมของเราเองทั้งภาษา
ระยะ 7  รวมพลัง          (ตอน 31–33) เข้าใจ Go runtime + โปรเจกต์จบคอร์ส
```

ลองเทียบกับ "ตึก" ตอนต้น: เริ่มที่ชั้นภาษา (ระยะ 1) ขุดลงถึงฮาร์ดแวร์ (ระยะ 2–3) ไต่ผ่าน OS (ระยะ 4) ขึ้นมาดูทฤษฎีและ compiler (ระยะ 5–6) แล้วปิดท้ายด้วยการต่อทุกชั้น (ระยะ 7) — เมื่อจบคอร์ส คุณจะรู้จักทุกชั้นของคอมพิวเตอร์ ไม่ใช่ในฐานะผู้โดยสาร แต่ในฐานะคนที่เดินสำรวจมาทุกชั้น

## โจทย์ประจำตอน

ทุกตอนจะมีโจทย์ 2 ระดับ เพื่อให้ "ความรู้" กลายเป็น "ของตัวเอง" — ตอนแรกขอเบา ๆ ก่อน

### ระดับ Drill (5–10 นาที)

ด้วยคำพูดของตัวเอง อธิบายให้คนที่ไม่เคยเขียนโปรแกรมฟังว่า:

1. "compiler" กับ "kernel" ต่างกันยังไง (ห้ามใช้ศัพท์ dev ซ้อนศัพท์)
2. "framework" กับ "ภาษาโปรแกรม" ต่างกันยังไง

ถ้าอธิบายให้คนนอกฟังรู้เรื่อง แปลว่าเข้าใจจริง — ถ้าติดขัด ให้กลับไปอ่านส่วน "ตึกหลายชั้น" อีกครั้ง

### ระดับ Mini-project (30–60 นาที)

1. **วาดแผนที่ตึกของคุณเอง** — วาด "ตึก 5 ชั้น" ของซอฟต์แวร์ตามที่คุณเข้าใจ แล้วเขียนชื่อเทคโนโลยีที่รู้จักลงในแต่ละชั้น (ชั้น 5 อาจเป็นเว็บที่คุณใช้ประจำ, ชั้น 4 เป็น framework ที่เคยได้ยิน) ไม่ต้องถูกต้องสมบูรณ์ — จุดประสงค์คือให้เห็นว่า "สิ่งที่ฉันรู้ตอนนี้" อยู่ชั้นไหน และ "สิ่งที่คอร์สนี้จะสอน" อยู่ชั้นไหน
2. **เขียนเป้าหมายส่วนตัว 1 ย่อหน้า** — ตอบคำถาม "เครื่องมืออะไรที่ฉันอยากสร้างเองสักวัน" (ไม่ต้องใหญ่ จะเป็นสคริปต์ (โปรแกรมสั้น ๆ ช่วยงานอัตโนมัติ) ช่วยงานเล็ก ๆ ก็ได้) แล้วเก็บไว้ให้ดี เพราะตอนจบคอร์ส (ตอนที่ 33) คุณจะกลับมาเปิดดูว่า "ตอนนี้ฉันสร้างได้หรือยัง"

## สรุปตอนที่ 01

- "เขียนเว็บได้" คือการใช้เครื่องมือชั้นบนให้คล่อง ส่วน "รู้พื้นฐานที่แท้จริง" คือการเข้าใจทุกชั้นใต้เครื่องมือ ตั้งแต่ compiler ถึง OS ถึงฮาร์ดแวร์
- คนที่สร้างเครื่องมือที่คุณใช้อยู่ทุกวัน (Unix, Emacs, Linux, Git, Go, UTF-8) ล้วนเข้าใจชั้นใต้ แล้วใช้ความเข้าใจนั้น**สร้างเครื่องมือใหม่เมื่อของเดิมไม่พอใจ**
- ความรู้นี้ทำให้คุณเร็วในระยะยาว เพราะของที่ไม่เปลี่ยนคือรากฐาน ส่วนของที่เปลี่ยนทุกปีคือเปลือกนอก
- คอร์สนี้จะพาเราขุดลงไปทีละชั้นด้วยภาษา Go เป็นพาหนะ — 33 ตอน 7 ระยะ

ตอนหน้า (ตอน 02) เราจะติดตั้งเครื่องมือจริง: Go, โปรแกรมแก้โค้ด และ terminal (หน้าต่างคำสั่ง) แล้วรันโปรแกรมแรกด้วยมือคุณเอง

ระหว่างรอ ลองหาคำตอบว่า "ระบบปฏิบัติการที่คุณใช้อยู่ตอนนี้คืออะไร และมันใช้ kernel อะไร" — คำถามนี้แหละคือจุดเริ่มต้นของการรู้จักชั้นใต้
