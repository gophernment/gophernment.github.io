ตอนที่ 11 เราเห็น CPU วนลูป **fetch → decode → execute** (อ่านคำสั่ง → ถอดความหมาย → ลงมือทำ) แล้วพบว่าคำสั่งที่ CPU ตัวจิ๋วของเรา "อ่าน" จริง ๆ เป็นแค่**เลข 4 บิต** เช่น `0010` แปลว่า LOAD, `0111` แปลว่า ADD

คำถามธรรมชาติของตอนนี้คือ: **แล้วคนเขียนโปรแกรมจริง ๆ ต้องเขียนเป็นเลข 0/1 พวกนี้เองเหรอ?** ถ้าใช่ โปรแกรมใหญ่ ๆ อย่างเบราว์เซอร์หรือเกมคงเขียนไม่ไหวแน่

คำตอบคือ **ไม่ต้อง** — เรามี "ภาษาคนกลาง" ที่มนุษย์อ่านออก แต่ยังตรงกับเลขเครื่องแบบ 1 ต่อ 1 อยู่ ภาษานั้นชื่อ **assembly** และตอนนี้เราจะลงมือเขียนมันเป็นครั้งแรก

## 0. ปัญหา: เขียนเลข 0/1 ตรง ๆ มนุษย์ทนไม่ได้

ดูเลขเครื่องของ CPU จิ๋วตอน 11 อีกครั้ง (16 บิต ต่อคำสั่ง 4 ตัวนี้เป็นแค่ตัวอย่างเครื่อง 4 บิต):

| เลข 4 บิต | ความหมาย |
|---|---|
| `0010` | โหลดค่าจาก RAM มาใส่ ACC |
| `0111` | บวก ACC กับค่าจาก RAM |
| `1011` | เขียน ACC กลับลง RAM |
| `1100` | แสดงผลที่ LED |

CPU อ่านเลขเหล่านี้แล้วทำงานถูกต้อง 100% แต่**คน**จะจำได้ยังไงว่า `0111` คือ "บวก" ไม่ใช่ "ลบ" หรือ "คูณ"? พอโปรแกรมมี 100 คำสั่ง มันคือเลข 0/1 เรียงกันยาวหลายร้อยหลัก — แก้จุดเดียว ต้องไล่หาว่าเลขตัวไหนคือคำสั่งไหน ผิดพลาดง่ายมาก

> **คำศัพท์: assembly (แอสเซมบลี)** = ภาษาที่ให้เราเขียนคำสั่งเป็น "ตัวอักษรย่อที่จำง่าย" แทนเลขเครื่อง เช่น เขียน `ADD` แทน `0111` — แล้วมีโปรแกรมตัวหนึ่งชื่อ **assembler** (แอสเซมเบลอร์ = ตัวแปล) แปลตัวอักษรกลับเป็นเลขเครื่องให้ แบบ **1 ต่อ 1** (หนึ่งบรรทัด assembly → หนึ่งคำสั่งเครื่องพอดี ไม่มากไม่น้อย)

จุดสำคัญที่สุดที่ต้องจดไว้ตั้งแต่นาทีนี้:

> **assembly ไม่ใช่ภาษา "สูง" อย่าง Go — มันคือเลขเครื่องในชุดคนอ่าน** หนึ่งบรรทัด `ADD R1, R1, #1` กลายเป็นเลข 16 บิตหนึ่งตัวพอดี ไม่มีตัวแปร ไม่มี `if`/`for` สำเร็จรูป มีแต่ register, เลข, และการกระโดด

ทำไมต้องเรียนมัน ถ้า Go เขียนง่ายกว่าเยอะ? เพราะ assembly คือ**ชั้นเดียวกับสิ่งที่ CPU เห็น** — เขียน assembly ได้ เท่ากับคุณ "เห็นทะลุ" ลงไปว่าโปรแกรม Go ที่เขียนเมื่อหลายตอนก่อน จริง ๆ แล้ว CPU กำลังทำอะไรอยู่ ตรงนี้เองคือ "พื้นฐานที่แท้จริง" ที่เราตามหา

ดูภาพที่ 1 ตัวอย่างการแปลงหนึ่งบรรทัดให้เห็นภาพก่อน

![การแปลง assembly เป็น machine instruction 16 บิต](/assets/diagrams/ep12-01-assembly-to-machine.svg)

ภาพที่ 1: `ADD R1, R1, #1` (ซ้าย) ถูก assembler แปลเป็นเลข 16 บิต `0001 0010 0110 0001` (ขวา) แบบ 1 ต่อ 1 — สังเกตว่าแต่ละส่วนของบรรทัด (ADD, R1, R1, #1) มี "ช่อง" ของบิตที่ตรงกันชัดเจน

## 1. รู้จัก LC-3: เครื่องจำลองที่เราจะเขียนให้

เราจะไม่เขียน assembly ของชิปจริง (x86 / ARM) เพราะมันซับซ้อนเกินไปสำหรับก้าวแรก — แต่จะใช้ **LC-3** (Little Computer 3) ซึ่งเป็นเครื่องจำลองเพื่อการศึกษา ออกแบบมาให้เรียบแต่ครบทุกแนวคิดที่เครื่องจริงมี

> **คำศัพท์: ISA** (Instruction Set Architecture = สถาปัตยกรรมชุดคำสั่ง) = "พจนานุกรม" ที่บอกว่าเครื่องตัวนี้มีคำสั่งอะไรบ้าง แต่ละคำสั่งมีเลข opcode เท่าไหร่ มี register กี่ตัว — เราเจอคำนี้ครั้งแรกในตอน 11 แล้ว LC-3 ก็คือ ISA ตัวหนึ่ง เช่นเดียวกับที่ x86 (ชิป Intel/AMD) และ ARM (ชิปมือถือ / Raspberry Pi) มี ISA ของตัวเอง

LC-3 มี "ตัวละคร" ที่เรารู้จักจากตอน 10–11 อยู่แล้ว เพียงแต่คราวนี้เราเป็นคน**สั่งมัน**โดยตรง:

- **หน่วยความจำ 16 บิต** — มี 2¹⁶ = **65,536 ช่อง** แต่ละช่องเก็บข้อมูลได้ 16 บิต (1 word = 1 คำ = 16 บิต) และแต่ละช่องมี "address" (เลขที่ช่อง) กำกับเหมือนตู้จดหมาย
- **register 8 ตัว** ชื่อ **R0–R7** — ที่พักข้อมูลชั่วคราวใน CPU (ตอน 10) แต่ละตัวเก็บได้ 16 บิต นึกภาพเป็น "ลิ้นชัก 8 ใบ" ที่ CPU หยิบของเข้าออกได้เร็วที่สุด
- **condition code 3 ตัว** ชื่อ **N / Z / P** — flag 1 บิตที่ CPU ตั้งอัตโนมัติทุกครั้งที่เขียนค่าลง register (เดี๋ยวอธิบายละเอียดตอนเขียน loop)
- **PC** (Program Counter — ตัวชี้ว่าคำสั่งถัดไปอยู่ไหน) กับ **IR** (ที่พักคำสั่งที่เพิ่งอ่าน) — ตัวเอกจากตอน 11 ยังอยู่ครบ

> **คำศัพท์: opcode** (operation code = รหัสการทำงาน) = ส่วนของคำสั่งที่บอก "ทำอะไร" · **operand** (โอเปอร์แรนด์) = ส่วนที่บอก "ทำกับข้อมูลตัวไหน" — ใน LC-3 คำสั่งทุกตัวยาว 16 บิต โดย **4 บิตซ้ายสุดคือ opcode** (เก็บได้ 2⁴ = 16 ค่า แต่ LC-3 ใช้จริง 15 คำสั่ง เหลือ 1 ช่องว่างไว้) และ 12 บิตที่เหลือเป็น operand ซึ่งหน้าตาจะต่างกันไปตามคำสั่ง

## 2. คำสั่งที่ต้องใช้ในตอนนี้ (เราจะเรียนแค่ 9 ตัว)

LC-3 มีคำสั่ง 15 ตัว แต่ตอนนี้เราจะใช้แค่ 9 ตัวที่จำเป็นต่อการเขียน loop + ฟังก์ชัน:

| คำสั่ง | opcode | ความหมาย (แบบภาษาคน) | ตัวอย่าง |
|---|---|---|---|
| `ADD` | `0001` | บวก: เอา 2 ค่ามาบวก เก็บผลลง register | `ADD R1, R1, #1` |
| `AND` | `0101` | AND แบบบิต: ใช้ "เคลียร์ register ให้เป็น 0" ได้ | `AND R2, R2, #0` |
| `NOT` | `1001` | กลับบิตทุกตัว (0↔1): ใช้สร้าง "ค่าลบ" | `NOT R4, R3` |
| `LD` | `0010` | โหลดค่าจากหน่วยความจำเข้า register | `LD R3, LIMIT` |
| `ST` | `0011` | เก็บค่า register ลงหน่วยความจำ | `ST R2, RESULT` |
| `BR` | `0000` | กระโดดแบบมีเงื่อนไข (branch) | `BRnz LOOP` |
| `JSR` | `0100` | เรียกฟังก์ชัน (จำที่กลับไว้ก่อน) | `JSR MULT` |
| `RET` | — | กลับจากฟังก์ชัน (= `JMP R7`) | `RET` |
| `TRAP` | `1111` | ขอบริการจากระบบ (เช่น จบโปรแกรม) | `HALT` |

สังเกตสามเรื่องสำคัญที่จะเจอซ้ำ ๆ ตลอดบทความนี้:

**เรื่องที่ 1 — register คือ "ตัวแปร" เพียงอย่างเดียวที่มี** ใน assembly ไม่มีตัวแปรชื่อสวย ๆ อย่าง `sum` หรือ `total` มีแต่ R0–R7 ที่เรา**ต้องจำเอง**ว่าเก็บอะไรอยู่ ตรงนี้แหละที่ทำให้มือใหม่รู้สึกว่า assembly "เปลือย" — ไม่มีอะไรช่วยเตือนว่า register ไหนเก็บค่าอะไร มีแค่คอมเมนต์ที่เราเขียนกำกับไว้ให้ตัวเอง

**เรื่องที่ 2 — `#` นำหน้าคือ "ค่า immediate"** (ค่าเลขที่เขียนตรง ๆ ในคำสั่ง ไม่ใช่ register) เช่น `ADD R1, R1, #1` แปลว่า "เอา R1 บวกกับเลข 1 แล้วเก็บกลับ R1" — ส่วน `ADD R2, R2, R1` (ไม่มี `#`) แปลว่า "เอา R2 บวกกับ**ค่าที่อยู่ใน register R1**" ความต่างแค่มี `#` หรือไม่มี `#` นี้ สำคัญมาก อ่านพลาดโปรแกรมพังทันที และค่าที่ตามหลัง `#` เป็น**ค่าติดลบได้**ด้วย (เช่น `#-1` แปลว่า "ลบ 1") เพราะช่อง immediate เก็บค่าได้ตั้งแต่ −16 ถึง +15 (แบบ two's complement จากตอน 08)

**เรื่องที่ 3 — LC-3 ไม่มีคำสั่งลบ (SUB)** นี่คือจุดที่ชวนงงที่สุดสำหรับมือใหม่ เวลาจะลบ เราต้อง "สร้างค่าลบ" เองด้วยวิธี two's complement ที่เรียนในตอน 08: กลับบิตทุกตัวด้วย `NOT` แล้วบวก 1:

```
NOT R4, R3      ; กลับบิตทุกตัวของ R3 → R4 = ~R3
ADD R4, R4, #1  ; บวก 1 → R4 = -R3  (เลขลบของ R3)
ADD R4, R4, R1  ; R4 = R1 + (-R3) = R1 - R3  ← นี่คือการลบ
```

สามบรรทัดนี้คือ "สูตรลบ" มาตรฐานของ LC-3 เราจะใช้มันจริงในโปรแกรมแรก

> **ทำไม LC-3 ไม่ออกแบบคำสั่งลบมาให้?** เพื่อความเรียบง่าย — การลบ `a - b` ก็คือการบวก `a + (-b)` อยู่แล้ว และเครื่องรู้วิธี "กลับบิต + บวก 1" อยู่แล้ว (มันคือสอง's complement จากตอน 08) นักออกแบบ ISA จึงตัดคำสั่งลบออก เหลือแค่บวก อันนี้คือตัวอย่างจริงของ "ISA ยิ่งเล็ก ยิ่งเรียนง่าย" ซึ่งเป็นเหตุผลที่ LC-3 มีแค่ 15 คำสั่ง ในขณะที่ x86 มีเป็นร้อย

## 3. ลงมือทำ: โปรแกรมแรก — loop บวกเลข 1 ถึง 5

ถึงเวลารันจริงแล้ว โปรแกรมแรกของเราคือการบวกเลข `1 + 2 + 3 + 4 + 5` โดยใช้ **loop** (ลูป = การวนทำซ้ำ) — ซึ่งก็คือแนวคิดเดียวกับ `for` ใน Go (ตอน 04) เพียงแต่คราวนี้เราสร้างมันด้วยมือจาก "การกระโดด + flag"

ก่อนเขียนโค้ด มาดูภาพที่ 2 ที่วาดภาพรวมของลูปไว้ก่อน จะได้เห็น "แผนที่" ทั้งหมด

![การวนลูปด้วย condition code และ BR](/assets/diagrams/ep12-02-loop-condition-codes.svg)

ภาพที่ 2: ลูปใน assembly ไม่มีคำสั่ง `for` สำเร็จรูป — มีแค่ "ทำ → เปรียบเทียบ → กระโดดกลับ (หรือไม่กระโดด)" ซึ่งเป็นกลไกเดียวกับที่ Go ใช้เบื้องหลัง `for` ทุกตัว

เขียนโปรแกรมลงไฟล์ชื่อ `sum.asm`:

```
.ORIG x3000
    AND R2, R2, #0      ; R2 = 0  (ผลรวม เริ่มจากศูนย์)
    AND R1, R1, #0      ; R1 = 0
    ADD R1, R1, #1      ; R1 = 1  (ตัวเลขปัจจุบัน เริ่มจาก 1)
    LD  R3, LIMIT       ; R3 = 5  (ขีดจำกัด วนถึงเลขไหน)
LOOP
    ADD R2, R2, R1      ; ผลรวม = ผลรวม + ตัวเลขปัจจุบัน
    ADD R1, R1, #1      ; ตัวเลขปัจจุบัน = ตัวเลขปัจจุบัน + 1
    NOT R4, R3          ; R4 = ~R3   (เริ่ม "สูตรลบ")
    ADD R4, R4, #1      ; R4 = -R3
    ADD R4, R4, R1      ; R4 = R1 - R3  (ตัวเลขปัจจุบัน − ขีดจำกัด)
    BRnz LOOP           ; ถ้าผลเป็นลบหรือศูนย์ → วนกลับไปทำ LOOP
    HALT                ; มิฉะนั้น จบโปรแกรม (R2 = 15)
LIMIT .FILL #5
.END
```

**ไล่บรรทัดสำคัญทีละตัว:**

- `.ORIG x3000` (อ่านว่า "ออริจิน") = บอก assembler ว่าให้วางโปรแกรมเริ่มที่ address `x3000` (เลขขึ้นต้นด้วย `x` = เลขฐานสิบหก จากตอน 08) — `x3000` เป็นตำแหน่งมาตรฐานที่ LC-3 วางโปรแกรมของผู้ใช้ (พื้นที่ก่อนหน้านั้นสงวนไว้ให้ระบบ)
- `AND R2, R2, #0` และ `AND R1, R1, #0` = เคลียร์ R2 และ R1 ให้เป็น 0 — เป็นเทคนิคยอดนิยม เพราะการ AND ค่าใด ๆ กับ 0 จะได้ 0 เสมอ (จำจากตารางความจริง AND ตอน 09: 1 AND 0 = 0, 0 AND 0 = 0)
- `ADD R1, R1, #1` = ตั้งค่าเริ่มต้น R1 = 1 (ตัวเลขแรกที่จะบวก)
- `LD R3, LIMIT` = โหลดค่าที่ label ชื่อ `LIMIT` เข้า R3 — ตรงนี้ `LIMIT` คือ **label** (เลเบล = ป้ายชื่อติดที่ตำแหน่งหนึ่งในโปรแกรม ให้เราอ้างถึงด้วยชื่อแทนการนับ address เอง) ตัว assembler จะแทน label ด้วย address จริงให้ และทำนองเดียวกัน คำว่า `LOOP` ที่อยู่เดี่ยว ๆ บนบรรทัดของตัวเองก็คือ label อีกตัว — เป็น "จุดหมาย" ที่ `BRnz` จะกระโดดกลับมา
- `ADD R2, R2, R1` + `ADD R1, R1, #1` = ตัวลูป — บวกค่าปัจจุบันเข้ากองผลรวม แล้วเลื่อนไปตัวถัดไป
- `NOT R4, R3` → `ADD R4, R4, #1` → `ADD R4, R4, R1` = "สูตรลบ" สามบรรทัดจากตอนที่ 2 — คำนวณ R1 − R3 เพื่อดูว่า "เลยขีดจำกัดหรือยัง"
- `BRnz LOOP` = หัวใจของลูปทั้งหมด — `BR` ย่อจาก **branch** (กระโดด) และ `nz` บอกเงื่อนไขว่ากระโดดเมื่อ flag **N หรือ Z** ถูกตั้ง — นี่คือ "if (เงื่อนไข) วนต่อ" ของ assembly
- `HALT` = คำสั่งจบโปรแกรม (จริง ๆ แล้วเป็นตัวย่อของ `TRAP x25` — TRAP = การขอบริการจากระบบ เช่น "หยุดเครื่อง", "พิมพ์ตัวอักษร")
- `.FILL #5` = pseudo-instruction (คำสั่งหลอก = คำสั่งที่ assembler เข้าใจ แต่ไม่ใช่คำสั่งเครื่องจริง) ที่บอกให้จองช่องหน่วยความจำ 1 ช่องแล้วใส่ค่า 5 ลงไป
- `.END` = บอก assembler ว่าจบไฟล์แล้ว

**แล้ว condition code N/Z/P ทำงานยังไงกันแน่?** นี่คือกลไกที่ทำให้ `BRnz` ตัดสินใจได้:

> **คำศัพท์: condition code (N/Z/P)** = flag 3 ตัว (1 บิตต่อตัว) ที่ CPU ตั้งค่า**อัตโนมัติทุกครั้ง**ที่เขียนผลลัพธ์ลง register — ถ้าผลลัพธ์เป็น**ลบ** (negative) ตั้ง N · เป็น**ศูนย์** (zero) ตั้ง Z · เป็น**บวก** (positive) ตั้ง P แล้วคำสั่ง `BR` จะอ่าน flag เหล่านี้มาประกอบการตัดสินใจว่าจะกระโดดหรือไม่

ลองเดินโปรแกรมในหัวทีละรอบ (เรียกว่า **trace** = การไล่ค่าทีละบรรทัด):

| รอบ | หลัง `ADD R2, R2, R1` → R2 | หลัง `ADD R1, R1, #1` → R1 | ค่า `R1 − R3` | flag | BRnz วนต่อ? |
|---|---|---|---|---|---|
| 1 | 1 | 2 | 2 − 5 = −3 | N | ✅ วน |
| 2 | 3 | 3 | 3 − 5 = −2 | N | ✅ วน |
| 3 | 6 | 4 | 4 − 5 = −1 | N | ✅ วน |
| 4 | 10 | 5 | 5 − 5 = 0 | Z | ✅ วน |
| 5 | 15 | 6 | 6 − 5 = +1 | P | ❌ หลุด → HALT |

ตอนจบ **R2 = 15** = ผลรวมของ 1+2+3+4+5 พอดี — loop ทำงานถูกต้อง

> **ความลับที่ซ่อนอยู่ในตารางนี้:** สังเกตว่า flag ถูกตั้ง**โดยคำสั่ง `ADD R4, R4, R1`** (บรรทัดสุดท้ายก่อน `BR`) ไม่ใช่ตั้งโดย `BR` เอง — `BR` แค่ "อ่าน" flag ที่คำสั่งก่อนหน้าเพิ่งตั้งไว้ นี่คือเหตุผลว่าทำไมใน assembly ลำดับคำสั่งถึงสำคัญมาก: ถ้าเราเผลอแทรกคำสั่งอื่น (ที่เขียน register) ไว้ระหว่างการบวกกับ `BR` flag จะถูกเปลี่ยน และ `BR` จะตัดสินใจผิดทันที

ถึงตรงนี้ ถ้าอยากเห็นว่าทำไมเรื่องนี้ถึง "สำคัญต่อชีวิตจริง" ลองนึกถึง `for i := 1; i <= 5; i++` ใน Go (ตอน 04) — ในที่สุด compiler (คอมไพเลอร์ = โปรแกรมที่แปลงโค้ดภาษาสูงอย่าง Go ให้กลายเป็นภาษาเครื่อง) ก็แปลงมันเป็นกลไกแบบเดียวกับภาพที่ 2 นี้เป๊ะ: ตั้งค่าเริ่ม → เปรียบเทียบ → ตั้ง flag → กระโดดกลับ (หรือหลุดออก) เราไม่ได้ "กำจัด" ลูปที่ซับซ้อน เราแค่ได้เครื่องมือที่เขียนมันสั้นลง

## 4. เรียกฟังก์ชัน: JSR + RET (กลไกเดียวกับ Go เรียกฟังก์ชัน)

ใน Go (ตอน 05) เราเขียน `func` แล้วเรียกด้วยชื่อฟังก์ชันสบาย ๆ — เบื้องหลังมีคำถามสองข้อที่ตอนนั้นเรายังตอบไม่ได้:

1. ตอนเรียกฟังก์ชัน CPU **กระโดดไปที่โค้ดของฟังก์ชัน** ยังไง?
2. ตอนฟังก์ชันจบ CPU **รู้ได้ยังไงว่าต้องกลับมาตรงไหนต่อ**?

assembly ตอบทั้งสองข้อด้วยคำสั่ง 2 ตัว: `JSR` (กระโดดไป) + `RET` (กระโดดกลับ) ดูภาพที่ 3 ก่อน

![การเรียกฟังก์ชันด้วย JSR และ RET ผ่าน R7](/assets/diagrams/ep12-03-jsr-ret-r7.svg)

ภาพที่ 3: `JSR MULT` จำ address ถัดไป (`x3003`) ไว้ที่ register **R7** ก่อนกระโดดไปฟังก์ชัน `MULT` — พอฟังก์ชันจบ `RET` (ย่อจาก `JMP R7`) ก็กระโดดกลับมาที่ `x3003` พอดี

> **คำศัพท์: return address (รีเทิร์น แอดเดรส)** = "ที่อยู่สำหรับกลับ" — address ของคำสั่งที่ต้องกลับมาทำต่อเมื่อฟังก์ชันจบ · **subroutine (ซับรูทีน)** = อีกชื่อหนึ่งของฟังก์ชันในระดับเครื่อง · **calling convention (คอลลิง คอนเวนชัน)** = ข้อตกลงว่า register ตัวไหนใช้ส่งค่าเข้า/รับค่ากลับ และใครเป็นคนเก็บรักษา register — เป็นหัวข้อเต็ม ๆ ของตอน 15

โปรแกรมที่สอง: ฟังก์ชัน `MULT` ที่คูณเลขด้วยการบวกซ้ำ (3 × 4 = 12) เขียนลงไฟล์ `mult.asm`:

```
.ORIG x3000
MAIN
    LD  R0, A           ; R0 = 3  (ตัวตั้ง)
    LD  R1, B           ; R1 = 4  (ตัวคูณ)
    JSR MULT            ; เรียกฟังก์ชัน MULT (R7 = ที่กลับ = x3003)
    ST  R2, RESULT      ; เก็บผล R2 (= 12) ลงหน่วยความจำ
    HALT
A      .FILL #3
B      .FILL #4
RESULT .FILL #0

; ---- ฟังก์ชัน MULT: คำนวณ R2 = R0 * R1 ด้วยการบวกซ้ำ ----
MULT
    AND R2, R2, #0      ; R2 = 0  (ตัวสะสมผลคูณ)
MLOOP
    ADD R2, R2, R0      ; R2 = R2 + R0  (บวกตัวตั้งเข้าไปอีกครั้ง)
    ADD R1, R1, #-1     ; R1 = R1 - 1  (นับถอยหลังตัวคูณ)
    BRp MLOOP           ; ถ้า R1 > 0 (flag P) → วนบวกต่อ
    RET                 ; กลับไปยัง caller (= JMP R7)
.END
```

**ไล่บรรทัดของฟังก์ชัน `MULT` (ส่วน MAIN ข้างบนตรงไปตรงมา — โหลดค่า แล้วเรียกฟังก์ชัน):**

- `AND R2, R2, #0` = เคลียร์ R2 (ตัวสะสมผลคูณ) เริ่มจาก 0 — **สำคัญมาก!** ถ้าไม่เคลียร์ ค่าค้างเก่าใน R2 จะทำให้ผลคูณผิดตั้งแต่เริ่ม
- `ADD R2, R2, R0` = บวกตัวตั้ง (R0) เข้าไปอีกครั้ง — นี่คือ "บวกซ้ำ" ที่ใช้แทนการคูณ
- `ADD R1, R1, #-1` = นับถอยหลังตัวคูณลงทีละ 1 (ค่าติดลบ `#-1` ใช้ได้ เพราะช่อง immediate เก็บได้ถึง −16 ตามที่เรียนในตอนที่ 2)
- `BRp MLOOP` = ถ้า R1 ยังเป็นบวก (flag P) → วนกลับไปที่ label `MLOOP` เพื่อบวกอีกครั้ง
- `RET` = จบฟังก์ชัน กระโดดกลับไปที่ address ที่ R7 เก็บไว้

ไล่ดูแล้วจะเห็นว่า `MULT` ก็คือลูปจากโปรแกรมแรกนั่นเอง — เพียงแต่มี `RET` ต่อท้ายเพื่อ "กลับ" ไปหาคนเรียก

**ไล่กลไกการเรียกฟังก์ชัน:**

1. `JSR MULT` ทำ **3 อย่างในจังหวะเดียว**: (ก) ก๊อป address ของคำสั่งถัดไป (`x3003`) ลง **R7** (ข) แล้วกระโดดไปที่ `MULT` — ดังนั้น R7 คือ "ที่ที่ต้องกลับมา" นี่เอง
2. ฟังก์ชัน `MULT` ทำงานจนถึง `RET` ซึ่งย่อมาจาก `JMP R7` = "กระโดดไปที่ address ที่ R7 ชี้" → กลับมาที่ `x3003` พอดี
3. `ST R2, RESULT` เก็บผลลัพธ์ 12 ลงหน่วยความจำ แล้ว `HALT`

เดิน trace ฟังก์ชัน `MULT` (R0=3, R1=4 ตั้งแต่แรก):

| วน | `ADD R2, R2, R0` → R2 | `ADD R1, R1, #-1` → R1 | flag | BRp วนต่อ? |
|---|---|---|---|---|
| 1 | 3 | 3 | P | ✅ วน |
| 2 | 6 | 2 | P | ✅ วน |
| 3 | 9 | 1 | P | ✅ วน |
| 4 | 12 | 0 | Z | ❌ หลุด → RET |

ผลลัพธ์ **R2 = 12** = 3 × 4 พอดี (การคูณก็คือ "บวกซ้ำ" — เราเพิ่งเห็นด้วยตาว่ามันเป็นเช่นนั้นจริง ๆ)

> **จุดอันตรายที่มือใหม่ต้องรู้: ฟังก์ชัน "ทับ" ค่า register ของผู้เรียกได้** สังเกตว่า `MULT` เปลี่ยนค่า **R1** (นับถอยหลังจนเหลือ 0) — ถ้า `MAIN` ยังอยากใช้ค่าเดิมของ R1 ต่อหลังกลับมา มันจะพบว่า R1 กลายเป็น 0 ไปแล้ว! วิธีแก้คือก่อนเรียกฟังก์ชัน ต้อง **save** (เก็บค่าเดิมไว้ที่ไหนสักแห่ง เช่น ในหน่วยความจำ) แล้วหลังกลับมาค่อย **restore** (คืนค่า) — นี่คือที่มาของ calling convention และเป็นเหตุผลที่ register จำนวนจำกัด (8 ตัว) กลายเป็น "ทรัพยากรมีค่า" ที่ต้องบริหาร

สองแนวคิดนี้ — "loop = กระโดดกลับ + flag" และ "ฟังก์ชัน = JSR จำที่กลับ + RET" — คือหัวใจของ assembly ทั้งหมด ต่อให้เขียนโปรแกรมระดับสูงแค่ไหน ในที่สุดมันก็ถูกแปลงลงมาเป็นกลไกสองอย่างนี้ทั้งสิ้น

## 5. วิธีรันจริง ๆ (ใน LC3Tools)

เราพิสูจน์ว่าโค้ดถูกต้องโดยการรันจริง (ไม่ใช่แค่ "อ่านแล้วน่าจะถูก"):

**ถ้าใช้ GUI:**
1. ดาวน์โหลด LC3Tools จากหน้า Releases (เลือกไฟล์ตามระบบ: `.AppImage` สำหรับ Linux, `.dmg` สำหรับ macOS, `.exe` สำหรับ Windows)
2. เปิดโปรแกรม → สร้าง/เปิดไฟล์ `sum.asm` → วางโค้ดด้านบนลงไป
3. กดปุ่ม **Assemble** เพื่อให้ assembler แปล assembly → machine code (ถ้าไม่มี error แปลว่า syntax ถูก)
4. กด **Run** หรือใช้ **Step** เพื่อเดินทีละคำสั่ง แล้วดูค่า register R0–R7 เปลี่ยนไปทีละบรรทัด
5. สังเกตว่า R2 จบที่ `15` (โปรแกรมแรก) หรือ `12` (โปรแกรมที่สอง) — และดู R7 เปลี่ยนค่าตอน `JSR` ด้วย

**ถ้าใช้ command line** (built จาก source): ตัว `assembler` รับไฟล์ `.asm` แล้วสร้างไฟล์ `.obj` (object file = machine code ที่รันได้) จากนั้น `simulator` โหลด `.obj` แล้วเปิด shell ให้เราพิมพ์คำสั่งควบคุม (พิมพ์ `help` ดูคำสั่งได้):

```
assembler sum.asm        ; แปล sum.asm → sum.obj
simulator sum.obj        ; โหลดแล้วเปิด shell จำลองเครื่อง
```

> **ทำไม "รันจริง" ถึงสำคัญ:** assembly ลงโทษความผิดพลาดเล็ก ๆ อย่างโหดร้าย — ลืม `#` ตัวเดียว (ใช้ register แทน immediate) โปรแกรมจะได้คำตอบผิดเงียบ ๆ ไม่มี error ฟ้อง การเดินเครื่องทีละคำสั่งดู register เปลี่ยนไป คือวิธีเดียวที่จะจับความผิดแบบนี้ได้

## 6. โจทย์ฝึก (2 ระดับ)

### ระดับ 1 — drill (ฝึกความแม่นยำ)

1. จงเขียน assembly (โดยไม่ดูเฉลย) ให้ `ADD R1, R1, #2` — แล้วแปลงเป็นเลข 16 บิตเอง (ใบ้: opcode ของ ADD = `0001`, R1 = `001`, และ `#2` ใน 5 บิต = `00010` และอย่าลืมบิต i = 1)
2. ในโปรแกรม `sum.asm` ถ้าเปลี่ยน `BRnz LOOP` เป็น `BRp LOOP` — โปรแกรมจะทำงานต่างจากเดิมยังไง? (ใบ้: ลอง trace รอบแรกดูว่า flag เป็นอะไร แล้ว BRp จะทำยังไง)
3. ทำไม "สูตรลบ" ต้องมี `NOT` ก่อน แล้วค่อย `ADD #1` — ถ้าเอา `ADD #1` ก่อนแล้วค่อย `NOT` จะได้ค่าอะไร?
4. ถ้าฟังก์ชัน `MULT` ไม่มีบรรทัด `RET` — หลังทำงานเสร็จ CPU จะไปทำคำสั่งอะไรต่อ? (ใบ้: ดูว่า PC ชี้ที่ไหน)

### ระดับ 2 — mini-project: นับถอยหลังแล้วพิมพ์

เขียนโปรแกรมใหม่ `countdown.asm` ที่ทำงานดังนี้:

1. ตั้ง R1 = 5 (เริ่มนับถอยหลังจาก 5)
2. วน loop: ลด R1 ลงทีละ 1 จนกว่าจะเป็น 0 แล้วหยุด
3. **ท้าทายขึ้น:** แปลง R1 เป็นตัวอักษร `'0'`–`'5'` แล้วพิมพ์ออกจอด้วยคำสั่ง `OUT` (ใบ้: `OUT` พิมพ์ตัวอักษร 1 ตัวตามค่าใน R0 — โค้ด **ASCII** (แอสกี = รหัสมาตรฐานที่กำหนดเลขให้ตัวอักษรแต่ละตัว เราเจอเรื่องนี้ในตอน 08) ของเลข `'0'` คือ `x30` ดังนั้น "แปลงเลข → ตัวอักษร" คือการบวก R1 ด้วย `x30` ก่อนพิมพ์; ส่วน `HALT` = `TRAP x25` และ `OUT` = `TRAP x21` เป็นบริการระบบที่ LC-3 เตรียมไว้ให้)

ตรวจผล: หน้าจอควรพิมพ์ `54321` เรียงลงมา (หรือเรียงเป็นบรรทัดต่อเนื่องกัน ขึ้นกับว่าคุณแทรก `TRAP x21` พิมพ์ตัวขึ้นบรรทัดหรือไม่) — ถ้าพิมพ์ได้ครบ 5 ตัวและหยุดเอง คุณเขียน loop + TRAP ได้จริงแล้ว

## สรุป

วันนี้เราเขียน "ภาษาเครื่อง" ด้วยมือเป็นครั้งแรก และเห็นทะลุสิ่งที่ Go ปิดบังไว้:

- **assembly** = เลขเครื่องในชุดคนอ่าน — `ADD R1, R1, #1` แปลเป็นเลข 16 บิตหนึ่งตัวแบบ 1 ต่อ 1 โดย **assembler**
- **LC-3** = ISA เพื่อการศึกษา 16 บิต · 8 register (R0–R7) · condition code N/Z/P · 15 คำสั่ง
- **loop** ไม่มีคำสั่งสำเร็จรูป — ใช้ "เปรียบเทียบ → ตั้ง flag → `BR` กระโดดกลับ" สร้างเอง
- **ฟังก์ชัน** = `JSR` (จำที่กลับไว้ที่ R7 แล้วกระโดด) + `RET` (= `JMP R7` กระโดดกลับ)
- **condition code N/Z/P** ถูกตั้งอัตโนมัติทุกครั้งที่เขียน register แล้ว `BR` อ่านมันเพื่อตัดสินใจ
- และที่ลึกที่สุด: **ทุก `if`/`for`/`func` ใน Go สุดท้ายก็คือกลไกกระโดด + flag + จำที่กลับเหล่านี้เอง**

จากนี้ไป เวลาคุณเขียน Go แล้วเห็น `for` หรือเรียกฟังก์ชัน คุณจะ "เห็น" ภาพเบื้องหลังทันที: register กำลังถูกบวก/เทียบ, flag ถูกตั้ง, PC กระโดดไปมา, R7 จำที่กลับไว้ — นี่คือความรู้สึกของคนที่เข้าใจ "พื้นฐานที่แท้จริง"

ตอนต่อไปเราจะก้าวจาก "ภาษาเครื่อง" เข้าสู่ **ภาษา C** — ภาษาที่ใกล้เคียง hardware มากกว่า Go แต่ยังอ่านง่ายกว่า assembly มาก เราจะเรียน pointer (ตัวชี้) และเห็นว่าทำไม C ถึงเป็น "ภาษาที่เปิดให้คุณจับหน่วยความจำโดยตรง" ซึ่งจะพาเราไปสู่เรื่อง memory safety และ buffer overflow ในตอนถัด ๆ ไป
